# CHANGELOG карты репозиториев

> История изменений [`repos-map.md`](./repos-map.md). Имя и путь карты **неизменны** — на неё
> ссылаются другие доки, поэтому версионируется содержимое, а не файл.
>
> **Когда писать сюда.** Появилась/исчезла репа · сменилась зона ответственности · переехал
> контент между репами · сверили карту с GitHub целиком. Мелкие правки формулировок — не пишем.
>
> **Версия карты по SemVer:** MAJOR — пересборка структуры карты · MINOR — добавлена/удалена репа ·
> PATCH — уточнение описания существующей.
>
> Строки, помеченные **`авто`**, дописаны деплойером (`templates/deploy.sh`) при создании новой репы.
> Их нужно раскрыть руками: описать зону и убрать маркер «НЕ ОПИСАНА» в карте.

## [3.3.0] — 2026-08-25

**Продолжение записи 3.2.1 — владелец уточнил, что имел в виду обе стороны:**
*«я именно это и хотел, смысл папки удалять то просто»* — локальную папку без GitHub-репы
удалять бессмысленно. Оба GitHub-репозитория (`bron-kerbosch`, `health-report-generator`,
оба `PUBLIC`, имена сверены `gh repo list` перед действием) **удалены `gh repo delete`**.
Необратимо: URL, история, звёзды не восстановить. Записи карты убраны целиком (не помечены
устаревшими — репы не существует нигде). Счёт **61 → 59 заведено**, оглавление
«🚀 Продукты» правлено (12 ссылок → 10, метка (11)→(9) по прежней методологии подсчёта).

Урок для следующего раза: 3.2.1 остановилась на «источник переехал», решив, что публичные
GitHub-записи вопрос отдельный и трогать их не нужно. Оказалось — владелец имел в виду
именно это с самого начала, просто не проговорил явно в первом сообщении; уточнение пришло
только когда он увидел на GitHub прежнее число 61.

## [3.2.1] — 2026-08-25

**Заказ владельца:** `bron-kerbosch` и `health-report-generator` — «даже не пет-проекты,
просто попробовал что-то», отдельная локальная репа для них избыточна. Приведены к паттерну
`vk-graph`: источник переехал в `it-base` (`02-code-archive/algorithms/bron-kerbosch` и
`01-projects/health-report-generator`), локальные standalone-репы удалены. Публичные записи
в карте (🌐, ADR-009) остались — это витринные GitHub-зеркала, публикуемые из `it-base`
по белому списку, их существование от локальной репы не зависело.

При переносе обнаружено: копии внутри `it-base` были **устаревшими** (застыли на дате
первичной миграции 20.08 — старый английский README в стиле публичного зеркала, без
`NOTES.md`). Актуальные версии (README на русском, `NOTES.md` с самокритикой, курсовая
под правильным именем файла) жили только в standalone-репах. Перенесён актуальный контент,
не то, что уже лежало в `it-base`.

## [3.1.0] — 2026-08-16

Пять реп получили настоящие записи. Карта сверена с GitHub целиком.

**Добавлены записи**

- `control-panel` — локальная панель управления системой. Границы прописаны
  с `mission-control` (что планируется ↔ чем это открывают) и с `productivity`

  GitHub Pages публикует пользовательский сайт только из репы `<логин>.github.io`.
  Единственное исключение из правила именования, отмечено прямо в записи.

**Исправлено — карта врала три недели**

Три витринных зеркала (`vk-graph`, `health-report-generator`, `bron-kerbosch`)
числились в разделе «Запланированы, ещё не заведены» с текстом «Ещё не заведена»,
хотя были созданы на GitHub 15.08 вместе с закрытием ADR-009. Раздел «Запланированы»
удалён как пустой, зеркала перенесены в «Продукты» с описанием зон и границ.

Проверка в деплойере этого не ловила: она искала имя репы подстрокой по всему файлу,
а имя встречалось — в разделе запланированных. Разбор дефекта — PIT-017.

**Счётчики приведены к факту**

- Репозиториев: 49 заведено · 3 запланировано → **54 заведено · 0 запланировано**
- Класс `product`: 6 → **11**
- Оглавление и итоговая строка пересчитаны

## [2.0.0] — 2026-07-24 — Проектные репы, статус актуальности, авто-сопровождение (MAJOR)

Карта перестала быть только списком зон жизни: добавлен второй раздел — **проектные репы**
(работающие продукты со своим SemVer и релизами), потому что их стало больше, чем «складов по
теме», и в старой структуре им не было места. Появился блок статуса, чтобы по карте было видно,
можно ли ей верить сегодня. И главное — карта больше не ведётся только руками: деплойер сам
регистрирует репу, которую завёл.

### Added
- **Блок «Статус карты»** — версия карты, дата актуальности, дата последней полной сверки с
  GitHub, способ сопровождения, ссылка на этот changelog.
- **Раздел «🛠️ Проектные репы»**: `personal-finance-dss`/`finpilot`, `dota-dossier`,
  `portrait-of-taste`, `exam-kit`, `character-a-analysis`.
- **Авто-регистрация.** `templates/deploy.sh` при создании новой репы дописывает её в карту
  заглушкой `🆕 … НЕ ОПИСАНА`, проставляет свежую дату актуальности и добавляет строку сюда.
- Этот файл.

### Changed
- Пояснение к маркеру 🆕 и правило «имя файла не меняем, версионируем содержимое».

### Notes
- Карта заведомо **неполная**: на аккаунте ~47 реп, описаны зоны жизни + подтверждённые
  проектные. Остальные подтянутся сами при первом же прогоне деплойера по их архивам —
  специально не выдумываю описания для реп, которых не видел.
- Следующая полная сверка глазами — при накоплении заглушек 🆕 или раз в ~2 месяца.
