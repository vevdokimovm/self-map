## §0а. Исполнитель — `scripts/make_document.py`

Кит описывает **чем что делается**; скрипт это делает. Документ без
исполнителя остаётся справкой, которую надо помнить (`69` §4е).

```bash
python3 scripts/make_document.py ONBOARDING.md --to pdf
python3 scripts/make_document.py данные.md --to xlsx --out ~/Developer/т.xlsx
python3 scripts/make_document.py книга.md --to epub --title "Название"
python3 scripts/make_document.py --selftest        # семь проверок
```

**Канарейка проверяет не только «файл создался»**, но и что `xlsx`
без markdown-таблиц **отказывает**, а не отдаёт пустой файл молча.

🔴 **Порог размера в канарейке зависит от формата.** Первая редакция
требовала >100 байт для всех — и `txt` (46 байт чистого текста) объявлялся
дефектом. Плоский текст **меньше исходника по построению**: разметка снята,
служебных структур нет. Единый порог сравнивал форматы разной природы.

## §1. 🔴 Почему без библиотек — и когда это перестанет быть верным

`openpyxl`, `python-docx`, `ebooklib` **не установлены**, и ставить их
не потребовалось: `EPUB` и `XLSX` — это **zip с фиксированной структурой XML**,
а `DOCX` умеет сам macOS.

| Довод за библиотеку | Довод против |
|---|---|
| проще писать сложное | 🔴 диск занят на 95 % |
| меньше своего кода | зависимость надо обновлять и она ломается |
| | простой документ собирается за 20 строк |

> **Правило: библиотека ставится, когда своё решение перестало быть проще.**
> Для «отдать человеку таблицу» — не перестало. Для «прочитать чужой
> `.xlsx` с формулами и стилями» — перестанет сразу, и тогда `openpyxl`.

## §2. PDF — единственный путь, переживший проверку

**Пять вариантов проверены, четыре отпали:**

| Способ | Итог |
|---|---|
| `cupsfilter` из RTF | 🔴 `No filter to convert from text/rtf` |
| `cupsfilter` из HTML | 🔴 то же для `text/html` |
| PyObjC + WebKit | 🔴 модуля `Quartz` нет ни в brew-, ни в системном Python |
| `groff -T pdf` | 🔴 `groff` в системе отсутствует |
| **Chrome `--headless --print-to-pdf`** | 🟢 **205 КБ за секунду** |

```bash
python3 scripts/md_to_pdf.py ONBOARDING.md --out ~/Developer/ONBOARDING.pdf
```

🔴 **Первая редакция была написана под `cupsfilter` по рассуждению**
(«штатное средство macOS, значит есть») и упала на первом запуске.
`PIT-184`: утверждение о своих возможностях требует того же основания,
что утверждение о состоянии диска.

🔴 **Chrome ищется поиском, а не одной строкой:** у владельца программы
разложены по папкам-категориям, реальный Chrome в `/Applications/browsers/`,
а в корне — алиас Finder. Проверка «есть ли `/Applications/Google Chrome.app`»
дала бы ложное «нет» (`PIT-187`).

## §3. EPUB — минимальная рабочая структура

Три обязательных файла, и порядок первого важен:

```
mimetype                  ← ZIP_STORED, БЕЗ сжатия, первым в архиве
META-INF/container.xml    ← указывает на .opf
c.opf                     ← метаданные + manifest + spine
p.xhtml                   ← содержимое
```

🔴 **`mimetype` кладётся без сжатия и первым** — иначе читалки отказываются
открывать файл. Это не рекомендация спецификации, а условие работы.

Проверено: `file --mime-type` → `application/epub+zip`.

## §4. XLSX — шесть файлов, из них два про связи

```
[Content_Types].xml           ← какой файл чем является
_rels/.rels                   ← корневая связь → workbook
xl/workbook.xml               ← список листов
xl/_rels/workbook.xml.rels    ← связь лист → файл листа
xl/worksheets/sheet1.xml      ← сами ячейки
```

**Ячейка с текстом пишется так** (`inlineStr` — без таблицы общих строк):

```xml
<c r="A1" t="inlineStr"><is><t>Привет</t></is></c>
```

🔴 **Половина структуры — файлы связей.** Забыть `_rels` = получить архив,
который Excel откроет как повреждённый; сообщение об ошибке при этом
не назовёт причину.

## §4а. 🔴 Куда класть собранное — в репу, а не в `~/Developer`

**Ошибка вахты 04.09.2026, поймана владельцем.** Собранный онбординг лёг
в `~/Developer/onboarding/` — **вне системы репозиториев**.

| Место | Что это |
|---|---|
| `~/Developer` | приёмник **артефактов**: архивы версий, разовые выгрузки |
| `<репа>/…/output/` | 🟢 всё, что должно жить, версионироваться и уехать в бэкап |

**Файл вне репы не попадает никуда:** ни в архив версии, ни в раздачу,
ни на GitHub. Он существует до первой чистки папки.

> Тот же класс, что `PIT-G`: артефакт положен туда, где его **один раз
> удобно оставить**, а не туда, где ему место по канону.

Собранные документы кита — [`output/`](output/), там же правило целиком.

## §5. Чего этот кит НЕ даёт

- **чтения чужих файлов.** Всё выше — про **создание**. Разобрать присланный
  `.xlsx` со стилями и формулами вручную дороже, чем поставить `openpyxl`;
- **PPTX** — не проверялся, повода не было. Структура сложнее XLSX;
- **вёрстки книжного качества.** PDF собирается браузером: это верстка
  веб-страницы, а не типографика. Для диплома или печати нужен LaTeX;
- **сохранения при обратной конверсии.** `md → docx → md` теряет разметку,
  и это свойство `textutil`, а не дефект.

`scripts/md_to_pdf.py` · `00-infrastructure/43-archive-naming-and-packaging.md`
(как называть то, что отдаёшь).
