# 09 — Кит автоматизации: как правило становится механизмом

> **Заказ владельца, 28.08.2026:** *«давай сделаем кит про разные механизмы
> автоматизации теории, правил — чтобы они происходили автоматически. Вот хуки,
> гейты, сторожа, скрипты и что там есть, у нас куча материала на это»*.
>
> Материал действительно есть и разбросан: правила в `08`/`69`/`80`, реализация
> в 29 скриптах, 4 хуках и 11 канарейках. **Кит не дублирует их** — он отвечает
> на два вопроса, на которые ни один из них не отвечает: *что уже
> автоматизировано* и *каким механизмом закрывать новое правило*.

---

## 1. Главный тезис

> **Правило, записанное текстом, — обещание. Механизм — гарантия.**

Это не мнение системы, а официальная позиция Anthropic (внешний ресёрч
28.08.2026, `reports/research/claude-official-practice-vs-internal-2026-08-28.md`
§1.1):

> «Claude treats them as context, **not enforced configuration**.»
> «Unlike CLAUDE.md instructions which are advisory, **hooks are deterministic**.»

**Проверено на себе, дважды.** Правило «проверяй вахту после `/login`»
существовало текстом и не сработало ни разу (`PIT-156`, затем 28.08.2026).
Причина не в забывчивости, а в **отсутствии события**, которое правило
запускает. Хук `watch-identity.sh` закрыл это за один заход.

---

## 2. Пять механизмов и когда какой брать

| Механизм | Срабатывает | Может ли остановить | Брать, когда |
|---|---|---|---|
| **Хук** | на событии харнесса (`SessionStart`, `Stop`, `PreToolUse`…) | да (`exit 2`) | нужно **детерминированно**, без участия памяти агента |
| **Гейт-скрипт** | по вызову в ритуале батча | да (ненулевой код) | проверка дорогая или нужна не всегда |
| **Канарейка** | внутри гейта, перед его выводом | да — роняет сам гейт | проверка сама может ослепнуть |
| **Сторож** (`ScheduleWakeup`) | по таймеру | нет, возобновляет | работа может оборваться и должна продолжиться |
| **Скилл** | по слэш-команде владельца | нет | нужна процедура, а не запрет |

### Правило выбора

```
Нужно, чтобы НЕ СЛУЧИЛОСЬ           → хук PreToolUse (exit 2)
Нужно, чтобы НЕ ЗАБЫЛОСЬ            → хук на событии (Stop/SessionStart)
Нужно, чтобы ПРОВЕРИЛОСЬ перед сдачей → гейт-скрипт в ритуале батча
Нужно, чтобы ПРОВЕРКА не соврала    → канарейка внутри неё
Нужно, чтобы РАБОТА не встала       → сторож
Нужно, чтобы ПРОЦЕДУРА была под рукой → скилл
```

🔴 **Не путать «нельзя» и «не забудь».** Хук, блокирующий работу ради
опрятности, дороже проблемы, которую решает: у системы **три** жёстких
стоп-класса (`06-autonomous-mode-kit/STOP_CONDITIONS.md`), и гигиена файлов
не среди них. Всё прочее — информирует, а не запрещает.

## 3. Что уже автоматизировано — реестр

### Хуки (`.claude/hooks/`, `.githooks/`)

| Хук | Событие | Что делает | Блокирует |
|---|---|---|---|
| `watch-identity.sh` | `SessionStart` | определяет вахту по `~/.claude.json`, кричит при смене личности | нет |
| `task-hygiene.sh` | `Stop` | считает закрытое в рабочих файлах задач, зовёт вынести в логи | нет |
| `ritual-gate.sh` | `Stop` | ритуал закрытия батча | да |
| `protect-base-mirror.sh` | `PreToolUse` (Edit/Write) | не даёт править `_base/` — это копия, не оригинал | **да** |
| `.githooks/pre-commit` | коммит | секреты · вес и форматы · версия деплойера · свежесть README | **да** |

### Гейты и инструменты (`scripts/`, 29 штук)

| Инструмент | Отвечает на вопрос |
|---|---|
| `revision_check.py` | цела ли репа: ссылки, реестры, числа в прозе, точка входа, размер |
| `readme_status_gate.py` | не отстал ли README от `VERSION` (`--create` заводит блок, `--fix` чинит) |
| `tasks_census.py` | сколько открытого и где; разрывы между доской и репами |
| `secrets_scan.py` | нет ли секрета в материале |
| `check_shell_antipatterns.py` | `for X in $VAR` и прочее, что ломается под zsh |
| `check_incoming_refs.py` | не сломает ли перенос папки ссылки в конфигах |
| `deploy_version_gate.py` | не разошлись ли копии `deploy.sh` |
| `owner_blockers.py` | какие репы ждут владельца |
| `batch_duration_report.py` | сколько реально занимает батч |

### Канарейки — 11 внутри `revision_check.py`, 6 скриптов с `--selftest`

```
selftest_cjk · selftest_mixed_script · selftest_exec_bits
selftest_registry_dupes · selftest_section_dupes · selftest_campaign_log
selftest_dangling_refs · selftest_resume_point_refs
selftest_stale_version_prose · selftest_card_heading_levels
selftest_prose_counts
```

**Зачем канарейка отдельно от проверки.** Проверка может ослепнуть — и это
не гипотеза: за 28.08.2026 семь раз подряд гейт молча давал неверный ответ,
потому что был откалиброван под один частный мир (`PIT-153`, `157`, `158`,
`159`, `160`, `085`, плюс языковой). Канарейка проверяет **различение**:
что проверка краснеет там, где должна, и молчит там, где не должна.
Смягчение, которое ослепило бы её, роняет её саму.

## 4. Как завести новый механизм — порядок

1. **Назвать событие.** Нет события — нет механизма, есть пожелание.
   Это единственная причина, по которой правило про вахту не работало.
2. **Выбрать тип** по таблице §2.
3. **Написать так, чтобы отказ был громким.** Хук, молча вернувший пустое, —
   худший исход: он выглядит работающим. Первая редакция
   `watch-identity.sh` читала email из keychain (там только токен) и вышла
   с кодом 0 — поймано первым прогоном, не в проде (`PIT-016`).
4. **Проверить ВЫВОД, а не факт запуска.** Обе ветки: срабатывает там, где
   должен, и молчит там, где не должен.
5. **Завести канарейку**, если механизм — проверка.
6. **Записать в этот реестр** (§3) и в `08-automation-triggers.md`, если
   у механизма есть событие-триггер.

### Четыре правила, выведенные из собственных ошибок

| Правило | Откуда |
|---|---|
| Обход проверки ценой ухудшения содержания = чинить надо **проверку** | `PIT-159` |
| Массовый инструмент **умножает** неверный допуск на охват | `PIT-160` |
| Гейт, кричащий 2659 раз ради одной правоты, **не читают вовсе** | `PIT-085` |
| Сухой прогон обязан проверять **всё**, что проверяет реальный | `PIT-161` |

## 5. Чего в ките намеренно нет

- **Готовых хуков «на все случаи».** Хук пишется под конкретное событие
  конкретной репы; универсальный набор был бы шумом, который отключат целиком.
- **Автоматического переноса задач в логи.** Заказ владельца звучал как
  «выполняется → проставляется и выносится», но перенос требует **суждения**:
  в какой приёмник, с какой формулировкой, что сохранить. `task-hygiene.sh`
  поэтому **считает и зовёт**, а не переносит: инструмент, притворяющийся,
  что решает второе, хуже отсутствующего (`71` §7г-бис).
