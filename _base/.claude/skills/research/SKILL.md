# `/research` — многошаговое исследование темы

> 🔴 **Архитектурная поправка 28.08.2026.** Первая версия делегировала всё
> одному агенту `researcher`, который сам должен был параллелить через
> вложенный `Agent`. Официальная документация Claude Code подтверждает, что
> вложенность до 3 уровней поддерживается по умолчанию
> (`code.claude.com/docs/en/sub-agents` — «Let subagents spawn their own
> subagents»), но **два независимых живых прогона это не подтвердили** —
> агент реально не смог вызвать `Agent` изнутри себя, хотя тул был в его
> `tools`. Расхождение между документацией и эмпирикой не разбирал глубже —
> обошёл его тем, что уже дважды подтверждено рабочим в этой же сессии:
> **параллельный `Agent` из текущей, верхнеуровневой сессии.**

## Роли — как в оригинале, но лидер это ты сам (текущая сессия)

1. **Классифицируй запрос** — depth-first / breadth-first / straightforward
   (`.claude/agents/prompts/research_lead_agent.md`, раздел «Query type
   determination», если нужны примеры).
2. **Реши число субагентов** по таблице сложности (1 / 2-3 / 3-5 / 5-10,
   по умолчанию 3) — `.claude/agents/researcher.md` шаг 2.
3. **Запусти всех субагентов одним сообщением, параллельно** — вызов `Agent`
   (`subagent_type: general-purpose`) N раз в одном ответе, не по одному.
   Каждому — плотный промпт по методу `.claude/agents/prompts/
   research_subagent.md`: один угол, бюджет вызовов, `WebSearch` короткими
   запросами + `WebFetch` для полных страниц, критическая оценка источников,
   отчёт тебе — не готовый текст для пользователя.
4. **Дождись всех, синтез делай сам** — ты, лидер, никогда не поручаешь
   финальный текст субагенту (жёсткое правило оригинала). Ищи противоречия
   между отчётами субагентов, называй их прямо.
5. **Цитирование — отдельным финальным проходом по своему же тексту**, не
   вперемешку с синтезом (`.claude/agents/prompts/citations_agent.md` —
   принцип, адаптация: не отдельный вызов, а сознательная вторая читка).
6. **Сохрани результат файлом**, не только в чат:
   - тема касается живого дока системы → правка туда, как раздел, с датой
     и источниками (образец: `14-claude-usage-and-limits.md` §8);
   - тема новая → `base-repo/reports/research/<slug>-YYYY-MM-DD.md`.
7. **Передай владельцу путь к файлу** — находка без файла теряется вместе
   с сессией (`20-knowledge-capture-protocol.md`).

## Когда агент `researcher` всё же уместен

Тема **straightforward** (один факт, один угол) — тогда один делегированный
`Agent(subagent_type: researcher)` экономит твой контекст и не требует
оркестрации. На **breadth/depth-first** темах — не делегируй лидерство,
веди сам по шагам 1-7 выше (см. поправку).

## Когда НЕ вызывать вообще

- Быстрая справка/одно число/факт — обычный `WebSearch` дешевле.
- Тема уже отвечена в базе — `Grep`/`Glob` по репе ДО похода в веб.

## Честный статус

**Не полный паритет** с Research-режимом claude.ai — там нативный
`run_blocking_subagent`, внутренние тулы (Slack/Gmail/Drive), до 20
субагентов. Здесь — `Agent`/`WebSearch`/`WebFetch`, параллельность через
верхнеуровневую сессию, не через нативный вложенный примитив (эмпирически
не сработал дважды, расхождение с доками не разобрано). Методология
(классификация, синтез только лидером, честные противоречия, цитирование
отдельным проходом) перенесена полностью — это несёт основную ценность
процесса, не только инфраструктура параллелизма.

**Статус, 28.08.2026:** архитектура пересмотрена после двух живых
прогонов агента `researcher`, оба реально выполнили работу (52 принципа
и карта источников скиллов/плагинов соответственно), но без реальной
параллельности внутри себя.
