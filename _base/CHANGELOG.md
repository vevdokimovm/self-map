  есть утверждение о состоянии после второго прогона. Шаблон и три кейса-образца.

## [1.22.0] — 2026-07-29 — Тесты пересобраны по зонам ответственности (MINOR)

Ревизия показала, что дело было не в отдельных багах, а в устройстве набора: кейсы писались
по следам находок, то есть покрывали ровно те пути, по которым уже прошёл человек. Такой
набор структурно не способен опередить находки — он растёт вслед за ними. Сквозная
нумерация 1…56 заменена девятью зонами ответственности, каждая названа по **последствиям
отказа**, а не по устройству кода.

### Changed
- **`tests/test_deploy.sh`**: кейсы получили идентификаторы зон (`A1`, `C4`, `G2`).
  Буква говорит, что проверяется; цифра — номер внутри зоны. Прогон печатает покрытие
  по зонам, поэтому тонкое место видно **до** того, как в него провалятся.
- **`tests/README.md`** пересобран: девять таблиц по зонам с формулировкой «отказ означает…»,
  правила поддержки, честный список непокрытого и известное ограничение (кейсы делят
  песочницу, прогонять целиком).

### Added
- **`reports/incidents/reactive_testing_retrospective.md`** — разбор ситуации: хронология
  «кто нашёл каждый дефект» (один из семи — тесты), почему зелёный набор молчал, что
  изменено в процедуре, три новых правила.

### Fixed
- **Выравнивание в сводке по зонам.** `printf` считает байты, а кириллица многобайтовая —
  колонки разъезжались. Убраны колонки, разделитель вместо padding.

### Verified
- 197 проверок зелёные, 56 кейсов, сумма по зонам сходится с итогом.

### Notes
- Зелёный набор говорит ровно одно: ранее найденные ошибки не вернулись. Про то, чего
  в наборе нет, он не говорит ничего — и это молчание легко принять за отсутствие проблем.

## [1.20.2] — 2026-07-29 — Безопасность чистки ассетов: два дефекта и покрытие тестами (PATCH)

Единственная разрушительная операция деплойера — удаление ассетов — была написана, но
никогда не выполнялась: тестов на неё не было, а стаб `gh` не умел `delete-asset`.
Прямой вопрос «а это точно проверено?» оказался обоснованным: в коде нашлись два дефекта.

### Fixed
- **Удаление предшествовало загрузке замены** — при обрыве сети релиз мог остаться без
  ассета вовсе. Порядок изменён: сначала загрузка и подтверждение, потом снятие дубля.
- **Чистка была недостижима** у релизов, где канонический ассет уже есть, — то есть ровно
  в том сценарии, ради которого флаг и вводился.

### Added
- Предупреждение, если `DROP_LEGACY_ASSETS=1` задан без режима ревизии.
- Поддержка `DRY=1` для чистки.
- **Тесты 49–51** на разрушительный путь, включая проверки того, что удалять нельзя.

### Verified
- 174 проверки зелёные, 51 кейс.

### Notes
- Урок: код, который не выполнялся ни разу ни в одном тесте, нельзя называть рабочим —
  особенно если он необратим. Здесь путь был недостижим и содержал ошибку порядка операций,
  и оба факта вскрылись только при попытке написать тест.

## [1.7.0] — 2026-07-09 — Универсальный деплойер: любая репа из архива одной командой

Ответ на вопрос владельца «почему деплой версионный?»: универсальное ядро (publish.sh) было,
не хватало универсальной внешней обвязки «zip → push» как у FINPILOT-публикатора. Теперь она —
канон в репе; версионные одноразовые обёртки больше не нужны.

### Added
- **`templates/deploy_from_zip.sh`** — универсальный деплой любой репы системы из архива:
  `zsh deploy_from_zip.sh <repo>-vX_Y_Z.zip` → sha256-сверка (`SHA=`), разворот обёртки
  (PIT-007), **маркеры корня перед деструктивом**, клон, чистая замена дерева кроме `.git`
  (PIT-004), `add -A -f` (PIT-006), push с ретраями, автопроверка **«файлов в коммите ==
  файлов в дереве»** (строгое равенство вместо «больше нуля»), затем сам вызывает
  `publish.sh --version <V> --auto-asset` из дерева. Имя репы и версия выводятся из обёртки
  `<repo>-vX_Y_Z/` и/или файла `VERSION` (оба есть → обязаны совпадать, иначе стоп; ни одного →
  только push с предупреждением). `ALSO_PUBLISH="X.Y.Z ..."` — доделка старых релизов
  (заглушечные описания, недостающие ассеты) тем же прогоном. Пара к publish.sh: тот работает
  внутри клона, деплойер — снаружи. Вписан в `25` §3, триггер в `08`, карта README,
  START-HERE шаг 6.

### Changed
