# Инструменты: что уже написано и где потолок каждого

> **Главное.** Перед тем как писать свой скрипт — прочитать эту страницу. Первый прогон
> синтеза начался с написания собственного аудитора при живом `collect_to_base.py`,
> который делает то же самое и лучше.

---

## 1. Разделение труда: скрипт против модели

Зафиксировано в mission-control:ADR-010 одной строкой:

> **Где решает совпадение — скрипт. Где решает смысл — модель.**

| Задача | Кто | Почему |
|---|---|---|
| Клонировать 57 реп, разложить копию, закоммитить, запушить | скрипт | детерминировано, повторяемо, быстро |
| Найти файлы с одинаковым sha1 в N репах | скрипт | точное сравнение |
| Понять, что четыре разных документа — про одно и то же | **модель** | нужен смысл, не хеш |
| Решить, нужен ли этой репе этот раздел базы | **модель** | нужен контекст репы |
| Переписать четыре протокола в одну методичку | **модель** | это письмо, а не копирование |

## 2. `sync-base.sh` v2.1 — раздача вниз

`mission-control/scripts/sync-base.sh`, 82 строки.

**Что делает:** клонирует базу и все неархивные репы через `gh`, для каждой приватной
удаляет `_base/`, копирует базу целиком, чистит `.git` и `.repo-id`, переименовывает
`VERSION` → `BASE_VERSION`, кладёт `DO-NOT-EDIT.md`, коммитит и пушит.

**Что в нём хорошо:**
- **Предохранитель по факту, а не по списку.** Публичность проверяется через
  `gh repo view --json isPrivate` для каждой репы, независимо от `SKIP_MIRRORS`. Список —
  намерение, видимость — факт. Именно забытая строка в списке вызвала утечку базы
  в публичный `finpilot` 08.08.2026.
- Не требует заранее скачанных реп — клонирует сам.

**Где потолок — то, ради чего операцию делают вручную:**

| Ограничение | Следствие |
|---|---|
| **Копирует базу целиком, без разбора** | `chess` получает `04-product-dev-kit` (TDD-гейт, CI, ADR-дисциплина для IT-продукта), `01-claude-context` (профиль, здоровье, вера), `00-manifest-aot` (16 архетипов). Ни одно не имеет отношения к шахматам |
| **Лекарство конкурирует с болезнью** | ADR-003 обосновывает вложение тем, что правила должны быть в сессии. Но 3,2 МБ базы в архиве репы съедают то самое контекстное окно, ради которого существует канон «один zip = полный контекст» |
| **Видит только `_base/`** | Старая плоская копия базы в собственной `00-infrastructure/` репы скрипту не видна. Он физически не может завершить миграцию поколений — а она не завершена в 12 репах |
| **Актуальность = совпадение версии** | `if [ "$cur" = "$BASE_VER" ] → пропустить`. Если `_base/` побит руками, но `BASE_VERSION` совпал — скрипт пройдёт мимо |
| **Нет режима «что именно этой репе нужно»** | Решение о составе принять невозможно: у скрипта нет понятия «нужность» |

## 3. `collect_to_base.py` v2.0.0 — сбор вверх

`mission-control/scripts/collect_to_base.py`, 556 строк. **Перенос, а не отчёт.**

**Правило переноса — объективное, без гадания:**

- файл в ≥ MIN репах **и** содержимое всех копий одинаково → переносим;
- копии различаются → конфликт, не трогаем;
- реже порога → остаётся местным;
- путь в базе занят другим содержимым → не трогаем без `--overwrite`.

**Что закрыто в v2.0.0** (аудит 13.08.2026, 40 реп, покрытие 76,4 %): корень репы раньше
не сканировался вообще — мимо проходили `START-HERE.md` (25 реп), `00-CLAUDE-STOP.md` (11),
`repos-map.md` (3). Ключом кандидата стал путь, а не имя файла.

**Где потолок — прямо признано в mission-control:ADR-010:**

> Скрипт не понимает смысла и не может отличить «два документа про одно» от «два документа
> про разное». Четыре похожих, но не идентичных протокола он либо объявит конфликтом,
> либо не заметит вовсе — **свести их в одну методичку он не может в принципе.**

Отсюда и вводился Claude Code. Роадмап P1.7: «`collect_to_base.py` сводить документы
по смыслу не умеет и не научится».

| `enumerate_candidates.py` | опись кандидатов | 🗑 **отставлен и удалён**: список каталогов содержания вписан по памяти, реальные пути не проверены → 545 файлов справочника в «читать». Разбор — `../../reports/incidents/enumerator_invented_paths_incident.md` |

| `revision_check.py` (базовый) | гейт ревизии | пополнен за прогон: **канарейка на токен-слип** и **проверка смешения кириллицы с латиницей в имени**. Обе поймали реальные случаи в первую же минуту |

## 🔴 Правило этого каталога

**Инструмент, признанный негодным, описывается здесь В МОМЕНТ — с указанием потолка.**
Иначе его напишут заново: за один прогон это случилось дважды (PIT-032, PIT-074).

Формат записи о потолке — не «работает / не работает», а **где именно он врёт**:
охват в процентах, класс пропускаемого, условие, при котором ошибается молча.
«Не подошёл» — бесполезная запись; «видит 36 % и не видит `standards/`» — рабочая.

**Главный вывод прогона про инструменты:** автоматизируется **механика**, не **суждение**
(PIT-081). Годятся перечисление, хэши, арифметика. Как только инструменту нужен список
«что чем считать» из головы — он не пишется.
