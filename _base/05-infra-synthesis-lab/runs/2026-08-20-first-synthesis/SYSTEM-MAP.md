# Карта системы репозиториев — полное понимание

**Составлено:** 2026-08-20 · **Источники:** 41 документ базы + 22 протокола `mission-control`
+ 11 ADR + проверка диска и GitHub

> **Разделение источников.** Помечено явно: **[док]** — прочитано в документации (замысел),
> **[диск]** — снято командой (факт). Расхождения между ними вынесены в §14.

# 1. Что это за система и зачем

**57 приватных и публичных репозиториев на `vevdokimovm`, организованных как ООП-иерархия.**
Одна репа = одна зона жизни, зоны не пересекаются.

Это **не витрина** — это персональная система анализа и поддержания информации в актуальном
состоянии. Отсюда следует: грузится всё, включая персональные данные, риски осознаны.
Единственное железное исключение — **секреты** (пароли, ключи, токены, данные карт).

Главный принцип, ради которого всё построено:

> База знаний ценна не объёмом, а **актуальностью, отсутствием дублей, обобщённостью
> и лёгкостью**. Большой сырой файл → тезисный `.md` с полной сутью и логикой.
> Всё, что генерируется или дублируется — вон. Всё, что читается один раз — в тезис.

Практическая причина лёгкости: **чем легче репа, тем дольше Claude видит её целиком,
а не через RAG.** Тяжёлая репа = Claude находит не то.

# 2. Иерархия: базовый класс и наследники

`base-repo` — **базовый класс** в терминах ООП. Единственный источник правды по неймингу,
структуре, шаблонам и протоколам. Меняешь правило один раз здесь — применяется ко всем.

```
base-repo (родитель)
   ├── правила ──────────► 00-infrastructure/ (53 нумерованных дока)
   ├── шаблоны ──────────► templates/
   ├── отчётность ───────► reports/ (шаблоны, гайды, реестры, папки по типам)
   ├── карта ────────────► repos-map.md
   └── киты ─────────────► 00-manifest-aot/ · 01-claude-context/ · 02-methodology-library/
                            03-role-kit/ · 04-product-dev-kit/ · 05-infra-synthesis-lab/
        │
        │  раздача 1-в-1
        ▼
<любая репа>/
   ├── _base/               ← ЗЕРКАЛО базы. Чужое. Затирается целиком при раздаче.
   │    ├── BASE_VERSION    ← не VERSION (иначе спутается с версией самой репы)
   │    └── DO-NOT-EDIT.md
   ├── 00-infrastructure/   ← СВОЁ. Локальные протоколы этой репы.
   └── <тематический контент>
```

**Правило одной строкой: всё, что в `_base/` — не моё; всё, что вне — моё.**

Это снимает задачу трёхстороннего слияния целиком:

| Направление | Операция | Конфликты |
|---|---|---|
| **Вниз** (раздача) | `rm -rf _base && cp -r <база> _base` | невозможны — в `_base/` нет ничего локального |
| **Вверх** (сбор) | сравнение `00-infrastructure/` с `_base/00-infrastructure/` | нет — результат список кандидатов, не автомерж |

**Решение владельца (2026-08-20):** база отдаётся **1-в-1 в КАЖДУЮ репу**, целиком, без
профилей и урезаний. В этом весь смысл — единообразие. Профильная раздача по классу репы
рассмотрена и **отвергнута**.

# 3. Две инфраструктурные репы и граница между ними

| | `base-repo` | `mission-control` |
|---|---|---|
| Отвечает на | **как работать** | **что делать и куда идти** |
| Содержит | правила, стандарты, протоколы, шаблоны | состояние: цели, задачи, планы, решения |
| Меняется | редко, осознанно, версией | постоянно |
| Зависит от жизни | нет | целиком |
| Раздаётся в репы | да, 1-в-1 | нет, один экземпляр |

**Проверочный вопрос: изменится ли этот файл, если завтра поменяются мои цели?**
Да → `mission-control`. Нет → `base-repo`.

Примеры на границе: «как оформлять ROADMAP» → база (правило). «Что в моём роадмапе сейчас» →
`mission-control` (состояние). «Формат ADR» → база. «Почему выбрал МИСИС, а не ИТМО» →
`mission-control`.

`mission-control` держит: `MISSION.md` (горизонты 2/1/5/10 лет), `ROADMAP.md` (P1/P2/P3 по всей
системе), `TASKS.md` (действия владельца вне песочницы), `BACKLOG.md`, `BOARD.md`, `INBOX.md`,
`HANDOFF.md`, 22 протокола, 11 ADR, `plans/`, `daily/`, `profile/`, `scripts/`.

# 4. Пять классов реп

Класс машиночитаемый, лежит в `.repo-class`. Отвечает на три вопроса сразу: навсегда или
временно · можно ли вливать/выносить · требовать ли CHANGELOG и релизы.

| Класс | Что это | Судьба | Сколько |
|---|---|---|---|
| **infra** | инфраструктура системы, тематики нет | вечно | 2 |
| **core** | зона жизни | вечно, не мерджится никуда | 14 |
| **satellite** | самостоятельный домен, вынесен ради удобства | отдельно неопределённо долго | 23 |
| **temp** | часть core-репы, вынесенная из-за объёма | **вернётся в родителя** | 6 |
| **product** | работающий продукт | своя жизнь, релизы | 11 |

**Главное различие — satellite против temp.** Оба вынесены «ради удобства», но будущее разное:
спутник это свой домен (шахматы не часть чего-то большего), а временная репа — раздел чужой
репы, и **родитель у неё указан с первого дня**. Иначе через год никто не вспомнит, что куда
вливать, и все временные станут вечными.

**Смена класса правится в трёх местах:** `.repo-class`, GitHub topics, `repos-map.md`.
Расхождение означает, что правде верить нельзя нигде.

# 6. Анатомия репы: обязательные файлы

## 6.1. Опознавательные знаки

| Файл | Что отвечает | Меняется |
|---|---|---|
| `.repo-id` | `vevdokimovm/<имя>` — **принадлежность** | один раз при заведении, **никогда** больше |
| `VERSION` | какая версия лежит в дереве **прямо сейчас**, без `v` | каждый релиз |
| `.repo-class` | машиночитаемый класс | при смене класса |
| `.repo-meta` | метаданные для деплойера | скриптом |

**Почему два файла, а не один:** `.repo-id` и `VERSION` отвечают на разные вопросы и меняются
с разной частотой. Держать принадлежность и версию вместе — рисковать принадлежностью при
каждом релизе.

Деплойер читает `.repo-id` **прямо из zip**, до создания репы. Несовпадение → отказ,
репа-сирота не заводится. Это защита от «переименовал архив — уехал не туда».

## 6.2. Четыре журнала, четыре вопроса

| Файл | Вопрос | Содержит |
|---|---|---|
| `ROADMAP.md` | **что дальше** | будущее, только открытые пункты, P1/P2/P3 |
| `ROADMAP_HISTORY.md` | **что построили и когда** | закрытое, с версией |
| `TASKS.md` | **что я должен сделать сам** | действия владельца вне песочницы |
| `TASKS_HISTORY.md` | **что я уже сделал** | закрытое, с **датой** (не версией) |

Плюс два соседних: `CHANGELOG.md` — «что вошло в версию» (поставка), `WATCHLOG.md` §0 —
«где стоим прямо сейчас» (точка остановки).

**Ключевое разделение ROADMAP/TASKS:** ROADMAP — что построить **в проекте** (может ассистент);
TASKS — что сделать **владельцу** вне репы (получить доступ, сходить, прислать, решить).
Разные исполнители, разные блокировки. Смешивать нельзя.

**ROADMAP строится по приоритетам, не по вехам.** Веха отвечает «когда» и врёт, как только
съезжает срок. Приоритет отвечает «зачем сейчас» и верен, пока не изменилась цель.
**P1 не копится: больше пяти пунктов — это список желаний.**

Обязательный раздел в конце — **«Что осознанно НЕ делаем»** с обоснованием. Без него
отвергнутые идеи возвращаются по кругу каждые пару месяцев.

Чего в этих файлах быть не должно: текущей версии (она в `VERSION`), пересказа CHANGELOG,
**сроков в ROADMAP** (карта, не план-график), задач ассистента в TASKS.

## 6.3. `WATCHLOG.md` — вахтенный журнал

Репу ведут с **четырёх аккаунтов Claude (V/J/M/S)** по очереди. Общей памяти между аккаунтами
нет — журнал самодостаточен для любого входящего.

| Секция | Что |
|---|---|
| §0 | **RESUME POINT** — где стоим, что дальше |
| §1 | аккаунты и протокол приёмки вахты |
| §2 | направление репы: тема, зачем, что НЕ входит |
| §3 | **ровно 10** последних изменений (добавил сверху — удали снизу) |
| §4 | находки и грабли — **не переоткрывать** |
| §5 | правила этой репы сверх общих |

**Протокол непрерывности:** журнал обновляется **по ходу** работы, не в конце. Токены кончаются
внезапно. В любой момент файл обязан отражать реальную текущую точку.

**Журнал ≠ CHANGELOG.** Журнал — снимок «где мы», CHANGELOG — полная история. Находка живёт
в типизированном отчёте, а в журнал попадает только **ссылка-выжимка**.

## 6.4. `README.md` — витрина

Порядок секций жёсткий: заголовок → описание 1–2 предложения → заметка о языке →
`## Highlights` (витрина со ссылками) → `## Repository map` (**таблица, обязательна**) →
доп. секции → `## Data & privacy note` → дубль на русском → контакты.

## 6.5. Прочее

`START-HERE.md` (вход) · `00-CLAUDE-STOP.md` (🔴 читать до первого действия) ·
`.gitignore` из шаблона · `.githooks/pre-commit` (секреты и тяжёлое)

# 7. Система отчётности

## 7.1. Диспетчер: триггер → тип → шаблон → папка → реестр

| Триггер | Тип | Папка | Реестр |
|---|---|---|---|
| Дефект с влиянием | **Инцидент** (post-mortem) | `reports/incidents/` | `incidents_summary.md` |
| Искали причину, **дефекта НЕ оказалось** | **Расследование** | `reports/investigations/` | `investigations_summary.md` |
| Найден конкретный баг | **Bug card** | `reports/incidents/` | `incidents_summary.md` |
| Архитектурное решение | **ADR** | `reports/adr/` | сквозная нумерация |
| Слияние линий вахт | **Merge-отчёт** | `reports/merges/` | — |
| Повторная ошибка воркфлоу | **Pitfall** | `reports/pitfalls.md` | сам файл |
| Измерить неизвестную величину | **Эксперимент** | `reports/experiments/<тема>/` | README темы |

Сводные: **Release-отчёт** · **Ситуация-репорт** (крупная кампания: было → сделали → что пошло
не так → уроки) · **Security-аудит** · **Ревизия** · **SRS** · **Тест-отчёт**.

## 7.2. Различение по сути

- **Инцидент vs расследование** — была ли реальная поломка. Да → инцидент. Причину искали,
  дефекта нет → расследование, и главный вопрос «сломано ли?» получает честное «нет».
- **Расследование vs pitfall** — была ли причина неочевидной. Докапывались → расследование.
  Причина известна сразу, повтор привычки → pitfall (одна строка).
- **ADR** — про **выбор из альтернатив** с обоснованием, не про поломку.

## 7.3. Автофиксация: семь триггеров T1–T7

Сработал класс события → артефакт создаётся **сразу**, без просьбы:

| # | Триггер | Артефакт |
|---|---|---|
| T1 | грабли инструментов/окружения | pitfall `PIT-NNN` |
| T2 | инцидент | post-mortem |
| T3 | баг с поучительным корнем | post-mortem + CHANGELOG |
| T4 | находка про канон/предмет | заметка в `WATCHLOG §4` |
| T5 | архитектурное решение | ADR |
| T6 | шаблонное действие | методичка/гайд |
| T7 | урок процесса | правило в профильную методичку |

**Обязательные поля:** **корень** (не симптом) и **свой вклад** (что сделал не так сам).

**Порог против шума** — фиксируем, если выполнено хотя бы одно: повторяемость · цена ошибки ·
неочевидность. При сомнении — фиксировать («больше = лучше»: лишний отчёт уберут на ревизии,
потерянное знание — нет).

**Как это выходит автоматическим:** Claude между сессиями не работает, поэтому «автоматизм» =
дисциплина вахты + **ворота закрытия батча** (триггер не оформлен → батч не готов) +
строка-указатель в инструкциях проекта.

> Знание, добытое дорого, но не записанное — потеряно. Фиксируй **в момент**, а не «в конце
> сессии».

# 8. Пять правил чистоты

1. **Актуальность.** Устаревшее — обновить или удалить. Наличие файла значит «держу
   и поддерживаю», а не «свалил и забыл».
2. **Без дублей — одна тема, одно место.** Дубли жрут токены и **сбивают RAG-выборку**,
   из-за чего Claude находит не то.
3. **Обобщённость — тезис, а не копипаст.** Канон — твой тезисный разбор, источник рядом
   как приложение.
4. **Лёгкость.** Репа — хранилище знаний, а не архив файлов.
5. **Только своё в своей зоне.** Чужое — в свою репу или `misc-vault`.

Отдельный принцип для исследовательских реп: **наличие ≠ согласие**. В `truth-seeking`
материал значит «разбираю», а не «согласен».

## 8.1. Пороги размера и форматы

| Порог | Значение |
|---|---|
| 🟢 ≤50 МБ | норма и цель |
| 🟡 100 МБ | мягкий потолок, терпимо в исключениях |
| 🔴 500 МБ | жёсткий — выше Claude физически не принимает архив целиком |

| Формат | Правило |
|---|---|
| `.docx`/`.pptx`/`.odt` | **не место в репе** → `.md`-конспект 1:1 по смыслу |
| `.zip`/`.rar` | **не место** → распаковать и разобрать. Архив ≠ знание |
| `.pdf` | только ≤5 МБ и как первоисточник/результат |
| картинки | только по делу, каждая **≤0.5 МБ**; TIFF → PNG всегда |
| `.html` | ок для результатов анализа и дашбордов |
| скрипты | ок; артефакты сборки (`.exe`, `.o`, `bin/`, `obj/`, `.cbp`) — **вон** |
| `.md` | основа; держать <2 МБ (иначе GitHub не отрендерит) |

Лимиты GitHub [док]: файл >50 МиБ — warning · >100 МиБ — **блокировка пуша** · браузер 25 МиБ ·
рендер `.md`/Mermaid только <2 МБ · рендеримых в diff максимум 25 · репа софт ~1 ГБ, хард ~5 ГБ.

# 9. Версионирование: три механики

| Механика | Когда | Примеры |
|---|---|---|
| **Версия** (`VERSION` + тег + релиз) | сущность отдаётся наружу как единица, откатывается целиком, на неё ссылаются по версии | репа, продукт, матмодель, набор стандартов |
| **История** (`<имя>-CHANGELOG.md` рядом) | имя и путь **обязаны остаться прежними**, сущность одна и всегда актуальна | `repos-map.md`, карты, реестры, живые справочники |
| **Обе** | часть живёт своим ритмом внутри версионируемой репы | `repos-map.md` внутри `base-repo`; скрипты в `templates/` |

**Отдельное правило для инструментов:** если у штуки есть **поведение, которое можно сломать**,
у неё есть версия (`SCRIPT_VERSION` в шапке) и журнал. Смена дефолтного поведения — **MAJOR**,
даже если снаружи ничего не поменялось.

**Гигиена:** механику заводим **сразу**, не задним числом. История, начатая постфактум,
восстанавливается только по памяти, а память врёт. Сомневаешься — **история дешевле**.

# 10. Упаковка и доставка

## 10.1. Имя архива

```
<repo>-vX.Y.Z.zip        # dota-dossier-v2.12.0.zip
```

Внутри версии — **только точки**. Между именем и версией — дефис. Легаси-форматы принимаются
(подчёркивания, дефисы, без `v`, хвосты `copy`/`(1)`), но помечаются `→ канон: …`.
В релиз ассет уезжает **всегда с точками**.

## 10.2. Упаковка — причина №1 сбоев доставки

```
dota-dossier-v2.12.0.zip
└── dota-dossier-v2.12.0/      ← ОДНА папка-обёртка
    ├── README.md              ← маркер корня, обязателен
    ├── VERSION                ← обязан совпасть с именем архива
    └── ...
```

| Как ломается | Что происходит |
|---|---|
| плоская упаковка | однажды **снесла репу** при `rsync --delete` |
| `__MACOSX`/`.DS_Store` рядом с обёрткой | в корне уже не один объект → обёртка не разворачивается |
| двойная обёртка | то же уровнем глубже |
| нет `README.md` | деплойер **отказывается** чистить репу — защита от сноса не туда |
| `VERSION` ≠ имени | версия пропускается: признак, что подсунут не тот архив |

```bash
cd ~/work/<repo>-vX.Y.Z/..
zip -qr <repo>-vX.Y.Z.zip <repo>-vX.Y.Z -x '*.DS_Store' '*__MACOSX*'
```

## 10.3. Единый деплойер

**`templates/deploy.sh` — один на всю систему. Второго не заводится никогда:** новая возможность
становится режимом внутри него, не отдельным файлом. Путь «архив из `~/Downloads` → клон →
чистая замена дерева → коммит → тег → push → GitHub Release».

```
DRY=1 zsh ~/Downloads/deploy.sh    # план без изменений
zsh ~/Downloads/deploy.sh          # прогон
```

Отставлены 2026-07-24: `publish.sh`, `deploy_from_zip.sh`, `push_base_repo.sh`, `sync-all.sh`,
`deploy_all.sh`. **Ссылаться на них больше нельзя.**

# 11. Источник правды и вахта

**Источник правды любой репы — её ветка `main` на GitHub.** Архив, локальная папка, zip
в переписке — производные копии. Расходится — прав GitHub.

Почему GitHub: он единственный, у него есть история и теги, и он единственный доступен всем
четырём вахтам одновременно. Локальная папка живёт на одной машине — вахта с другого аккаунта
её не видит.

**Канон «один zip = полный контекст»** читается точнее: zip нужен, чтобы Claude прочитал репу
целиком за одну сессию. Это про контекстное окно, а не про хранение. **Zip — вагон, а не склад.**

**Проверка перед выпуском версии — обязательна всегда**, даже для реп, которые «недавно
проверялись»: `gh release list -R vevdokimovm/<репа> --limit 1`. §0 журнала — ориентир для
человека, **не источник правды** для решения о номере версии. [Инцидент 19.08: версия взята
из памяти, релиз v0.1.0 уже существовал, архив пересобирали.]

# 12. Зоны доступа Claude Code (ADR-010)

Claude Code вводится с **двумя ограничениями**:

**Первое — только коммерческие условия.** Вход исключительно по ключу из Anthropic Console.

| Вход | Условия | Обучение | Хранение |
|---|---|---|---|
| Подписка Pro/Max | потребительские | **включено** по умолчанию | 5 лет |
| Ключ из Console | коммерческие | **нет** | 30 дней |

**Второе — только открытая зона.** Разделение **физическое**: открытая зона клонируется
в `~/claude-workspace/`, агент запускается только оттуда. Запреты в `settings.json` — второй
рубеж, потому что правила конфигурации это декларация, а отсутствие клона — факт.

| Зона | Репы | Режим |
|---|---|---|
| 🟢 открытая | `base-repo`, `mission-control`, `it-base`, `ml-base`, `edu-base`, `academic-portfolio`, `algorithms`, `career`, `productivity`, `research-craft`, технические спутники | свободно |
| 🟡 серая | `self-map`, `christ-walk`, `family`, `truth-seeking` | **по одному файлу** через веб-чат, объём разглашения выбирает человек |
| 🔴 закрытая | `health-vault`, `legal-knowledge-base` | **никогда** |

Массовые правки — через `git worktree` с ручным ревью `git diff` перед пушем.
Раздача базы, развёртывание реп и перенос экспортов остаются за скриптами.

> **Где решает совпадение — скрипт. Где решает смысл — модель.**

# 15. Одиннадцать принятых решений (ADR)

| # | Решение |

| 005 | старые репы **архивируются**, не удаляются (история коммитов — ценность). ⚠️ неприменим постфактум: 29 реп уже удалены |
| 006 | при выносе папки исходная остаётся с указателем на канон |

# 16. Что осознанно НЕ делается

| Идея | Почему отклонена |
|---|---|
| массовое переименование реп | цена — `.repo-id`, `REPO_MAP`, карта, все ссылки; выигрыш косметический |
| отдельная репа под «менеджера задач» | у сущности нет своего контента |
| полное дублирование при выносе папок | два источника правды |
| общий роадмап как автоагрегат локальных | у 8 из 11 core-реп локальных роадмапов нет |
| второй деплой-скрипт | новая возможность = режим внутри `deploy.sh` |
| внешние трекеры как канон | не доезжают в архив, ломают «один zip = полный контекст» |

> **Одной строкой:** 57 реп в пяти классах наследуют единую инфраструктуру от `base-repo`,
> которая раздаётся 1-в-1 в `_base/` каждой репы при жёстком разделении «чужое/своё»;
> состояние и планирование живут отдельно в `mission-control`; репу ведут четыре аккаунта
> по очереди через самодостаточный `WATCHLOG`; знание фиксируется автоматически по семи
> триггерам в типизированные отчёты с обязательным корнем; чистота держится пятью правилами
> и порогами размера; доставка идёт одним деплойером из канонично упакованного архива;
> источник правды — всегда GitHub, а не память и не локальная папка.
