# Процедура прохода: как смотреть репу, чтобы ничего не пропустить

> **Зачем этот файл.** Четыре инструмента подряд пропускали материал, потому что каждый
> **выбирал** нужное по списку, а список писался по памяти. Разбор —
> `reports/incidents/filter_lists_from_memory_pattern.md`, урок — PIT-074.
>
> Здесь процедура, которая **по построению** не может пропустить файл. Она заменяет
> все прежние способы описи. Никаких «умных» фильтров в ней нет намеренно.

---

## 0. Главный принцип: вычитание вместо выбора

**Было (четыре раза подряд, и все четыре неверно):** из всех файлов **выбрать** те, что
похожи на метод, — по списку каталогов, по именам, по эвристике. Список пишется головой,
голова не знает структуры, материал теряется молча.

**Стало:** очередь работ начинается как **100 % файлов репы** и уменьшается **только**
явно записанным решением. Файл уходит из очереди по одной из двух причин:

| Причина выбытия | Кто решает | Проверяемо |
|---|---|---|
| байт-в-байт совпадает с файлом в базе | `sha256` | да, объективно |
| прочитан и решение записано в `decisions.md` | человек | да, по записи |

**Третьей причины нет.** Ни «выглядит как контент», ни «каталог называется `profiles/`»,
ни «расширение не `.md`». Если файл не прочитан и не совпал с базой — он **в очереди**.

Отсюда свойство: полнота проверяется арифметикой. `в очереди + совпало + решено = всего`.
Расхождение = потеря, и она видна сразу.

## 1. Четыре команды листинга (выполняются для КАЖДОЙ репы)

Копипастой, без изменений. `R` — имя репы.

```bash
R=personal-finance-dss
cd ~/Documents/система_репозиториев/$R
```

**1.1. Всё, что есть — одним числом.** Точка отсчёта: с этим числом сверяется всё дальше.

```bash
find . -type f -not -path "*/.git/*" -not -path "./_base/*" | wc -l
```

**1.2. Перепись каталогов с числом файлов.** Все типы файлов, не только `.md`.
Читается глазами целиком — по ней принимаются решения о каталогах.

```bash
find . -type f -not -path "*/.git/*" -not -path "./_base/*" \
  | sed 's|/[^/]*$||' | sort | uniq -c | sort -rn
```

**1.3. 🔴 Скрытые каталоги — ОТДЕЛЬНОЙ командой.** Их не видно в обычном просмотре
и они не вспоминаются. Именно так едва не потерялись `.claude/` с шестью скиллами,
четырьмя субагентами и одиннадцатью хуками.

```bash
find . -type d -name ".*" -not -path "*/.git/*" -not -path "./_base/*" \
  | while read d; do printf "%4s  %s\n" "$(find "$d" -type f | wc -l | tr -d ' ')" "$d"; done
```

**1.4. Перепись расширений.** Показывает, какие носители метода есть кроме `.md`:
скрипты, конфиги, `evals.json`, хуки.

```bash
find . -type f -not -path "*/.git/*" -not -path "./_base/*" \
  | sed 's|.*/||; s|^[^.]*$|(без расширения)|; s|.*\.|.|' | sort | uniq -c | sort -rn
```

**Вывод всех четырёх команд вставляется в `decisions.md`** — не пересказ, а сам вывод.
Читающий обязан видеть, на чём стоят решения.

## 2. Решение по каждому каталогу

По переписи (1.2) каждый каталог получает **явную** отметку. Не «остальное — контент»,
а построчно, весь список.

| Отметка | Значение | Что дальше |
|---|---|---|
| **М** | метод: как работать, а не что наработано | читать все файлы целиком |
| **С** | содержание: результат предметной работы | не читать, **но записать причину** |
| **?** | непонятно по имени | **открыть 2–3 файла и посмотреть** — только после этого М или С |

**Правило `?`:** сомнение разрешается **открытием файла**, а не рассуждением о названии.
`knowledge/guides/` звучит как содержание — внутри 29 методичек. `examples/` звучит как
примеры — внутри отчёты о распознавании, то есть метод.

**Каталог `С` записывается с причиной.** «`profiles/` — С: разборы конкретных людей,
366 файлов» — проверяемо. «остальное контент» — не проверяемо и запрещено.

## 3. Сверка с базой

Для всех файлов из каталогов **М**:

```bash
# что уже есть в базе байт-в-байт
python3 - <<'PY'
import hashlib
from pathlib import Path
BASE = Path.home()/"Documents"/"base-repo"
REPO = Path.cwd()
base = set()
for p in BASE.rglob("*"):
    if p.is_file() and ".git" not in p.parts:
        base.add(hashlib.sha256(p.read_bytes()).hexdigest())
same = new = 0
for p in sorted(REPO.rglob("*")):
    if not p.is_file() or ".git" in p.parts or "_base" in p.parts: continue
    h = hashlib.sha256(p.read_bytes()).hexdigest()
    if h in base: same += 1
    else:
        new += 1
        print(f"{p.relative_to(REPO)}")
print(f"\n--- совпало с базой: {same} · в очереди: {new}", flush=True)
PY
```

Хэш — единственный фильтр, которому можно доверять: он не знает имён и не помнит структуру.

> ### 🔴 …но только если обе стороны нормализованы одинаково
>
> Добавлено 21.08.2026 из `mission-control/reports/2026-08-13-old-repos-migration.md` §4.
>
> **Случай.** Одиннадцать ноутбуков едва не задвоились. В целевой репе они лежали
> **с выводами ячеек**, из источника шли **очищенными** — код тот же, хеши разные.
> Сверка честно отвечала «этих файлов в базе нет», и они поехали бы второй копией.
> После нормализации обеих сторон «новых» стало **2 вместо 13**.
>
> **Хеш не врёт — он отвечает на вопрос «одинаковы ли БАЙТЫ».** Если тебя интересует
> «одинаково ли СОДЕРЖАНИЕ», байты сначала приводятся к одному виду **с обеих сторон**,
> и только потом хешируются.
>
> Что расходится, не меняя смысла: выводы ячеек в ноутбуках · концевые пробелы
> и перевод строки в конце файла · CRLF против LF · порядок ключей в JSON ·
> BOM · время модификации внутри архива.
>
> **Правило:** прежде чем опереться на хеш, назови, **что именно** ты сравниваешь.
> Не назвал — сравниваешь байты и получишь ложное «различаются» на каждой косметике.

## 4. Чтение

### 🔴 Порядок внутри репы: сначала корень, потом всё остальное

Добавлено 21.08.2026 из `SYN-019`. Файлы корня (`BOARD`, `ROADMAP`, `BACKLOG`,
`WATCHLOG`, `MISSION`, `START-HERE`) — это **список того, что репа уже знает о себе**.
Прочитанные последними, они превращают часть прохода в переоткрытие: вахта потратила
батч на замер расхождения копий репы, а задача «решить, какая копия канон» уже стояла
открытой в `BOARD.md`, который лежал в непрочитанном хвосте очереди.

**Правило:** корень читается **первым**, до каталогов. Замер делается **после** —
и тогда он либо усиливает уже записанное числом (запись называла три копии, замер нашёл
пять), либо является настоящей находкой. Оба исхода полезны; порядок наоборот даёт
только первый, и с потерей времени.

---

Всё, что осталось в очереди после §3 и лежит в каталогах **М**, читается **целиком**.
Режим А (`00-infrastructure/33-token-budget-and-modes.md`): понижение глубины — только
явным решением с записанной причиной, молчаливое понижение — брак.

Читается **содержимое**, а не заголовки. Решение о файле принимается после прочтения,
а не по имени.

## 3а. Число реп — единственный довод, не зависящий от читающего

Добавлено 21.08.2026, извлечено из `mission-control/00-infrastructure/14-system-audit.md`
(поднято в базу как `77-system-wide-audit.md` §4).

**Файл, независимо появившийся в пяти репах, почти наверняка описывает общесистемное
правило.** Никто его туда не рассылал — он возник пять раз потому, что проблема общая.

Это важно ровно потому, что **все остальные сигналы — суждения**. «Похоже на метод»,
«выглядит переиспользуемым» ошибаются молча, и именно так четыре инструмента подряд
теряли материал (PIT-074). Число реп суждением не является.

| Встречается в | Как читать |
|---|---|
| 1 репе | сигнала нет, решает чтение содержания по §4 |
| 2–3 репах | сравнить редакции: возможно, одна отстала |
| **5+ репах** | почти наверняка база; вопрос не «поднимать ли», а **в какой редакции** |

> **Ловушка:** одинаковое **имя** ≠ одинаковое содержание. Пять `pitfalls.md` могут
> оказаться пятью разными файлами — так и было, реестр сводился из пяти независимых
> линий нумерации. Число реп — довод **начать сравнение**, а не вывод. Сравнивать
> хешом и структурой (`grep '^## '`), не темой.

**Как считать, не выбирая по списку:** по всем репам собрать имена файлов из служебных
каталогов и посчитать частоту. Инструмент допускается — здесь он **перечисляет
и считает**, решений не принимает (§7).

> ### 🔴 Сначала искать готовый инструмент, потом писать свой
>
> **Случай 21.08.2026.** Частотный сигнал вывел на плоские legacy-копии базы в репах,
> и это записали как находку. Через час выяснилось, что у базы **уже есть**
> `scripts/legacy_delta.py` ровно под эту задачу, и его картина **шире**:
> 977 дублей, 216 старых версий, **91 имя** против трёх найденных вручную.
>
> Правило `04-watchlog-protocol.md` («прежде чем строить инвентаризацию — искать готовую»)
> существовало **до** замера и было нарушено. Класс — **PIT-072**.
>
> **Порядок перед любым собственным скриптом:**
> 1. `ls scripts/` базы и `tools/README.md` кампании — что уже написано и где его потолок;
> 2. запустить найденное и посмотреть вывод;
> 3. только потом писать своё — и в решении назвать, **чего не хватило в готовом**.
>
> Своё здесь не было бесполезным: инструмент **считал** файлы, но не объяснял,
> **почему они не могут обновиться**. Это и есть законный повод дописать — но заявлять
> надо разницу, а не всю находку.

## 4а. При сомнении — повышать

**Закон 4 стандарта (решение владельца 20.08.2026).** Сомнение «повышать или пропустить,
кажется уже покрыто» разрешается **в пользу повышения**.

Причина — асимметрия цены: **лишнее видно и снимается ревизией за минуту; пропущенное невидимо**
и не отличается от «этого и не было». Обнаружится оно в худший момент — когда понадобится,
в чужой репе, без источника под рукой.

- «И так покрыто» — **гипотеза**, а не вывод. Проверяется сравнением **структуры**
  (`grep '^## '`), а не темы, размера или названия.
- Проверка не сделана → **повысить** и пометить «сверить при ревизии».
- Проверка сделана и это действительно дубль → не повышать, но записать в решениях
  **чем именно** дубль. Иначе следующая вахта переоткроет вопрос.

Отсечение лишнего — **отдельная фаза** (`21-revision-protocol.md`), а не побочный эффект
спешки при сборе.

## 5. Запись решения

По каждому прочитанному файлу — строка в `decisions.md`:

| Решение | Когда |
|---|---|
| ⬆️ **повысить** | метод, применимый вне этой репы |
| 🔗 **свести** | то же, что уже есть в базе или в другой репе → одна методичка с указанием обоих источников |
| 📍 **оставить локальным** | метод, завязанный на предмет именно этой репы |
| 🗑 **в корзину** | покрыто существующим и/или противоречит действующему стандарту |

**Файл не покидает очередь без записи.** Прочитал и не записал — считается непрочитанным.

## 5а. 🔴 Реестры обновляются ПО ХОДУ прохода, а не в конце

Требование владельца 21.08.2026: *«не забывай их во время синтеза обновлять,
поддерживать актуальными»*.

Проход по репе — главный поставщик материала для реестров: именно здесь чужие грабли
встречаются пачками. Но записываются они в конце батча, «когда будет время», —
и не записываются никогда, потому что токены кончаются внезапно.

### Три реестра, и у каждого своя единица

| Куда | Что туда идёт | Единица |
|---|---|---|
| `reports/pitfalls.md` | **случай**: что произошло, признак, лечение | `PIT-001…NNN` |
| `reports/incidents/PITFALLS.md` | **+1 к счётчику класса**, если случай не первый | `PIT-A…G` |
| `05-infra-synthesis-lab/PITFALLS.md` | грабли **самого процесса синтеза** | `SYN-NNN` |

**Случай и класс — не одно и то же, и заполняются оба.** Карточка отвечает «что это
было», счётчик — «сколько раз мы уже так делали». Растущий счётчик означает, что
заплатки не работают и нужна механическая проверка, а не ещё одна правка.

### Что делать, встретив грабли в чужой репе

1. **Найти класс в лидерборде** — 30 секунд, заголовки.
2. **Класс есть** → `+1` к счётчику, случай одной строкой в его разделе.
   **Класса нет** → завести с счётчиком 1.
3. **Если класс достиг 3** — заплатки не работают: нужна механическая проверка
   (тест, гейт, инвариант). Это отдельная задача, не побочный эффект прохода.
4. Карточка случая — в `reports/pitfalls.md`, если случай самостоятельно ценен.

**Счётчик не сбрасывается никогда.** Он про историю, а не про текущее состояние.

> ### 🔴 Реестр в чужой репе — источник, а не цель
>
> У многих реп есть свои `pitfalls.md`. Замер 21.08.2026: у девяти они **байт-в-байт
> одинаковы** (раздача старой базы, `PIT-001…012`); свои линии только у
> `character-a-analysis` (33 карточки), `portrait-of-taste` (17),
> `personal-finance-dss` (17).
>
> **Пишем всегда в базу.** Правка чужого реестра по ходу прохода — это правка
> материала, который сейчас читаешь: следующая вахта не поймёт, что здесь было
> изначально, а что дописано.
>
> **Отдельно: лидерборд классов тоже размножен.** Копия в
> `dota-dossier/reports/infrastructure/PITFALLS.md` уже отстала — в ней нет `PIT-G`.
> Счётчик, размноженный по репам, перестаёт считать: класс сработал в одной,
> вырос там, в копиях молчит. **Лидерборд болеет тем, что должен ловить.**

**Признак, что дисциплина поехала:** прошли репу, подняли документы — и ноль записей
в реестрах. Значит либо репа была стерильна (бывает, но редко), либо грабли встречались
и не записывались.

## 6. Приёмка репы

Репа закрыта, когда сходится арифметика:

```
всего файлов (1.1)  ==  совпало с базой  +  в каталогах С  +  прочитано и записано
```

Не сходится — репа **не закрыта**, и разница ищется поимённо. Итог заносится в `decisions.md`
строкой вида: `personal-finance-dss: всего 1043 = база 118 + С 640 + прочитано 285`.

### 🔴 Дополнено 22.08.2026 — два обязательных уточнения формулы

**1. Версия базы пишется в формуле.** Слагаемое «совпало с базой» — не свойство репы,
а **отношение между репой и базой**, и база под ним двигается. Приёмка, записанная без
версии, через месяц не воспроизведётся, и вахта будет искать ошибку в репе, которой там нет
(`SYN-023`). Правильно:

```
character-a-analysis: всего 337 = база(v2.1.0) 78 + С 68 + прочитано и решено 191
```

**2. Совпавшее с ЗАКРЫТОЙ РЕПОЙ кампании вычитается наравне с базой.** Репы системы
пересекаются: спин-офф, ре-мерж, общий корпус. Файл, байт-в-байт совпадающий с уже
прочитанным в другой закрытой репе, **не читается повторно** — основание проверяемо
(sha256), а не «кажется, это то же самое».

```
self-map: всего 629 = база(v2.18.0) 77 + character-a-analysis 148 + С 371 + прочитано 33
```

Слагаемое **называется поимённо** — из какой репы вычитаем. «Совпало с чем-то ранее»
не проверяется и запрещено.

🔴 **Из вычитания исключаются ТРИВИАЛЬНЫЕ совпадения.** Дополнено 22.08.2026 после того,
как вход в `research-craft` дал их сразу два вида:

| Что совпало | Почему это не перенос |
|---|---|
| **пустой файл** (`sha256 = e3b0c442…`) | все `.gitkeep` совпадают со **всеми** пустыми файлами системы; хеш пустоты не доказывает происхождение |
| **boilerplate**: `VERSION` с «0.1.0», типовой `.gitignore` | совпал сразу с **двумя** репами — это шаблон новой репы, а не перенос из конкретной |

**Признак тривиальности:** файл совпал с **несколькими** репами сразу, либо его содержимое
не несёт информации (пусто, одна строка версии, стандартный игнор-лист). Такие файлы
идут в **«прочитано и решено»**, а не в вычитание — иначе слагаемое «совпало с закрытой
репой» надувается и приёмка сходится на пустом месте.

> **Хеш доказывает тождество байтов, а не общее происхождение.** Для вычитания нужно
> второе, и оно требует, чтобы файл был **содержательным** (`SYN-025`: хеш сравнили,
> файлы не открыли).

### 🔴 `_base/` — это раздача базы, и она вне листинга намеренно

Раздача живёт в `_base/` (у покрытых реп — **295 файлов**), а `00-infrastructure/`
предназначен для **локальных** правил репы. Формулировка из `research-craft/START-HERE.md`,
дословно:

> «`_base/` — общие правила системы (зеркало `base-repo`), раздаётся скриптом
> `deploy.sh --sync-base`, **не редактировать здесь**. Локальные правила этой репы,
> если появятся, живут в `00-infrastructure/` и в `_base/` не попадают.»

Отсюда два следствия для прохода:

1. **§1 исключает `./_base/*` правильно** — это не материал репы, а зеркало базы.
   Считать его в приёмке нельзя, но и «репа без инфраструктуры» из его отсутствия
   в листинге **не следует**.
2. **«Базу не получала» законно только когда нет НИ `_base/`, НИ совпадений по хешу.**
   Отсутствие `00-infrastructure/` означает лишь «нет локальных правил» (`SYN-030`).

**Проверка полноты разметки** (`SYN-027`): число размеченных каталогов обязано сойтись
с числом каталогов в выводе §1.2. Расхождение — незакрытая разметка, сколько бы файлов
ни было прочитано.

## 6а. 🔴 Каталог закрывается той же проверкой, что и репа

Добавлено 21.08.2026 из `SYN-021`.

Приёмка репы (§6) не может соврать — она сходится арифметикой. Приёмка **каталога**
до сих пор не проверялась ничем: «`docs/` закрыт 10 из 10» писалось по памяти о батче.
В `exam-kit` таких «закрытых» файлов оказалось **8 из 10**: два не имели ни одной записи
решения, и один из них — `WORKFLOW.md`, центральный документ репы.

Опасность в том, что ошибка нижнего уровня **поднимается наверх молча**: приёмка репы,
собранная из этих же чисел, сойдётся — с двумя непрочитанными файлами внутри.

```bash
for f in $(ls <репа>/<каталог>/); do
  grep -q -- "$f" decisions.md || echo "НЕТ ЗАПИСИ: $f"
done
```

Пусто — каталог закрыт, число «N из N» писать можно. Не пусто — нельзя.

> **Пропускается не периферия.** Пропущенным оказался файл, на который ссылаются
> все девять остальных: обилие ссылок создаёт ощущение прочитанности. Проверять
> в первую очередь то, что «и так понятно».

## 7. Чего в этой процедуре нет намеренно

- **Белых списков каталогов** — четыре раза подряд именно они теряли материал.
- **Фильтра по расширению** — метод бывает скриптом, хуком, `evals.json`, `settings.json`.
- **Порогов и эвристик «похоже на служебку»** — похожесть решает человек после открытия файла.
- **Автоматической классификации «метод / содержание»** — отменена как класс: она ошибается
  молча, а молчаливая ошибка не ловится.

Инструменты допускаются **только** там, где нет решений: перечислить файлы, посчитать хэши,
сверить арифметику. Как только инструменту требуется список из головы — он не пишется.
