## ✅ `_base/` не создавался для четырёх приватных реп — найдено и исправлено 27.08.2026

**Найдено по прямому вопросу владельца** («почему база не раздана в
personal-finance-dss?»): `sync_base_local.py --all` обновляет **только** те
репы, где `_base/` уже существовал (`d.name != "base-repo" and
(d / "_base").is_dir()`) — он не создаёт папку с нуля. Четыре приватные репы
никогда не получали `_base/` вообще (не отставание — полное отсутствие):
`personal-finance-dss`, `character-a-analysis`, `portrait-of-taste`,
`mission-control`.

**Исправлено в этом же заходе:** все четыре получили `_base/` v3.59.4 через
`sync_base_local.py <репа>` (одиночный режим создаёт папку, если её нет).
Проверено: среди оставшихся реп без `_base/` — только публичные
(`algorithms-site`, `claude-usage`, `finpilot`, `game-analytics-engine`,
`salvation`, `vevdokimovm.github.io`, `vevdokimovm`, `vk-graph`), где `_base/`
не раздаётся намеренно по правилу ADR-004 (приватность).

**Ничего не осталось решить** — записано для истории, не как открытая
задача. Стоит проверить в `sync_base_local.py`, не завести ли `--all`
режим, который создаёт `_base/` и для реп без него (сейчас `--all` тихо
пропускает такой случай — тот самый баг, который скрывал эту дыру).
