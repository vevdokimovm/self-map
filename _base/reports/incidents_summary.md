# Реестр инцидентов

Краткие сводки по каждому **инциденту** — была реальная поломка/дефект и/или влияние на
пользователя/систему. Расследования, где реального дефекта НЕ оказалось (внешняя причина, артефакт
метода, недопонимание), — в отдельном парном реестре `investigations_summary.md`.

Полные разборы (post-mortem) лежат в `incidents/`. Формат разбора — `incident_postmortem_guide.md`;
шаблон карточки дефекта — `bug_report_template.md`. В каждой записи — не только корень, но и
**решение / шаги** (а если не закрыто — что опробовано и что дальше).

> **Как читать этот файл.** Это реестр-индекс: строки-сводки для быстрого контекста. Полные разборы —
> в `incidents/`. В base-repo (родительский шаблон) реальных инцидентов нет — реестр наполняется по
> мере жизни наследующей репы.

## Формат записи

```markdown
### INC-<ТЕМА> / BUG-<NNN> — <короткое имя>

- **Суть:** <что произошло, симптом>
- **Корень:** <настоящая причина, не симптом>
- **Решение / шаги:** <что сделано; если не закрыто — что опробовано / почему / что дальше>
- **Статус:** <закрыт / в работе>. Полный разбор — `incidents/<тема>_incident.md`.
```

### INC-BASH-CLASSIFIER-OUTAGE — архивация встала: Bash режется «temporarily unavailable»

- **Суть:** финальный шаг батога (сделать zip репы) не проходил — каждая нетривиальная Bash-команда
  возвращала «claude-sonnet-5 temporarily unavailable, auto mode cannot determine safety»; `echo` и
  read-only тулы при этом работали. Работа вся на диске, но архив не собирался; пользователь ждал вживую.
- **Корень:** внешний — классификатор безопасности авто-режима Cowork временно недоступен → команды, не
  признаваемые заведомо безопасными без него, отклоняются (read-only и тривиальный `echo` идут мимо).
  Управляемая часть — ассистент долбил идентичную команду ~15 раз и пере-нарративил вместо ранней смены
  тактики.
- **Решение / шаги:** дождались восстановления классификатора → одна простая команда упаковала архив →
  отдан с sha256 + deploy-однострочник. Урок — **PIT-013** + профилактика в разборе (не долбить, упрощать,
  backoff/`send_later`, не пере-нарративить).
- **Статус:** закрыт. Полный разбор — `incidents/bash_classifier_channel_outage_incident.md`.

### INC-PUBLISH-STUB-NOTES — релиз v1.5.0 ушёл с заглушкой вместо описания

- **Суть:** GitHub Release v1.5.0 опубликован с текстом-заглушкой `Release 1.5.0`, хотя секция
  `## [1.5.0]` в CHANGELOG была написана полностью.
- **Корень:** `publish.sh` v1 искал changelog только по пути `CHANGELOG.md` от текущей папки;
  в base-repo он живёт в `00-infrastructure/CHANGELOG.md` → не найден → **молчаливый** фолбэк
  на заглушку (fail-silent), публикация «успешна».
- **Решение / шаги:** `templates/publish.sh` v2 (v1.6.0) — поиск changelog по кандидатам от
  текущей папки и корня git-репы, громкое предупреждение вместо заглушки, режим доделки
  заполняет заглушечные описания существующих релизов. Владельцу: перезапустить
  `publish.sh --version 1.5.0` — доделка заполнит релиз.
- **Статус:** закрыт (v1.6.0). Полный разбор — `incidents/publish_stub_release_notes_incident.md`.
