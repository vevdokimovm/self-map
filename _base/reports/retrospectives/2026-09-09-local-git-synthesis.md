# Синтез: два дня перевода выпуска на локальный git

**07–09.09.2026** · версии `4.190.0` → `4.202.0` (13 батчей)
**Исход:** 🟡 пилот на четырёх репах, масштабирование остановлено владельцем

---

## §1. Что получилось

**Выпуск идёт одной командой.** `publish.py <репа>` — шесть шагов, каждый
проверяется: атрибуция → описание парсером деплойера → ассет → коммит →
тег → push → релиз. `deploy.sh` не тронут, его роль сужена и записана
в его же шапке.

**Требования владельца исполняются механизмом, а не памятью:**

| требование | чем закрыто | проверено |
|---|---|---|
| Claude не в contributors | `attribution_check.py` + хук `commit-msg` + гейт | 🟢 **552 коммита, ноль упоминаний** |
| описания как у деплойера | `release_notes.py` — парсер **извлекается** из `deploy.sh` | 🟢 совпадает с эталоном |
| ассеты как у деплойера | имя `<репа>-v<версия>.zip` | 🟢 на всех релизах |
| остальное как деплойер | шесть шагов `publish.py` | 🟡 без зеркал и BACKFILL |

**Девять инструментов**, каждый с канарейкой: `publish`, `git_adopt`,
`release_notes`, `attribution_check`, `shell_ascii_check`, `diff_view`,
`owner_present`, `working_tree_guard`, `git_health`.

---

## §2. 🔴 Главный урок: точный замер не спасает от ложного вывода

Оценка задачи менялась **четыре раза**, и каждая версия была подтверждена
собственным замером:

| # | вывод | почему оказался ложным |
|---|---|---|
| 1 | «4 ГБ истории, канал не вытянет» | мерился полный клон, который не нужен |
| 2 | «448 КБ, задача решена» | это только `fetch`; докачка переехала на `status` |
| 3 | «`read-tree` вместо `reset` решает» | обе команды ни при чём |
| 4 | **`core.autocrlf=input`** | 🟢 подтверждено контролируемым экспериментом |

> **Замер может быть точным, метод правильным, а вывод ложным — если
> мерялась не та стадия.**

🔴 **Ни один из трёх ложных выводов вахта не опровергла сама.** Первый снял
вопрос владельца («в чём проблема, если нужен один файл?»), остальные —
независимый ресёрч с экспериментом в песочнице. Собственный замер каждый
раз «подтверждал» текущую версию, потому что мерил ровно то, что вахта
уже считала главным.

## §3. 🔴 Второй урок: код возврата 0 не означает «сделано»

За один день нашлось **пять** недостающих настроек (`PIT-211`). Все пять:
инструмент отработал, ни одна команда не упала, симптом не наступил.

| настройка | если её нет |
|---|---|
| `extensions.partialClone` | git считает репу **повреждённой** |
| `core.autocrlf=false` | `status` уходит в сеть **по запросу на файл** |
| upstream ветки | `push` падает; 🔴 **сторож эталона врал** |
| `core.hooksPath` | репа **без защиты от секретов** |
| `maintenance.auto` ≠ `false` | репа **никогда не делает авто-`gc`** |

**Первую нашёл ресёрч. Остальные четыре — ручной перебор списка после неё.**

> **Одна найденная недостача в списке проверок — повод перепроверить
> весь список, а не только её.**

Растворено `git_health.py` в ревизионном гейте: теперь срабатывает само.

## §4. Три опасения, которых не существовало

| опасение | оказалось |
|---|---|
| Time Machine раздует бэкап | 🟢 **бэкапы не идут вовсе** — диск не подключён |
| NFD/NFC даст ложные diff | 🟢 **0 путей** в индексе всех четырёх реп |
| нужен `git maintenance` | 🟢 порог авто-`gc` — **~14 лет**, вызовет сам `commit` |

🔴 **Два из них были моими же утверждениями**, высказанными без проверки:
«TM перепишет packfile целиком» (packfile при коммите **не меняется**)
и «решается одной настройкой» (TM **не понимает шаблонов**).

---

## §5. Что осталось нерешённым

1. 🔴 **Две руки на публикации.** Уже стоило пропущенного тега `v4.192.0`
   и релиза `v4.193.0`. Механизм известен — `lockf` + `fcntl.flock`,
   оба идут в `flock(2)` — **не реализован**.
2. **Эталон не защищён механически.** `working_tree_guard.py` считает цену
   (`clean -fd` в `it-base` — **310 МБ**), но перехватить `git` не может.
3. **Поведение на 67 репах неизвестно** — нагрузка масштабируется
   нелинейно, четыре репы об этом не скажут.

---

## §6. Оценка работы: 78/100

**За что снято.** Три отозванных вывода подряд, каждый выпущен батчем
до опровержения. Пять недостач, существовавших с первой заведённой репы.
Четыре релиза, написанных отсебятиной при готовом стандарте, который
читался получасом раньше (`PIT-209`).

**За что не снято.** Диагноз в итоге верен и подтверждён независимо;
требования владельца закрыты механизмами, а не обещаниями; каждая ошибка
записана карточкой с механизмом, а не заплаткой.

**Пять карточек за два дня:** `PIT-207` (защита блокировала бы законное) ·
`PIT-208` (две руки) · `PIT-209` (релизы отсебятиной) · `PIT-210`
(`autocrlf`) · `PIT-211` (код 0 ≠ сделано).
