# ADR-001: Библиотека универсальных методичек внутри base-repo
Дата: 2026-07-09  ·  Статус: Accepted

## Контекст

FINPILOT за вехи 4–5 накопил ~25 предметных методичек и гайдов (архитектура, кибербез,
диаграммы/ГОСТы, анализ исследований, научная статья, процессы команды и т.д.) — знания
универсальные, не привязанные к продукту. Владелец приказал перенести их в шаблонную систему
реп по принципу «all in»: не отбирать сейчас, внести всё, отбор — на ревизии
(«лучше сделать лишнюю методичку и убрать, чем не сделать и потерять»).

Силы против: собственное правило base-repo — «тематический контент в тематических репах,
здесь только инфраструктура» (`WATCHLOG.md §2`, `05-knowledge-base-rules.md`). Прямая заливка
25 файлов в `00-infrastructure/` размыла бы инфраструктурную зону и нумерацию.

## Решение

Заводим **отдельный блок `02-methodology-library/`** — общий фонд универсальных методичек с
явным жизненным циклом:

1. Файлы вносятся **as-is** (имена и содержимое донора, провенанс в README библиотеки).
2. README библиотеки держит таблицу-навигатор: файл → про что → **кандидат-репа** при
   растаскивании.
3. На плановой ревизии (`21`) каждый файл получает исход: остаётся / переезжает в
   тематическую репу / сливается / удаляется. До ревизии не выбрасывать ничего.
4. Инфраструктурные протоколы в библиотеку не попадают — только в `00-infrastructure/`
   (дубли донора с уже существующими доками 06/07/20/21/22 и т.п. — не вносятся, фиксируются
   в мёрж-манифесте).

## Альтернативы

- **Раскидать сразу по тематическим репам** (it-base, edu-base…). Отвергнуто: ломает «all in
  одним батчем» (нужны правки N реп), решения о судьбе файлов принимались бы наспех, часть
  фонда реально нужна всем репам сразу.
- **Всё в `00-infrastructure/` следующими номерами.** Отвергнуто: смешивает «правила игры»
  с предметными знаниями; нумерация инфраструктуры потеряла бы смысл.
- **Не переносить, оставить в FINPILOT + ссылки.** Отвергнуто приказом владельца: FINPILOT —
  приватный продукт, знания должны жить в шаблонной системе независимо от него.

## Последствия

- Плюсы: ничего не потеряно; одна точка входа в общий фонд; растаскивание — управляемый
  процесс с зафиксированными кандидатами; base-repo остаётся чистым по зонам.
- Минусы / на что подписались: +~1 МБ текста в родительской репе до ревизии; риск, что
  «отбор потом» затянется (лечится: пункт растаскивания стоит в ROADMAP базы).
- Влияние: новый корневой блок в структуре base-repo; карта в корневом `README.md`;
  ревизия репы (`21` §4) включает библиотеку в периметр.
