# ADR-006 — Скиллы и агенты раздаются плагином из `base-repo`, а не копиями

**Статус:** ✅ **ПРИНЯТ И ИСПОЛНЕН 30.08.2026** (вахта V)

> **Проблема владельца, дословно:** *«в тех чатах почему-то нет наших
> агентов-скиллов вообще ни одного. Что это, почему так, как это исправить?»*
>
> **Его же требование к решению:** *«мне больше нравится [вариант со ссылкой],
> потому что всё внутри системы живёт, не на устройстве»*.

---

## 1. Контекст — почему скиллов не было видно

**Замер 30.08.2026: из 62 реп скиллы видны в 2.**

🔴 **Причина не в раздаче — она отработала.** Скиллы доехали во все репы,
но легли в `_base/.claude/skills/`, а Claude Code ищет их в `.claude/skills/` —
**на уровень выше**. Всё, что внутри кита, для него невидимо.

| Где лежит | Видит ли Claude Code |
|---|---|
| `~/.claude/skills/` | ✅ всегда, в любом проекте |
| `<репа>/.claude/skills/` | ✅ при работе в этой репе |
| `<репа>/_base/.claude/skills/` | 🔴 **нет** — внутренность кита |

---

## 2. Решение

**Плагин `base-kit`, живущий в `base-repo/.claude/plugin/`, подключённый
одной символьной ссылкой в `~/.claude/skills/base-kit`.**

Внутри плагина `skills/` и `agents/` — тоже **символьные ссылки** на
`../skills` и `../agents`, то есть на оригиналы. **Копий не возникает нигде.**

```
base-repo/.claude/
├── skills/          ← ОРИГИНАЛ, 9 скиллов
├── agents/          ← ОРИГИНАЛ, 4 агента
└── plugin/
    ├── .claude-plugin/plugin.json
    ├── skills  → ../skills      (ссылка)
    └── agents  → ../agents      (ссылка)

~/.claude/skills/base-kit → repos/base-repo/.claude/plugin   (единственная ссылка на устройстве)
```

**Проверено запуском 30.08.2026:**

```
base-kit 1.0.0 · Source: base-kit@skills-dir
  Skills (9)  analyst, auto, expert, handoff, limits, options, research, tokens, vitals
  Agents (4)  base-coverage-probe, researcher, repo-inventory, token-probe
  Always-on:  ~2 132 tok
```

Видно **из любой репы** — проверено из `portrait-of-taste`.

---

## 3. Альтернативы — и почему отвергнуты

**а. Копия девяти скиллов в `~/.claude/skills/`.** Отвергнуто: копия рядом
с оригиналом требует синхронизации, а несинхронизированная копия расходится
молча. Ровно то, от чего уходит вся система (`72-source-of-truth.md`).

**б. Голая символьная ссылка на каждый скилл** (`~/.claude/skills/vitals` →
`base-repo/.claude/skills/vitals`). Отвергнуто по находке исследования:
известен баг валидации (`anthropics/claude-code#25367`) — скилл выполняется,
но выдаёт `Error: Unknown skill` при обнаружении. Работает, но шумит.

🔴 **Плагин снимает этот баг**, потому что ссылка ведёт не на скилл,
а на **каталог плагина** — а плагины по ссылке официально поддержаны
(`claude plugin init` сам создаёт их в `~/.claude/skills/<имя>/`).

**в. Раздача в `.claude/` каждой репы.** Отвергнуто: 62 копии одного и того
же, каждая может разойтись.

**г. MCP-сервер со скиллами.** Отвергнуто как несоразмерное: требует
процесса и настройки ради того, что решается ссылкой.

---

## 4. Последствия

**Хорошие.** Один источник — правка в `base-repo` действует везде мгновенно,
без раздачи. Всё содержание **внутри системы репозиториев**; на устройстве
только одна ссылка. Официальный механизм, а не обход.

**Плохие, и их надо назвать.**

- **~2 132 токена на каждую сессию** — около 1 % окна 200K. Плата за то, что
  девять скиллов доступны везде;
- 🔴 **ссылка сломается, если `base-repo` переместить.** Лечится
  пересозданием одной командой, но знать надо;
- плагин **не попадает в архив репы**: `.claude/plugin/` состоит из ссылок,
  а `pack_release.py` их не разворачивает. Для восстановления с нуля нужна
  команда из §5.

---

## 5. Восстановление с нуля

```bash
ln -sfn ~/repos/base-repo/.claude/plugin ~/.claude/skills/base-kit
```

Проверка: `claude plugin details base-kit` показывает 9 скиллов и 4 агента.

---

## 6. Чего решение НЕ даёт

- **не делает скиллы видимыми внутри `_base/`** — кит по-прежнему раздаёт
  их копией, и эта копия по-прежнему невидима для Claude Code. Она остаётся
  как **содержимое архива**: репа, распакованная из zip, несёт скиллы
  с собой, даже если плагин не подключён;
- **не решает вопрос сессий:** `/resume` по-прежнему показывает чаты
  текущего рабочего каталога. Это отдельная механика, разобранная
  в `00-infrastructure/97-claude-code-capabilities.md` §6-кватер.
