# migrations/ — кампании переноса

Отчёты о **массовом переносе файлов между хранилищами**: диск → репы, сведение копий,
схлопывание дублирующих деревьев. Жанр заведён 22.08.2026 (`../../00-infrastructure/19-reporting-system.md`).

## Зачем отдельный жанр

Перенос не подходил ни под один существующий тип: это не инцидент (ничего не сломалось),
не расследование (причину не искали), не эксперимент (величина известна). При этом
операция **необратимая и массовая** — то есть ровно тот класс, где происходит молчаливая
потеря данных, а обнаруживается она месяцами позже.

## Что обязан нести отчёт

| Раздел | Почему обязателен |
|---|---|
| **точка старта числом** | «было 7.4 ГБ» — без этого кампания неотличима от намерения |
| **механизм и почему именно он** | `copy`+`verify` против `rename`: выбор меняет и скорость, и обратимость |
| **таблица «источник → цель → сколько файлов»** | поимённо, иначе пропуск целой папки невидим |
| 🔴 **чем доказан перенос** | sha256-сверка или атомарность `rename` — «скрипт сказал ok» не доказательство |
| **что НЕ перенесено и почему** | отказ и молчаливый пропуск выглядят в файлах одинаково |
| **допущения по адресам** | куда класть `аналитика` — суждение вахты, оно называется строкой |
| **инциденты по дороге** | защита, сработавшая на реальных данных, ценнее описания защиты |

## Три правила операции — `../../00-CLAUDE-STOP.md` §3

1. **Не перезаписывать** — коллизия кладётся рядом с суффиксом и логируется.
2. **Доказывать диффом множеств** — удаление источника только после сверки.
3. **Тяжёлое сворачивать в служебку**, а не выбрасывать и не складировать.

## Инструмент

`scripts/migrate_to_repos.py` — карта «папка → репа», четыре режима
(`--plan`, `--copy`, `--move`, `--verify-and-clean`). Защиты, каждая из инцидента:

| Защита | Из чего родилась |
|---|---|
| `SECRET_PATTERNS` + карантин | `.env` с живым токеном уехал в репу (`PIT-012` повторно) |
| `PRESERVE_DIRS` + `unmoved_precious()` | фильтр переноса снёс `.git`, который сам же защищал (`PIT-121`) |
| `REGENERABLE_DIRS` | `.venv` и `node_modules` поехали внутрь knowledge-репы |
| исключение `*.example` | `.env.example` — шаблон, не секрет |

## Стоп-классы

- **Незакоммиченные изменения.** `git status --short` до любого удаления рабочей копии:
  наличие remote доказывает сохранность закоммиченного и **ничего не говорит** о прочем.
  Замер 22.08.2026: `finpilot` держал **184** незакоммиченных изменения при чистом `origin`.
- **Каталог под iCloud.** `brctl status`: там файлы могут быть заглушками, и операция идёт
  по сети, а не по диску (`PIT-120`). `os.rename` в пределах одной ФС этого избегает.
- **Секреты.** В репу не едут никогда — из git не удаляются, а отзываются у провайдера.
