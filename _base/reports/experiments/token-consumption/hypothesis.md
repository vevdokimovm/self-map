# Гипотеза: модель расхода токенов Claude (живая, v0.1)

> Текущая рабочая модель «сколько токенов/лимита стоит запрос и от чего это зависит». Ведётся по
> методологии `../../../00-infrastructure/28-empirical-experiment-methodology.md`. **Не истина —
> гипотеза**, сходящаяся с данными. Живой narrative-контекст (якоря, тариф, промо) — в
> `../../../00-infrastructure/16-limits-empirical-estimate.md`; здесь — операционная модель + факторы +
> что мерить. Автоснимок текущей оценки из данных даёт `python3 analyze.py`.

Единица: **Opus-эквивалент** расхода лимита (Opus 4.8 = 1.0×). План: **Pro**.

---

## 1. Целевые величины (TARGET)

- `T_ctx` — токены контекста, занятые ходом (окно 200K, модель-независимо).
- `C` — расход лимита за ход (что деплетит бар сессии/недели) = `M × работа`.

## 2. Факторы (FACTORS — от чего зависит)

| # | Фактор | Тип | Ожидание |
|---|---|---|---|
| F1 | модель (`M`) | катег. | множитель: Fable 2.0 · Opus 1.0 · Sonnet 0.4 · Haiku 0.15 |
| F2 | усилие/thinking (off/normal/high) | катег. | high жжёт заметно больше (thinking = выходные токены) |
| F3 | объём входа (сообщение + история) | число | линейный рост; кэш снижает |
| F4 | объём выхода | число | линейный |
| F5 | tool calls (кол-во) | число | каждый вызов+результат = токены в контекст |
| F6 | вложения (картинки/PDF) | число | дорого: тысячи токенов за штуку |
| F7 | позиция в диалоге / накопление | 1/mid/late | контекст растёт → вход дорожает |
| F8 | состояние кэша (fresh/warm) | катег. | промах кэша = полное перечитывание входа |
| F9 | поверхность (Chat/Project/Cowork/Code) | катег. | Cowork ≈ 20× (VM-оверхед); Code эффективнее |

## 3. Текущая модель (DECOMPOSE)

```
C_ход ≈ M × ( a·вход + b·выход + Σ(tool) + Σ(вложение) + thinking ) + кэш-оверхед
```

Известные оценки (уточняются `analyze.py` по мере данных):

| Параметр | Оценка v0.1 | Доверие | Источник |
|---|---|---|---|
| Размер сессии | ≈ 200K токенов | 🟢 | 45 сообщ × ~4.4K **И** = окну (два якоря сошлись) |
| 1% сессии | ≈ 2000 токенов | 🟡 | 1 точный замер (Code: 48K = +24%) |
| Множитель Fable | 2.0× | 🟡 | статус Claude Code (нужна OFAT-пара для 🟢) |
| Множитель Sonnet | ~0.4× | 🔴 | приор из цен API |
| Множитель Haiku | ~0.15× | 🔴 | приор из цен API |
| Вложение | ~тысячи токенов/шт | 🔴 | приор (регрессия уточнит при данных) |
| Сессий/неделю | 4–8 | 🟡 | сообщество (A3) |
| Cowork | ≈ 20 обычных чатов/сессия | 🟡 | практики |

Практические переводы: **1 короткое сообщение ≈ 3–5K токенов (~0.5% сессии)**; **тяжёлая сессия ≈
полный проход 200K**.

## 4. Известные напряжения (фальсифицируемость — где модель проверится)

- Если неделя ≈ 1.2M и выжигать полностью → ~5M/мес (~$47), но A3 даёт ~$20/мес. Значит: полную неделю
  стабильно не выжать **либо** сейчас промо-инфляция недельного (до 13.07.2026). **Тест:** следить за
  баром «All models» до/после 13.07 — просядет ли.
- Множители Sonnet/Haiku — приоры из цен API, не из замеров расхода лимита. **Тест:** OFAT-пары.

## 5. Что мерить дальше (backlog экспериментов, OFAT)

Приоритет — закрыть 🔴/🟡 (лучший инструмент — **Claude Code**, точный счётчик токенов + %):

1. **Калибровка сессии (🟡→🟢):** 3–5 чистых замеров в Code «N токенов = X%» → уточнить `tokens_per_1%`.
2. **Множители моделей (🔴→🟢):** один и тот же baseline-запрос на Opus и Fable (и Sonnet/Haiku) → Δ% на каждом.
3. **Усилие F2:** тот же запрос, effort off / normal / high → Δ.
4. **Вложения F6:** тот же запрос + 0/1/2 картинки → Δ на вложение.
5. **Tool calls F5:** тот же запрос с N и N+k вызовами → Δ на вызов.
6. **Накопление F7:** один запрос в начале vs в конце длинного диалога → рост входа.
7. **Кэш F8:** повтор сразу (warm) vs после паузы > TTL (промах) → цена промаха.
8. **Поверхность F9:** эталон в Chat vs Cowork vs Code → множители поверхности.

Каждый замер → строка в `measurements.csv` → `python3 analyze.py` пересчитает модель.

## 6. Как обновлять

1. Снял замер (Code предпочтительно) → строка в `measurements.csv` (все факторы + результат).
2. `python3 analyze.py` — печатает обновлённую оценку и что ещё 🔴.
3. Раз в N замеров — перенеси уточнённые числа в таблицу §3 (и в `16-limits-empirical-estimate.md`,
   если сдвинулись якоря). `python3 analyze.py --update-hypothesis` допишет автоснимок сюда.
