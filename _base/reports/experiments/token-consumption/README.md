# Эксперимент: расход токенов Claude

Первый боевой инстанс системы-экспериментатора (`../../../00-infrastructure/28-empirical-experiment-methodology.md`).
Цель — вывести **конкретный расход токенов/лимита на запрос** для каждой модели и то, как он зависит
от усилия, объёма запроса, tool calls, вложений, времени, поверхности. Не разовый ответ — уточняемая
модель, которая копит данные и сходится.

## Файлы

| Файл | Что |
|---|---|
| `hypothesis.md` | Текущая модель: цель, факторы, формула, оценки + доверие, напряжения, backlog |
| `measurements.csv` | Лог опытов (факторы + результат), пополняется по ходу |
| `analyze.py` | Пересобирает модель из CSV: калибровка, множители моделей (OFAT), дельты, регрессия; печатает оценку + что мерить дальше |
| `session_metrics.py` | **Шаг раньше `analyze.py`:** вынимает эмпирику из сырого лога сессии (`~/.claude/projects/*/*.jsonl`) и печатает готовую строку для `measurements.csv`. Потолок назван в шапке скрипта |

## Как пользоваться

Текущая оценка из накопленных данных:

```
python3 analyze.py
```

**Замер этой сессии — одной командой** (запускается шагом 2 скилла `/handoff`,
до `/clear` и до сборки архива):

```
python3 session_metrics.py
```

Он сам находит лог проекта текущей папки, считает контекст по ходам, hit rate, TTL записи
в кэш, прирост, цену хода по бакетам 25K — и выдаёт строку для CSV. Решения (что считать
подтверждением, что опровержением, какой пункт backlog закрыт) принимает вахта: скрипт
только перечисляет и считает.

Снял новый замер → допиши строку в `measurements.csv`, затем снова `python3 analyze.py`
(обновлённая модель). Флаг `--update-hypothesis` дополнительно допишет автоснимок в `hypothesis.md`:

```
python3 analyze.py --update-hypothesis
```

> Команды копируй **по одной, без комментариев в строке** — в zsh с выключенным `interactive_comments`
> текст после `#` уходит в скрипт как аргумент (грабли `../../pitfalls.md` PIT-005).

**Лучший инструмент замера — Claude Code, команда `/usage`** (заменила `/cost`): точная разбивка
input/output/cache read/cache write по каждой модели за сессию, плюс атрибуция по skills/subagents/MCP
на платных планах — точнее, чем просто % в статус-строке. `/context` дополнительно показывает, что
именно занимает контекст (system prompt, CLAUDE.md, MCP-листинг, прочитанные файлы), полезно когда
непонятно, откуда рост. Веб/приложение даёт только %, без разбивки — грубее, нужен пересчёт через
калибровку. Механика, откуда берётся расход (кэш, tool calls, модели) — `../../../00-infrastructure/49-token-economy-and-prompting.md`.

## Протокол одного замера (OFAT)

1. Свежая сессия/старт.
2. Ровно одна прогонка: зафиксировать все факторы, менять **один** (см. backlog в `hypothesis.md §5`).
3. Снять результат (Code: «N токенов, X% сессии, Y% недели»).
4. Строка в `measurements.csv`: дата, поверхность, модель, усилие, вход, выход, tool_calls, вложения,
   позиция, кэш, tokens_measured, pct_session, pct_week, baseline_id, заметка.
5. `python3 analyze.py`.

## Статус

v0.3 (2026-08-21) — **7 точек**. Число не переписывать руками, оно считается:

```
python3 -c "import csv;print(sum(1 for _ in csv.DictReader(open('measurements.csv'))))"
```

Что закрыто данными: сессия ≈ 200K 🟢 · cache hit rate 🟢 · subagent-изоляция 🟢 ·
**потолок контекста >710K** 🟢 (было >325K) · **цена хода растёт с контекстом** 🟢 —
опровергла прежнее «почти не растёт», и опровергла **не новым замером, а новым диапазоном**
(`../../../00-infrastructure/28-empirical-experiment-methodology.md` §10б).

Что остаётся приором 🔴/🟡: множители моделей · effort · вложения · кэш-промах ·
поверхность · другой аккаунт.

🔴 **Чего этими данными измерить нельзя:** расход субагентов. Записей `isSidechain`
в логах родителя **ноль** при потраченных 191 487 токенах — цифра бралась из
task-уведомлений, а не из JSONL. Пункт backlog остаётся открытым до тех пор, пока
не найдены собственные логи агентов.
