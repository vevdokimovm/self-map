# Эксперимент: расход токенов Claude

Первый боевой инстанс системы-экспериментатора (`../../../00-infrastructure/28-empirical-experiment-methodology.md`).
Цель — вывести **конкретный расход токенов/лимита на запрос** для каждой модели и то, как он зависит
от усилия, объёма запроса, tool calls, вложений, времени, поверхности. Не разовый ответ — уточняемая
модель, которая копит данные и сходится.

## Файлы

| Файл | Что |
|---|---|
| `hypothesis.md` | Текущая модель: цель, факторы, формула, оценки + доверие, напряжения, backlog |
| `measurements.csv` | Лог опытов (факторы + результат), пополняется по ходу |
| `analyze.py` | Пересобирает модель из CSV: калибровка, множители моделей (OFAT), дельты, регрессия; печатает оценку + что мерить дальше |

## Как пользоваться

Текущая оценка из накопленных данных:

```
python3 analyze.py
```

Снял новый замер → допиши строку в `measurements.csv`, затем снова `python3 analyze.py`
(обновлённая модель). Флаг `--update-hypothesis` дополнительно допишет автоснимок в `hypothesis.md`:

```
python3 analyze.py --update-hypothesis
```

> Команды копируй **по одной, без комментариев в строке** — в zsh с выключенным `interactive_comments`
> текст после `#` уходит в скрипт как аргумент (грабли `../../pitfalls.md` PIT-005).

**Лучший инструмент замера — Claude Code**: статус-строка показывает точные токены и % лимита (сессия
и неделя). Веб/приложение даёт только % — грубее, нужен пересчёт через калибровку.

## Протокол одного замера (OFAT)

1. Свежая сессия/старт.
2. Ровно одна прогонка: зафиксировать все факторы, менять **один** (см. backlog в `hypothesis.md §5`).
3. Снять результат (Code: «N токенов, X% сессии, Y% недели»).
4. Строка в `measurements.csv`: дата, поверхность, модель, усилие, вход, выход, tool_calls, вложения,
   позиция, кэш, tokens_measured, pct_session, pct_week, baseline_id, заметка.
5. `python3 analyze.py`.
