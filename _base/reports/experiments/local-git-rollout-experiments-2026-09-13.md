**Дата:** 13.09.2026 · **Решение:** 🟢 раскатить на 58 приватных реп

> **Владелец 13.09.2026, дословно:** *«проведи ресерчи сделай локальные
> временные эксперименты чтобы точно понять выгодно ли переводить систему
> в .git каждой репы. вообще минусы ли есть. и если все ок сделай всем гит»*.

## Как это исследовалось

Все опыты шли на **копиях** реп в `/tmp/gitexp` (`ditto`), оригиналы
не трогались. Сетевые лимиты GitHub проверял отдельный агент-исследователь
по первоисточникам (docs.github.com, git-scm.com). Push проверялся на
**локальном «сервере»**: полный bare-клон `quick-answers` с настоящей историей.
На GitHub тестовых данных не отправлялось.

Копии: `edu-base` (2279 файлов, 771 МБ), `exam-kit`, `quick-answers`.

### Э5. Поиск переименований тянул из сети всю историю изменений

Коммит в `edu-base` под запретом докачки падал, без запрета висел минутами.
`GIT_TRACE_PACKET` показал **1151 запрос**. Причина: чтобы распознать
переименование, git сравнивает содержимое старого и нового файла, а старых
версий в частичной репе нет.

| | с переименованиями | `--no-renames` |
|---|---|---|
| `diff --cached` без сети | 🔴 код 128 | 🟢 код 0 |
| коммит с хуками без сети | 🔴 висел | 🟢 код 0 |

**Исправлено:** `diff.renames=false` и `status.renames=false` ставятся при
заведении, `git_health.py` их проверяет. Цена: переименование в выводе
выглядит как «удалён + добавлен». На историю и на GitHub это не влияет.

### Э7. Тонкий пакет требует старых версий файлов

Обычный `push` шлёт **тонкий** пакет, то есть дельты от старых версий.
В частичной репе этих версий нет:

| | без сети | с сетью |
|---|---|---|
| обычный push | 🔴 `unpacker error` | 🟡 работает, докачивает базы по одной |
| **`push --no-thin`** | 🟢 **работает** | 🟢 работает |

`fsck --full` на приёмной стороне после `--no-thin` чист, старые файлы
на месте. **Исправлено** в `publish.py`.

### Э8. Два правила противоречили друг другу

Хук `pre-commit` запрещает `.docx` и `.rtf`, а презентационный кит
**обязан** их выдавать: для этого он и существует. В базе конфликт
не проявлялся, потому что файлы давно не менялись. Первая же раздача
в наследницу остановила коммит. **Исправлено** узким исключением
по каталогу `11-presentation-kit/output/`; лимиты веса и проверка
секретов там действуют.

### Найдено чтением кода, до опытов

🔴 `release_notes.py` брал `CHANGELOG.md` **только из базы**. Первый же
выпуск чужой репы получил бы описание из чужого журнала. Исправлено:
`publish.py` передаёт журнал выпускаемой репы.

## Лимиты GitHub — по первоисточникам

| лимит | значение |
|---|---|
| один файл | **100 МБ** — жёсткий отказ всего push; 50 МБ — предупреждение |
| один push | 2 ГБ |
| размер репы | жёсткого нет; рекомендовано до 1 ГБ, «настоятельно» до 5 ГБ |
| частота | рекомендация на **одну** репу: 6 push/мин; 58 разных подряд — в пределах |
| LFS | для файлов до 100 МБ **не нужен** |

**Скан всех 67 реп (только чтение):** вложенных `.git` — 0; реп без
`.gitignore` — 0; файлов крупнее 100 МБ — 2, оба внутри `.venv` публичных
реп, которые не раскатываются. `control-panel/.env` закрыт `.gitignore`.

## Почему 58, а не 67

**9 публичных реп исключены намеренно:** `algorithms-site`, `claude-usage`,
`finpilot`, `game-analytics-engine`, `personal-finance-dss`, `salvation`,
`vevdokimovm`, `vevdokimovm.github.io`, `vk-graph`. Большая часть из них —
**зеркала**, и `deploy.sh` публикует их с фильтрацией содержимого. Push
из рабочей копии в публичную репу выложил бы всё подряд, включая то,
что зеркалам не положено. Для них остаётся `deploy.sh`.

## Итоговые настройки на каждую репу

| настройка | зачем | откуда |
|---|---|---|
| `user.name/email` — владелец | подпись не зависит от окружения | условие владельца |
| `extensions.partialClone=origin` | иначе git считает репу повреждённой | `PIT-211` |
| `core.autocrlf=false` | иначе `status` уходит в сеть по файлу | `PIT-210` |
| `diff.renames=false`, `status.renames=false` | иначе коммит тянет историю | 🆕 Э5 |
| `core.hooksPath` | защита от секретов и подписи ассистента | `PIT-211` |
| upstream `origin/main` | `push` и счётчик незапушенного | `PIT-211` |
| push `--no-thin` | push без сети | 🆕 Э7 |
| ~~`core.fsmonitor`~~ | не включать | 🆕 Э10 |

Все проверяемые пункты стережёт `git_health.py` в ревизионном гейте.
