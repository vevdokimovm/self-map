# experiments/ — эмпирические эксперименты (реверс-инжиниринг количеств)

Дом типа **«эксперимент/измерение»**: реверс-инжиниринг неизвестных количественных характеристик
закрытых систем через контролируемые замеры, декомпозицию на факторы и итеративное уточнение модели.
Методология (переиспользуемая для любой такой задачи) — `../../00-infrastructure/28-empirical-experiment-methodology.md`.
Тип в диспетчере — `../../00-infrastructure/19-reporting-system.md`; роутер — `../report_types.md`.

Не «разбор того, что случилось» (это `../incidents/` / `../situations/`), а **активное измерение
неизвестной величины**: ставим опыты, копим данные, собираем и уточняем модель.

## Структура эксперимента

```
<тема>/
  README.md         — величина, зачем, статус, как запускать
  hypothesis.md     — текущая модель: формула + коэффициенты + доверие + напряжения + backlog
  measurements.csv  — лог опытов (факторы + результат), пополняется
  analyze.py        — пересобирает модель из CSV, печатает оценку и что мерить дальше
```

Ключевое: **автоматизация обязательна** — набор данных + скрипт-анализатор делают эксперимент
самодействующим (добавил замер → прогнал → уточнённая модель), а не разовым числом.

## Эксперименты

| Тема | Что меряем | Статус |
|---|---|---|
| `token-consumption/` | расход токенов/лимита на запрос по моделям и факторам (усилие, объём, tools, вложения, время, поверхность) | v0.1, копим замеры |
| `pdf-delivery-channels/` | качество чтения одного PDF по трём каналам доставки (прямой PDF в чат · PDF в ZIP · файл в проекте): vision vs OCR vs текстовый слой, влияние инверсии тёмной темы и DPI | завершён (одноразовый бенчмарк на 1 стр.); протокол выведен в §5 |

## Как завести новый эксперимент

Скопируй структуру `token-consumption/` под свою тему, заполни `hypothesis.md` (цель + факторы),
заведи `measurements.csv` с нужными колонками-факторами, адаптируй `analyze.py`. Порядок — по
методологии `28` (TARGET → FACTORS → DESIGN → INSTRUMENT → MEASURE → DECOMPOSE → REFINE → VERSION).
