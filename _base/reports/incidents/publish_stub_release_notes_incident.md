# Инцидент: релиз v1.5.0 ушёл с заглушкой вместо описания (publish.sh v1)

- **ID:** INC-PUBLISH-STUB-NOTES · **Дата обнаружения:** 2026-07-09 · **Статус:** закрыт (v1.6.0)
- **Тип:** дефект инструмента с видимым влиянием (публичный артефакт релиза) → post-mortem
  по `../incident_postmortem_guide.md`.

## Симптом

GitHub Release `v1.5.0` репы `base-repo` опубликован с описанием-заглушкой (`Release 1.5.0`)
вместо подготовленной секции `## [1.5.0]` из CHANGELOG — при том, что секция была написана
полностью (слияние линии C, нейминг-ревизия кита, `--auto-asset` и т.д.).

## Диагностика и корень

`publish.sh` v1 искал changelog **только по одному пути** — `CHANGELOG.md` относительно
текущей папки. В base-repo летопись живёт в `00-infrastructure/CHANGELOG.md` (решение
v1.3.0: инфраструктурные журналы — в инфраструктурной папке). Файл не найден → скрипт
**молча** подставлял заглушку и продолжал публикацию. Ошибки не было, предупреждения не
было — цепочка «bump → tag → push → release» отчиталась успехом.

**Корень:** молчаливый фолбэк на заглушку при ненайденном источнике описания. Классический
антипаттерн «fail-silent»: скрипт предпочёл «хоть что-то опубликовать» вместо «громко спросить».
Вторичный фактор: единственный жёстко зашитый путь поиска не учитывал собственную же
конвенцию base-repo о расположении CHANGELOG.

## Масштаб

Один релиз (`v1.5.0`). Данные целы: секция CHANGELOG в репе полная, тег корректный,
ассет (`--auto-asset`) не пострадал. Влияние — витринное: у релиза нет человеческого
описания и заголовка.

## Устранение

1. **`templates/publish.sh` v2** (внесён в v1.6.0): changelog ищется по кандидатам
   `$CHANGELOG_FILE → CHANGELOG.md → 00-infrastructure/CHANGELOG.md → docs/CHANGELOG.md`,
   сначала от текущей папки, затем от корня git-репы. Секция не найдена → **громкое
   предупреждение** вместо молчаливой заглушки.
2. **Режим доделки** там же: перезапуск `zsh templates/publish.sh --version 1.5.0` на
   существующем теге не падает, а достраивает недостающее — в т.ч. **заполняет
   заглушечное описание** из CHANGELOG (`gh release edit`) и ставит человеческий заголовок.
   Осмысленное (не-заглушечное) описание при этом никогда не перезаписывается — тег и
   релиз заморожены (`21-revision-protocol.md`).

## Действие владельцу

Перезапустить `zsh templates/publish.sh --version 1.5.0 --auto-asset` из корня клона —
скрипт увидит существующий тег, найдёт секцию в `00-infrastructure/CHANGELOG.md` и
заполнит описание/заголовок релиза v1.5.0. Ничего не сломает: режим доделки идемпотентен.

## Уроки

- **Fail-loud, не fail-silent.** Инструмент, не нашедший источник данных, обязан кричать,
  а не тихо подменять результат заглушкой. То же правило у FINPILOT-публикатора после
  аварии wipeout: корень не опознан по маркерам → версия пропускается громко.
- **Инструмент обязан знать конвенции своей же системы.** Скрипт из `templates/` должен
  уметь работать со структурой, которую предписывает сам base-repo.
- Замороженное (описание вышедшего релиза) достраивается только из «пусто/заглушка»;
  осмысленное — не трогается автоматикой никогда.
