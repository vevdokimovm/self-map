# Репорт: предупреждение starship в терминале

**Дата:** 2026-07-30 · **Где:** оболочка macOS, не в коде проектов
**Статус:** косметика, но зашумляет вывод любого скрипта

---

## 1. Что видно

После почти каждой команды в терминале появляется строка:

```
[WARN] - (starship::config): Error in 'StarshipRoot' at 'node': Unknown key
```

Она вклинивается между выводом скрипта и приглашением, и в логах прогонов выглядит
как будто её напечатал скрипт. **Это не так.**

---

## 2. Что такое starship

Твоё приглашение командной строки — вот эта красивая строка:

```
╭─ ~/downloads on  main via  v3.10.0
╰─❯
```

Её рисует не zsh, а отдельная программа — **starship**. Она читает конфиг
`~/.config/starship.toml` и по нему решает, что показывать: путь, ветку git, версию
Node/Python, батарею и так далее.

---

## 3. Что именно сломано

Расшифровка сообщения по частям:

| Часть | Значение |
|---|---|
| `starship::config` | ошибка в конфиге, не в работе |
| `StarshipRoot` | корневой уровень файла `starship.toml` |
| `at 'node'` | ключ, на котором споткнулась |
| `Unknown key` | starship такого ключа не знает |

То есть в `~/.config/starship.toml` есть **`node`**, а starship понимает только
**`nodejs`**. Ключ либо переименовали в новой версии starship, либо в конфиг попала
опечатка при копировании чужого примера.

Функционально: блок про Node.js **не работает** — версия Node в приглашении не показывается
(или показывается дефолтом, а не твоими настройками). Всё остальное работает.

---

## 4. Как починить

Посмотреть, что там:

```bash
grep -n -A5 'node' ~/.config/starship.toml
```

Дальше один из двух вариантов.

**Если блок нужен** — переименовать секцию:

```toml
# было
[node]
format = "via [⬢ $version](bold green) "

# стало
[nodejs]
format = "via [⬢ $version](bold green) "
```

**Если не нужен** — удалить весь блок `[node]` с его строками.

Проверка:

```bash
starship config          # откроет конфиг в редакторе
starship explain         # покажет, что starship рисует и почему
```

После правки — новая вкладка терминала. Предупреждение исчезнет.

---

## 5. Почему стоило разобраться, а не игнорировать

Предупреждение печатается в **stderr** оболочки и попадает в любой лог, куда ты копируешь
вывод. В этой сессии оно несколько раз оказывалось внутри логов прогонов деплойера — и
каждый раз приходилось отдельно устанавливать, что это не скрипт.

Шум в выводе стоит времени ровно тогда, когда что-то ломается по-настоящему: чужие строки
приходится сначала отсеять, а на это уходит внимание.

---

> **Одной строкой:** приглашение рисует starship, в её конфиге ключ `node` вместо `nodejs`
> — блок про Node.js не работает и на каждую команду печатается предупреждение;
> переименовать секцию или удалить её, и вывод станет чистым.
