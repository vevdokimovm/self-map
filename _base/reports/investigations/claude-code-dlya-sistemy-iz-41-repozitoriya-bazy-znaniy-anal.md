# Claude Code для системы из 41 репозитория-базы знаний: анализ и практическое руководство

## TL;DR
- **Да, Claude Code решает вашу задачу.** Он умеет то, чего не умеет `collect_to_base.py`: читать десятки локальных репозиториев, находить смысловые (а не хеш-) пересечения между .md-файлами и синтезировать сводные методички — плюс сам делает git/gh-операции, запускает ваши скрипты и работает в цикле по всем репам. Ставится одной командой `curl -fsSL https://claude.ai/install.sh | bash`.
- **Ключевой риск — приватность.** У вас медицинские, генетические и правозащитные данные. Если авторизоваться через подписку Pro/Max (потребительские условия), обучение на ваших данных ВКЛючено по умолчанию, а данные хранятся 5 лет (30 дней, если отключить). Правильный путь для вас — **Console/API-ключ (коммерческие условия): обучения нет по умолчанию, хранение 30 дней.** Zero Data Retention соло-разработчику самостоятельно включить нельзя (только через отдел продаж, per-organization), а Claude Code вообще не покрывается HIPAA-режимом.
- **Что делать:** начните с API-биллинга (не подписки), запускайте синтез в отдельной git-ветке/worktree с обязательным ревью перед `git push`, вынесите инструкции в `CLAUDE.md`, а раздачу базы обратно в 41 репу оставьте вашему детерминированному `deploy.sh`. Для чисто «синтезной» задачи дешевле и безопаснее всего может оказаться дописать `collect_to_base.py` через Anthropic API с Batch (−50%) и prompt caching (−90% на кэш-чтение).

## Key Findings

**1. Что такое Claude Code в 2026.** Это агентный CLI-инструмент Anthropic, который, по официальному определению, «reads your codebase, edits files, runs commands, and integrates with your development tools». Работает на нескольких «поверхностях» с одним движком: терминал, расширение VS Code, плагин JetBrains (IntelliJ IDEA, PyCharm, WebStorm), desktop-приложение (вкладка Code) и веб (claude.ai/code). Все они читают общие `CLAUDE.md`, настройки и MCP-серверы. Ключевое отличие от веб-чата Claude: прямой доступ к файловой системе и git без ручной упаковки zip — то есть именно то, что убирает вашу боль «один zip = полный контекст».

**2. Установка на macOS.** Требования: macOS 13.0 (Ventura) или новее (Apple Silicon или Intel), 4 ГБ RAM, интернет, git. Рекомендуемый способ — нативный установщик: `curl -fsSL https://claude.ai/install.sh | bash` (кладёт бинарь в `~/.local/bin/claude`, авто-обновляется в фоне, **Node.js не требуется**). Альтернативы: Homebrew (`brew install --cask claude-code`, не авто-обновляется) и npm (`npm install -g @anthropic-ai/claude-code`, требует Node.js 18+). Запуск: `cd проект && claude`.

**3. Применимость к синтезу документов.** Claude Code читает много репозиториев в одной сессии через `--add-dir`/`/add-dir` и `additionalDirectories` в settings.json. Он справляется с сотнями файлов за счёт: (а) subagents — изолированных дочерних агентов с собственным контекстным окном, куда выносится «шумная» работа (чтение 50 файлов), а в основной контекст возвращается только сводка; (б) авто-компактирования контекста при приближении к лимиту; (в) поиска по файлам (Grep/Glob) вместо загрузки всего в контекст. Он умеет git/gh (коммит, ветки, PR), запускать ваши скрипты (`collect_to_base.py`, `sync-base.sh`) и работать в цикле.

**4. Модели и контекст (2026).** По умолчанию Claude Code на Anthropic API использует Sonnet (актуально — Sonnet 5, `claude-sonnet-5`), на Claude Max — Opus 5. Opus/Sonnet поддерживают контекст 1M токенов, но «просто свалить репозиторий в контекст» — ошибка: возникает «context rot», качество падает. Нужна структура: `CLAUDE.md`, поиск, subagents.

**5. Приватность — критично для вашего кейса.** Расклад по тарифам подтверждён официальной документацией (code.claude.com/docs/en/data-usage):
- **Consumer (Free/Pro/Max):** обучение на ваших данных и coding-сессиях ВКЛючено по умолчанию. Дословно: «Users who allow data use for model improvement: 5-year retention period... Users who don't allow data use for model improvement: 30-day retention period. Privacy settings can be changed at any time at claude.ai/settings/data-privacy-controls». То есть хранение — 5 лет, если включено, и 30 дней, если отключить.
- **Commercial (Team/Enterprise/API):** дословно «Anthropic does not train generative models using code or prompts sent to Claude Code under commercial terms, unless the customer has chosen to provide their data to us for model improvement (for example, the Developer Partner Program)» — обучения нет по умолчанию; стандартное хранение 30 дней. Соло-разработчик получает коммерческие условия, авторизуясь через Console/API-ключ.
- **Zero Data Retention (никакого хранения на серверах):** соло-разработчик сам включить не может. Дословно: «Zero data retention: available to qualified accounts for Claude Code on Claude for Enterprise. ZDR is not included in the standard Enterprise plan; it is enabled on a per-organization basis by your account team after confirming eligibility».
- **HIPAA/BAA:** доступен self-serve для API через Console, но **Claude Code явно не покрывается HIPAA-режимом** (в разделе «What HIPAA readiness does not cover»: «Claude Code: Claude Code is not covered under HIPAA readiness»).
- **Локальный кэш:** «Claude Code clients store session transcripts locally in plaintext under `~/.claude/projects/` for 30 days by default» (меняется через `cleanupPeriodDays`).

**6. Стоимость (2026).** Claude Code входит в Pro ($20/мес, или $17 при годовой оплате), Max ($100 5x / $200 20x), Team Premium ($100–125/место, мин. 5 мест). Лимиты: скользящее 5-часовое окно + недельный потолок; лимиты общие для Claude-чата и Claude Code. Точные токен-квоты Anthropic не публикует, только множители (Pro=1x, Max=5x/20x). Альтернатива — API-биллинг по токенам: Opus 5 $5/$25 за 1M, Haiku 4.5 $1/$5. Sonnet 5 сейчас по вводной цене $2/$10 за 1M токенов до 31 августа 2026, с 1 сентября — стандартные $3/$15. Batch API даёт −50% (асинхронно, до 24 ч), prompt caching — −90% на кэш-чтение; комбинация может дать до −95%.

## Details

### Установка и первый запуск (пошагово)

```bash
# 1. Установка (нативный установщик, без Node.js)
curl -fsSL https://claude.ai/install.sh | bash

# 2. Проверка
claude --version

# 3. Запуск в репозитории
cd ~/knowledge-base/base-repo
claude
```

**Авторизация и выбор условий приватности (важнейший шаг для вас).** При первом запуске Claude Code предложит войти. Есть два принципиально разных пути:
- Вход через подписку claude.ai (Pro/Max) → **потребительские условия** → обучение включено по умолчанию, хранение 5 лет.
- Установка `ANTHROPIC_API_KEY` из Anthropic Console → **коммерческие условия** → обучения нет по умолчанию, хранение 30 дней.

Для ваших данных выбирайте второй путь:
```bash
export ANTHROPIC_API_KEY="sk-ant-..."   # добавьте в ~/.zshrc
claude
```
Проверить, под какими условиями работает сессия: `claude config get` — если источник авторизации это API-ключ, вы под коммерческими условиями. Если случайно вошли под подпиской и хотите переключиться — `claude logout` и заново.

> ⚠️ Обратная ловушка тоже есть: если у вас установлен `ANTHROPIC_API_KEY`, Claude Code будет биллить по токенам, даже если вы платите за подписку. Многие получают неожиданные счета так. Решайте осознанно, что вам нужно — подписка или API.

### Настройка для многих репозиториев

**Вариант А — одна база + доступ к репам через additionalDirectories.** В `base-repo/.claude/settings.json`:
```json
{
  "permissions": {
    "additionalDirectories": ["../repo1", "../repo2", "../repo3"]
  }
}
```
Либо на лету: `/add-dir ~/knowledge-base/repo1`. Флаг при запуске: `claude --add-dir ../repo1 --add-dir ../repo2`. Чтобы Claude подхватывал `CLAUDE.md` из добавленных папок: `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1 claude --add-dir ...`. Не добавляйте весь диск — это раздувает область поиска и снижает эффективность. Важно по безопасности: любая папка, добавленная через `--add-dir`/`/add-dir`/`additionalDirectories`, становится читаемой И редактируемой в сессии — добавляйте только то, что действительно нужно, и никогда — папки с секретами.

**Вариант Б — git worktrees для безопасного синтеза.** Claude Code имеет нативную поддержку через флаг `-w`/`--worktree`:
```bash
claude -w synthesis-guides
# создаёт изолированный worktree в .claude/worktrees/synthesis-guides/,
# новую ветку и сессию, ограниченную этой папкой; основная рабочая копия не тронута
```
Это ключевой приём безопасности: синтез идёт в отдельной ветке, вы ревьюите diff и только потом мержите/пушите. На практике команды к середине 2026 надёжно ведут 4–8 параллельных worktree на разработчика — выше упираются в ревью, а не в Claude.

### CLAUDE.md — проектная память

Файл в корне репо, который Claude читает в начале каждой сессии; становится частью системного промпта. Держите его коротким и человекочитаемым. Для вашей задачи, например:

```markdown
# CLAUDE.md — База знаний

## Назначение
Система из 41 приватного репозитория. base-repo — центральная база.
Служебные .md собираются сюда через collect_to_base.py и раздаются через deploy.sh.

## Что можно и что нельзя
- НИКОГДА не делай git push без явного подтверждения.
- Синтез веди только в отдельной ветке (worktree).
- collect_to_base.py и deploy.sh — детерминированные, НЕ переписывай их логику копирования.

## Рабочий процесс синтеза
1. Найди похожие .md по теме (Grep/Glob) в добавленных репозиториях.
2. Выведи список кандидатов и предложи план объединения ДО записи.
3. Создай сводный документ в guides/, убрав смысловые дубли.
4. Покажи diff. Жди ревью. Только потом коммить.

## Команды
- Сбор базы: python collect_to_base.py
- Раздача: ./deploy.sh
```

Anthropic рекомендует иерархию: глобальный `CLAUDE.md` в корне + локальные в подпапках. Личные глобальные настройки — в `~/.claude/CLAUDE.md`. Правило Anthropic: в `CLAUDE.md` кладут то, что «impossible to know unless someone tells you» — соглашения, «почему A, а не B», подводные камни (кэши, фиче-флаги, миграции).

### Разрешения (permissions) и режимы автономности

Иерархия settings-файлов (по приоритету): enterprise managed (`/Library/Application Support/ClaudeCode/managed-settings.json`) → `.claude/settings.local.json` (личное, в gitignore) → `.claude/settings.json` (командное, в git) → `~/.claude/settings.json` (глобально ваше).

Режимы (`defaultMode` или переключение по Shift+Tab):
- `default` — спрашивает перед каждым редактированием/командой.
- `acceptEdits` — авто-принятие правок файлов, но прочее гейтится.
- `plan` — только чтение и анализ, без изменений (идеально для первого прогона по репам).
- `dontAsk` — авто-отказ, кроме явно разрешённого в allow.
- `bypassPermissions` — пропускает все запросы (опасно, только в изолированной среде).

Пример безопасной конфигурации `settings.json` для вашего кейса:
```json
{
  "permissions": {
    "defaultMode": "plan",
    "allow": [
      "Read",
      "Grep",
      "Glob",
      "Bash(git status:*)",
      "Bash(git diff:*)",
      "Bash(python collect_to_base.py:*)"
    ],
    "deny": [
      "Bash(git push:*)",
      "Bash(rm -rf:*)",
      "Read(./**/*.key)",
      "Read(./**/secrets*)"
    ]
  }
}
```
Deny-правила приоритетнее allow. Важно: сообщалось о багах (GitHub Issues #6631, #6699, регрессии в #12918, #27040 на февраль 2026), когда deny-правила (особенно на Read/Write) срабатывают не всегда — не полагайтесь на deny как на единственную защиту секретов; лучше физически не давать доступ к таким папкам. Интерактивно правила удобно настраивать командой `/permissions`.

Anthropic 24 марта 2026 выпустила «Auto mode» как более безопасную замену `--dangerously-skip-permissions`: классификатор пропускает безопасное и останавливает опасное. Для ваших данных всё равно рекомендуется ручное ревью перед пушем.

### Кастомные слэш-команды

Markdown-файлы в `.claude/commands/` (проектные) или `~/.claude/commands/` (глобальные). В 2026 они слились со skills (начиная с v2.1.101, апрель 2026), но однофайловый формат работает без изменений. Пример `/synth`:
```markdown
---
allowed-tools: Read, Grep, Glob, Write
description: Синтез сводной методички из похожих .md
argument-hint: [тема]
---
Найди все .md по теме "$ARGUMENTS" во всех добавленных репозиториях.
Выведи список файлов-кандидатов. Предложи структуру сводного документа.
После моего подтверждения создай guides/$ARGUMENTS.md, убрав смысловые дубли
и сохранив всё уникальное. НЕ коммить без отдельной команды.
```
Вызов: `/synth онбординг`. `$ARGUMENTS` подставляет все переданные аргументы; можно использовать позиционные `$1`, `$2`.

### Subagents

Определяются в `.claude/agents/*.md`. Для вашей задачи полезен «исследователь-читатель» на дешёвой модели, чтобы не жечь контекст основной сессии:
```markdown
---
name: md-explorer
description: Read-only поиск и картирование .md по репозиториям. Возвращает краткую сводку.
tools: Read, Grep, Glob
model: haiku
---
Ищи .md по заданной теме. Никогда не редактируй файлы.
Верни: список путей, 1-строчное резюме каждого, отметку смысловых пересечений.
```
Правило: узкий scope + минимум инструментов + чёткий формат вывода. Ревьюер/исследователь должен иметь только `[Read, Grep, Glob]`, никогда `[Edit, Write]` — иначе он «дрейфует» и превращается в обычного универсального агента. Встроенные subagents: General, Explore, Plan — Claude выбирает их сам.

### Хуки

Shell-команды на события. Пример авто-форматирования в `.claude/settings.json`:
```json
{
  "hooks": {
    "PostToolUse": [
      { "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "npx prettier --write $CLAUDE_FILE_PATH" }] }
    ]
  }
}
```
Хуки получают переменные `CLAUDE_FILE_PATH`, `CLAUDE_TOOL_NAME`, `CLAUDE_TOOL_INPUT`, `CLAUDE_SESSION_ID`, `CLAUDE_PROJECT_DIR`. Хук на `PreToolUse` с matcher «Bash» может блокировать опасные команды детерминированно (надёжнее, чем deny-правила).

### MCP-серверы

Model Context Protocol подключает внешние источники (Google Drive, Jira, Slack, собственные инструменты). Для вашего кейса локального синтеза MCP скорее не нужен — Claude Code и так имеет прямой доступ к ФС. Но filesystem-MCP актуален, если вы пойдёте путём Claude Desktop/Cowork (см. Альтернативы): в `claude_desktop_config.json` (`~/Library/Application Support/Claude/`) прописывается `npx -y @modelcontextprotocol/server-filesystem <разрешённые папки>`, требует Node.js, каждая операция запрашивает подтверждение.

### Стоимость и лимиты подробно

- **Pro $20/мес** — Anthropic позиционирует как «short coding sprints in small codebases»; ~45 промптов за 5-часовое окно (оценка третьих сторон, Anthropic точных цифр не публикует). Включает Cowork.
- **Max $100 (5x) / $200 (20x)** — для тех, кто регулярно упирается в лимиты Pro; на Max по умолчанию Opus 5. Точных токен-квот Anthropic не публикует — только множители к базе Pro.
- **API-биллинг** — по токенам, без месячного минимума. При интенсивной работе с большими объёмами файлов часто выгоднее подписки за счёт: Batch API (−50%, асинхронно до 24 ч) и prompt caching (кэш-чтение ~0.1x базовой цены, −90%; окупается уже после 1–2 обращений). Комбинация может дать до −95%.

Важные факты 2026: с 6 мая 2026 Anthropic удвоила 5-часовые лимиты для всех платных планов (Pro, Max, Team, seat-based Enterprise) и убрала пиковое троттлинг для Pro/Max. Есть опция overage — доплата по токенам после исчерпания лимита (с настраиваемым потолком расходов). Месячный потолок докупки — $2000 для Pro/Max, $3000 для Team.

**Что дешевле для вас.** Если синтез — периодическая пакетная задача по 41 репе, то собственный Python-скрипт на API с Batch+caching почти наверняка дешевле Max. Если вы хотите интерактивно вести всю систему репозиториев ежедневно — подписка Pro (или Max при частых упорах в лимит) проще и предсказуемее.

### Альтернативы для задачи синтеза

1. **Claude Code (CLI)** — максимум контроля, git-нативность, subagents, worktrees. Лучший выбор, раз вы уже владеете git/gh/скриптами.
2. **Claude Cowork** — «Claude Code без терминала», агентное desktop-приложение для не-разработчиков (research preview, запущено 12 января 2026, на Windows — 10 февраля 2026), даёт доступ к локальной папке и делает многошаговую работу (в т.ч. «синтез разрозненных заметок в связный черновик»). Тот же движок (Agent SDK), что у Claude Code. Для вас избыточно упрощён и хуже управляем, чем CLI.
3. **Claude Desktop + filesystem-MCP** — вкладка Code в desktop = тот же Claude Code с GUI и визуальным ревью diff; для не-git-задач можно подключить filesystem-MCP. Требует Node.js. Разумно, если хотите визуально смотреть изменения.
4. **Anthropic API из своего Python-скрипта** — дописать `collect_to_base.py`, чтобы он сам вызывал модель для синтеза. Максимальная предсказуемость, детерминированный контроль над тем, какие файлы уходят в облако, и самая низкая цена (Batch+caching). Минус — вы сами пишете оркестрацию (chunking, дедупликация, сборка промптов). **Для чисто синтезной подзадачи это, вероятно, оптимально по цене/приватности.**

## Recommendations

**Этап 1 — пилот (1–2 дня), только чтение.**
1. Создайте отдельный Anthropic Console-аккаунт, возьмите API-ключ, положите `export ANTHROPIC_API_KEY=...` в `~/.zshrc`. Это ставит вас под коммерческие условия (нет обучения, хранение 30 дней). При регистрации в Console вы принимаете Commercial Terms от своего имени — это разрешено для физлица.
2. Установите Claude Code нативным установщиком. Запустите в `base-repo` в режиме `plan`.
3. Дайте задачу: «найди 4–5 похожих .md по теме X в добавленных репах, покажи пересечения, предложи план сводной методички». Ничего не пишем. Оцените качество синтеза.
*Порог перехода дальше:* если синтез на реальных данных вас устраивает по качеству ≥80% — идём в этап 2.

**Этап 2 — управляемая запись.**
4. Напишите `CLAUDE.md` (шаблон выше) и `settings.json` с deny на `git push` и на папки с секретами.
5. Ведите синтез в git worktree (`claude -w synthesis`). Обязательное ревью diff перед мержем.
6. Оставьте `deploy.sh`/`collect_to_base.py` детерминированными — раздачу базы в 41 репу НЕ отдавайте модели.

**Этап 3 — решение по стоимости и по приватности.**
7. Если задача синтеза оказывается регулярной и пакетной — вынесите её в Python-скрипт на Anthropic API с Batch+prompt caching; это дешевле Max и даёт вам полный контроль над тем, что уходит в облако.
8. По приватности примите как факт: ZDR соло вам недоступен без отдела продаж, а Claude Code не покрывается HIPAA. Значит: (а) физически исключите самые чувствительные репозитории (медицина/генетика/правозащита) из области, которую видит Claude Code — не давайте `--add-dir` на них и запретите Read через deny; (б) для по-настоящему чувствительного синтеза рассмотрите локальную модель (Ollama/LM Studio) или ручную работу; (в) уменьшите `cleanupPeriodDays` и включите FileVault, потому что локальный транскрипт лежит в plaintext 30 дней.

**Что изменит решение (триггеры):**
- Стабильные упоры в лимит на Pro → перейти на Max 5x.
- Счёт по API за месяц > $100 при интерактивной работе → перейти на подписку.
- Anthropic откроет ZDR/HIPAA для Claude Code соло-разработчикам → можно расширить область на чувствительные репы.

## Caveats

- **Точные токен-лимиты Anthropic не публикует** — все цифры «45 промптов», «88k токенов» и т.п. это оценки третьих сторон, а не официальные данные; реальный расход зависит от длины сессии, модели и функций.
- **Модельный ландшафт быстро меняется.** На момент подготовки (август 2026) актуальны Sonnet 5 / Opus 5 / Fable 5; названия и цены менялись несколько раз за 2026 г. (в т.ч. вводная цена Sonnet 5 действует только до 31 августа 2026). Проверяйте `claude.com/pricing` и `code.claude.com/docs`.
- **Даты изменения потребительских условий.** Официальный анонс Anthropic «Updates to Consumer Terms and Privacy Policy» опубликован 28 августа 2025, дедлайн выбора для пользователей — «You have until October 8, 2025 to make your choice». Суть (обучение по умолчанию при включённой настройке + 5 лет / 30 дней) от точной даты не зависит. Коммерческие продукты (Team/Enterprise/API) этими изменениями не затронуты.
- **Известные жалобы/подводные камни:** после авто-компактирования модель «глупеет» и перечитывает файлы; на больших репах — «context rot» и «ложное сходство» (путает похожие модули); сообщалось о нестабильности deny-правил; были product-layer регрессии качества (март 2026, разрешены к 20 апреля 2026). Всегда ревьюйте вывод как «PR от талантливого новичка»: прогоняйте проверки, сверяйте с паттернами проекта.
- **Флаг-контент.** Даже при коммерческих условиях/ZDR: если сессия помечена системами trust & safety, Anthropic может хранить входы/выходы до 2 лет, а классификаторные оценки — до 7 лет. Транскрипты `/feedback`, `/bug`, `/share` хранятся 5 лет — не используйте их с чувствительными данными.
- **`bypassPermissions` / `--dangerously-skip-permissions`** — не используйте на репозиториях с приватными данными.
