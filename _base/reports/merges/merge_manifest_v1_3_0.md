## 1. Контекст: почему возникло слияние

Над `base-repo` параллельно работали разные аккаунты (V/J/M/S). Возникли **две линии одного
состояния**:

- **Линия A (на GitHub, канон):** v1.2.0 — доки `11`–`17` (практикум сжатия, кейс academic-portfolio,
  лимиты GitHub/Claude, грабли, интервью-методичка) + большой кит `01-claude-context/` (41 файл) +
  корневой `.gitignore`.
- **Линия B (эта вахта):** система отчётности (`reports/`), протоколы (философия/диспетчер/захват/
  ревизия/мёржи/непрерывность/changelog/версии), `publish.sh`, `CHANGELOG_TEMPLATE`, `VERSION`.

Обе линии независимо назвали свою работу **v1.2.0** и обе заняли номера `11`+ в `00-infrastructure/`.
Классическая ситуация из `22-merge-protocol` §1 (≥2 линий одного состояния) → нужна консолидация.

## 3. Метод (по `22-merge-protocol`)

1. **Линия A — база.** Взята как канон (она на GitHub, за ней осознанные решения других вахт,
   включая уже задокументированное разрешение 3-сторонней коллизии `09/10`). Слияние строилось
   **поверх копии A**, чтобы гарантированно ничего из A не потерять.
2. **Разложение по измерениям** (для доков: полнота · тема · точность · ссылки). Совпавшие файлы
   исключены сразу (`diff` по базе `01`–`10`).
3. **По каждому измерению — сильнейшее с доводом.** Уникальное из B добавлено; дубли B отброшены в
   пользу эволюционировавшего канона A.
4. **История не тронута.** Записи A (`1.0.0`/`1.1.0`/`1.2.0`) в `CHANGELOG` не редактировались;
   добавлена `1.3.0` сверху.

## 6. Дедупликация

Дубли ловились **по содержимому** (`diff`), не по имени:

- `gotchas`/`limits` из кита загружались в обе линии; в A они уже жили как `15`/`16` с починенными
  под свою нумерацию ссылками → канон A, дубли B отброшены.
- Личный кит (Preferences/Память/Cowork-global) — полноценно в `01-claude-context/` A; временные
  копии B в `claude/examples/` отброшены.
- Уникальное из B (modes, memory-методичка) проверено `grep` по всей A на отсутствие — добавлено.

## 10. Уроки (что запомнить на будущие слияния)

1. **Канон — то, что на GitHub.** Строить слияние поверх копии канона, а не поверх своей линии —
   тогда чужое гарантированно не теряется. (Тот же урок, что в `situations/2026-07-08-*`: реальное
   состояние — источник истины.)
2. **Дубли — по содержимому, не по имени/номеру.** Одинаковый по теме файл мог эволюционировать в
   одной линии (починенные ссылки) — побеждает эволюционировавший, а не «мой».
3. **Коллизию номеров разрулить один раз и записать** (здесь §5 + `CHANGELOG` Notes) — иначе
   следующая вахта наступит снова.
4. **Перенумерация = чинить ВСЕ ссылки** (полные имена + backtick + заголовки + пути подпапок), затем
   `grep`-проверка на остатки. Скрипт по убыванию номеров, чтобы не каскадило.
5. **Уникальное отделять от дублей проверкой `grep` по всему канону**, а не на глаз.
