# Ситуация-репорт: 67 оригиналов за служебками, которых не было на диске

> **Рубрика:** «Разбор ситуации и какие уроки я вывел».
> **Дата:** 15 сентября 2026. **Вахта:** Claude Code J.
> **Масштаб:** 183 служебки в 67 репах, 2.3 ГБ оригиналов в трёх хранилищах, iCloud-синк
> папки «Документы» при переполненной квоте.
> **Повод:** владелец заказал стандарт на сырые экспорты. Перед его написанием
> понадобились реальные числа, и первая же сверка нашла потерю.

---

## 1. Что было на входе

Служебка — это `.md`-паспорт вместо тяжёлого файла: что это, откуда он, sha256
и строка **«оригинал сейчас»** с путём на диске. Её обещание — «файл цел, лежит вот тут».

Обещание никто не проверял. Первый видеопрогон утром 15.09 споткнулся о него же:
путь из служебки вёл в пустоту, и скрипт написал 🟢 над пустой заметкой
(`07-media-to-text-lab/runs/2026-09-15-video-first-run.md`, поломка 1).

Оригиналы жили в трёх местах, и ни одно правило не называло главным ни одно из них:

| хранилище | что там |
|---|---|
| `~/Documents/_heavy-originals/<репа>/` | на него указывали **все 183** служебки |
| `<репа>/reports/imports/heavy-originals/` | 28 реп, ~1.3 ГБ |
| `~/Downloads` | разрозненные выгрузки |

## 2. Что показала сверка

`scripts/raw_originals_check.py` сверяет каждую служебку с диском **по sha256, а не по
имени**. Если путь пуст, скрипт ищет файл с тем же именем во всех хранилищах и признаёт
находку только при совпадении хэша.

| статус | служебок | что это значило |
|---|---|---|
| путь существует, хэш совпал | **0** | ни одно обещание не было верным дословно |
| цел, но лежит в iCloud-папке | 4 | нарушение, но не потеря |
| по пути пусто, файл найден в другом хранилище | **112** | файл цел, строка врёт |
| файл есть, хэш другой | 0 | |
| **не найден нигде** | **67** | |

У `Documents/_heavy-originals` на тот момент было **4 файла**, хотя на него ссылались 183 паспорта.

## 3. Как искали 67

Ненайденное проверялось по нарастающей стоимости: сначала дёшево, потом дорого.

| шаг | где | нашлось |
|---|---|---|
| 1 | хэш по всем репам, `Documents`, `Downloads`, `Desktop` | **4** — под другими именами в других репах |
| 2 | корзина | 0 (пуста) |
| 3 | локальный git `academic-portfolio` | 0: история начинается 06.09, это раскатка git, а не история файлов |
| 4 | выжимки рядом и по содержимому | **4 смысловых дубля**: пропал `.pptx`, но цел `.pdf` той же презентации с выжимкой. У остальных 59 только паспорт «Содержание не извлечено» |
| 5 | архив **самого раннего релиза** `academic-portfolio v0.2.1` (1 ГБ) | **59 из 61** уникальных, хэш каждого совпал |
| 6 | оглавления всех релизов `edu-base` — по HTTP Range, без скачивания | **1** (v0.2.0), достан один файл из архива (12 МБ) |
| 7 | оглавления всех релизов `academic-portfolio` и `legal-knowledge-base` | 0 |

🔴 **Оригиналы нашлись в архиве релиза, а не в git.** В git их не было никогда: тяжёлое не
пушится. Архив раннего релиза оказался единственной полной копией, пережившей вынос.

### Итог по 67

| исход | служебок |
|---|---|
| найдено на диске под другим именем | 4 |
| восстановлено из релизов, хэш совпал | 60 файлов (59 + 1) |
| **не восстановлено** | **3 файла** |

Не восстановлены:

| файл | размер | в каком-либо релизе |
|---|---|---|
| `academic-portfolio/.../Пример гифки приложения.pptx` | 67.3 МБ | нет |
| `academic-portfolio/.../Чавез Феррейра/ВКР_презентация.pptx` | 51.9 МБ | нет |
| `legal-knowledge-base/.../ШП пособие «Призыв на военную службу».pdf` | 157.5 МБ | нет; две служебки — один файл, sha256 совпадает |

Все три тяжелее 50 МБ. **Почему их нет в архивах, не установлено**: порог `>50` в
`pack_release.py` относится к размеру архива целиком, а не к отдельному файлу. Оставался последний шанс — «Недавно удалённые» на icloud.com до начала октября;
**владелец решил не искать** (15.09.2026). Утрата признана в служебках явной строкой.

Восстановленное лежит в `~/raw-originals/<репа>/` по исходным путям из паспортов.

## 4. Попутно: iCloud и «Документы»

Проверка места под единое хранилище показала, что `~/Documents` **синкается с iCloud**,
при этом включена оптимизация хранилища, а квота переполнена (`Quota exceeded` в `brctl`).
При нехватке места macOS заменяет файл заглушкой в облаке, и для хранилища оригиналов
это худший вариант. Заглушек не нашлось.

Владелец отключил синк. Как и предупреждалось, **локальная `~/Documents` опустела**:
всё уехало в `iCloud Drive/Documents`. Файлы были скачаны целиком (заглушек 0),
все 1482 возвращены в `~/Documents`, sha256 сверен у каждого, расхождений 0.
Облачная копия пока не удалена.

Единое место для оригиналов — **`~/raw-originals/<репа>/`**: корень домашней папки
iCloud не синкает. Из `Documents` туда перенесены 3 файла со сверкой хэша, четвёртый
(мастер-класс, 382 МБ) ждёт конца идущего прогона распознавания.

## 5. Что пошло не так

**Причина пропажи не установлена.** Известно, чего не было:

1. **Служебка признавалась готовой без проверки пути.** Строка «оригинал сейчас»
   записывалась в момент выноса и больше никем не сверялась. 0 из 183 оказались верны дословно.
2. **Оригинал удалялся при пустой выжимке.** У 59 из 60 восстановленных служебка честно
   писала «Содержание не извлечено». То есть удалить разрешили файл, суть которого нигде не сохранена.
3. **Хранилищ было три, и одно из них синкалось с iCloud** при переполненной квоте.
4. **Вывод «нашлось по имени» был бы ошибкой.** Одноимённый двойник с другим хэшем
   в selftest проверки специально не засчитывается.

## 6. Уроки

1. 🔴 **Оригинал не удаляется, пока нет выжимки.** Служебка «Содержание не извлечено» —
   это указатель, а не замена. Её наличие не даёт права удалить файл.
2. 🔴 **Путь в паспорте проверяется машиной, а не доверием.** `raw_originals_check.py`
   даёт код 1 при `lost` и `changed`, его место — в гейте.
3. **Архив раннего релиза — страховка, которой нет у git.** Тяжёлое никогда не попадает
   в историю, а в архив попадает. Удалять ранние релизы нельзя.
4. **Искать сперва по оглавлению.** Zip хранит оглавление в конце: по HTTP Range видно,
   есть ли файл в архиве на 272 МБ, без скачивания. Один файл достаётся так же.
5. **Хранилище оригиналов — вне синкаемых папок.** `Documents` и `Desktop` на этом маке
   синкались с iCloud, `~` нет.
6. **Отключение iCloud-синка «Документов» опустошает локальную папку.** Это поведение
   macOS, а не сбой: файлы нужно вернуть из `iCloud Drive/Documents` и сверить.

- [x] 112 устаревших путей переписаны (`raw_originals_check.py --fix`, 175 правок вместе с перенесённым; 3 найденных по хэшу — вручную той же функцией).
- [x] Второе хранилище `reports/imports/heavy-originals/` перенесено в `~/raw-originals`: 167 файлов, 1.4 ГБ, sha256 каждого, ошибок 0.

## 8. Попутная страховка

По заказу владельца у всех 67 реп докачаны **последние 5 коммитов целиком**
(`git fetch --depth=5` + `git backfill`): 67/67 без сбоев, пропущенных объектов 0,
`.git` всех реп 6.73 → 6.84 ГБ (+103 МБ) за 8 минут. У `education-paths`, `migration`,
`photo-archive` в истории всего 4 коммита.

🔴 **Сегодняшние файлы это бы не спасло**: последние 5 коммитов у всех реп сделаны после
выноса тяжёлого. Это страховка от свежих поломок рабочей копии, а не от этой потери.

## 9. Свой же урок, не применённый к себе

Ход, в котором написан этот отчёт, **сам дал двадцатый случай `PIT-G`**: вахта завела
реестр `asr-timings.csv` и инструмент к нему, не объявив ни журнал в `.runtime-writes`,
ни инструмент в README лаборатории, — и не запустила гейт. Поймал хук на выходе.

🔴 При этом урок №2 выше («проверяется машиной, а не доверием») писался в этом же ходу.
**Занятость классом ошибок не защищает от него** — наоборот, создаёт иллюзию, что предмет
уже учтён. Разобрано в `reports/incidents/PITFALLS.md`, `PIT-G`, случай 20.

## 10. Побочная находка: почему скрипты теряли `+x`

Проверка споткнулась о то, что `video_to_note.py` не запустился — «permission denied».
Это тянулось месяцами и считалось случайностью (`PIT-151`, память вахты от 27.08).

**Причина найдена и она системная.** `scripts/github_sync.py` распаковывал релизный архив
через `zipfile.extractall`, который **не восстанавливает права**: упаковщик их пишет
(в архиве реально 51 файл с 0o755), а распаковка молча выдаёт всем 0o644. Это дерево шло
в `git add` — и каждый деплой коммитил скрипты неисполняемыми, а каждая раскатка
воспроизводила потерю во всех репах.

Исправлено: `распаковать()` восстанавливает режим из `external_attr`, канарейка в
`--selftest` проверяет круг «упаковали → распаковали → права те же». Бит возвращён
84 скриптам канона, 4694 побайтово совпадающим копиям в `_base` и 148 собственным скриптам
реп; 177 расходящихся копий оставлены штатному синку. Память о PIT-151 переписана
с гипотезы на установленную причину.
