## 1. Назначение одной фразой

**Взять zip-архивы версий из папки и привести GitHub в состояние, где у каждой версии есть
коммит, тег и релиз по стандарту.**

Всё остальное в скрипте — следствие этой фразы.

---

## 2. Вход

| Что | Откуда | Обязательность |
|---|---|---|
| Архивы `<repo>-vX.Y.Z.zip` | папка (по умолчанию — где лежит скрипт) | да |
| Состояние GitHub | `gh` + git | да |
| `CHANGELOG.md` внутри архива/репы | секция версии | да, иначе релиз не создаётся |
| `.repo-id` в корне | `owner/repo` — принадлежность | нет, но при несовпадении с целевой репой публикация останавливается (§48) |
| `VERSION` в корне | версия дерева | нет, но без него распакованные копии не опознаются при уборке |
| Флаги режимов | переменные окружения | нет, у всех есть дефолт |
| `repos-map.md` | base-repo на GitHub | только для `ALL_REPOS=1` |

---

## 3. Выход: что обязано быть после успешного прогона

Для **каждой опубликованной версии** — все пять пунктов, иначе версия считается
незавершённой и попадает в отчёт об ошибках:

1. **Коммит** в `main` с деревом ровно из архива, сообщение `<repo> vX.Y.Z — <тезис>`.
2. **Тег** `vX.Y.Z`, указывающий на этот коммит (а не на соседний).
3. **Релиз** с заголовком `<repo> vX.Y.Z — <тезис>`.
4. **Тело релиза** = секция версии из `CHANGELOG.md`, шапка нормализована к `## [X.Y.Z]`.
5. **Канонический ассет** `<repo>-vX.Y.Z.zip` — из архива, а если архива нет, собранный
   из самого тега.

И на диске **не остаётся** локального архива этой версии: он дубликат того, что уже в репе.
Не удалён — значит комплект неполный, и причина названа.

Плюс `~/Downloads/deploy_last_run.log` — построчный итог прогона.

## 4. Инварианты

Нарушение любого — дефект, а не «особенность». Каждый закреплён тестом.

| # | Инвариант | Почему |
|---|---|---|
| И1 | Опубликованный тег никогда не переписывается | история версий неизменяема |
| И2 | Существующая репа не разрушается: дерево трогается только после подтверждения маркеров корня (`README.md`, порог файлов) | однажды снесли содержимое репы плоским архивом |
| И3 | Релиз без описания не создаётся | пустой релиз выглядит готовым и не чинится годами |
| И4 | Тег указывает на своё дерево, не на соседнее | git-кэш по mtime врал (PIT-014) |
| И5 | Ничего не удаляется, пока замена не подтверждена на месте | при обрыве связи можно остаться без единственной копии |
| И6 | Осмысленное описание не переписывается без `FORCE=1` | ручной текст ценнее сгенерированного |
| И7 | Повторный прогон на тех же данных ничего не меняет | идемпотентность |
| И8 | Сбой на одной версии или репе не роняет остальные | батч должен доезжать |
| И9 | «Не смог узнать» ≠ «нет»: при сбое связи сущность не считается отсутствующей | иначе скрипт создаёт то, что уже есть |
| И10 | Имена файлов сравниваются буквально, не как регулярки | точка в версии матчила подчёркивание и стирала ассет |
| И13 | Распакованный каталог удаляется только при пяти условиях одновременно: имя разбирается как `<repo>-vX.Y.Z`, внутри `VERSION` совпадает с именем, внутри **нет** `.git`, версия полностью на GitHub. Каталоги ищутся **в папке напрямую**, а не по списку архивов прогона | каталог без версии в имени — это рабочая копия владельца, снести её нельзя |
| И12 | Локальный архив удаляется только после подтверждения тега на remote, релиза и ассета совпадающего размера | иначе удаляется единственная копия |
| И11 | Рабочая папка живёт во временной директории и удаляется при **любом** выходе — нормальном, по ошибке, по Ctrl+C | лежала в `Downloads` и оставалась после каждого прерывания: три забытые папки заняли ~5 ГБ и переполнили диск прямо посреди прогона |
| И14 | Репы из `MIRRORS` массовые режимы не трогают. Работа с зеркалом — только явным `ONLY` или `MIRRORS_ONLY=1` | служебные файлы (`_base/` с внутренними протоколами и картой приватных реп) один раз уже уехали в публичную репу (v4.10.0/4.13.0) |
| И15 | Ремонтные режимы (`REPAIR`, `AUDIT`, `ASSETS_ONLY`, `CHLOG_FILL`, `ALL_REPOS`) репозиториев **не создают** | `ALL_REPOS` берёт список из карты и однажды воссоздал удалённую репу, потому что строку из карты не убрали (v4.11.0) |
| И16 | `.repo-id` внутри архива старше `REPO_MAP`: карта применяется, только когда маркера нет | карта переписывала цель по имени архива, после чего проверка ниже браковала архив за несовпадение с уже переписанным именем (v4.5.0) |
| И17 | В заголовок релиза не попадает служебный вывод: диагностика идёт в stderr, код возврата проверяется, текст проходит `safe_title()` | цветовые escape-коды уехали в заголовок публичного релиза (PIT-016, v4.16.0) |
| И18 | Версия в `WATCHLOG` §0 сверяется с публикуемой; расхождение — репа пропускается | §0 протух четыре раза подряд: шапка на одной версии, тело на другой (PIT-018, v4.16.0) |
| И19 | Список активных реп с GitHub сверяется с `repos-map.md` на **каждом** прогоне, а не только когда репа создана в этом прогоне | репу заводят руками через `gh`, и в карту она не попадала никогда: за месяц карта отстала на восемь реп (v4.14.0) |
| И20 | `SCRIPT_VERSION` соответствует содержимому файла | версия — единственный способ узнать, что накатано; расхождение уже давало «работает пропатченный, представляется старым» (v4.5.0) и даунгрейд рабочего инструмента (PIT-063) |

## 4а. Порядок как часть контракта: «сначала X, потом Y»

Инварианты §4 говорят, **что** гарантируется. Этот раздел — про **очерёдность**: почти каждая
строка здесь появилась после инцидента, где шаги переставили местами. Порядок в таких случаях
и есть защита, а не стилистика.

| Сначала | Потом | Почему |
|---|---|---|
| снос мусора macOS (`__MACOSX`, `.DS_Store`, `._*`) | разворот папки-обёртки | иначе в корне не один объект и разворот не срабатывает |
| проверка маркера корня (`README.md`, порог файлов) | **любое** деструктивное действие | не подтвердили, что это корень репы — не сносим ничего (И2) |
| чтение `.repo-id` из архива | создание репы на GitHub | несовпадение → стоп **до** того, как удалённая сторона тронута |
| `unzip -t` (целостность) | создание репы на GitHub | битый архив не должен родить репу-сироту |
| сверка версии в `WATCHLOG` §0 | коммит, тег и пуш этой версии | точка входа в вахту не должна опубликоваться протухшей (И18) |
| `git rm --cached -r .` | `git add -A -f` | иначе git по mtime и размеру решит «файл не менялся» (PIT-014, PIT-061) |
| коммит | сверка числа файлов «в коммите vs в дереве» | расхождение видно **только** сразу после коммита |
| загрузка канонического ассета **подтверждена** | удаление дублей под старым именем | иначе сбой сети снесёт единственную копию без замены (И5) |
| проверка `git status --porcelain` | вывод об успехе или провале коммита | «нечего коммитить» ≠ «коммит не прошёл» |
| всё содержимое версии распаковано и проверено | сборка заголовка релиза | заголовок нужен и тегу, и сообщению коммита — считается один раз |

**Практическое применение — ручные прогоны.** Когда деплойер запустить нельзя (репа заведена
не им, разовая починка), этот список — то, что теряется первым. Ошибка при ручном повторе почти
всегда не «сделал не то», а **«сделал в другом порядке»**.

*Извлечено из `mission-control/00-infrastructure/21-git-push-protocol.md` — построчного разбора
деплойера (20.08.2026, синтез инфраструктур).*

## 5. Таблица решений

Что происходит с найденным в папке архивом:

| Ситуация на входе | Результат |
|---|---|
| Имя по канону, версии на GitHub нет | публикуется полностью (5 пунктов §3) |
| Имя историческое (`_`, `-`, без `v`, `vX.Y`) | публикуется, имя помечается в выводе |
| Имя с хвостом ` copy`, ` 1`, `(1)` | **не** публикуется, названо в выводе как дубль |
| Служебный архив (`files*.zip`, `N.zip`) | пропускается молча, только счётчиком |
| Тег версии уже есть | пропускается |
| Версия ниже старшего тега | пропускается, если нет `BACKFILL=1` |
| Нет `README.md` в корне архива | отказ, репа не трогается |
| `.repo-id` указывает на другую репу | отказ **до** создания репы, обе репы названы |
| `.repo-id` отсутствует | публикация идёт, в выводе напоминание |
| `VERSION` внутри ≠ версии в имени | отказ по этой версии |
| Битый zip | отказ, соседние версии публикуются |
| Файлов меньше порога | отказ: это не репа |
| Нет секции в `CHANGELOG` | дерево и тег публикуются, релиз — нет |
| Репы на GitHub нет | создаётся приватной, вносится в `repos-map.md` |
| GitHub не отвечает | репа/версия пропускается с пометкой, не считается отсутствующей |

Что происходит с **уже существующим** релизом (только в режиме ревизии):

| Состояние релиза | Действие |
|---|---|
| Всё по стандарту | ничего, молча |
| Заголовок без тезиса | заголовок пересобирается |
| Тело-заглушка (`Release 1.0.0` и т.п.) | тело берётся из CHANGELOG |
| Тело осмысленное, но ≠ CHANGELOG | не трогается, выводится `~ отличается` |
| Нет канонического ассета | собирается из тега и загружается |
| Есть дубль под старым именем | снимается **после** подтверждения канона |
| Нет секции в CHANGELOG | описание и заголовок сохраняются как есть |

## 6. Чего скрипт не делает никогда

- Не переписывает опубликованный тег и не меняет его дерево.
- Не создаёт релиз без описания.
- Не удаляет ничего, кроме дубля архива **той же версии** под старым именем.
- Не публикует рабочие копии и дубликаты.
- Не чинит битую историю тегов молча — только сообщает в блоке «ТРЕБУЕТ ТВОЕГО РЕШЕНИЯ».
- Не удаляет локальный архив, пока не подтверждены тег, релиз и ассет на GitHub.

## 7. Поведение при отказах

| Отказ | Реакция |
|---|---|
| Сеть моргнула на операции | до 3 повторов с нарастающей паузой, только на транзиентных ошибках |
| Клон/пуш идёт устойчиво медленнее `CLONE_LOW_SPEED_LIMIT` дольше `CLONE_LOW_SPEED_TIME` | git сам обрывает передачу (это не завершение работы, а транзиентная ошибка — уходит в тот же повтор с паузой) |
| Сеть не отвечает дольше `GH_TIMEOUT` | операция прерывается, версия помечается, прогон продолжается |
| `gh` не авторизован | остановка на старте с объяснением |
| Диск заполнен | ошибка копирования видна в выводе, версия помечается |
| Чего-то не хватает для решения | пункт уходит в блок «ТРЕБУЕТ ТВОЕГО РЕШЕНИЯ» |

Правило: **скрипт либо делает правильно, либо не делает и говорит.** Третьего состояния —
«сделал криво и промолчал» — быть не должно.

## 8. Как менять поведение

0. **Прочитать `reports/incidents/PITFALLS.md`** — заголовки классов с счётчиками.
   Полминуты, и половина повторов не случается.
1. **Сначала правится этот файл** — контракт. Если изменение не выражается таблицей
   решений или инвариантом, оно не продумано.
2. **Потом тест** в соответствующей зоне (`tests/README.md`), воспроизводящий новое
   поведение и старое как несоответствие. **Обязательно с утверждением о втором прогоне** —
   шесть дефектов подряд были живы именно в устоявшемся состоянии, куда фикстура первого
   прогона не заглядывает.
3. **Потом код** — режимом внутри `deploy.sh`, никогда отдельным скриптом.
4. **Версия скрипта + запись в `deploy-CHANGELOG.md`.** Смена дефолта — MAJOR:
   команда та же, поведение другое.
5. **Прогон стенда под zsh на боевой машине:** `zsh base-repo/tests/test_deploy.sh`.
   Все четыре дефекта класса PIT-B пришли с macOS/zsh и стендом не ловятся.
6. **Прогон `DRY=1` на реальной папке** — стенд линуксовый, боевая машина macOS,
   класс различий BSD/GNU тестами не ловится.

## 9. Границы

Скрипт **не** заменяет: ручной git для повседневной работы в репе, CI, бэкап
(GitHub — не бэкап, а единственная копия после удаления архивов).

Стенд не проверяет: права токена, реальную приватность реп, лимиты GitHub API,
поведение BSD-утилит macOS, рендер markdown в вебе.
