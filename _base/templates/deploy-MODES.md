# `deploy.sh` — режимы и ключи

> Шпаргалка. Все режимы включаются переменными окружения перед командой.
> Правило одного скрипта — `templates/README.md`, история — `templates/deploy-CHANGELOG.md`.
>
> Ничего запоминать не нужно: без флагов скрипт делает то, ради чего запускается
> в 95% случаев.

---

## Пять команд, которые покрывают всё

```bash
# 1. Обычный день: опубликовать новые версии из папки. Быстро.
zsh ~/Downloads/deploy.sh

# 2. Посмотреть план, ничего не меняя.
DRY=1 zsh ~/Downloads/deploy.sh

# 3. Одна конкретная репа.
ONLY="dota-dossier" zsh ~/Downloads/deploy.sh

# 4. Привести к стандарту ВСЮ систему (долго, раз в несколько месяцев).
ALL_REPOS=1 zsh ~/Downloads/deploy.sh

# 5. Только посмотреть, что можно удалить, ничего не удаляя.
VERIFY=1 zsh ~/Downloads/deploy.sh
```

---

## Что делает дефолт

Без единого флага: находит версионные архивы в своей папке → группирует по репам →
для **новых** версий делает коммит, тег, push и релиз с каноническим ассетом → **удаляет
локальные архивы, которые полностью уехали на GitHub** (тег + релиз + ассет подтверждены).

Заодно убираются **распакованные зеркала** — каталоги вида `<repo>-vX.Y.Z`, которые
остаются после ручного разворачивания архива. Только доказуемые копии: имя с версией,
`VERSION` внутри совпадает, `.git` отсутствует, версия на GitHub. Каталог без версии
в имени (рабочая копия) не трогается никогда.

Архив, доехавший до GitHub, — дубликат того, что уже лежит в репе, держать его незачем.
Не удалилось — значит чего-то не хватает, и скрипт скажет чего. Отключается `KEEP_ARCHIVES=1`.

**Старые релизы не проверяет.** Это осознанно: ревизия истории нужна редко, а публикация —
каждый день. Раньше ревизия шла всегда, и прогон занимал часы.

## Область работы

| Ключ | Что делает |
|---|---|
| `ONLY="repo1 repo2"` | только эти репы |
| `SKIP="repo1 repo2"` | все, кроме этих |
| `IGNORE="regex"` | пропустить архивы по шаблону имени |
| `ALL_REPOS=1` | взять список реп из `repos-map.md` (фолбэк — `gh repo list`), а не только те, где есть архивы. Включает `AUDIT=1` |

Первый аргумент — папка с архивами. По умолчанию та, где лежит сам скрипт:
`zsh ~/Downloads/deploy.sh ~/other-folder`

---

## Глубина работы

| Ключ | Что делает |
|---|---|
| `DRY=1` | только план, ноль изменений |
| `AUDIT=1` | проверить и починить **все** релизы обрабатываемых реп |
| `REPAIR=1` | то же, что `AUDIT=1` (историческое имя) |
| `FORCE=1` | синхронизировать описания даже там, где текст осмысленный, но расходится с CHANGELOG. Включает `AUDIT` |
| `BACKFILL=1` | публиковать версии **ниже** старшего существующего тега |
| `ASSETS_ONLY=1` | только догрузить ассеты, дерево не трогать |
| `VERIFY=1` | ничего не менять; проверить, какие локальные архивы уже полностью на GitHub |

**Про `FORCE`.** Без него описание, которое отличается от CHANGELOG, но выглядит осмысленно,
не переписывается — выводится строка `~ описание отличается от CHANGELOG`. С ним всё
приводится к журналу. Если секции в CHANGELOG нет, `FORCE` описание **не** трогает:
брать текст неоткуда.

## Ассеты

| Ключ | Что делает |
|---|---|
| `KEEP_LEGACY_ASSETS=1` | **не** снимать дубли под старым именем (страховка) |

Дубль под старым именем — нарушение §42, поэтому он снимается **сам** при приведении
релиза к стандарту (`AUDIT=1`, `FORCE=1`, `ALL_REPOS=1`). Отдельного флага помнить не надо.

**Флаг работает только вместе с режимом ревизии** (`AUDIT=1` или `ALL_REPOS=1`):
в дефолтном режиме уже опубликованные релизы не обходятся вовсе. Если задать его одного,
скрипт скажет об этом и ничего не сделает.

Порядок операций жёсткий: сначала канонический ассет загружается и его наличие
подтверждается, и только потом снимается дубль. Обратный порядок мог бы при обрыве сети
оставить релиз вообще без ассета.

По стандарту §42 у релиза ровно три ассета: канонический `<repo>-vX.Y.Z.zip` плюс два
авто-архива GitHub. После бэкфилла у части релизов их четыре — рядом с каноническим лежит
старый (`finpilot_v6_6_0_intl.zip`). Флаг снимает **только** дубль той же версии; любые
другие вложения не трогаются, потому что удаление ассета необратимо.

**Ассет собирается даже без архива на диске.** Если исходной зипки нет, канонический
`<repo>-vX.Y.Z.zip` строится из самого тега (`git archive`) — то же дерево, обёртка по §43.
В выводе видно источник: `(из: архив)` или `(из: тег)`.

## Служебное

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `OWNER` | `vevdokimovm` | владелец репозиториев |
| `PRIVATE` | `1` | новые репы создаются приватными |
| `GH_TIMEOUT` | `120` | предел на один вызов `gh`, секунд |
| `KEEP_WORK` | `0` | `1` — не удалять рабочую папку (отладка) |
| `KEEP_ARCHIVES` | `0` | `1` — **не** удалять опубликованные архивы (по умолчанию удаляются) |
| `MIN_FREE_MB` | `2048` | ниже этого порога свободного места прогон не начинается |
| `REPO_MAP` | `finpilot=personal-finance-dss` | архив едет в репу с другим именем |
| `VARIANT_REPOS` | `finpilot` | у кого срезается постфикс сборки (`_intl`) |
| `SERVICE_RE` | см. скрипт | что считать служебным архивом (`files*.zip`, `N.zip`) |
| `NO_COLOR=1` | — | вывод без цвета |

## Рецепты

```bash
# Первый запуск после долгого перерыва — сначала посмотреть
DRY=1 zsh ~/Downloads/deploy.sh

# Одна репа целиком под стандарт, включая старые релизы
AUDIT=1 ONLY="portrait-of-taste" zsh ~/Downloads/deploy.sh

# Разовая большая уборка: вся система + синхронизация описаний + чистка дублей
FORCE=1 ALL_REPOS=1 DROP_LEGACY_ASSETS=1 zsh ~/Downloads/deploy.sh

# Залить старые версии в репу, где их не было
BACKFILL=1 ONLY="exam-kit" zsh ~/Downloads/deploy.sh

# Освободить диск
VERIFY=1 zsh ~/Downloads/deploy.sh
xargs -d '\n' rm -- < ~/Downloads/safe_to_delete.txt
```

## Что скрипт не делает никогда

- Не публикует рабочие копии и дубликаты (`(copy)`, ` 1`, `(1)`).
- Не трогает служебные архивы (загрузки из чата).
- Не создаёт релиз без описания: нет секции в CHANGELOG — нет релиза.
- Не переписывает опубликованный тег.
- Не удаляет ничего без явного флага.
