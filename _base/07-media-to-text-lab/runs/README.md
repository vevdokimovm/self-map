# runs — прогоны лаборатории превращения медиа в текст

Каждый прогон — **один источник, доведённый до текста**: что вошло, что вышло,
что потеряно и почему. Не отчёт о работе, а **воспроизводимая запись**:
по ней следующий прогон делается без переоткрытия метода.

| Прогон | Источник |
|---|---|
| [`2026-08-22-telegram-export.md`](2026-08-22-telegram-export.md) | HTML-экспорт Telegram Desktop, канал «МОЗГ. ПСИХОЛОГИЯ. ЗАВИСИМОСТЬ» |
| [`2026-08-23-docs-to-md.md`](2026-08-23-docs-to-md.md) | документы (`.docx`, `.pdf`) в Markdown — первый проход |
| [`2026-08-23-screenshots.md`](2026-08-23-screenshots.md) | скриншоты: что извлекается, что теряется |
| [`2026-08-27-docs-to-md-second-pass.md`](2026-08-27-docs-to-md-second-pass.md) | второй проход по документам — что дал повтор |
| [`2026-08-27-image-queue-first-look.md`](2026-08-27-image-queue-first-look.md) | первый взгляд на очередь изображений |

🔴 **Числа прогонов живут в `measurements.csv`, а не здесь.** Здесь — что
делали и почему; там — сколько вошло и вышло. Разделение не формальное:
ряд чисел без событий не объясняет сам себя, а события без чисел не проверяются
(`00-infrastructure/94` §2).

**Чего в прогоне НЕ пишут:** пересказ содержимого источника. Прогон отвечает
на вопрос «как это переведено в текст», а не «что там было» — второе живёт
в самом переведённом тексте.
