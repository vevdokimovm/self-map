| `semgrep` | ~196 ток. | включён |
| `hookify` | ~292 ток. | включён |
| `chrome-devtools-mcp` | ~654 ток. | включён |
| **итого включено** | **~1 142 ток.** | |
| `skill-creator` | ~112 ток. | 🔴 выключен |
| `claude-md-management` | ~175 ток. | 🔴 выключен |
| `claude-code-setup` | ~139 ток. | 🔴 выключен |

**1 142 токена — это 0,57 % окна в 200K.** Три выключенных полезных стоили бы
ещё **426 токенов, то есть 0,21 %**.

> **Вывод:** аргумент «не включаем, чтобы не съедало контекст» здесь

🔴 **Важное различие, которое печатает сам инструмент:** хуки помечены
как `harness-only — no model context cost`. Плагин, состоящий из одних хуков
(`security-guidance`), **не стоит контекста вообще** — он работает в обвязке,
не в окне модели.

## §3. Три плагина, которые нам нужны и выключены

### `skill-creator` — 🔴 закрывает дыру, о которой мы не знали

Умеет не только создавать скиллы, но и **прогонять эвалы**: подобрать тестовые
промпты, запустить на них Claude со скиллом и без, сравнить результаты
количественно, «оптимизировать описание скилла для точности срабатывания».

**Зачем нам.** У наших четырёх скиллов **проверки срабатывания нет вообще**.
Описание с триггер-фразами написано — а сработает ли скилл на живой формулировке
владельца, никто не мерил. Это ровно тот класс дефекта, который мы весь день
ловим у себя: **механизм без проверки различения**.

### `claude-md-management` — аудит памяти проекта

«Аудит качества CLAUDE.md, захват уроков сессии, поддержание памяти проекта
в актуальном состоянии».

**Зачем нам.** У нас `CLAUDE.md` подтягивает два больших файла контекста,
и они не проверялись на актуальность ни разу. Это тот же `PIT-167` —
недатированное утверждение о состоянии.

### `claude-code-setup` — рекомендатель автоматизаций

«Сканирует кодовую базу и рекомендует 1–2 автоматизации в каждой категории:
хуки, скиллы, MCP-серверы».

**Зачем нам.** Взгляд снаружи на то, что стоит автоматизировать. У нас
**шесть из девяти событий хуков свободны**, и решать, какие занять, пока
приходилось самим.

## §4. Флаги командной строки, которых мы не используем

Сняты из `claude --help` версии 2.1.251.

### 🔴 Прямо про наши боли

| Флаг | Что делает | Зачем нам |
|---|---|---|
| `--exclude-dynamic-system-prompt-sections` | выносит per-machine части (cwd, env, память, git-статус) из системного промпта в первое сообщение | **улучшает переиспользование кэша** — а у нас целая лаборатория расхода токенов и замеренная цена промаха кэша в сотни тысяч токенов |
| `--autocompact <auto\|tokens>` | задаёт окно автокомпакта (100k–1M) | компакт у нас случается сам; здесь им можно управлять |
| `--fallback-model <список>` | автопереход на другую модель при перегрузке, с повтором основной каждый ход | **прямая защита от простоя** в длинных прогонах |
| `--max-budget-usd` | предел трат на вызовы API | ограничение сверху для ночных прогонов |
| `--effort <low…max>` | уровень усилия на сессию | у нас `high` в настройках; на механической работе дешевле |

### Фоновые сессии — целое семейство, о котором мы не знали

```
claude --bg            запустить сессию в фоне, вернуть id
claude agents          список фоновых сессий
claude attach <id>     открыть фоновую сессию в этом терминале
claude logs <id>       вывод фоновой сессии
claude stop <id>       остановить (разговор сохраняется)
claude respawn --all   перезапустить все под текущей версией Claude Code
claude rm <id>         удалить сессию и её worktree
```

🔴 **Это может заменить самодельный ночной контур.** Наш `night.sh` держит
`caffeinate` и перезапускает `claude` внешней обёрткой; `--bg` + `respawn`
дают то же самое штатно и с управлением.

### Диагностика поломанной конфигурации

| Флаг | Что делает |
|---|---|
| `--safe-mode` | отключает **все** кастомизации: CLAUDE.md, скиллы, плагины, хуки, MCP, команды, агенты, стили. Для поиска, что именно сломано |
| `--bare` | минимальный режим: без хуков, LSP, синхронизации плагинов, авто-памяти, автообнаружения CLAUDE.md |
| `--restricted` | убирает Bash и всё, что исполняет код; файловые инструменты — только в рабочих каталогах |
| `-d --debug [фильтр]` | отладка с фильтром категорий: `"api,hooks"` или `"!1p,!file"` |
| `claude doctor` | проверка здоровья установки |

### Программное использование

| Флаг | Что делает |
|---|---|
| `-p --print` | ответ и выход — для конвейеров |
| `--output-format json\|stream-json` | структурированный вывод |
| `--json-schema <схема>` | **валидация структурированного вывода по JSON Schema** |
| `--input-format stream-json` | потоковый ввод в реальном времени |
| `--session-id <uuid>` | задать конкретный id сессии |
| `--fork-session` | при возобновлении завести новый id вместо переиспользования |

### Прочее, что стоит знать

- `--worktree [имя]` и `--tmux` — изолированный git-worktree на сессию;
- `--add-dir` — дать доступ к каталогам вне рабочего;
- `--agents <json>` — определить агентов прямо в командной строке;
- `--permission-mode` — `acceptEdits` · `auto` · `bypassPermissions` ·
  `manual` · `dontAsk` · `plan`;
- `--setting-sources user,project,local` — какие слои настроек грузить;
- `--plugin-dir` / `--plugin-url` — плагин на одну сессию, без установки;
- `--remote-control` — удалённое управление сессией;
- `--teleport` — перенос сессии;
- `--cloud` — облачная сессия;
- `--from-pr` — возобновить сессию, привязанную к PR;
- `claude import` — импорт конфигурации из другого ИИ-агента;
- `claude setup-token` — долгоживущий токен (нужна подписка).

## §5. Управление плагинами — команды, которых мы не знали

```
claude plugin details <имя>   состав плагина + ПРОЕКЦИЯ РАСХОДА ТОКЕНОВ
claude plugin eval [цель]     прогон эвалов против плагина со скорингом
claude plugin init <имя>      завести свой плагин в ~/.claude/skills/<имя>/
claude plugin enable/disable  включить/выключить
```

🔴 **`claude plugin init` заводит плагин, который автоподхватывается
следующей сессией** как `<имя>@skills-dir`. То есть свой набор скиллов можно
оформить плагином без публикации в маркетплейс.

## §6. Что из этого мы внедряем — и в каком порядке

| № | Действие | Цена | Что даёт |
|---|---|---|---|
| 1 | включить `skill-creator` | 112 ток. | проверка срабатывания наших 4 скиллов — сейчас её нет |
| 2 | включить `claude-code-setup` | 139 ток. | взгляд снаружи: какие из 6 свободных событий хуков занять |
| 3 | включить `claude-md-management` | 175 ток. | аудит актуальности файлов контекста |
| 4 | `--exclude-dynamic-system-prompt-sections` | 0 | экономия кэша — проверить замером |
| 5 | `--fallback-model` в ночном контуре | 0 | защита от простоя при перегрузке модели |
| 6 | заменить самодельный `night.sh` на `claude --bg` + `respawn` | 0 | штатный механизм вместо обёртки |

**Первые три — решение владельца** (включение плагинов меняет его среду).
Пункты 4–6 — работа вахты.

### 🔴 Как включить, если владелец решит — одной командой на каждый

```bash
claude plugin enable skill-creator@claude-plugins-official
claude plugin enable claude-code-setup@claude-plugins-official
claude plugin enable claude-md-management@claude-plugins-official
```

**Что изменится немедленно:** появятся скиллы `/skill-creator` (создание
и **эвалы** скиллов), `/claude-automation-recommender` (что автоматизировать),
инструменты аудита `CLAUDE.md`. Цена — **426 токенов** на сессию, 0,21 % окна.

**Что изменится не сразу, но важнее:** у наших девяти скиллов появится способ
проверить **срабатывание**. Сейчас его нет: описания с триггер-фразами
написаны, а сработает ли скилл на живой формулировке владельца — не мерил
никто. Это тот же класс, что мы ловим весь день — **механизм без проверки
различения**.

**Откатить:** `claude plugin disable <имя>` — обратимо полностью, состояние
хранится в `~/.claude/settings.json`.

🔴 **Почему вахта не включает сама:** плагины живут в **глобальных**
настройках владельца и действуют во всех его проектах, а не только в этой
системе. Правка чужой среды без спроса — не работа, а самоуправство,
даже когда полезна.

## §6-тер. Три РАЗНЫЕ сущности, которые легко спутать

Вопрос владельца 29.08.2026: *«это же агенты Антропик? как ими пользоваться,
в каких ситуациях»*. Сущностей три, вызываются по-разному, и путать их вредно.

| | Что это | Как вызывается | Кто вызывает |
|---|---|---|---|
| **Субагенты** | отдельная сессия со своим контекстом | инструментом `Agent` | **только я**, слешем нельзя |
| **Встроенные скиллы** | инструкции, загружаемые в мою сессию | `/имя` | **владелец или я** |
| **Плагины** | наборы скиллов, агентов и хуков | сначала включить, потом `/имя` | владелец включает |

🔴 **Отсюда практическое следствие:** субагента владелец позвать не может —
он просит словами, а вызываю я. Скилл — может слешем. Плагин — сначала надо
включить в настройках.

### Субагенты Anthropic — что есть и когда звать

| Агент | Когда уместен | Когда НЕ уместен |
|---|---|---|
| **`Plan`** | спроектировать многошаговое изменение до того, как что-то трогать | простая правка — план дороже дела |
| **`Explore`** | найти что-то по многим файлам, когда нужен **вывод, а не дампы** | известно, где искать — дешевле `grep` |
| **`general-purpose`** | своя задача с точным промптом (наши исследования) | когда хватает одной команды |
| **`claude-code-guide`** | вопросы про сам Claude Code | вопросы про наш код |

### Встроенные скиллы — по ситуациям

| Скилл | Ситуация у нас | Применимость |
|---|---|---|
| **`/code-review`** | 🔴 **13 681 строка Python в `scripts/`, ни одного ревью** | **высокая** |
| **`/simplify`** | те же скрипты: чистка без охоты за багами | высокая |
| **`/verify`** | проверить, что код **работает**, а не что он красивый | средняя — гейт проверяет форму, не работу |
| **`/security-review`** | `secret.py`, работа с ключами, `deploy.sh` | точечно |
| **`/loop`** | повторять по расписанию — у нас сторож самодельный | стоит попробовать |
| **`/fewer-permission-prompts`** | сканирует транскрипты, предлагает список разрешений | разово, полезно |
| **`/run`** | запустить приложение и посмотреть | только `control-panel`, `finpilot` |
| **`/init`** | сгенерировать `CLAUDE.md` новой репе | при заведении репы |
| **`/dataviz`**, **`/design`** | графики и макеты | почти нет — у нас текст |

### Плагины — что включено и что стоит

**Включены:** `security-guidance` (хуки, **0 токенов контекста**), `hookify`
(~292), `semgrep` (~196), `chrome-devtools-mcp` (~654).

**Выключены и стоят включения:** `skill-creator` (~112) — эвалы на скиллах,
которых у нас нет; `claude-code-setup` (~139) — рекомендует, какие из шести
свободных событий хуков занять; `claude-md-management` (~175) — аудит
актуальности файлов контекста.

🔴 **`code-review` как плагин против `/code-review` встроенного:** встроенный
доступен всегда и работает по diff; плагин добавляет **несколько
специализированных агентов со скорингом уверенности**. Для 13 тысяч строк,
написанных за день одним лицом, второе честнее — но и дороже.

### Чего у нас НЕТ и почему это важно знать

**Ни одна из 47 наших Python-программ не проходила ревью.** Гейт проверяет
Markdown: связность, числа, иероглифы, пределы. Код он не смотрит вовсе —
кроме мета-гейта, который следит за живостью проверок, но не за их качеством.

Это прямая дыра, и закрывается она встроенным инструментом за одну команду.
