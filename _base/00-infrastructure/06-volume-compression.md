# 06 — Протокол сжатия объёма (большой файл → тезисный `.md`)

> Первый этап работы с уже загруженной репой и постоянная практика дальше: заменить
> тяжёлые сырые файлы (`.docx`, `.pdf`, длинные выгрузки) на лёгкие тезисные `.md` —
> **с сохранением полной сути и логики**, без воды. Зачем — `02-claude-workflow.md`
> §2 (лёгкая репа дольше видна Claude целиком, а не через RAG).

## Что значит «сжать без потери сути»

Не пересказ «покороче», а **дистилляция**: убрать воду и повторы, сохранить все
факты, определения, логические связи и структуру. После сжатия по `.md` можно
восстановить те же выводы, что и по оригиналу — потерялся только объём, не смысл.

- **Факты, числа, определения, формулировки** — переносятся 1:1.
- **Вода** (вводные абзацы, риторика, повторы, «как известно…») — вырезается.
- **Структура и логика** — сохраняются (те же разделы, тот же ход мысли).
- **Свои слова** — переформулировать, а не копипастить куски (правило обобщённости).

## Алгоритм

1. **Прочитать целиком**, выделить смысловые блоки (это будущие разделы `.md`).
2. По каждому блоку — **вытащить тезисы**: факты, определения, ключевые связи.
3. **Собрать `.md`**: заголовок → короткое «что это и зачем» → разделы с тезисами →
   при необходимости таблицы/списки → первоисточник в конце (если ценен).
4. **Сверить с оригиналом**: пройтись по ключевым пунктам исходника — все ли на
   месте в `.md`. Ничего важного не выпало?
5. **Решить судьбу оригинала:**
   - Ценен как первоисточник (документ, который может понадобиться дословно) →
     оставить рядом как приложение (`sources/`), в README отметить.
   - Не нужен дословно → канон это `.md`, оригинал держишь **локально у себя**, в
     репу тяжёлый файл не коммитишь.

## Проверка качества сжатия

- Открыл `.md` через неделю — понятна ли суть без оригинала? Да → сжато хорошо.
- Можно ли по `.md` сделать те же выводы/действия? Да → логика сохранена.
- Осталась ли вода, которую можно убрать без потери смысла? Нет → плотность ок.

## Жёсткие правила по типам файлов

Репа — **хранилище знаний, а не архив файлов**. Отсюда конкретика по форматам:

| Формат | Правило |
|---|---|
| `.docx`, `.pptx`, `.odt`, `.rtf` | **Не место в репе.** Всё → `.md`-конспект 1:1 по смыслу. Оригинал локально. |
| `.zip`, `.rar`, `.7z` | **Не место в репе.** Распаковать, содержимое разобрать по правилам. Архив ≠ знание. |
| `.pdf` | Оставляем **только если ≤5 МБ** и он ценен как первоисточник/результат (скан документа, статья, сгенерированный отчёт анализа). Тяжелее 5 МБ → сжать (рендер сканов в 100–150 dpi) или законспектировать в `.md`. |
| Картинки (`.png`, `.jpg`, …) | Только если **необходимы**: лого, диаграмма, график результата анализа, скрин для разбора. Каждая **≤0.5 МБ**. Не «фотоальбом», а иллюстрация к тексту. Тяжёлые → сжать/ресайз. TIFF → PNG всегда. |
| `.html` | Ок для результатов анализа, интерактивных отчётов, дашбордов. |
| Скрипты (`.py`, `.sql`, …) | Ок — код анализа, утилиты. Артефакты сборки (`.exe`, `.o`, `bin/`, `obj/`, `.cbp`) — вон, пересобираются. |
| `.md` | Основа репы. Держать <2 МБ на файл (иначе GitHub не отрендерит — см. ниже). Большой раздел — бить на несколько. |

**Как выглядит здоровая репа:** преимущественно `.md` (конспекты, суть, логика, тезисы), немного картинок (лого/графики), немного PDF (первоисточники/результаты ≤5 МБ), скрипты анализа, результаты анализа в `.pdf`/`.html`. Всё. Никаких zip/docx/pptx.

## Что физически умеет GitHub (лимиты, факты из GitHub Docs)

Правила размеров выше — не вкусовщина, а подстройка под механику GitHub:

- **Файл >50 МиБ** → git выдаёт warning, пуш проходит, но производительность страдает.
- **Файл >100 МиБ** → GitHub **блокирует пуш**. Нужен Git LFS (для knowledge-реп это сигнал, что файл вообще не туда — конспектируй).
- **Загрузка через браузер** → макс **25 МиБ** на файл.
- **Рендер `.md`/Mermaid** → GitHub рендерит если файл **<2 МБ**; сложнее — падает в plain text или не отображается. Отсюда правило дробить крупные `.md`.
- **Рендеримых файлов в одном diff** (картинки, PDF) → максимум **25**.
- **Размер репы** → софт-предупреждение ~1 ГБ, хард-предел ~5 ГБ (GitHub напишет до отсечки).

Вывод: мелкие файлы + лёгкая репа = всё рендерится, быстро клонируется, не упирается в LFS.

## Пороги размера репы (наш стандарт)

Три порога, детально — в `01-repo-standard.md` §4:

- 🟢 **≤50 МБ — норма и цель.** В среднем репа должна быть такой.
- 🟡 **100 МБ — мягкий потолок.** Выше — неудобно (медленный клон/пуш), терпимо в исключениях.
- 🔴 **500 МБ — жёсткий потолок.** Выше Claude физически не принимает архив целиком, работа с репой в Claude ломается.

Числа 500/100/50 — рабочий ориентир; исключения разбираем по конкретному кейсу и при необходимости обновляем правила.

## Форма результата

Тезисный `.md` по стандарту письма (`07-writing-methodology.md`): плотно,
структурно, применимо. Имя файла — по неймингу (`01-repo-standard.md`): англ,
kebab-case, с префиксом порядка если это раздел темы.
