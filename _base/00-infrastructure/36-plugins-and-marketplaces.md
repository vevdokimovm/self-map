# 36 — Плагины и маркетплейсы

> **Что это и зачем.** Плагин — это **бандл**: упакованный набор скиллов, коннекторов, MCP-серверов,
> хуков и агентов под одну область работы. Вместо того чтобы поштучно включать скиллы и коннекторы,
> ставишь один плагин — и получаешь готовый набор под роль (Engineering, Sales, Legal…). Маркетплейс —
> витрина плагинов. Документ: **что такое плагин, чем отличается от скилла/коннектора, что мы поставили,
> как ставить и как собрать свой.**
>
> Кластер: скиллы (что внутри плагина) — `37`, коннекторы — `35`, поверхности — `26`, плейбук «как
> сделать» — `41`.

---

## 0. Одной строкой

Плагин = **коробка «скиллы + коннекторы + MCP + хуки + агенты» под область**. Ставишь коробку — её скиллы
падают прямо в твоё `/`-меню.

---

## 1. Иерархия: тул → скилл → коннектор → плагин → маркетплейс

| Уровень | Что это | Пример |
|---|---|---|
| **Инструмент (tool)** | Одно действие | `search_threads`, `Read`, `create_trigger` |
| **Скилл (skill)** | Упакованный сценарий, запуск `/name` | `/code-review`, `/morning` |
| **Коннектор** | Мост к сервису (пачка тулов) | Gmail, Slack (`35`) |
| **Плагин** | Бандл скиллов+коннекторов+MCP+хуков+агентов под область | **Engineering**, Sales, Legal |
| **Маркетплейс** | Витрина/каталог плагинов | `knowledge-work-plugins` |

Плагин — это способ **не собирать набор руками**. Кто-то уже скомпоновал под роль «инженер» нужные
скиллы (ревью, дебаг, ADR, тесты) — ты ставишь одним движением.

---

## 2. Что мы поставили (эта сессия, июль 2026)

**Плагин `Engineering`** (маркетплейс `knowledge-work-plugins`). Дал в `/`-меню кластер инженерных
скиллов:

| Скилл | Что делает |
|---|---|
| `/engineering:code-review` | Ревью изменений на безопасность/производительность/корректность (PR/дифф) |
| `/engineering:debug` | Структурная отладка: воспроизвести → изолировать → диагноз → фикс |
| `/engineering:architecture` | ADR: выбор технологии с trade-offs и последствиями |
| `/engineering:system-design` | Проектирование систем, API, модели данных, границы сервисов |
| `/engineering:testing-strategy` | Тест-стратегии и планы (покрытие, архитектура тестов) |
| `/engineering:tech-debt` | Инвентаризация и приоритизация техдолга |
| `/engineering:deploy-checklist` | Пред-деплой чек-лист (миграции, флаги, откат) |
| `/engineering:incident-response` | Инцидент: триаж → коммуникация → блеймлесс-постмортем |
| `/engineering:documentation` | Техписьмо: README, ранбуки, API-доки |
| `/engineering:standup` | Стендап-апдейт из активности (коммиты/PR/тикеты) |

Эти скиллы **прямо в тему FINPILOT и карьеры**: `/engineering:code-review` и `/engineering:testing-strategy`
ложатся на TDD-дисциплину проекта, `/engineering:architecture` — на ADR, `/engineering:standup` —
на weekly review.

**Коннекторы, предложенные в эту сессию:** Microsoft Learn (доки MS/Azure), Exa (веб+код-поиск) — `35`.

**Агенты** (не плагин, но соседний слой — субагенты для делегирования): доступны типы `Explore`
(быстрый поиск по коду), `Plan` (архитектор плана), `general-purpose`, `claude-code-guide` и др.
Разбор слоя агентов/сабагентов — `40` §Субагенты.

> Личные роли-команды (`/mentor`, `/reviewer`, `/architect` …) из моего `Agents.md` — это **другое**: не
> плагин, а мои промпт-режимы. Плагинные скиллы `/engineering:*` их дополняют, не заменяют.

## 3. Установить готовый плагин

1. `ListPlugins` — что уже стоит (не предлагать повторно установленное).
2. `SearchPlugins` по роли/задаче (`["engineering","developer"]`).
3. `SuggestPluginInstall` с топ-2–3 → карточка. **Org-плагины (если организация опубликовала свои) —
   всегда первыми:** они заточены под реальные инструменты компании.
4. Ставишь → скиллы плагина появляются в `/`-меню сразу.

---

## 4. Собрать/кастомизировать свой плагин

Для этого есть скилл **`cowork-plugin`** (создать плагин с нуля или подогнать установленный под
организацию). Когда полезно тебе:

- **Свой «FINPILOT-плагин»:** бандл из скилла «пиши тест по нашему TDD+гейтам», коннекторов проекта и
  хука проверки секретов — один раз собрал, разворачиваешь на всех 4 аккаунтах.
- **Плагин «repos-map»:** скиллы ведения knowledge-реп (ревизия по `21`, ситуация-репорт по `19`) +
  правила из base-repo. Тогда протоколы репы становятся вызываемыми `/`-командами, а не текстом,
  который надо помнить.

Механика сборки (структура, манифест, где живут скиллы/хуки) — по скиллу `cowork-plugin`; глубоко в
MCP-часть — скилл `mcp-builder` (`35` про коннекторы как MCP).

---

## 5. Плагин vs скилл vs коннектор — когда что

| Хочу | Беру |
|---|---|
| Одно повторяемое действие/сценарий | **Скилл** (`37`) |
| Доступ к внешнему сервису | **Коннектор** (`35`) |
| Готовый набор под целую роль сразу | **Плагин** (этот док) |
| Свести свои конвенции в вызываемый набор для всех аккаунтов | **Собрать плагин** (`cowork-plugin`) |

---

## 6. Чек-лист

1. Задача пахнет целой ролью (инженер/юрист/продажи)? → искать **плагин** (`SearchPlugins`).
2. Уже стоит? (`ListPlugins`) → не предлагать повторно.
3. Есть org-плагин? → он первым.
4. Нужен один сценарий, не роль? → это **скилл** (`37`), не плагин.
5. Свои конвенции хочешь разложить на все аккаунты? → **собрать плагин** (`cowork-plugin`) + внести в репу.
