# 14 — Claude: токены, сессии, недельные лимиты, модели

> Как реально устроены лимиты Claude (потребительские планы). Данные — из support.claude.com и официальных материалов Anthropic на июль 2026. ⚠️ Anthropic **намеренно не публикует точные токены** — цифры ниже это то, что известно/оценено; финальная правда всегда в **Настройки → Usage** твоего аккаунта.

---

## 1. Твоя модель vs реальность

Ты описал: месяц X, неделя Y (Y≤X), 5-часовая сессия Z, ждёшь 5ч → снова Z, но ≤Y в неделю и ≤X в месяц.

**Почти верно, с одной поправкой:** у потребительских планов **нет отдельного месячного токен-пула X**. Реальных ограничения **два**: (1) **5-часовая сессия** и (2) **недельный лимит**. Недельный — это и есть внешняя граница. «Месячное» появляется только в двух местах: спенд-кэп **usage credits** (настраиваемый) и отдельный **месячный кредит на непрограммный доступ** (Agent SDK / headless: $20 Pro / $100 Max 5x / $200 Max 20x, с 15.06.2026). Плюс третье ограничение — не про объём, а про длину одного чата: **контекст 200K токенов**.

---

## 2. Три ограничения

**① 5-часовая сессия (rolling).** Стартует с **первого сообщения**, не по часам/полуночи. Отправил первое в 9:00 → окно до 14:00, что бы ты ни делал внутри. Выжег — пауза до сброса (14:00). Ничего не слал до 15:00 → следующее сообщение открывает свежее окно. `/clear` (новый чат) **не сбрасывает** лимит — он account-level.

**② Недельный лимит.** Сбрасывается в **фиксированное время, назначенное твоему аккаунту** (не обязательно понедельник, хотя у тебя на скрине — Mon 8:59 PM; у каждого своё). На Pro исторически был один бар «все модели», сейчас видно **два бакета: «All models» и отдельный «Fable»** (см. §4).

**③ Контекст 200K токенов** — рабочая память одного чата (все модели, платные планы; Enterprise — 500K на части моделей). Это **длина**, а не объём использования: упёрся — начинай новый чат / используй Projects. При включённом code execution Claude сам суммаризует старые сообщения при подходе к лимиту.

**Всё общий пул:** claude.ai + Claude Code + Desktop + Cowork тянут из **одной** сессии и одного недельного лимита. Час болтовни в claude.ai урезает то, что осталось на Claude Code.

---

## 3. Точные значения Z / Y / X

**Не публикуются.** Это подтверждают все независимые источники: официально Anthropic даёт **только мультипликаторы** (Pro = 1x, Max 5x, Max 20x) и говорит, что расход зависит от длины/сложности диалога, выбора модели, фич и уровня усилий. **Любая точная цифра типа «44 000 токенов за окно» — выдумана.** Единственный надёжный сигнал — твой дашборд Usage.

**Что известно конкретно:**
- **Контекст:** 200K токенов (500K Enterprise на части моделей).
- **Оценка Pro:** ~**45 сообщений за 5-часовое окно** для коротких несложных диалогов (официальная прикидка Anthropic). Независимые тесты: ~10–45 промптов/окно на Pro. Длинные промпты, вложения, Opus/Fable, tool use — **сильно** уменьшают это число.
- **5-часовые лимиты удвоили** 06.05.2026 (Pro/Max/Team) и убрали пиковые урезания; недельные подняли на 50% до 13.07.2026 (промо).
- **Мультипликаторы и грубый $-эквивалент** (оценка сообщества, не официально): Pro ≈ $20, Max 5x ≈ $100, Max 20x ≈ $200 нотального API-расхода в месяц.

**Меняется ли от подписки:** да — это и есть мультипликатор. Max 5x = 5× бюджета Pro, Max 20x = 20× Pro. Сессия и недельный масштабируются с тарифом; механика (5ч + неделя) одинаковая.

## 4. Fable 5 (твой вопрос H) и расход по моделям

**Fable 5 — самая мощная и самая «прожорливая».**
- **Расход:** Claude Code прямо показывает предупреждение и говорит: **«использует твои лимиты ~в 2 раза быстрее Opus»**. Одна тяжёлая агентная сессия Fable может выжечь всё 5-часовое окно на Pro.
- **API-цена (публикуется точно):** **$10 / млн вход, $50 / млн выход** — это **ровно 2× Opus 4.8** и ~5× вводной ставки Sonnet 5. Batch — вдвое дешевле ($5/$25), кэш-чтение — 1/10 входной цены.
- **Отдельный недельный бакет** на Pro (твой скрин: бар «Fable» отдельно от «All models»).
- **Доступ (в движении, сверяй!):** через **7 июля 2026** Fable включён в план до **50% недельного лимита**; **с 8 июля** уходит на **usage credits** (оплата по API-ставкам, отдельно от подписки). Без включённых credits Fable-запросы просто не идут. Opus 4.8 / Sonnet / Haiku в плане остаются как были.
- **Safeguards-роутинг:** у Fable 5 защитный классификатор может **перенаправлять часть запросов на Opus 4.8** с уведомлением (иногда цепляет безобидное — например, обычный код/дебаг, пока настраивают).

**Скорость расхода по моделям (directional, больше = быстрее жжёт лимит):**

| Модель | Относительный расход | API $/Mtok (вход/выход) |
|--------|----------------------|--------------------------|
| **Fable 5** | ~**2× Opus** (самый прожорливый) | $10 / $50 |
| **Opus 4.8** | базовый тяжёлый | $5 / $25 |
| **Sonnet 5** | заметно дешевле Opus (~в разы) | ~$3 / $15 |
| **Haiku 4.5** | самый экономный | самый низкий |

Точный «% подписки» Anthropic не конвертирует, но пропорция расхода ≈ пропорция API-цены. **Нюанс:** Fable 5 и Opus 4.8 используют новый токенизатор, дающий ~**30% больше токенов** на тот же текст (влияет на API-счётчики; про % подписки Anthropic это не заявляет).

## 5. Usage credits (страховка)

Pro / Max 5x / Max 20x могут включить (**Настройки → Usage**, только в веб-версии, нужна привязка карты). После исчёрпания лимита — продолжаешь по **стандартным API-ставкам**. Кэп редемпшна $2000/день, настраиваемый месячный спенд-кэп, авто-пополнение. Сессия при этом всё равно сбрасывается каждые 5ч как обычно. С 8 июля credits — единственный путь к Fable на подписке.

---

## 6. Как работать оптимально

1. **Правильная модель под задачу.** Дефолт — Opus 4.8 (в плане). Fable 5 — только на реально трудное (2× расход). Sonnet/Haiku — на рутину (сильно дешевле).
2. **Projects кэшируют контекст** — загруженное в Project knowledge **не тратит лимит повторно** (только новые/некэшированные куски). Ровно поэтому кит держим в Projects, а не вставляем каждый раз.
3. **Планируй тяжёлую работу под 5-часовые окна.** Знай, когда стартовало окно.
4. **Новый чат под новую тему** — меньше контекст, меньше расход.
5. **Группируй вопросы в одно сообщение** вместо серии коротких.
6. **Effort/thinking-настройки** влияют на расход — выше усилие = быстрее жжёт.
7. **Research-режим** тратит быстрее (много поисков) — под задачу.

---

## 7. Практический вывод для 4-аккаунтной схемы

Мультиаккаунтность — это буквально **умножение недельных/сессионных лимитов** (у каждого аккаунта свой пул). Вахта между аккаунтами через WATCHLOG — способ продолжать работу, когда на одном выжег окно. Держать в голове: у каждого аккаунта своя сессия и свой недельный сброс (у всех — фиксированное время, смотри в Usage каждого).

## 8. 🔴 Изображения: три разных продукта — три разных числа, не путать

Найдено 27.08.2026: `METHOD_IMAGES.md` §10 обобщил находку **claude.ai** («This
chat has 84 of 100 images… Consider starting a new chat» — дословная фраза
веб-интерфейса) на «любое изображение», включая работу Claude Code с диска.
Владелец поймал подмену: *«ты только раздели на два разных понятия веб-клод и
клод-код. в вебе там ограничения на чат что только 100 изображений грузить
можно. здесь же клод код с устройства все фотки сразу видим и может
обрабатывать»*. Проверено дословно по официальной документации (см. Источники) —
владелец прав, цифры разные и означают разное.

### Точные цифры (дословно из документации)

| Продукт | Лимит | Источник |
|---|---|---|
| **claude.ai** (веб/приложение) | **20 изображений на сообщение** — жёсткий, API отклонит больше | «20 per message on claude.ai» |
| **claude.ai**, весь разговор | UI сам предлагает начать новый чат около **~100** накопленных изображений (не жёсткий отказ — подсказка интерфейса) | наблюдение 18.08.2026, `character-a-analysis` №40, ровно эта фраза легла в §10 METHOD_IMAGES.md |
| **Anthropic Messages API** (то, на чём построен **Claude Code**) | **100 на запрос** для моделей с контекстом 200K · **600 на запрос** для остальных моделей | «100 per request on the API, for models with a 200k-token context window. 600 per request… for all other models» |
| Размер запроса целиком (API) | **32 МБ** на стандартных эндпоинтах — часто срабатывает раньше лимита по числу | «request size limits (32 MB for standard endpoints) can be reached first» |
| Размер одного изображения | 8000×8000 px макс.; если в запросе **>20** изображений — на каждое действует более строгий предел (рекоменд. ≤2000px по длинной стороне) | «If a single API request contains more than 20 images, a stricter per-image dimension limit applies» |

### Почему это разные ограничения, а не одно под разными именами

- **claude.ai** — продукт с чат-интерфейсом, лимит и подсказка «новый чат» —
  решение UI, к самому API отношения не имеет напрямую.
- **Claude Code** — CLI поверх Messages API, тот же путь, что любой SDK-клиент.
  Инструмент `Read` кладёт изображение в тело запроса как `image`-блок ровно
  так же, как в примерах API-документации. Продуктовых ограничений claude.ai
  (20/сообщение, подсказка на ~100) физически нет — Claude Code не проходит
  через тот интерфейс.
- Значит формальный потолок для Claude Code — **100–600 на запрос** (в
  зависимости от модели) плюс **32 МБ** на весь запрос — числа другого порядка,
  чем 20/100 у claude.ai.

### 🔴 Но накопительный эффект есть — и вот где он реальный

Дословно из документации: *«In a multi-turn conversation… Claude has access to
every image from earlier turns»* и *«each request resends the full
conversation history. If images are base64-encoded, the full image bytes are
included in the payload on every turn»*. Это значит: лимит «на запрос» в живом
растущем диалоге на практике становится лимитом на **весь разговор с начала**,
потому что каждый следующий ход API-уровня заново включает все предыдущие
изображения — пока их не вытеснит компакция контекста.

**Значит защита — не магическое число «100», а бюджет:**
1. **Размер запроса (32 МБ)** — реалистичный потолок наступает раньше числа
   изображений, особенно на несжатых кадрах с телефона (несколько МБ каждый).
2. **Токен-бюджет контекста** — каждое изображение стоит реальные визуальные
   токены (`⌈width/28⌉ × ⌈height/28⌉`, у стандартного тира ≈1300-1600 на кадр
   среднего размера); сотни кадров в одном непрерывном разговоре съедят
   контекст независимо от формального числового лимита.
3. **Не растить один разговор без границ.** Бить большую партию на отдельные
   под-задачи (в Claude Code — форки/агенты), каждая со своим свежим бюджетом
   запроса — не потому что где-то стоит стена «100», а потому что это и есть
   способ не упереться ни в 32 МБ, ни в контекст.

**Открыто, не проверено:** как именно `Read`-тул Claude Code упаковывает
изображение перед отправкой (сырой байт файла как есть или с
даунсемплингом) — не подтверждено документацией API (та описывает только
формат `image`-блока, не поведение конкретного инструмента). Не заявлять как
факт без проверки.

### Практический вывод для кампаний разбора фото (`METHOD_IMAGES.md`)

Резать большие фотоархивы на партии по **бюджету размера/контекста**, а не по
заученному «100 картинок» — то правило было верным для claude.ai, не universal.
Ориентир для Claude Code: партия ~50-90 изображений через отдельный форк —
запас и по 32 МБ (обычные телефонные JPEG), и по контексту, и глубоко под
формальным API-потолком 100-600/запрос. `METHOD_IMAGES.md` §10 исправлен
27.08.2026 — ссылается сюда, не повторяет цифру самостоятельно.
