# 48 — Опознавательные знаки репозитория

> **Кому этот файл.** Тем, кто ведёт любой из репозиториев системы `vevdokimovm`.
> Нужно добавить два маленьких файла, чтобы деплойер надёжно опознавал репу и её версию.
> Без них скрипт работает, но угадывает по имени архива — а имя можно переименовать.
>
> **Время на внедрение: 2 минуты.** Шаги — в §5.

---

## 1. Зачем

Деплойер решает три вопроса про каждый архив и каждую распакованную папку:

1. **Это вообще наш репозиторий?** (или скачанная из интернета программа)
2. **Какой именно?** (`finpilot_v7_1_0_intl.zip` едет в `personal-finance-dss`)
3. **Какая версия?**

До сих пор он отвечал по **имени файла** и по наличию `README.md`. Обе подсказки внешние:
переименовал архив — и он уедет в другую репу; папка с чужой программой может выглядеть
как наша (в боевом прогоне под рассмотрение попадал `Z-Library-3.2.0/`).

Два файла внутри дерева решают это изнутри: их нельзя потерять при переименовании
и нельзя подделать случайно.

---

## 2. `.repo-id` — принадлежность

Файл в корне репозитория. Одна строка:

```
vevdokimovm/personal-finance-dss
```

Формат: `<владелец>/<имя-репы>`. Без пустых строк, без комментариев, без BOM.

**Что даёт:**

| Ситуация | Без `.repo-id` | С `.repo-id` |
|---|---|---|
| Архив переименовали руками | уедет в репу по новому имени | **стоп**, публикация не идёт |
| Ошибка в `REPO_MAP` | архив уедет не туда молча | **стоп** с указанием обеих реп |
| Чужая папка похожа на нашу | спасают только вторичные признаки | не наша — не рассматривается |
| Распакованная копия во вложенных обёртках | опознать нечем | опознаётся на глубине до 3 уровней |

**Как проверяется:** деплойер читает файл **прямо из zip**, до создания репозитория.
Несовпадение с целевой репой — отказ по этой версии, репа-сирота не заводится.
Файла нет — публикация идёт, но в выводе напоминание.

---

## 3. `VERSION` — версия

Файл в корне. Одна строка с версией **без** префикса `v`:

```
7.2.0
```

**Что даёт:** сверку с версией из имени архива (защита от «положил не тот файл»)
и опознание распакованных копий при уборке диска.

**Важно:** `VERSION` — не замена `CHANGELOG.md`. Журнал отвечает «что изменилось»,
`VERSION` — «какая версия лежит в этом дереве прямо сейчас». Деплойер читает оба
и сверяет между собой.

**Кто уже без него:** на 30.07.2026 `personal-finance-dss` не имеет `VERSION` — практика
новее самого репозитория. Из-за этого распакованные копии его версий не убираются с диска
автоматически: опознать нечем.

---

## 4. Почему два файла, а не один

Они отвечают на разные вопросы и меняются с разной частотой.

`.repo-id` пишется **один раз при заведении репы** и больше не меняется никогда.
`VERSION` меняется **каждый релиз**. Держать принадлежность и версию в одном файле —
значит рисковать принадлежностью при каждом обновлении версии.

---

## 5. Внедрение: по шагам

Из корня репозитория:

```bash
# Шаг 1. Принадлежность. Подставь настоящее имя репы.
echo 'vevdokimovm/ИМЯ-РЕПЫ' > .repo-id

# Шаг 2. Версия. Подставь текущую, без 'v'.
echo '1.2.3' > VERSION

# Шаг 3. Убедись, что файлы НЕ игнорируются
grep -nE '(^|/)\.repo-id|(^|/)VERSION' .gitignore   # должно быть пусто

# Шаг 4. Убедись, что они попадут в архив поставки
#   Если архив собирается скриптом — проверь, что он не исключает файлы,
#   начинающиеся с точки. Типовая ошибка: zip -x '.*'
```

**Шаг 5 — проверка.** Собери архив следующей версии и прогони:

```bash
DRY=1 zsh ~/Downloads/deploy.sh
```

В выводе по этой репе **не должно быть** строки `нет .repo-id`. Если она есть — файл
не попал в архив (чаще всего из-за исключения точечных файлов при упаковке).

**Шаг 6.** Дальше — обычный прогон. При каждом релизе обновлять только `VERSION`.

---

## 6. Частые ошибки

| Ошибка | Как проявляется | Что делать |
|---|---|---|
| `zip -x '.*'` при упаковке | `.repo-id` не попал в архив, скрипт напоминает об отсутствии | убрать исключение точечных файлов |
| `.repo-id` в `.gitignore` | файла нет ни в репе, ни в архиве | убрать из `.gitignore` |
| `v7.2.0` в `VERSION` | версия не сходится с именем архива → отказ | писать без `v` |
| Две строки в `.repo-id` | читается только первая — сработает, но неаккуратно | одна строка |
| Имя репы с опечаткой | **отказ публикации** с указанием обеих реп | исправить файл |

---

## 7. Что будет, если не внедрять

Ничего не сломается: оба файла проверяются мягко, публикация идёт. Теряется только защита:

- архив, переименованный руками, уедет в репу по новому имени;
- распакованные копии версий не убираются с диска автоматически;
- ошибка в `REPO_MAP` не будет обнаружена.

Планируется сделать `.repo-id` обязательным после того, как его заведут все активные репы.
До этого момента — напоминание в выводе, не отказ.

---

> **Одной строкой:** `echo 'vevdokimovm/имя-репы' > .repo-id` и `echo 'текущая.версия' > VERSION`
> в корень, проверить что не в `.gitignore` и не исключены при упаковке — и деплойер
> опознаёт репу изнутри, а не по имени файла, которое можно переименовать.
