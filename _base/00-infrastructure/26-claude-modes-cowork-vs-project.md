# 26 — Claude: поверхности — Cowork vs Project vs Code (на примере FINPILOT)

> Методичка: чем отличаются поверхности/слои Claude, где что живёт, плюсы-минусы, расход токенов, контекст, большие задачи. Данные — из support.claude.com + разборов практиков (июль 2026). Пример сквозной — мой продукт **FINPILOT**.

---

## 1. Слоистая модель: «насколько широко бьёт инструкция»

Claude — не один инструмент, а стек слоёв. Каждый отвечает на вопрос «как широко это должно дотягиваться»:

| Слой | Где задаётся | Действует на | Для чего |
|------|--------------|--------------|----------|
| **Profile Preferences** | Настройки → Профиль | **все обычные чаты** claude.ai | «Кто я и как всегда со мной работать» (тон, код-стиль) |
| **Cowork Global instructions** | Настройки → Cowork | **все Cowork-задачи** | Рабочий стиль/дефолты для агентной работы |
| **Project instructions** (чат-проект) | внутри чат-проекта | чаты **этого проекта** | Контекст конкретной работы/кодбазы |
| **Cowork Project / Folder instr.** | Cowork-проект / папка | задачи в **этой папке** | Проектная специфика Cowork (локально) |
| **`CLAUDE.md`** в папке | файл в корне папки | Cowork/Code при открытии папки | Авто-загружаемый контекст папки |
| **Skills** | Настройки → Skills | **все поверхности**, но **только когда релевантно** | Повторяемые задачи; грузятся по контексту, до 5 сразу |

**Ключевое:** Preferences и Cowork Global — **параллельные слои для разных поверхностей**, не иерархия. Preferences НЕ дотягивается до Cowork автоматически, и Cowork НЕ видит чат-проекты сам. **Skills — исключение:** работают на всех поверхностях и грузятся только по релевантности (поэтому токен-эффективнее, чем длинный always-on).

---

## 2. Три поверхности (+ Code)

- **Chat** — думать: брейншторм, вопросы, быстрые ответы. Без файлов, без автономии. Просто разговор.
- **Chat Project** — persistent контекст для повторяющихся задач с одним фоном: грузишь файлы в knowledge base + инструкции, они в каждом чате проекта (на платных — RAG, +до 10× ёмкости). Облачный, шарится с командой. **Но: не создаёт файлы и не запускает код.**
- **Cowork** — делать: агент читает/пишет твои файлы, создаёт реальные документы (xlsx/docx/pptx/pdf), многошаговые задачи, коннекторы (Gmail/Drive/Notion), scheduled tasks. Работает в **изолированной VM (песочница)**, удалённое исполнение (beta). **Не умеет git/terminal** (это к Code). Cowork-проекты — локальные, память в файлы (`claude.md`/`memory.md`), обновляется ~раз в 24ч; **нет облачной синхры и шаринга**.
- **Code** — строить в кодбазе: git-aware, терминал, запускает тесты/линтер/гейты, прямой доступ к файлам, **самый токен-эффективный** для кода.

## 3. Сравнение по осям

| Ось | Chat | Chat Project | Cowork | Code |
|-----|------|--------------|--------|------|
| **Файлы** | загрузка в облако (20 файлов/чат, 30 МБ/файл) | то же + knowledge base | **локальные, лимитов нет** | **локальные, прямой доступ** |
| **Вывод** | текст, копируешь сам | текст | **готовые файлы в папке** | код в репе + коммиты |
| **Контекст** | 200K, деградация к 90% | 200K + RAG (×10 ёмкость знаний) | **больше эффективно** (работа по файлам, сабагенты) | держит контекст всей репы |
| **Код/тесты/git** | копипаст | копипаст | ❌ песочница, без git/terminal | ✅ тесты, линтер, git, коммиты |
| **Память** | онлайн, жёсткий лимит | чат-память + папка | **в файлы на диске** | по репе/CLAUDE.md |
| **Расход токенов** | базовый | базовый | **≈ 20+ обычных чатов/сессия** | **эффективнее Cowork** для того же |
| **Большие многошаговые** | ❌ упирается в контекст | ограниченно | ✅ без таймаута диалога | ✅ без таймаута, тайтовый цикл |
| **Шаринг/облако** | — | ✅ облако, команда | ❌ локально | по гиту |

## 4. Плюсы / минусы (кратко)

**Chat** ➕ ноль настройки, быстро ➖ нет памяти/файлов, копипаст, деградация на длинном.
**Chat Project** ➕ persistent контекст, RAG, шаринг, стыкуется с Preferences ➖ не делает файлы/код, облачные лимиты загрузки.
**Cowork** ➕ реальные файлы, локальный доступ, большой эффективный контекст, автоматизация, расписание ➖ **жжёт лимит быстро**, песочница (без git/terminal), проекты локальные без синхры, агентные ошибки (ревьюить).
**Code** ➕ реальная инженерия, git/тесты, токен-эффективность, контекст репы ➖ нужен минимальный тех-порог (но у меня он есть).

## 5. 🎯 FINPILOT — что где делать

FINPILOT = живой кодбейс (git, сотни тестов, TDD, `docs/`, WATCHLOG, мультиаккаунт). Раскладка по поверхностям:

| Задача по FINPILOT | Поверхность | Почему |
|--------------------|-------------|--------|
| **Писать/рефакторить код, гонять pytest, гейты, коммиты, обновлять WATCHLOG** | **Claude Code** ⭐ | Единственный с git/terminal/тестами; держит контекст репы; **токен-эффективный**. Cowork не умеет git, chat — копипаст-ад. |
| **Генерить deliverables:** ВКР `.docx`, презентация `.pptx`, отчёты, Excel из данных | **Cowork** | Делает реальные файлы; наводит их в папке. |
| **Кросс-файловый анализ, синтез, организация `docs/`, ресёрч** | **Cowork** | Локальный доступ + большой контекст + сабагенты. |
| **Обсудить архитектуру/матмодель, спланировать веху, Q&A по стандартам** | **Chat Project** | Грузишь `docs/` + матмодель как knowledge (RAG), брейнштормишь. Репу не трогает — и не надо. |
| **Универсальные дефолты** (тон, код-стиль, «TDD обязателен») | **Preferences** (чат) + **Cowork Global** | Always-on по каждой поверхности. |
| **Повторяемые конвенции** (напр. «пиши тест по нашему TDD+гейтам») | **Skill** | Грузится только когда пишешь тесты → токен-эффективно, на всех поверхностях. |

**Вахта между аккаунтами:** лучше всего в **Code** (WATCHLOG в репе, эмпирическая сверка файлов, гейты). Cowork может вести WATCHLOG как бухгалтерию, но код-часть вахты — Code.

**Практический дефолт для FINPILOT:** **Code — основной инструмент разработки**, Cowork — под документы/отчёты/анализ, Chat Project — под дизайн/планирование. Не делать рутинный код в Cowork (дорого + песочница) и не копипастить репу в chat.

## 6. Расход токенов — конкретика

- **Cowork жжёт агрессивно:** одна сессия ≈ 20+ обычных чатов. Резервировать под задачи, где реально нужен файловый вывод/многошаговость, а не под рутину. Планировать под 5-часовые окна (см. `14-claude-usage-and-limits.md`, `16-limits-empirical-estimate.md`).
- **Code эффективнее Cowork** для той же работы (нет VM-оверхеда и скриншотов) → весь код FINPILOT гнать в Code, не в Cowork.
- **RAG в чат-проектах** расширяет ёмкость знаний до ×10 — можно держать весь кит в knowledge base проекта.
- **Контекст ≥90% = хуже ответы** (важные инструкции «тонут»). Не тащить лишнее; начинать свежий чат/задачу под новую тему.
- **Skills** грузятся по релевантности, а не всегда → дешевле длинных always-on инструкций. Длинные Global/Preferences бьют по каждому запросу — держать их лёгкими, повторяемое выносить в Skills.

---

## 7. Большие/глубокие задачи

- **Code и Cowork** тянут часовые многошаговые задачи без таймаута диалога и коллапса контекста (файлы + сабагенты). Большой рефактор или полный прогон тестов FINPILOT → **Code**; генерация большого документа/пакета отчётов → **Cowork**.
- **Chat** для больших многошаговых не годится — упрётся в 200K и деградацию.
- **Явно говорить Claude, где он работает:** «ты в Cowork-сессии, доступ к папке проекта, сохраняй в OUTPUTS/» — снимает класс ошибок (Claude ведёт себя по-разному в chat/Cowork/Code).

---

## 8. Чеклист «какую поверхность взять»
1. Нужны git/тесты/правка кода FINPILOT? → **Code**.
2. Нужен реальный файл на выходе (docx/xlsx/pptx) или работа с локальными файлами? → **Cowork**.
3. Обсудить/спланировать/спросить с опорой на мои доки, без правки файлов? → **Chat Project**.
4. Быстрый вопрос без контекста? → **Chat**.
5. Повторяю одну и ту же инструкцию везде? → вынести в **Skill**.
6. Универсальное поведение? → **Preferences** (чат) + **Cowork Global** (агент).
