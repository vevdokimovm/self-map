# Типы разборов: что и когда писать (роутер)

> Какой формат выбрать под ситуацию. Это **навигатор**, а не сам шаблон: критерии, таблица «когда
> что», ссылки на практические гайды по каждому типу и на общую теорию. Сами шаблоны — в
> файлах-гайдах своих типов. Диспетчер с папками и реестрами — `00-infrastructure/19-reporting-system.md`.

Четыре типа разбора + общая методичка-теория:

| Тип | Когда | Практический гайд | Реестр |
|---|---|---|---|
| **Post-mortem (инцидент)** | был сбой с влиянием / near miss | `incident_postmortem_guide.md` | `incidents_summary.md` |
| **Investigation report (расследование)** | долго разбирались, причину нашли, но реального дефекта НЕТ | `investigation_report_guide.md` | `investigations_summary.md` |
| **Bug card (карточка дефекта)** | найден конкретный дефект | `bug_report_template.md` | `incidents_summary.md` |
| **Pitfall (частая ошибка воркфлоу)** | повторяющаяся ошибка процесса, причина известна сразу | — (строка-урок) | `pitfalls.md` |
| **Ситуация-репорт (рубрика)** | разбор крупной кампании целиком (было→сделали→что не так→уроки) | `situations/README.md` | таблица выпусков в `situations/` |

Общая теория (культура blameless, RCA-методы, runbook, ADR/RFC, SLO/error budget) — отдельно в
`documentation_methodology.md`.

## 1. Когда что писать

| Ситуация | Документ |
|---|---|
| Сбой с влиянием (даунтайм, потеря данных, деградация; для knowledge-репы — серьёзная потеря/поломка знаний) | **Post-mortem** |
| Near miss («чуть не упало», обошлось) | **Post-mortem** (дешёвый урок) |
| Долго/сложно разбирались, нашли причину, но реального дефекта нет (внешнее, артефакт, подход) | **Investigation report** |
| Найден конкретный дефект | Карточка **BUG-XXX** |
| Повторяющаяся ошибка воркфлоу (кривая команда, привычка), причина ясна сразу | **Pitfall** (строка в `pitfalls.md`) |
| Принято архитектурное/структурное решение | **ADR** (`adr/adr_template.md`) |
| Тривиальная опечатка без влияния | Ничего, просто фикс |

Различение по сути:
- **Инцидент vs расследование** — была ли реальная поломка/дефект / влияние. Да → инцидент; причину
  искали, но дефекта нет → расследование. Главный вопрос расследования («сломано ли?») получает
  честный ответ «нет».
- **Расследование vs pitfall** — была ли причина неочевидной. Искали, докапывались → расследование
  (отдельный файл). Причина известна сразу, это повтор привычки → pitfall (одна строка, без файла).
- **Bug card** — ортогонально: фиксирует сам дефект; часто рождается ВНУТРИ post-mortem (если
  корень — баг) и ссылается оттуда.

Форматы комбинируются: post-mortem → внутри ссылка на BUG-XXX и/или на новый runbook (если будет
повторяться).

## 2. Разборы оформляются автоматически

Как только событие квалифицируется по таблице выше — разбор делается **сам, в момент события**, не
дожидаясь отдельной просьбы (`00-infrastructure/20-knowledge-capture-protocol.md`). Полные разборы
(post-mortem, investigation) — отдельными файлами в `incidents/` / `investigations/`; в реестрах
остаются сводки-строки. Pitfall и bug card — легче, живут строками/карточками.

## 3. Как отличить артефакт от дефекта (частый случай в расследованиях)

Огромная доля «страшных» подозрений оказывается **артефактом методики**, а не реальным дефектом.
Признаки, что перед тобой артефакт, а не поломка:
- симптом исчезает при смене способа замера (стабилизация, другой инструмент, другой момент);
- «заведомо рабочий» контрольный путь даёт тот же симптом → значит, дело в среде/методике, не в
  предмете;
- различие рассеянное/микроскопическое, а не компактное/системное.

Общий урок (он же антипаттерн в гайде инцидентов): **не списывать на «невозможно» / «сломано», не
перебрав все каналы и обходы**. Investigation report существует именно чтобы заменить отмашку
доказанным выводом.

---

## 4. ADR — отдельная ось

ADR (architecture decision record) — не про поломку, а про **осознанный выбор из альтернатив** с
обоснованием. Когда выбрал X вместо Y (структуру, подход, инструмент) — фиксируешь контекст, решение,
альтернативы, последствия. Шаблон и правила — `adr/adr_template.md`. Через полгода никто не вспомнит,
почему так, — и начнут переделывать «потому что непонятно». ADR хранит причину.
