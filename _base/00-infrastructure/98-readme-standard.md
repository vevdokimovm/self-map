# 98. Стандарт README — что обязано быть в каждой репе

**Заведено 29.08.2026** по требованию владельца: *«сделай стандарт README
на основе того, как он сделан у `personal-finance-dss` — там самый подробный —
и сделай у всех других по этому стандарту подробный README»*.

---

## §0. 🔴 Прямо копировать образец нельзя, и вот почему

`personal-finance-dss` — README **программного продукта**: архитектура
слоистого монолита, API, быстрый старт, переменные окружения, тестирование,
безопасность. 570 строк, и каждая уместна.

Но у репы `chess` нет API. У `philosophy` нет быстрого старта. Требовать
от них этих разделов — значит получить 60 файлов с заголовком «API»
и пустотой под ним, то есть ровно ту болезнь, с которой мы боролись
29.08.2026: **раздел, который выглядит как содержание и им не является**.

**Замер по классам репозиториев:**

| Класс | Реп | Средний README |
|---|---|---|
| `product` | 9 | **165 строк** |
| `infra` | 2 | **189 строк** |
| `core` | 12 | 61 строка |
| `satellite` | 38 | 69 строк |

Разница не в небрежности — **у продукта просто больше того, что надо
рассказать**. Поэтому стандарт задаёт **общий скелет плюс разделы по классу**,
а не единый шаблон на всех.

---

## §1. Общий скелет — обязателен для ЛЮБОЙ репы

Порядок важен: читатель уходит после подписи, и всё, что ниже неё, не читается
(проверено 29.08.2026 — раздел «Что это и зачем» стоял под контактами).

| № | Раздел | Что в нём | Откуда берётся |
|---|---|---|---|
| 1 | **Заголовок + `<!-- STATUS -->`** | версия · дата · одна строка о последнем батче · ссылки на `ROADMAP`/`TASKS`/`WATCHLOG` | пишет `bump_repo.py` |
| 2 | **Одна фраза о репе** | что это, без воды | `MANIFEST.md` §2 |
| 3 | **`## Что это и зачем`** | три предложения: что · чем НЕ является · с чем не пересекается | `MANIFEST.md` §1 |
| 4 | **`## С чего начать`** | 3–4 пункта: что открыть первым и в каком порядке | человек |
| 5 | **`## Структура`** | таблица: папка · файлов · **что внутри по существу** | `rebuild_readme.py` |
| 6 | **`## Data & privacy note`** | приватность и запрет секретов | шаблон |
| 7 | **Подпись** | контакт | шаблон |

🔴 **Пункт 5 — не список папок, а описание содержания.** Строка вида
«`01-openings/` · 2 файла · 1 заметка» описанием не является: она выглядит
как ответ и не отвечает. Столбец берётся из `MANIFEST.md` §3, где его написал
человек, иначе — из заголовков самих файлов, иначе — честная пометка
«описания нет».

## §2. Дополнительно для класса `satellite` и `core` — базы знаний

Эти репы держат **знание**, а не работающий код. Им нужны:

| Раздел | Зачем |
|---|---|
| **`## Что здесь можно узнать`** | 4–6 пунктов: конкретные вопросы, на которые репа отвечает. Не «тактика», а «какие бывают тактические мотивы и как их тренировать» |
| **`## Границы`** | чего в репе НЕТ и где это искать. Снимает половину поисков впустую |
| **`## Как это пополняется`** | откуда приходит материал: разбор конспектов, выгрузки, живая практика |

**Целевой объём: 90–130 строк.** Сейчас в среднем 61–69 — то есть примерно
вдвое меньше, чем нужно.

## §3. Дополнительно для класса `product` — работающий код

Разделы взяты из `personal-finance-dss` — там они заслужены:

| Раздел | Обязателен? |
|---|---|
| **`## Текущее состояние`** (версия, что работает, что нет) | да |
| **`## Как это работает`** — архитектура и ключевое решение | да |
| **`## Быстрый старт`** — команды, которые реально запускаются | да |
| **`## Тестирование и качество`** — чем проверяется | да |
| **`## Технологии`** | да |
| **`## История версий`** — вехи, а не changelog | если версий больше 3 |
| **`## API`** | если есть внешний интерфейс |
| **`## Безопасность`** | если работает с чужими данными |
| **`## Переменные окружения`** | если они есть |

🔴 **Раздел заводится, только если под ним есть содержание.** Пустой
«## API» хуже отсутствующего: он обещает и не даёт.

## §4. Дополнительно для класса `infra` — база и планировщик

| Раздел | Зачем |
|---|---|
| **`## Как этим пользоваться`** | рабочий цикл: что делать в типичной ситуации |
| **`## Где какие сущности лежат`** | какой файл что держит **и какого класса** — с живыми примерами, а не именами файлов |
| **`## Механизмы`** | что проверяется автоматически и чем |
| **`## Где стоим`** | числа состояния, а не ощущение |

## §5. Правила, общие для всех разделов

1. **Числа проверяются гейтом.** Проза, разошедшаяся с диском, роняет батч
   (`PIT-091`). Поэтому число в README — обязательство, а не украшение.
2. **Утверждение о состоянии без даты читается как настоящее время**
   (`PIT-167`). Либо дата рядом, либо формулировка, которая не устареет.
3. **Ничего не сочиняется.** Где описания нет — пишется, что его нет.
   Придуманное «зачем» хуже пустого места: пустое видно, придуманное — нет.
4. **Раздел, который выглядит как содержание и им не является, — дефект.**
   «TODO — заполнить вручную», «1 заметка», пустой столбец `Contents`.
5. **Порядок разделов фиксирован** (§1). Всё, что ниже подписи, не читается.

## §6. Что автоматизировано, а что нет

| Часть | Кто делает |
|---|---|
| статусная строка, версия | `bump_repo.py` |
| таблица структуры с описанием | `rebuild_readme.py` |
| раздел «Что это и зачем» | `rebuild_readme.py` (переносит из `MANIFEST.md` §1) |
| проверка чисел против диска | `revision_check.py` |
| **«С чего начать», «Границы», «Что можно узнать»** | 🔴 **человек** |

Последняя строка принципиальна: **что открыть первым и чего в репе нет —
знает только тот, кто в ней работал**. Инструмент может перенести написанное,
но не может это придумать.
