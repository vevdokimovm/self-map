## 2. Область

**Применяется к:** любой кампании, где содержимое многих реп просматривается подряд
и общее поднимается в `base-repo` — синтез инфраструктуры, сведение служебок, сбор
манифестов, разбор очереди изображений по всем репам.

**Не применяется к:** правке одной репы, раскатке базы в потомки
(`53-infrastructure-sync-standard.md`), ревизии (СТ-003 — она проверяет соответствие,
а не поднимает общее).

**Отличие от СТ-003 одной строкой:** синтез отвечает «что из реп должно стать общим»,
ревизия — «соответствует ли то, что есть, тому, что записано».

## 3. Термины

| термин | значение |
|---|---|
| **кампания** | проход по множеству реп с единой целью и единым журналом в `05-infra-synthesis-lab/runs/<дата>-<имя>/` |
| **проход по репе** | одна репа от листингов до приёмки; единица работы кампании |
| **подъём** | перенос знания из репы в базу переписанным, а не копированием |
| **вычитание** | метод отбора: файл рассматривается, только если он **не** совпал с базой и с уже закрытыми репами |
| **приёмка репы** | арифметика, в которой число файлов репы разложено по источникам без остатка |
| **М/С** | пометка каталога: **М**атериал (смотреть) или **С**лужебное (пропустить) |

## 4. Нормы

| № | норма | чем проверяется |
|---|---|---|
| **СТ-002.1** | У кампании есть каталог прогона `runs/<ГГГГ-ММ-ДД>-<имя>/` с `decisions.md` и очередью реп; он заводится **до** первой репы. | вручную; отсутствие каталога = кампании нет |
| **СТ-002.2** | Канон расположения репы назван строкой в `decisions.md` **до** первой команды, если копий на диске больше одной. | `SYN-017`; `repo-inventory` находит все копии |
| **СТ-002.3** | Каждая репа закрывается **арифметикой приёмки**: всего файлов = база + закрытые репы + С + прочитано и решено, без остатка. | `scripts/acceptance_audit.py` — сверяет записанную приёмку с диском сегодня |
| **СТ-002.4** | 🔴 Метрика прохода — **ноль файлов без записи**, а не число подъёмов. Репа с нулём подъёмов закрывается штатно. | арифметика §СТ-002.3: остаток ≠ 0 → репа не закрыта |
| **СТ-002.5** | Решение по каталогу (М/С) принимает вахта и записывает в `decisions.md`; механический агент его не принимает. | вручную; `repo-inventory` по определению не размечает |
| **СТ-002.6** | Знание поднимается **переписанным своими словами**, а не копированием файла. | вручную; копия обнаруживается сравнением с источником |
| **СТ-002.7** | Реестры и журналы обновляются **по ходу прохода**, а не в конце кампании. | `revision_check.py` (журналы, §94); обрыв кампании оставляет учтённое состояние |
| **СТ-002.8** | 🔴 Статус «ЗАКРЫТО» действителен, только пока живой измеритель даёт ноль. Обнуление статуса новым импортом — не ошибка записи, а устаревание. | `scripts/closed_campaign_gate.py` |
| **СТ-002.9** | Тяжёлое и непереносимое сворачивается в служебку по **СТ-001**, а не выбрасывается и не тащится в базу. | `scripts/raw_originals_check.py` |
| **СТ-002.10** | Урок кампании поднимается в базу **в момент находки**, а не в конце: лаборатория пополняется по ходу. | `STANDARD.md` §0а; пустой `PITFALLS.md` при непустом `decisions.md` — признак нарушения |

## 5. Порядок кампании

```
Ф0. Разведка      сколько реп, где лежат, что уже закрыто          СТ-002.1, .2
Ф1. Ревизия базы  что в базе УЖЕ есть — иначе поднимется дубль     → СТ-003
Ф2. Сбор          проход по репам: листинги → М/С → чтение         СТ-002.5
Ф3. Решения       подъём / дубль / отказ, каждое с основанием      СТ-002.6
Ф4. Сведение      как именно сводить пересекающиеся источники
Ф5. Раздача       база раскатывается в потомки                     → 53
```

**Проход по одной репе** (единица работы, вход — скилл `/synthesis-pass`):

```
1. Инвентарь     все копии на диске, четыре команды листинга      агент repo-inventory
2. Разметка      каждый каталог — М или С, с записью              СТ-002.5
3. Вычитание     сверка с базой и закрытыми репами по sha256      СТ-002.4
4. Чтение        только то, что осталось после вычитания
5. Решение       подъём/дубль/отказ → decisions.md по ходу         СТ-002.7, .10
6. Приёмка       арифметика без остатка                            СТ-002.3
```

## 6. Запреты

- Начинать проход, не назвав канон расположения репы при нескольких копиях.
- Считать репу закрытой при ненулевом остатке арифметики.
- Поднимать файл копированием вместо пересказа.
- Оставлять решения по каталогам механическому агенту.
- Копить записи в `decisions.md` и `PITFALLS.md` «до конца кампании».
- Писать «ЗАКРЫТО» там, где живой измеритель не проверяется.
- Пересказывать в стандарте содержание `STANDARD.md` — расхождение появится на первой правке (`PIT-178`).
