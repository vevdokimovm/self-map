## 2. Область

**Применяется к:** проверке того, что записанное совпадает с действительным — в одной
репе и во всей системе реп.

**Не применяется к:** подъёму общего из реп в базу (**СТ-002**), раскатке базы
(`53-infrastructure-sync-standard.md`), проверке кода на дефекты (code review).

**Три периметра — не путать** (`77` §0):

| периметр | вопрос | документ |
|---|---|---|
| одна репа | живое ли в ней всё, что лежит | `21-revision-protocol.md` |
| вся система, регулярно | не разъехались ли репы со стандартом | `77-system-wide-audit.md` |
| один ход вахты | не отстала ли обвязка от правки | гейт `revision_check.py` |

**Кампания чинит состояние, ревизия удерживает его.** Без ритма перекос накапливается
заново с прежней скоростью.

## 3. Термины

| термин | значение |
|---|---|
| **живой источник** | README, справочники, карты, методички — обязан быть актуальным, чинится |
| **замороженная запись** | `CHANGELOG`, отчёты в `reports/`, архивы — точка-во-времени, **не правится** |
| **ось ревизии** | одно измерение проверки: ссылки, актуальность, дубли, нейминг, лёгкость, зона |
| **гейт** | `scripts/revision_check.py` — машинная часть, идёт на каждом ходу |
| **показатель** | доля реп, прошедших проверку целиком |

## 4. Нормы

| № | норма | чем проверяется |
|---|---|---|
| **СТ-003.1** | 🔴 **Замороженная запись не правится при ревизии** — даже если её ссылка теперь ведёт не туда. Правка = переписывание истории. | вручную; `22-merge-protocol.md`. Единственная норма, нарушение которой необратимо |
| **СТ-003.2** | Живой источник, разошедшийся с диском, чинится в момент обнаружения, а не записывается в задачи. | `scripts/repo_revision.py` — врёт ли документация о диске |
| **СТ-003.3** | Ревизия одной репы идёт по **всем шести осям** (ссылки · актуальность · дубли · нейминг · лёгкость · зона); code-репы добавляют оси 7–9. | `21` §2; `scripts/per_repo_audit.py` — соответствие стандарту |
| **СТ-003.4** | Общесистемная ревизия — **раз в месяц**; внеочередная — при изменении самого стандарта. | `77` §2; дата последнего прогона в реестре |
| **СТ-003.5** | 🔴 Показатель ревизии — **доля реп, прошедших целиком**. Число правок и объём отчёта показателем не являются: они растут сами. | `77` §6 |
| **СТ-003.6** | 🔴 **Гейт запускается после правок и до конца хода** — включая правки, сделанные в ходе работы над самой проверкой. | хук `ritual-gate.sh`: блокирует выход при не-CLEAN |
| **СТ-003.7** | Новый артефакт объявляется в обвязке в том же ходу: инструмент — в README кита, журнал — в `.runtime-writes`, документ — ссылкой откуда-то. | `revision_check.py`: `check_tools_linked`, журналы (94), «документы, на которые никто не ссылается» |
| **СТ-003.8** | Утверждение «закрыто / готово / ноль» действительно, только пока живой измеритель это подтверждает. | `closed_campaign_gate.py`, `acceptance_audit.py` |
| **СТ-003.9** | 🔴 **Гейт сам обязан быть под тестом.** Проверка без канарейки — источник ложной уверенности, худший её отсутствия. | канарейки `selftest_*` в `revision_check.py`; `pit_gate_coverage.py` |
| **СТ-003.10** | Проверка объявляет своё слепое пятно: чего она **не** ловит — в докстроке. | `revision_check.py`: WARN «проверки, не объявившие слепое пятно» |
| **СТ-003.11** | Ритуал, пропущенный трижды подряд, чинится **изменением ритуала**, а не обещанием собраться. | `77` §6; счётчик пропусков |
| **СТ-003.12** | 🔴 У механизма доставки проверяется **доставленность на стороне получателя**, а не факт отработки. «Хук сработал» и «репа получила» — разные утверждения. | `scripts/delivery_check.py` + `check_delivery` в гейте |

## 5. Порядок

**Ревизия одной репы:**

```
1. Периметр      что ревизуем: живое / замороженное — разделить ДО правок   СТ-003.1
2. Машина        per_repo_audit.py + repo_revision.py — расхождения с диском СТ-003.2
3. Оси 1-6       ссылки · актуальность · дубли · нейминг · лёгкость · зона   СТ-003.3
4. Правка        живое чинится сразу; замороженное не трогается
5. Запись        что нашли и что изменили — в журнал репы
```

**Ревизия системы (ежемесячно):**

```
1. Охват         все репы, без выборки: число реп — довод, не зависящий от читающего
2. Таблица 1     соответствие стандарту: обязательные файлы, _base/, BASE_VERSION
3. Таблица 2     кандидаты в базу → передаются в кампанию синтеза (СТ-002)
4. Показатель    доля прошедших целиком; движется к единице или нет        СТ-003.5
5. Диагноз       не растёт несколько месяцев → чинится ритуал, а не усилие СТ-003.11
```

**Ревизия одного хода** (машинная, обязательная): гейт `revision_check.py` — сам на выходе.

## 6. Запреты

- Править замороженную запись ради «актуальности».
- Ревизовать выборку реп вместо всех и называть это общесистемной ревизией.
- Считать показателем число правок или объём отчёта.
- Заканчивать ход, не запустив гейт после своих правок — **особенно когда ход посвящён проверкам**.
- Заводить проверку без канарейки.
- Откладывать ритуал четвёртый раз вместо переделки ритуала.
