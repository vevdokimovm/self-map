# 43 — Нейминг и упаковка версионных архивов

> **Зачем.** Архив — это способ доставки репы: Claude отдаёт `.zip`, деплойер (`templates/deploy.sh`)
> превращает его в коммит, тег и релиз. Почти все сбои доставки — не в git и не в сети, а в том,
> **как назван и как упакован архив**. Два правила ниже закрывают весь класс этих сбоев.
> Формат описания релиза — `42-release-description-standard.md`, механика версий — `44`.

---

## 1. Имя архива: разделитель — ТОЧКА

```
<repo>-vX.Y.Z.zip
```

Пример: `dota-dossier-v2.12.0.zip`, `base-repo-v1.12.0.zip`.

- **Внутри версии — только точки.** `v2.12.0`, не `v2_12_0` и не `v2-12-0`.
  Точка — разделитель SemVer, так версия читается глазом и совпадает с содержимым `VERSION`.
- **Между именем репы и версией — дефис**: `<repo>` + `-v` + версия.
- Имя репы — ровно как на GitHub (kebab-case), без пробелов и заглавных.

**Легаси принимается целиком.** За годы накопились разные форматы, и старые архивы не должны
выпадать из системы. Деплойер понимает все варианты ниже:

| Формат | Пример | Как читается |
|---|---|---|
| канон | `dota-dossier-v2.12.0.zip` | 2.12.0 |
| подчёркивания в версии | `base-repo-v1_11_0.zip` | 1.11.0 |
| дефисы в версии | `repo-v1-2-0.zip` | 1.2.0 |
| `_` как разделитель имя↔версия | `repo_v1.2.0.zip` | 1.2.0 |
| без префикса `v` | `repo-1.2.0.zip` | 1.2.0 |
| две части версии | `repo-v2.7.zip` | 2.7.0 + предупреждение |
| хвосты ОС | `repo-v1_2_0__copy_.zip`, `repo-v1.2.0 (1).zip` | хвост срезается |

Каждый неканоничный файл помечается в выводе строкой `→ канон: <repo>-vX.Y.Z.zip`. Обработается
он всё равно — но переименуй у себя, чтобы разнобой не расползался дальше. **Направление одно:
всё новое именуем через точки.**

**Хвосты от системы срезаются автоматически:** ` copy`, `-copy`, `__copy_`, ` (1)`, `(2)`.
`dota-dossier-v2_12_0__copy_.zip` разбирается корректно — качать заново не нужно.

**Канонический ассет релиза всегда с точками.** Как бы ни назывался файл в папке, в релиз он
уезжает под именем `<repo>-vX.Y.Z.zip` — чтобы скачанные архивы разных реп и версий не смешивались
в `~/Downloads`.

## 1.1. Что деплойер НЕ трогает вообще

Не всякий zip в папке — поставка. Три категории отсекаются до любых действий:

| Категория | Примеры | Поведение |
|---|---|---|
| **Служебные архивы** — загрузки из чата, системные | `files.zip`, `files 10.zip`, `1.zip`, `16.zip`, `Archive_2.zip` | молча мимо, в конце строка «пропущено служебных: N» |
| **Рабочие копии и дубликаты** | `... (copy).zip`, `... copy.zip`, `..__copy_.zip`, `... (1).zip`, `...v1.2.5 1.zip` | **никогда не публикуются**, но перечисляются вслух |
| **Не прошедшие предполёт** | битый zip, нет `README.md`, мало файлов, `VERSION` ≠ имени | отказ с причиной, репа не создаётся |

Копия — это дубль, а не поставка: публиковать рабочую копию опаснее, чем пропустить её.
Нужен именно этот файл — переименуй в каноническое имя, и он поедет.

Про хвост ` 1`: macOS при повторной загрузке файла с тем же именем дописывает пробел и номер
(`character-a-analysis_v1.2.5 1.zip`). Версия при этом читается полностью, поэтому такой файл —
именно дубликат, а не ошибка нейминга.

Списки настраиваются: `SERVICE_RE="..."` переопределяет служебные, `IGNORE="regex"` добавляет свои.

### Вариантные постфиксы

У отдельных проектов исторически есть постфикс сборки: `finpilot_v6_20_1_intl.zip`
(`intl` — международная сборка того же последовательного проекта). Постфикс отбрасывается,
версия читается как `6.20.1` — но **только для реп из списка** `VARIANT_REPOS` (по умолчанию
`finpilot`), чтобы не откусить кусок имени у чужой репы. Каждый такой разбор печатается вслух:
`finpilot_v6_20_1_intl.zip → finpilot v6.20.1`.

## 2. Упаковка: обёртка обязательна, мусора нет

Это причина №1 сбоев доставки («упаковал — не пушится»).

### Правильно

```
dota-dossier-v2.12.0.zip
└── dota-dossier-v2.12.0/      ← ОДНА папка-обёртка в корне архива
    ├── README.md              ← маркер корня, обязателен
    ├── VERSION                ← 2.12.0, обязан совпасть с именем архива
    ├── CHANGELOG.md
    └── ...
```

### Неправильно

| Как ломается | Что происходит |
|---|---|
| **Плоская упаковка** (файлы в корне архива, без обёртки) | однажды снесла репу при `rsync --delete`; корень не опознаётся |
| **`__MACOSX/` и `.DS_Store` рядом с обёрткой** | в корне архива уже НЕ один объект → обёртка не разворачивается → в репу уезжает дерево, вложенное в папку |
| **Двойная обёртка** (папка в папке) | то же самое уровнем глубже |
| **Нет `README.md` в корне дерева** | деплойер не подтверждает корень и **отказывается** чистить репу — защита от сноса не туда |
| **`VERSION` ≠ версии в имени** | версия пропускается: это признак, что подсунут не тот архив |

### Как пакуем на macOS

```bash
cd ~/work/dota-dossier-v2.12.0/..
zip -qr dota-dossier-v2.12.0.zip dota-dossier-v2.12.0 -x '*.DS_Store' '*__MACOSX*'
```

Ключевое — архивируется **папка целиком** (не `cd` внутрь неё), а `-x` отсекает мусор macOS.

### Что деплойер прощает сам

- сносит `__MACOSX/`, `.DS_Store`, `._*` **до** разворота обёртки (иначе обёртка не находится);
- разворачивает вложенность до 3 уровней, пока не найдёт `README.md`;
- при этом **никогда** не трогает репу, пока корень не подтверждён маркерами.

## 3. Чек-лист перед отдачей архива

1. Имя ровно `<repo>-vX.Y.Z.zip`, версия через точки?
2. В корне архива **одна** папка-обёртка `<repo>-vX.Y.Z/`?
3. Внутри неё `README.md` и `VERSION`, и `VERSION` = версии из имени?
4. Мусора macOS нет (`-x '*.DS_Store' '*__MACOSX*'`)?
5. Файлов больше 5 (иначе деплойер сочтёт, что это не репа)?

---

> **Одной строкой:** `<repo>-vX.Y.Z.zip` (**точки**, не подчёркивания) → внутри **одна**
> папка-обёртка с `README.md` и `VERSION`, совпадающим с именем, без `__MACOSX`/`.DS_Store`;
> легаси-имена принимаются, но помечаются, а канонический ассет в релизе всегда с точками.
