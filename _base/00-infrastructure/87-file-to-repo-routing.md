# 87 — Классификация: какой файл в какую репу

> **Заказ владельца 22.08.2026, дословно:** *«какая-то классификация по типу — какого типа
> файлы в какую репу идут. Это вдобавок к манифесту, чтобы было проще определять, что куда
> делегировать, а не на рандом или по наитию. Чем больше будем работать с конкретной репой,
> тем точнее будет классификация становиться»*.

🔴 **Зачем это понадобилось — из инцидента, а не из красоты.** Кампания переноса
22.08.2026 разложила 43 500 файлов по репам, назначая адрес **по имени папки-источника**:
`~/Documents/claude` → `claude-usage`. Внутри оказались три разные вещи, и одна из них —
`ADHD.pptx`, которой место в `misc-vault`. Владелец: *«нахера ты вообще в claude usage
положил срану презу про ADHD»*. Разбор — `PIT-124`.

> **Правила адресации не существовало — поэтому адрес брался из имени.**
> Имя папки это гипотеза о предмете, а не предмет.

Отличие от `76-repo-classes.md`: там ось **«база ↔ репа»** (правило или состояние).
Здесь ось **«какая именно тематическая репа»** — вопрос, который возникает уже после того,
как ясно, что файл не в базу.

---

## 1. Порядок решения — четыре вопроса, строго по очереди

Каждый следующий имеет смысл, только если предыдущий не дал ответа.

### Вопрос 0 (отсекающий). Это секрет?

Токен, ключ, коды восстановления, пароль → **не в репу вообще**,
`~/Documents/recovery_kits/` (`85-secrets-and-recovery-codes.md`).
Ответ «да» закрывает разговор: никакая тематическая репа не подходит.

### Вопрос 1. Это правило или состояние?

Правило (не изменится от смены целей) → **база**. Состояние → дальше
(`76-repo-classes.md` §«Два проверочных вопроса»).

### Вопрос 2. О чём файл ПО СОДЕРЖИМОМУ, а не по имени папки?

🔴 **Открыть и посмотреть.** Это тот самый шаг, пропуск которого дал `PIT-124`.
Папка `claude` содержала инструкции Claude (142 файла), выгрузки чатов (29) и случайное (3) —
три адреса, а не один.

### Вопрос 3. У предмета есть своя репа?

Есть → туда. Нет → `misc-vault` **осознанно**, а не «пока положу сюда».

> **`misc-vault` — не свалка, а решение «предмет не тянет на свою репу».**
> Записывается так же, как любое другое: с причиной.

## 2. Таблица маршрутизации — по предмету, не по расширению

Расширение почти ничего не говорит: `.pdf` бывает медкартой, законом и научной статьёй —
и это три разные репы. Поэтому таблица по **предмету**, а тип файла лишь уточняет,
что с ним делать дальше.

| Предмет | Репа | Типичные типы | Что делать с тяжёлым |
|---|---|---|---|
| анализы, медкарты, ПНД, прививки | `health-vault` | `.pdf` сканы, `.xlsx` динамика | 🔴 эталон остаётся **+** `.md`-выжимка |
| законы, повестки, доверенности, призыв | `legal-knowledge-base` | `.pdf`, `.docx` | эталон + выжимка |
| ВКР, курсовые, публикации, дипломы | `academic-portfolio` | `.pdf`, `.docx`, `.pptx`, `.tiff` | эталон сданного + выжимка |
| код, алгоритмы, учебные проекты, гисты | `it-base` | `.py`, `.sql`, `.ipynb` | 🔴 `.venv`/`node_modules` не переносятся |
| ML, нейросети, датасеты | `ml-base` | `.py`, `.ipynb` | датасет — служебкой, если публичный |
| вера, богословие, исповедь | `christ-walk` | `.md`, `.docx` | личное — как есть |
| психологические тесты, дневники, «кто я» | `self-map` | `.md`, `.pdf` | личное — как есть |
| мемуары, фото родных, семейные документы | `family` | `.pdf`, `.jpg`, `.docx` | эталон остаётся всегда |
| разборы утверждений, проверка фактов | `truth-seeking` | `.pdf`, `.md` | материал без разбора — служебкой |
| курсы, лекции, методички обучения | `edu-base` | `.pdf`, `.mp4`, `.docx` | видео → `ai-relay` на перевод |
| поступление в магистратуру | `master-admission` | `.pdf`, `.docx` | — |
| метод познания, логика, научный метод | `research-craft` | `.md`, `.pdf` | — |
| работа с Claude: замеры, лимиты, приёмы | `claude-usage` | `.md`, `.json` | 🔴 **публичная** — личное туда нельзя |
| звук и видео, требующие перевода в текст | `ai-relay` | `.mp3`, `.mp4`, `.wav` | это её предмет, а не балласт |
| всё остальное, осознанно | `misc-vault` | любые | по общему правилу |

🔴 **Публичные репы в этой таблице — особый случай.** `claude-usage`, `vk-graph`,
`algorithms-site`, `bron-kerbosch`, `health-report-generator`, `salvation`,
`vevdokimovm*` — витрины. Личное туда не кладётся **никогда**, даже если предмет совпал:
22.08.2026 в `claude-usage` уехали 152 файла личных инструкций, поймано перед сборкой
архивов (`PIT-123`). Проверка — свойством объекта, а не памятью:
`gh repo view … --json isPrivate`.

## 3. Что делать с тяжёлым — общее правило поверх таблицы

| Файл | Решение |
|---|---|
| **воспроизводим** (публичный датасет, канал, дистрибутив) | свернуть в служебку, оригинал удалить |
| **невоспроизводим** (скан, съёмка, рукопись) | 🔴 **эталон остаётся** + `.md`-выжимка рядом |
| регенерируемое (`.venv`, `node_modules`, `__pycache__`) | не переносится вовсе |
| архив `.zip` внутри репы | распаковать, содержимое — по таблице |

Метод перевода и требования к служебке — `../07-media-to-text-lab/README.md`.

## 4. Классификация уточняется от работы — как именно

Владелец назвал это прямо: *«чем больше будем работать с конкретной репой, тем точнее
будет классификация становиться»*. Механика:

1. Прошли репу ревизией → в её **манифест** пишется, что в ней уже лежит **по предмету**.
2. Случай, который таблица не покрыла, → строка сюда, с датой и примером.
3. Случай, где таблица **ошиблась**, → строка сюда **и** карточка `PIT`: ошибка адресации
   повторяема по построению.

> **Таблица, которую не правят после работы, через месяц описывает прошлую систему.**
> Признак живой классификации — дата последней правки не старше последней ревизии.
