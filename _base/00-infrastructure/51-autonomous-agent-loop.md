# 51 — Автономный цикл: один промпт до конца лимита

> **Этот документ — про механику: как запустить, чтобы не спрашивало.**
> Про **дисциплину** — что агент вправе решать сам, где обязан остановиться, чем
> доказывает сделанное — отдельный кит: [`06-autonomous-mode-kit/`](../06-autonomous-mode-kit/README.md).
> Механика без дисциплины даёт агента, который уверенно и быстро делает не то.

> Как настроить Claude Code так, чтобы отправить один промпт и дальше он работал
> самостоятельно, не спрашивая разрешений, до исчерпания лимита, и не останавливался
> при обрыве сети/VPN, а пытался повторить. Смежное: `34-cowork-scheduled-tasks.md`
> (периодические задачи — не то же самое, см. §5 здесь), `08-automation-triggers.md`.

## 0. `/auto-mode-setup` — обучение классификатора под окружение

Отдельная нативная команда (не то же самое, что headless/`bypassPermissions` ниже): не включает
автономность, а **калибрует** уже включённый по умолчанию auto-mode-классификатор под конкретную
репу/окружение — меньше ложных блокировок на безопасных командах.

- **Version-gated:** раскатывается поэтапно, не во всех сборках CLI сразу — в одной сессии команда
  может существовать, в другой (даже на той же машине, версия отличалась на 1 patch) выдавать
  `Unknown command`. Проверять через `/help` в конкретной сессии, не полагаться на факт работы
  где-то ещё. CLI-эквивалент для инспекции текущих правил без интерактивного сканирования —
  `claude auto-mode config` / `claude auto-mode defaults` / `claude auto-mode reset`.
- **Что делает:** сканирует репозиторий (и опционально shell history / другие репы) и предлагает на
  подтверждение: org/cloud/secrets-management контекст, trusted repo, доверенные домены, extra
  allow/soft-block/hard-block правила поверх дефолтного классификатора. Ничего не применяется без
  явного «Looks good — save it».
- **На base-repo (2026-08-20):** предложение оказалось консервативным — `Allow carve-outs: none`,
  `Extra hard blocks: none`, единственное добавление — soft-block на `git push --force` в этой репе,
  если появится remote (сейчас его нет — репа локальная, без `.git`, что калибровщик определил
  сам и пометил как «treat as private/local»). Настройка глобальная (не per-repo), сохранённая
  здесь конфигурация — часть общего профиля классификатора этого аккаунта.
- **Не путать с `bypassPermissions`/headless ниже** — это не механизм для «не спрашивай вообще
  ничего», а тонкая настройка того, что классификатор *и так* решает автоматически.

## 1. Headless-режим — база для любого автономного запуска

Флаг `-p` (`--print`) переключает CLI из интерактивного REPL в «один промпт → один
результат → выход»:

```bash
claude -p "Делай задачу X до конца, не спрашивая" --allowedTools "Read,Edit,Bash"
```

Ключевые флаги:
- `--output-format json` — даёт `result`, `session_id`, `total_cost_usd` (нужен для
  checkpoint/resume, см. §6).
- `--output-format stream-json` — построчный NDJSON, удобно логировать прогресс и
  ловить событие `system/api_retry`.
- `--bare` — пропускает автозагрузку hooks/skills/plugins/MCP/CLAUDE.md, быстрее и
  детерминированнее для скриптового запуска.
- `--continue` / `--resume <session_id>` — продолжение той же сессии.
- Коды выхода: `0` успех, ненулевой — сбой, `143` — убит SIGTERM (супервизором).

## 2. Разрешения — чтобы не спрашивать ничего

Полный список режимов (`permissions.defaultMode` / `--permission-mode`): `default`
(только чтение, спрашивает всё), `acceptEdits`, `plan`, `auto` (модель-классификатор
сама одобряет действия — дефолт на Pro/Max/Team), `dontAsk` (только предодобренные
инструменты — для CI), **`bypassPermissions`** (`=--dangerously-skip-permissions`, ничего
не спрашивает вообще).

Что `bypassPermissions` **не отключает** даже в bypass-режиме: явные `ask`-правила
в `permissions.ask`; инструменты `requiresUserInteraction` (включая уточняющие
вопросы); `rm`/`rmdir` по критическим путям (`/`, `~`) — это отдельный внутренний чек,
который не обходится ни allow-правилом, ни хуком.

**Официальная рекомендация:** `bypassPermissions` — только в изолированном контейнере/
VM без доступа к хост-системе, желательно от non-root пользователя. Более безопасная
альтернатива — **auto mode**: классификатор проверяет каждое действие в 2 стадии
(быстрый фильтр + reasoning на подозрительном), блокирует деструктив/эксфильтрацию,
эскалирует к человеку после 3 подряд отказов или 20 суммарных. На реальном трафике —
0.4% ложных срабатываний, но пропускает ~17% по-настоящему опасных действий: снижение
риска, не гарантия. Для по-настоящему «не спрашивай никогда» нужен именно
`bypassPermissions`, с пониманием, что это осознанный отказ от защиты, а не бесплатная
опция.

## 3. settings.json

```json
{
  "permissions": {
    "defaultMode": "bypassPermissions",
    "allow": ["Bash(npm run test *)", "Read", "Edit"],
    "deny": ["Bash(rm -rf *)", "Read(./.env)", "Read(./secrets/**)"]
  },
  "env": {
    "CLAUDE_CODE_RETRY_WATCHDOG": "1",
    "CLAUDE_CODE_MAX_RETRIES": "15",
    "API_TIMEOUT_MS": "600000"
  }
}
```

Порядок оценки правил: `deny → ask → allow`, побеждает первое совпадение. Иерархия
файлов: managed → CLI-флаги → `.claude/settings.local.json` → `.claude/settings.json` →
`~/.claude/settings.json`.

## 4. Hooks — не подменяют «дай новую задачу»

Важный нюанс: **Stop-хук сам не перезапускает агента новым промптом**, он умеет только
блокировать завершение текущего хода (`exit 2` / JSON `"decision": "block"`) — это
заставляет Claude продолжить текущий ход, не то же самое, что дать новую задачу.

Чтобы получить «продолжай дальше» (аналог `/loop`), два пути:
1. **Штатный `/loop`** — планирует повтор через `CronCreate`/`CronList`/`CronDelete`
   внутри сессии; переживает конец текущего хода, пока открыт терминал/фоновая сессия;
   истекает через 7 дней; минимальный интервал 1 минута.
2. **Своя обёртка** — внешний скрипт, который после каждого
   `claude -p --output-format json` парсит `result`/`session_id` и запускает новый
   `claude -p --continue "продолжай"`.

## 5. Сеть, VPN, обрывы

Встроенный retry с backoff есть, но ограничен по умолчанию:
- До **10 попыток** (`CLAUDE_CODE_MAX_RETRIES`, максимум 15) на серверные ошибки,
  обрывы, детект «компьютер уснул», 429 (кроме gateway spend-limit).
- **`CLAUDE_CODE_RETRY_WATCHDOG=1`** — снимает лимит попыток для capacity-ошибок,
  официально рекомендован именно для CI/unattended-сессий.
- `API_TIMEOUT_MS` (дефолт 600000 мс) — стоит поднять на нестабильных сетях/через VPN.
- `system/api_retry` в `stream-json` даёт `attempt`, `max_retries`, `retry_delay_ms`,
  `error` — логировать прогресс ретраев извне.

Но это retry **внутри одного запроса/сессии**, не переживание обрыва VPN на минуты-часы
или падения самого процесса `claude`. Для настоящей устойчивости — внешняя обвязка:
`while`/`until`-цикл в shell, tmux/nohup для персистентности независимо от разрыва SSH,
супервизор процесса (launchd/systemd) для автозапуска. Готовый community-инструмент —
[`claude-auto-retry`](https://github.com/cheapestinference/claude-auto-retry): tmux-
сессия, парсинг последних строк пейна на паттерны лимитов, ожидание сброса с учётом
таймзоны/DST, backoff `[30, 60, 120, 240, 300]`с ±15% джиттер на 429/500/502/503/504/529.

## 5а. 🔴 Снято с установленной версии, а не из документации — `2.1.238`

Раздел §5 собран по документации. Ниже — то, что **фактически предлагает CLI на этой
машине** (`claude --version` → `2.1.238`, `claude --help`). Читать вместе: документация
описывает намерение, `--help` — что доступно **сегодня и здесь**.
**Версию обязательно сверять при перечитывании:** ключи появляются и исчезают.

### Ключи, меняющие устройство автономного контура

| Ключ | Что даёт | Почему важен без владельца |
|---|---|---|
| `--max-budget-usd <сумма>` | жёсткий потолок трат на вызовы API (только с `--print`) | **стоп-условие, которое исполняет сам CLI.** Единственное из пяти классов `STOP_CONDITIONS.md`, не зависящее от дисциплины агента |
| `--fallback-model <a,b>` | автопереход на другую модель при перегрузе/недоступности; **primary пробуется заново в начале каждого хода** (только `--print`) | недельный прогон переживает деградацию провайдера без участия человека |
| `--session-id <uuid>` | **задать** идентификатор сессии, а не вычитывать его из ответа | обвязка перестаёт зависеть от парсинга JSON: id известен до старта |
| `--autocompact <auto\|токены>` | размер окна автокомпакта, `100k`–`1M` | длинный прогон упирается в контекст раньше, чем в лимит; ручка была неизвестна |
| `--fork-session` | при `--resume` завести новый id вместо переиспользования | ветвление прогона без порчи исходной линии |
| `--bg` / `--background` | запустить сессию фоновым агентом и сразу вернуть управление | несколько прогонов параллельно без терминала на каждый |
| `--forward-subagent-text` | текст и размышления субагентов идут в поток как сообщения с `parent_tool_use_id` (`--print` + `stream-json`) | **прямо бьёт по записанному пробелу** «расход субагентов в лог родителя не попадает»: канал наблюдения существует, просто он не включён по умолчанию |
| `--include-hook-events` | все события хуков в поток (`stream-json`) | наблюдаемость гейтов в прогоне без владельца |
| `--tools` / `--allowedTools` / `--disallowedTools` | сузить набор инструментов до нужного | сужение периметра дешевле, чем надежда на дисциплину |
| `--safe-mode`, `--bare` | старт без кастомизаций / минимальный режим | диагностика сломанной конфигурации, когда владельца нет |

### Уточнения к тому, что уже записано

- **`--permission-mode` имеет шесть значений**, а не два: `acceptEdits`, `auto`,
  `bypassPermissions`, `manual`, `dontAsk`, `plan`. Раздел §2 называл не все.
- **`--effort` — пять уровней** (`low`, `medium`, `high`, `xhigh`, `max`), подтверждает
  `66-model-and-effort-selection.md` после правки v1.91.0.
- **`--allow-dangerously-skip-permissions` ≠ `--dangerously-skip-permissions`.**
  Первый **делает режим доступным**, не включая его; второй включает. Для прогона,
  где часть работы обязана спрашивать, разница решающая.
- **`claude auto-mode reset`** — официальный способ **убрать секцию `autoMode`
  из пользовательских настроек**. Полезно знать: `/auto-mode-setup` дописывает её
  в глобальный файл, и до сих пор откат делался руками.
  *(Проверено 21.08.2026: в `~/.claude/settings.json` секции `autoMode` сейчас нет.)*

### 🔴 `Error: prompt is required when stop is not true` — планировщик падает молча внутри хода

Снято с кадра **12.08.2026, 11:23** (Claude Code, `~/Documents/finpilot`, Sonnet 5, `auto mode on`),
разобрано 25.08.2026. Ход выглядел так:

```
Оба ревью ещё выполняются в фоне — дождусь их завершения, прежде чем закрывать батч
  Error: `prompt` is required when `stop` is not true.
Жду завершения фоновых ревью (design-critic и a11y-auditor) — сообщат автоматически.
```

Вызов планировщика пробуждения (`ScheduleWakeup`) ушёл без обязательного `prompt` — тот
обязателен всегда, кроме случая `stop: true`. **Ход при этом не оборвался**: ошибка легла
строкой посреди ответа, сессия продолжила работать и просто осталась ждать уведомления,
которое пришло бы и без будильника.

> **Отказ планировщика не ломает текущий ход — он снимает страховку.** Пока фоновая работа
> досылает уведомление сама, разницы не видно; если она зависнет, будить сессию будет нечем,
> и авто-режим встанет до сторожа снаружи.

**Правило:** `stop: true` — единственный вызов без `prompt`. Любой другой несёт `prompt`,
`delaySeconds`, `reason` и `noop`. И отдельно: **будильник ставится не для опроса фоновой
работы** (о её завершении сессию извещают), а как длинный запасной удар на случай, что
уведомление не придёт вовсе.

**Что ещё на том же кадре** — цена субагентов, замерено по одному ходу:

| Субагент | Время | Токенов |
|---|---|---|
| `design-critic` (ревью Sankey в `AllocationPanel`) | 3m 16s | ↓ **59.2k** |
| `a11y-auditor` (аудит переключателя) | 2m 54s | ↓ **27.5k** |
| `Explore` (кадр 16:30, backend alternative grid) | 3m 52s | ↓ **35.8k** |

Оба ревью запущены как `Backgrounded agent` с пометкой **`Allowed by auto mode classifier`** —
то есть классификатор авто-режима пропускает запуск фоновых агентов без вопроса. Там же
`chrome-devtools-mcp` вызван **12 раз за три реплики** (7 + 3 + 2). Расход MCP-вызовов —
`49-token-economy-and-prompting.md`, выбор модели под батч — `66-model-and-effort-selection.md` §3а.

## 6. Упор в лимит — как поймать и продолжить после сброса

Claude Code печатает явные сообщения: `You've hit your session limit · resets 3:45pm`,
`You've hit your weekly limit · resets Mon 12:00am`. `/usage` показывает лимиты и время
сброса.

> ### 🔴 Время сброса лежит в логе машиночитаемо — парсить экран не нужно
>
> Найдено 21.08.2026. При отказе Claude Code пишет в `~/.claude/projects/*/*.jsonl`
> запись с полем `quotaLimits`:
>
> ```json
> {"status":"rejected","resetsAt":1787332200,"rateLimitType":"five_hour",
>  "overageStatus":"rejected","overageDisabledReason":"org_level_disabled"}
> ```
>
> **`resetsAt` — unix-таймстамп.** Ни разбора строки «resets 3:45pm», ни догадок
> о таймзоне и переходе на летнее время, ни зависимости от языка интерфейса.
> Типы окон, встреченные на этой машине: `five_hour` и `seven_day`.
> Читает `06-autonomous-mode-kit/bin/limits_watch.py`.
>
> **Две оговорки, обе стоили ошибки в первой редакции инструмента:**
>
> 1. **Запись появляется только в момент отказа.** Остатка лимита в логе нет —
>    «сколько осталось» по этим данным не считается, и выдумывать нельзя.
> 2. **Отказ ≠ блокировка до `resetsAt`.** В живом логе после отказа шли **149
>    успешных ходов**, а время сброса ещё не наступило. Значит блокировка
>    определяется **фактом** (есть ли успешный ход после отказа), а не временем.
>    Цикл должен пробовать с backoff, а не спать весь интервал целиком.
>
> **`overageStatus: rejected` (`org_level_disabled`)** — при упоре работа
> **останавливается**, а не продолжается платно. Для планирования недельного
> прогона это главный факт: ждать, а не надеяться.

**Встроенный автовозврат после сброса лимита есть только в Desktop-приложении**
(«Auto-continue when limits reset»). В CLI/headless такого штатного механизма нет.
Единственный официальный путь для CLI — поймать событие извне (код выхода/текст
stderr/`system/api_retry`) и запланировать повтор на время сброса через
`launchd`/`cron`, либо использовать `claude-auto-retry`, который парсит время сброса
из вывода и сам досылает «continue».

## 7. Официальный «отправил и забыл» — Routines

**Routines** (Anthropic, research preview) — облачные агенты на managed-инфраструктуре
Anthropic: `/schedule` в CLI или `claude.ai/code/routines`. Работают **полностью
автономно, без permission-picker вообще** — это ближе всего к «один промпт, ничего не
спрашивать». Триггеры: `Scheduled` (cron, минимум 1 час), `API` (`POST /fire` с
bearer-токеном), `GitHub` (события PR/Release). Доступно на Pro/Max/Team/Enterprise
с включённым Claude Code on the web. Не зависит от локальной машины — переживает разрыв
VPN/выключенный ноутбук в принципе, потому что не выполняется на нём.

**Практический вывод:** для сценария «скинул один промпт и жди, пока не кончится
лимит» официальный и самый надёжный путь — **Routines**, а не локальный watchdog.
Локальный watchdog нужен только если задача обязана выполняться именно на этой машине
(доступ к локальным файлам/сети, которых нет в облаке).

## 8. Watchdog на macOS — если нужен именно локальный запуск

Checkpoint/resume: сохранять `session_id` в файл, при рестарте продолжать через
`--resume`.

```bash
#!/usr/bin/env bash
SESSION_FILE="$HOME/.claude_session_id"
LOG="$HOME/claude_watchdog.log"
PROMPT="Делай задачу X до конца, ничего не спрашивая"

while true; do
  if [[ -f "$SESSION_FILE" ]]; then
    claude -p --resume "$(cat "$SESSION_FILE")" \
      --dangerously-skip-permissions --output-format json > /tmp/claude_out.json
  else
    claude -p "$PROMPT" --dangerously-skip-permissions \
      --output-format json > /tmp/claude_out.json
    jq -r '.session_id' /tmp/claude_out.json > "$SESSION_FILE"
  fi
  echo "$(date): exit=$? , см. /tmp/claude_out.json" >> "$LOG"
  sleep 15
done
```

launchd plist (держит скрипт живым при падении, не сам процесс `claude`):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.user.claude-watchdog</string>
  <key>ProgramArguments</key>
  <array><string>/bin/bash</string><string>/Users/you/scripts/claude_watchdog.sh</string></array>
  <key>KeepAlive</key><dict><key>SuccessfulExit</key><false/></dict>
  <key>StandardOutPath</key><string>/tmp/claude_watchdog.out.log</string>
  <key>StandardErrorPath</key><string>/tmp/claude_watchdog.err.log</string>
  <key>RunAtLoad</key><true/>
</dict></plist>
```

Загрузка: `launchctl load ~/Library/LaunchAgents/com.user.claude-watchdog.plist`.

## 9. Итог: что выбрать

| Сценарий | Механизм |
|---|---|
| Задача не требует локальной машины (нет доступа к специфичным локальным файлам) | **Routines** — самый надёжный, переживает обрыв VPN/сон ноутбука |
| Задача обязана идти локально (доступ к конкретным файлам/сети на этой машине) | headless `-p` + `bypassPermissions` + `--resume` + внешний shell-цикл + launchd |
| Повторяющаяся короткая задача по расписанию | `34-cowork-scheduled-tasks.md` (`create_trigger`) — не то же самое, что непрерывный автономный цикл |
| Нужно просто «не переспрашивай в рамках текущей сессии» | `auto mode` (дефолт) или `bypassPermissions` в settings.json, без внешней обвязки |

> обрыв VPN на часы — для этого нужна внешняя обвязка (shell-цикл + launchd) или,

> независимо от твоей машины»; штатного «жди сброса лимита и продолжай» в CLI нет,
