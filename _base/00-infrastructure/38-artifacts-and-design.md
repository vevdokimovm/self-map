# 38 — Артефакты и дизайн

> **Что это и зачем.** Артефакт — это самостоятельный файл-результат, который Claude отдаёт тебе так, что
> он **рендерится и живёт** (HTML-дашборд, диаграмма, SVG, отчёт), а не просто лежит текстом в чате.
> «Дизайн» — слой скиллов, которые делают эти артефакты красивыми и системными (палитры, темы, чарты,
> критика UX). Документ: **какие форматы рендерятся, правила single-file, чем доставка отличается от
> сохранённого артефакта, какие дизайн-скиллы есть.**
>
> Кластер: скиллы (многие из них строят артефакты) — `37`, поверхности — `26`, карта тулов — `40`.

---

## 0. Одной строкой

Артефакт = **файл-deliverable, который открывается и работает сам** (а не текст для копипаста). Два
режима отдачи: **доставить в чат** (`SendUserFile`) или **сохранить в галерею** (`create_artifact`).

---

## 1. Что рендерится (форматы-артефакты)

Особый рендеринг в интерфейсе — у этих типов:

| Формат | Когда брать |
|---|---|
| **Markdown** (`.md`) | Текстовый deliverable: отчёт, статья, письмо, гайд |
| **HTML** (`.html`) | Интерактив: дашборд, трекер, калькулятор, лендинг — **всё в одном файле** |
| **Mermaid** (`.mermaid`) | Диаграммы из текста: флоу, архитектура, ER |
| **SVG** (`.svg`) | Векторная графика, схемы |
| **PDF** (`.pdf`) | Печатный/пересылаемый документ |

**Single-file — закон.** HTML-артефакт = один файл: CSS и JS **внутри**, не отдельными файлами. Внешние
скрипты — только с `cdnjs.cloudflare.com`. Картинки — `data:`-URL инлайном.

**🔴 Запрет браузерного хранилища.** `localStorage` / `sessionStorage` / любые storage-API в артефактах
**не поддерживаются и ломают артефакт** в среде claude.ai. Данные держать в переменных/памяти на время
сессии. Это не совет, а жёсткое ограничение платформы.

## 2. Доставить vs сохранить (два разных действия)

| | `SendUserFile` | `create_artifact` (persisted) |
|---|---|---|
| Что делает | Кладёт файл в **этот разговор** (превью + скачать) | Рендерит и **сохраняет как именованный артефакт** в сайдбаре/галерее |
| Живёт | в этом чате | **между сессиями**, открывается позже без поиска чата |
| Обновляется | новой отправкой | **на месте** (`update_artifact`) |
| Шаринг | — | можно делиться с людьми |
| Когда | одноразовый вывод, черновик, «посмотреть эти числа сейчас» | то, к чему **вернёшься/будешь обновлять/покажешь** |

**Правило выбора.** Если вещь по своей природе перечитывается — **дашборд, трекер, статус-страница,
справочник, калькулятор** — сохраняй (`create_artifact`) по умолчанию. Явные сигналы «поделюсь / буду
обновлять / команда откроет» — тоже сохранять. Исключение — **одноразовое** («набросай быстро посмотреть»,
«визуализируй вот эти числа сейчас») → только `SendUserFile`. Поток: написать self-contained HTML →
`SendUserFile` (получить `file_uuid`) → `create_artifact` с этим `file_uuid`.

> Проза/таблицы/код, который вставишь в свой кодбейс (`.jsx`, `.py`, `.docx`) — идут через `SendUserFile`:
> там ценность в самом файле, не в рендере. `create_artifact` доступен, когда подключён десктоп Claude.

**Применение под меня.** «Живой трекер миграции» (визы/дедлайны/шаги), «дашборд статуса FINPILOT», «карта
repos-map как HTML» — это **сохранённые артефакты** (вернусь, обновлю). Разовый график «вот расход токенов
за эту неделю» — просто `SendUserFile`.

## 3. Дизайн-слой (скиллы)

Артефакт мало создать — его делают системным и читаемым дизайн-скиллы:

| Скилл | Для чего |
|---|---|
| **`dataviz`** | Любой чарт/график/дашборд: единая система, доступные палитры (свет/тьма), спеки марок. Читать **до** первой строки чарт-кода |
| **`theme-factory`** | Тема (цвета/шрифты) на артефакт: 10 пресетов или генерация своей |
| **`web-artifacts-builder`** | Сложные многокомпонентные HTML-артефакты (React/Tailwind/shadcn) — когда нужен стейт/роутинг |
| **`canvas-design`** | Статичный визуал-арт в `.png`/`.pdf` (постеры, обложки) |
| **`algorithmic-art`** | Генеративный арт на p5.js (сид, параметры) — этим делали Boreal Drift |
| **`design:*`** (плагин Design) | `design-critique`, `accessibility-review`, `design-system`, `ux-copy`, `design-handoff` — критика и системность интерфейсов |

**Правило для чартов:** любой график/дашборд/визуализация → сперва скилл `dataviz` (палитра, контраст,
типы марок), потом код. Иначе получаются случайные RGB и нечитаемые в тёмной теме чарты.

## 4. Чек-лист

1. Результат должен **открываться и работать** (не копипаст)? → это артефакт.
2. HTML → **один файл**, CSS/JS внутри, без `localStorage`, внешнее только с cdnjs.
3. Будешь возвращаться/обновлять/делиться? → `create_artifact` (сохранить), не только `SendUserFile`.
4. Одноразовое «посмотреть»? → `SendUserFile` хватит.
5. Есть чарт/дашборд? → сначала `dataviz`, потом код.
6. Нужна тема/системность? → `theme-factory` / `design:*`.
