# 52 — Железо: базовый снимок и что это значит для производительности

> Снят `system_profiler`/`sysctl`/`vm_stat` **2026-08-20**. Не «характеристики вообще»,
> а конкретное состояние **этой** машины на эту дату — переснимать при апгрейде/чистке
> диска, не считать замороженным фактом. Смежное: `49-token-economy-and-prompting.md`
> (расход токенов), `50-parallel-accounts-and-admin-orchestration.md` (параллельные
> вкладки — сюда упирается железом, см. §3).

## 1. Машина

| Параметр | Значение |
|---|---|
| Модель | MacBook Pro 15,2 (13″, 2018/2019, четырёхъядерный i5) |
| CPU | Intel Core i5-8259U @ 2.3 GHz, 4 физических ядра / 8 потоков (Hyper-Threading) |
| GPU | Intel Iris Plus Graphics 655, 1536 MB VRAM (динамическая) |
| RAM | **8 GB** |
| Диск | APFS SSD, 250.7 GB общий объём |

## 2. Текущее состояние — узкие места

**Диск почти заполнен: 13.4 GB свободно из 250.7 GB (5.3%).** Это не «есть место» —
это зона, где macOS начинает деградировать (медленнее Spotlight, swap-файлы жмутся
на то же место, Time Machine local snapshots не могут ротироваться нормально).
**Приоритет №1 для производительности — освободить диск**, не апгрейд CPU/RAM.

**RAM — жёсткий потолок в 8 GB, и своп это подтверждает:** `vm.swapusage: used = 2501M`
из 4096M выделенного свопа — то есть машина **уже в моменте снятия снимка** активно
подкачивает страницы на диск. Load average `3.33 / 3.93 / 4.58` на 4 физических ядрах —
устойчиво выше числа ядер, значит очередь задач на CPU тоже есть, не только память
в дефиците.

**Аккумулятор: Cycle Count 380, Condition — Service Recommended.** Не про
производительность CPU напрямую, но означает менее стабильное питание под нагрузкой
(троттлинг раньше, чем на здоровой батарее) — стоит держать в уме при долгих
автономных прогонах (`51-autonomous-agent-loop.md`) без подключения к сети питания.

**Термальных предупреждений нет** (`pmset -g therm` — чисто, `CPU_Speed_Limit = 100`) —
в моменте снимка троттлинга по теплу не было, узкое место именно RAM+диск, не нагрев.

## 3. Прямое следствие для задач из `49`–`51`

**Параллельные вкладки с разными аккаунтами (`50`) — на этом железе рискованно.**
8 GB RAM с уже занятым свопом при обычной фоновой нагрузке означает, что 3–4
одновременных инстанса Claude Code (каждый — Node-процесс + контекст сессии) с высокой
вероятностью упрутся в память раньше, чем в лимит токенов. Практический вывод:
- Пробовать параллельность на **2 вкладках**, не сразу на 4 — замерить реальный расход
  RAM на инстанс (`top -o mem`) перед тем, как планировать 4.
- Если 2 уже давят на своп — параллельность на этой машине не выигрыш, а проигрыш
  (своп на почти заполненном SSD — самое медленное, что можно получить).
- Автономные долгие прогоны (`51`) в фоне через launchd — по той же причине держать
  по одному активному инстансу, не параллелить с ручной работой в другой вкладке.

**Диск в 5.3% свободного — риск для любого автономного/долгого прогона.** Логи,
временные файлы, git-объекты, кэш пакетных менеджеров — при таком остатке можно
упереться в «no space left on device» посреди автономной сессии без присмотра.
Перед запуском `51`-сценария (`bypassPermissions` + watchdog на часы) — проверить
свободное место, не полагаться, что «как-нибудь хватит».

## 4. Что стоит сделать (не входит в объём этого снимка — на будущее)

- Освободить диск минимум до 🟢-порога (см. `06-volume-compression.md` — тот же принцип
  «лёгкость», применённый теперь и к самой машине, не только к репам).
- Проверить, что жрёт RAM в фоне на этой машине (`top -o mem`, `Activity Monitor`) —
  часто это браузер с десятками вкладок или фоновые синк-агенты (iCloud/Dropbox),
  а не сам Claude Code.
- Батарея на Service Recommended — заменить не срочно, но иметь в виду при длинных
  автономных прогонах без розетки.
