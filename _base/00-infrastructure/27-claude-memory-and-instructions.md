# 27 — Claude: память и инструкции (методичка про слои)

> Практический разбор: как устроена общая память, память проекта, общие инструкции (preferences), инструкции проекта, как всё это перекликается и как выжимать максимум.
> Составлено под твой сетап (4 аккаунта, контекст-файлы, FINPILOT). Актуально: июль 2026.
> ⚠️ Часть мех'аники Anthropic публично не документирует — где я опираюсь на наблюдаемое поведение, а не на жёсткую спеку, это помечено «(по поведению)».

---

## 0. Карта на один экран (mental model)

В голове держи **две независимые системы**, у каждой — **два уровня охвата (scope)**, плюс отдельный слой файлов:

```
┌─────────────────────────────────────────────────────────────┐
│  СИСТЕМА 1: ИНСТРУКЦИИ (ты пишешь явно, verbatim)            │
│    ├─ Global:  User Preferences (Settings → Profile)         │
│    │           + User Style (стиль письма, отдельно)         │
│    └─ Project: Project instructions (кастомные, на проект)   │
│                                                              │
│  СИСТЕМА 2: ПАМЯТЬ (движок сам выводит из твоих чатов)       │
│    ├─ Global memory:  автосводка + твои edits                │
│    │                   (охват: чаты ВНЕ проектов)            │
│    └─ Project memory:  своя, отдельная                       │
│                        (охват: чаты ВНУТРИ этого проекта)    │
│                                                              │
│  СЛОЙ ФАЙЛОВ: Project Knowledge                             │
│    └─ файлы/текст, всегда впрыскиваются в чаты проекта       │
│       (не память и не инструкции — «всегда в контексте»)    │
│                                                              │
│  ТЕКУЩИЙ ЧАТ: сообщения здесь-и-сейчас — высший приоритет    │
└─────────────────────────────────────────────────────────────┘
```

**Три вещи, которые надо усвоить сразу:**

1. **Инструкции = verbatim и надёжно. Память = пересказ и дрейфует.** Всё, что ОБЯЗАНО быть правильным (кто ты, стандарты кода, вектор миграции, «не медик»), живёт в инструкциях/файлах, а не в памяти.
2. **Scope-силосы не смешиваются.** Общая память и память проекта — разные ящики. Проект A не течёт в проект B и не течёт в общую память.
3. **Всё это — на аккаунт.** Ничего не синхронизируется между V/S/J/M. Единый источник правды — только твои файлы.

## 1. Общая память (Global Memory) — то, что мы сегодня меняли

Это **не одна сущность, а две разные штуки** в одном окне «Manage memory». Именно их путаница и вызвала твой вопрос «почему память не изменилась».

### 1.1. Автосводка (auto-summary) — большая карточка

Та самая карточка «Here's what Claude remembers about you».

- **Кто её пишет:** движок, не ты. Ты её напрямую не редактируешь.
- **Из чего собирается:** прошлые чаты (вне проектов) **+ твои edits**.
- **Когда обновляется:** **раз в ночь** (в самой карточке так и написано: *«regenerated each night»*). Мгновенно НЕ обновляется.
- **Дата «изменено N дней назад»:** это дата последней **ночной пересборки**, а не дата твоей правки. Поэтому после наших edits карточка ещё показывала старьё — пересборки с тех пор не было.

> 🔑 Вот почему тебе показалось, что «ничего не поменялось»: ты смотрел на автосводку (ночная, отстаёт), а меняли мы edits (мгновенные). Это два разных слоя.

### 1.2. Правки / Manage edits — то, чем реально рулишь ты

Внизу окна: «Manage edits» с цифрой (у тебя стало **1**).

- **Кто пишет:** ты (или я по твоей команде через инструмент).
- **Когда применяется:** **сразу**, персистентно.
- **Что делает:** **рулит ночной пересборкой автосводки.** Это твой руль, а не сама витрина.
- **Приоритет (по поведению):** edits **авторитетнее** сырого текста чатов. То есть если из старых чатов движок упорно выводит неверный факт, правка с явной корректировкой его перебивает.

### 1.3. Что конкретно мы сделали сегодня (worked example)

- **Было:** в edits лежали **2 почти одинаковых раздутых блока**, оба называли тебя «medical student» и тащили старые инструкции.
- **Сделали:** блок №1 переписали начисто (IT/АСУ, вектор миграции наверх, аккаунты V/S/J/M прояснены, FINPILOT/здоровье обновлены, вера как фундамент, приватный анализ вынесен и исключён); блок №2-дубль снесли. Итог: **2 → 1, исправлено.**
- **Что это чинит:** при следующей ночной пересборке автосводка должна перестать звать тебя медиком и подтянуть актуальный профиль.
- **Что это НЕ делает:** не меняет большую карточку мгновенно (ждём ночь) и **не трогает другие аккаунты** и **память твоих проектов**.

### 1.4. Прочие правила общей памяти

- **Охват:** общую память кормят **только чаты вне проектов**, и используется она **только вне проектов**.
- **Удаление чатов:** удалил чат → выведенные из него факты уходят из памяти (тоже ночью, не сразу).
- **Инкогнито (Incognito):** память **полностью выключена** — ни читает, ни пишет. Идеально для разовых веток, которые не должны влиять на профиль.
- **Тумблер:** память целиком можно выключить/включить; отдельные пункты — курировать.

### 1.5. Почему «медик» так залип

Ошибка налипла из **кучи старых чатов**, где термин «medical student» реально встречался (из-за объёма твоих медицинских самоанализов). Автосводка каждую ночь заново его выводила. Разовая правка обычно перебивает, но если факт «размазан» по десяткам чатов — движок может его тянуть снова. Лечение: (а) сильная явная правка с **отрицанием и причиной** (сделали), (б) если не помогло за ночь — **подчистить/удалить** самые «заразные» старые чаты.

## 2. Память проекта (Project Memory)

- У **каждого проекта — своя отдельная память.** В карточке общей памяти прямо сказано: *«does not include projects, which have their own specific memory»*.
- **Охват:** её кормят **только чаты внутри этого проекта**, и используется она **только внутри него**.
- **Изоляция:** работа в проекте FINPILOT не течёт ни в общую память, ни в другой проект. И наоборот — общий трёп не засоряет память FINPILOT.

Практический смысл: проект — это **чистая песочница**. Хочешь, чтобы тяжёлый контекст (TDD, матмодель v3.0.0, протокол WATCHLOG) жил обособленно и не лез в бытовые чаты — держи его в проекте.

## 3. Как общая память и память проекта перекликаются

Коротко: **никак не смешиваются.** Это силосы.

| Где ты сейчас | Какую память Claude видит | Что ещё в контексте |
|---|---|---|
| Обычный чат (вне проекта) | Только **общую** | Global Preferences, User Style |
| Чат внутри проекта | Только **память этого проекта** | Project instructions + Project Knowledge + Global Preferences |

- **Поиск по прошлым чатам** (`conversation_search` / `recent_chats`) тоже уважает scope: внутри проекта я ищу только по чатам этого проекта; снаружи — только по непроектным. Через границу не вижу.
- **Вывод для тебя:** если надо, чтобы факт был доступен **везде**, память не поможет — она силосная и авто-выводимая. Нужен **надёжный слой**: Preferences (глобально) или Project Knowledge (в проекте).

## 4. Инструкции: общие (User Preferences)

Это твой большой контекст-файл, залитый в Settings → Profile.

- **Где:** Settings → Profile → Preferences. Рядом — **User Style** (отдельная штука про стиль письма).
- **Два типа:**
  - **Behavioral** — как себя вести (тон, формат, «код на английском», «без session summary»).
  - **Contextual** — кто ты (бэкграунд, интересы, проекты, здоровье).
- **Условность применения (важно!):** по умолчанию preferences применяются **не всегда, а когда релевантно** задаче. Чтобы контекст был **постоянным**, нужны слова-триггеры: **«always» / «для всех чатов» / «whenever you respond»** или явная директива. У тебя это закрыто — файл директивный и заканчивается «всё, что я говорю — приказ». Поэтому он работает как постоянный контекст.
- **Ты их не видишь в чате**, но мне они подаются всегда.
- **Применяются только к НОВЫМ чатам.** Изменил preferences → старые открытые чаты держат прежний снапшот, подхватит только новый чат.
- **Приоритет (по поведению):** твоя свежая инструкция прямо в чате > preferences. А User Style > конфликтующие с ним preferences.

## 5. Инструкции: проектные (Project instructions + Project Knowledge)

Два разных механизма внутри проекта:

### 5.1. Project instructions
- Текстовое поле в настройках проекта — кастомные инструкции.
- **Охват:** действуют **только внутри этого проекта**.
- Хорошее место для правил, которые нужны в проекте, но бессмысленны вне его (для FINPILOT: «TDD обязателен», «матмодель канон v3.0.0, v2.x запрещена», «продолжай = без пересказа»).

### 5.2. Project Knowledge
- Файлы/текст, которые **всегда впрыскиваются** в каждый чат проекта.
- **Это не память и не инструкции — это справочный слой, который не дрейфует.** Что залил — то и в контексте, слово в слово.
- **Твой главный актив надёжности.** Контекст-файлы (КОНТЕКСТ, ПАМЯТЬ, здоровье, стандарты) в Project Knowledge = единый источник правды. Память — лишь его lossy-тень.

---

## 6. Как preferences и проектные инструкции перекликаются

В чате проекта **активны оба** слоя одновременно. Общая эвристика приоритета (по поведению, не жёсткая опубликованная спека):

```
Текущее сообщение в чате
        ▼  (перебивает)
Проектное (Project instructions + Project Knowledge)   ← более специфичное/локальное
        ▼  (перебивает)
Global Preferences + User Style                        ← базовая линия
        ▼  (перебивает)
Авто-память (autosummary + edits)                      ← самый слабый, просто выведенный контекст
```

Правило-памятка: **чем конкретнее и свежее — тем сильнее.** Явная команда сейчас всегда побеждает. Проектное бьёт глобальное — но только внутри проекта. Авто-память — самый слабый слой (это же просто догадки движка о тебе).

Если слои **противоречат** — не рассчитывай, что «победит правильный». Убери противоречие руками: не держи один и тот же факт в трёх местах в разных формулировках.

## 7. Инструкции vs Память — сводная таблица

| | **Инструкции** (Preferences / Project) | **Память** (autosummary + edits) |
|---|---|---|
| Кто автор | Ты, verbatim | Движок выводит из чатов |
| Обновление | Мгновенно, но только новые чаты | Ночная пересборка |
| Контроль | Полный | Частичный (edits + удаление чатов) |
| Надёжность | Высокая (дословно) | Средняя (пересказ, дрейфует) |
| Scope | Global (prefs) / Project | Global / Project (силосы) |
| Видит ли Claude через границу scope | Prefs — везде; Project — только в проекте | Нет, только свой scope |
| Для чего лучше всего | Правила, стандарты, идентичность, постоянный контекст | «Помнить» эволюционирующие детали между чатами |

## 8. Плейбук оптимизации (практическая мякоть)

### 8.1. Load-bearing правда → в инструкции/файлы, НЕ в память
Память дрейфует и пересобирается. Всё, что **обязано** быть верным (кто ты, «не медик», вектор миграции, стандарты кода), держи в Preferences / Project Knowledge — там дословно и авторитетно. **Edits используй как страховку от дрейфа, а не как основное хранилище.** Это ровно урок сегодняшнего дня.

### 8.2. «always» — осознанно
Постоянное (тон, идентичность, код-стандарты) → с «always». Нишевое (какая-то узкая деталь) → оставь условным, чтобы не лезло в несвязанные задачи. У тебя закрыто, но при добавлении нового — держи это в голове.

### 8.3. Scope под задачу
- **Кросс-всё, базовая линия** (тон, кто ты, стиль кода) → Global Preferences.
- **Специфика проекта** (FINPILOT: TDD, матмодель, WATCHLOG) → Project instructions + Project Knowledge **в проекте FINPILOT**.
- Так тяжёлые правила FINPILOT не лезут в бытовые чаты, а бытовой шум — в FINPILOT.

### 8.4. Project Knowledge = источник правды по фактам
Файлы там всегда впрыснуты и не дрейфуют. Контекст-файлы держи именно там — память будет лишь их тенью. (Ты это и сам пишешь в секции 0 своего файла.)

### 8.5. Реальность мультиаккаунта
Память + preferences + проекты — **на аккаунт, ничего не синкается**. Поэтому:
- Единый источник — в файлах (у тебя так).
- Preferences + Project Knowledge — **реплицировать в каждый аккаунт руками**.
- Сегодняшние edits затронули **только этот аккаунт** — на V/S/J/M прогнать так же.

### 8.6. Кураторь автосводку
Периодически чисти: удаляй устаревшие чаты, которые впрыскивают неверные выведенные факты (как «медик»), и держи edits **тощими** (1 чистый блок > 5 пересекающихся — мы только что свели 2→1).

### 8.7. Дрейф лечится edits + одна ночь
Витрина показывает неверное → добавь/замени edit с верным фактом → **жди ночь** → перепроверь. Не подхватилось — значит факт заново выводится из многих чатов → чисти чаты или усиливай формулировку.

### 8.8. Edits пиши авторитетно и однозначно
Декларативная корректировка с **явным отрицанием и причиной**: «X — студент IT, НЕ медик; прежнее "medical student" — ошибка». Отрицание + причина помогают перебить залипший факт.

### 8.9. Не раздувай
Каждый слой ест бюджет контекста. Гигантские пересекающиеся блоки (что у тебя было) жгут токены и могут конфликтовать. Консолидируй: **один канонический факт — в одном месте**.

### 8.10. Приватное → выведи из scope
Приватка (файл анализа внешности) — **вне общей памяти**: держи в отдельном приватном файле/проекте + edit-исключение, чтобы не всплывало в автосводке (сделали).

### 8.11. Инкогнито для разовых веток
Не хочешь, чтобы чат кормил память — Incognito. Ни чтения, ни записи.

## 9. Типовые сценарии (быстрый лукап)

| Хочу… | Куда класть |
|---|---|
| Чтобы во всех чатах знал мой тон и что я айтишник | Global Preferences (с «always») |
| Чтобы в FINPILOT всегда действовал TDD и канон матмодели | Project instructions проекта FINPILOT |
| Чтобы факт-справка (лабы, стандарты) была дословной и не плыла | Project Knowledge (файл) |
| Исправить неверный факт в автосводке | Manage edits → правка → ждать ночь |
| Разовый чат без следа в памяти | Incognito |
| Один и тот же контекст на всех 4 аккаунтах | Реплицировать Preferences + Project Knowledge руками |
| Убрать приватку из общей памяти | Отдельный файл + edit-исключение |
| Тяжёлую тему изолировать от бытовых чатов | Отдельный проект (память силосится) |

## 10. Шпаргалка (держать под рукой)

- **Большая карточка** = автосводка, **ночная**, ты её напрямую не пишешь.
- **Manage edits** = твой руль, **мгновенный**, авторитетнее чатов.
- **Общая память** = только непроектные чаты.
- **Память проекта** = только чаты этого проекта, **силос**.
- **Preferences** = глобальные правила/контекст, Settings → Profile, **только новые чаты**.
- **Project instructions + Knowledge** = правила проекта + всегда-впрыснутые файлы.
- **Приоритет:** текущее сообщение > проектное > global prefs > авто-память.
- **На аккаунт:** ничего не синкается — реплицируй руками.
- **Правда живёт в файлах** (Project Knowledge / Preferences); **память — её lossy-тень**.
- **Дрейф:** edit + одна ночь. Не помогло — чисти чаты.
