## 🔴 Урезание лимитов в часы пик: было и снято 06.05.2026

**Факт с датой, проверен по первоисточнику 22.08.2026** (повод — вопрос владельца
«бывает час пик, и лимит кончается быстрее»).

6 мая 2026 Anthropic объявил три изменения разом:

1. **удвоение пятичасовых лимитов** Claude Code для Pro, Max, Team и seat-based Enterprise;
2. 🔴 **снятие урезания лимитов в часы пик** для Claude Code на **Pro и Max**;
3. существенное повышение API-лимитов для моделей Opus.

Поводом названа сделка по вычислительным мощностям (Colossus 1, >300 МВт).

> **Механизм существовал.** До 06.05.2026 утверждение «в час пик лимит кончается быстрее»
> было **правдой для Claude Code Pro/Max**. С этой даты — нет, план даёт ровную ёмкость
> в течение суток.

🔴 **Граница утверждения названа явно:** снято **для Claude Code на Pro и Max**.
Про веб-интерфейс, про остальные планы и про поведение при аварийной нагрузке официальная
формулировка **не говорит ничего** — это «не проверено», а не «нигде нет» (`71` §5г).

**Что из этого следует для планирования расхода.** Три величины, которые под «нагрузкой»
смешивают, ведут себя по-разному:

| Величина | Зависит от нагрузки | Почему |
|---|---|---|
| цена хода в токенах | **нет, по построению** | `cache_read` = размер контекста; это арифметика |
| задержка ответа | вероятно да | очередь и доступная ёмкость — то, что задержка и отражает |
| скорость исчерпания лимита | **зависела до 06.05.2026** | см. выше |

Собственный замер задержки по часам (767 реплик, шесть логов) дал размах ×1.6,
**но атрибутировать его нагрузке нельзя** — часы различаются составом работы.
Разбор и инструмент — `reports/experiments/token-consumption/hypothesis.md` §2, `F10`
и `load_probe.py`.

**Источники:** [объявление Anthropic](https://www.anthropic.com/news/higher-limits-spacex) ·

Допущение блендинга (для $↔токены): типичный ход ~80% вход / 20% выход → **~$9/M** Opus-eq.

- **1% сессии ≈ 2K токенов** (при сессии 200K).

- **Сессий в неделю: ~4–8** (потом упираешься в недельный, а не только в 5ч).

## ⚠️ Известное напряжение в модели (то, что решаем итерациями)

Если Y ≈ 1.2M и выжигать **каждую** неделю полностью → ~5M/мес (~$47 нотально). Но A3 говорит ~$20/мес. Значит одно из двух: (а) полную неделю стабильно выжать нельзя, либо (б) сейчас **промо-инфляция** (недельные подняли +50% до 13.07.2026 — файл 14). После 13 июля недельный, вероятно, **просядет** — это будет первый естественный тест гипотезы (следим за баром «All models» до/после).

## 🎯 Как уточнять (протокол измерения → бинарный поиск)

**Самый точный способ — Claude Code** (показывает и токены, и % лимита в статус-строке):
1. Начни свежую сессию, сделай задачу, прочитай: «использовано N токенов» и «сессия X%».
2. `токенов_на_1% = N / X` → `Сессия = токенов_на_1% × 100`.
3. Аналогично для недельного бара.
Один такой замер **сразу заменяет всю оценку выше точным числом** для твоего аккаунта.

**В вебе/приложении** (только %): косвенно — повторяемая задача известного размера, замеряешь Δ% . Грубее, но работает.

**Бинарный поиск:** держим текущую оценку → каждый замер двигает константу `токенов_на_1%` вверх/вниз → диапазон сужается. 2–3 замера дадут ±10%.

**Что записывать (лог ниже):** дата, модель, что делал, ~токенов (если Code — точно; если веб — оценка), Δ% сессии, Δ% недели. Из накопленного пересчитываем таблицу.
