## 1. Что показывает `/context` (эталон)

В Claude Code команда выводит разбивку вида:

```
Context Usage
claude-haiku-4-5 · 64k/200k tokens (32%)
  System prompt:      2.9k  (1.4%)
  System tools:      14.6k  (7.3%)
  Messages:           1.3k  (0.7%)
  Free space:         136k  (68.1%)
  Autocompact buffer: 45.0k (22.5%)
```

Ценность не в цифре, а в **структуре**: видно, что съели инструменты, что сообщения, сколько
резерва оставлено под автосжатие. Отсюда сразу понятно, чем управлять.

## 2. Почему в вебе так не выйдет — и что делать

Веб-интерфейс расхода не публикует, изнутри разговора его не измерить. Остаётся **оценка по
входу**: мы знаем, что положили в контекст, и умеем это считать.

### Оценочные коэффициенты (практика)

| Что | Расход |
|---|---|
| Русский текст | ~1 токен на 2–3 символа |
| Английский текст / код | ~1 токен на 4 символа |
| Markdown-файл 10 КБ (рус.) | ~4–5k токенов |
| **Страница скана (картинка)** | **~1.5–2k токенов** |
| PDF-страница с текстовым слоем | ~0.5–1.5k |

Отсюда правило, подтверждённое на дневнике: **50 страниц скана ≈ 75–100k токенов** — то есть
источник надо резать примерно по 55 страниц на сессию.

### Скрипт оценки

```bash
# грубая оценка markdown-корпуса
find . -name "*.md" -exec wc -c {} + | tail -1 | awk '{printf "≈ %.0fk токенов\n", $1/2.5/1000}'

# оценка пачки сканов
ls *.jpg | wc -l | awk '{printf "≈ %.0fk токенов (по 1.75k/стр)\n", $1*1.75}'
```

Точнее — библиотекой `tiktoken` (кодировка не совпадает с Anthropic один-в-один, но порядок
величины даёт верно):

```bash
pip3 install tiktoken --break-system-packages
python3 -c "
import tiktoken, sys, pathlib
enc = tiktoken.get_encoding('cl100k_base')
total = sum(len(enc.encode(p.read_text(errors='ignore'))) for p in pathlib.Path('.').rglob('*.md'))
print(f'{total/1000:.1f}k токенов')"
```

## 3. Практические правила бюджета

1. **Диск ≠ контекст.** Вложенный архив ложится на диск; расход появляется только когда файл
   реально прочитан. Поэтому большой пакет — не проблема, а вот `cat` по всему дереву — проблема.
2. **Картинки — самая дорогая статья.** Массовый визуальный проход планируй в свежей сессии.
3. **Читай точечно.** `grep`/`sed -n '1,60p'` вместо `cat` целиком; полностью — только то,
   что действительно нужно целиком (реестр, протокол).
4. **Резерв под запись.** Если сессия должна закончиться правками файлов и сборкой — держи запас,
   иначе упрёшься ровно на финале.
5. **Сжатие ≠ обнуление.** После автосжатия разговор остаётся длинным по накопленному объёму —
   считать бюджет заново «с нуля» нельзя (это ловушка, стоившая нам батча Д-1).

## 4. Автоматизация «без ручного внесения»

Что реально автоматизируется на нашей стороне:

- **Метрика пакета при сборке.** Скрипт релиза печатает оценку токенов пакета — видно заранее,
  влезет ли.
- **Метрика источника перед чтением.** Перед проходом посчитать страницы × 1.75k и сравнить
  с реалистичным окном → сразу понятно, на сколько частей резать.
- **Запись факта в вахтлог.** Сколько страниц прошло до обрыва — эмпирика, которая уточняет
  коэффициенты со временем.

Чего автоматизировать **нельзя**: реального остатка окна изнутри веб-чата. Поэтому планируем
по пессимистичной оценке, а не по факту.

## 5. Протокол замера: без этих правил числа несравнимы

Шесть условий. Нарушено любое — цифры получены, но сравнивать их не с чем.

1. **Чистая сессия на каждый прогон.** История и кэш искажают и токены, и латентность.
2. **Не меньше трёх прогонов на комбинацию.** Один прогон — анекдот, а не замер.
3. **Ровно один параметр за раз.** Модель, усилие, длина промпта, набор коннекторов —
   по одному (тот же OFAT, что `28-empirical-experiment-methodology.md` §4).
4. **Окружение фиксируется:** версия инструмента, включённые коннекторы и плагины, заполнение
   контекста на старте, время суток.
5. **Медиана, а не среднее.** Хвосты латентности длинные, среднее по трём прогонам врёт.
6. **Сырое сохраняется до выводов** — выгрузка в отдельный каталог, потом строка в результаты.
   Иначе пересчитать по-другому уже не получится.

### Что имеет смысл мерить

| Эксперимент | Как | Метрика |
|---|---|---|
| Расход на задачу | `/context` до и после | дельта по категориям |
| Стоимость сессии | `/usage` | деньги, остаток лимитов |
| Латентность по усилию | 5–10 типовых задач, усилие low→max, ≥3 прогона | время до первого токена, полное время, прошли ли проверки |
| Вклад компонентов | baseline, затем поочерёдно отключать коннекторы, плагины, скиллы | дельта в токенах |
| Деградация на длинном контексте | одна задача при 20/40/60/80 % заполнения | корректность, число ошибок |
| A/B формулировок | две версии промпта, ≥3 прогона, изолированные сессии | токены, время, качество по рубрике |
| Активация скилла | эвалы: позитив, негатив, граница; 3 прогона на кейс | precision, recall, доля срабатываний |

### Чего не делать

**Не сравнивать свои числа с чужими напрямую.** Свой контекст, свои коннекторы, своя длина
промптов. Чужие замеры задают **порядок величины и направление**, свои — принимают решение.
