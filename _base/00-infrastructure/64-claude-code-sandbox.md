## 🔴 Чего Claude Code НЕ ограничен — в отличие от браузерной песочницы

**Проверено эмпирически 21.08.2026, не по документации.**

Для песочницы Claude.ai действует правило: **нет твоего токена и нет сетевого выхода
наружу**, поэтому приватная репа недостижима в принципе, а архив в чат нужен затем,
чтобы Claude вообще увидел содержимое. Отсюда разделение труда: *Claude пишет скрипты,
скрипты работают с репами*.

**В Claude Code это ограничение не действует.** Здесь доступен авторизованный `gh`
с токеном владельца:

| Возможность | Браузерная песочница | **Claude Code** |
|---|---|---|
| прочитать приватную репу | нет | **да** (`gh api repos/<owner>/<repo>`) |
| запушить в приватную репу | нет | **да** (`gh api -X PUT …/contents/…`) |
| выпустить релиз, поставить тег | нет | **да** |
| выйти в произвольную сеть | нет | ограниченно, через разрешённые инструменты |

Проверка, которой это установлено: приватная `self-map` читается через API, а три
коммита в `mission-control` за 20.08 сделаны прямо из сессии.

**Что из этого следует для работы.**

- Утверждение «архив в чат — единственный способ показать Claude содержимое» здесь
  **неверно**: он читает репу напрямую. Архив остаётся каноном передачи между сессиями
  (`73-chat-handoff.md`), но по другой причине — он **фиксирует состояние**, а не даёт доступ.
- Разделение «Claude пишет скрипты, скрипты работают с репами» здесь **не обязательное**,
  а **выбранное**: писать в чужую репу можно, но каждая такая запись — необратимое
  действие вовне, то есть стоп-класс (`06-autonomous-mode-kit/STANDARD.md` §2).
- **Опасность ровно в этом.** Сессия, унаследовавшая привычки браузерной песочницы,
  недооценивает свои права: команда, которая там была бы безобидной попыткой,
  здесь **меняет живую репу на GitHub**.

> Источник ограничения: `mission-control/00-infrastructure/17-gh-automation.md` §1 —
> верно для своей среды, **не переносить на Claude Code**. Класс PIT-063: документ
> описывает состояние, которое перестало быть общим.

## 🔴 Рабочая ФС эфемерна: это планируемое условие, а не авария

Раздел выше сравнивает песочницы по правам. Есть свойство, общее для обеих и куда более
дорогое на практике: **рабочий каталог может исчезнуть между ходами**, без предупреждения
и без ошибки.

Из `portrait-of-taste/standards/WORKSPACE_CONTINUITY_PROTOCOL.md` и `RESTORATION_PROTOCOL.md`,
где цена названа числом:

> «Файловая система между сессиями и абортами может сбрасываться. **За неделю потерял
> ~30 % времени на переработку.**»

Подтверждено независимо в `character-a-analysis`: две выжимки сессий сообщают, что
«среда исполнения **сброшена между ходами** — рабочие каталоги пусты, исходные файлы
недоступны для повторного замера» (`23-session-continuity.md` §5в).

### Три правила, которые это закрывают

**1. Проверка живости — первая команда сессии.** Не «начать работать и заметить»,
а один `ls` по ожидаемому пути с известным числом файлов. Пусто — восстанавливаемся,
и только потом работаем.

**2. Восстановление из последнего архива — часть протокола, а не импровизация.**
Порядок записан заранее: откуда брать, чем распаковывать, чем проверять целостность.
Импровизировать в момент, когда рабочий каталог уже пуст, — худшее время для решений.

**3. Критичный актив не живёт в эфемерном каталоге.** Всё, от чего зависит **воспроизведение
результата** — шаблоны оформления, скрипты-генераторы, эталонные образцы, тесты и гейты —
лежит **в репе**, а `/tmp` и рабочие каталоги считаются одноразовыми по построению.

> **Критерий:** если файл придётся писать заново, когда каталог опустеет, — он не рабочий
> черновик, а актив, и его место в репе.

### Почему это ошибка планирования, а не невезение

Сброс не является сбоем: среда **так устроена**. Работа, которая его не предусматривает,
теряет время **систематически**, и потеря выглядит как «пришлось переделать» —
то есть не опознаётся как один повторяющийся дефект. Именно поэтому она и накопилась
до трети недели, прежде чем была замерена.

**Родня:** `23-session-continuity.md` §3 (чекпоинт-дисциплина), §5в (в отчёте о себе
помечается, что уже нельзя перепроверить) · `43-archive-naming-and-packaging.md` (канон архива) ·
`00-CLAUDE-STOP.md` (массовые операции недеструктивны по построению).
