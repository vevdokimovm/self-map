# 29 — Claude на практике: что реально работает

> Практический репорт, а не теория. Это набитые в реальной работе приёмы: как вести
> knowledge-репы через Claude, где спотыкаешься, что ускоряет. Дополняет
> `02-claude-workflow.md` (там правила и лимиты) — здесь живой опыт и рабочие паттерны.

---

## 1. Главный принцип: Claude видит репу целиком, пока она лёгкая

Это не абстракция, а то, от чего зависит качество каждого ответа.

- Репа влезает в контекст (≈200K токенов) → Claude держит всю картину, отвечает точно,
  ловит связи между файлами.
- Репа переросла → включается RAG, Claude видит только выборочные куски, «слепнет» на
  общую структуру, начинает путать и терять контекст.

**Вывод, который проверен на деле:** сжатие в `.md` — не косметика, а условие того, что
Claude вообще полезен на большой репе. 700 МБ архива он не осилит; 50 МБ конспектов —
видит целиком.

---

## 2. Что реально ускоряет работу

### Загружай контекст один раз — в Проект, не в чат
Проект кэширует материалы и не жрёт лимиты при переиспользовании. Правила репы
(инфраструктуру) кладёшь в knowledge проекта один раз — и любой чат внутри уже их знает.
Не пересказывай контекст в каждом новом чате.

### Механику — скриптом, смысл — глазами
Разделение труда, которое экономит уйму времени и токенов:
- **Механика** (переименование, сжатие картинок/PDF, чистка мусора, поиск дублей) —
  Claude пишет скрипт, прогоняет разом по всей репе. Быстро, надёжно, не жрёт контекст
  на каждый файл.
- **Смысл** (конспект рукописи, разбор что важно/что вода) — только чтение глазами,
  файл за файлом. Тут скрипт не поможет.

### Набранный текст vs рукопись — разные инструменты
- PDF с **набранным текстом** (Creator: Pages/Word) → извлекается инструментом
  мгновенно и чисто, конвертируется в `.md` скриптом. Проверка: `pdftotext file.pdf -`
  выдаёт связный текст — значит текстовый.
- PDF-**скан рукописи** → только чтение глазами (OCR почерк берёт плохо). `pdftotext`
  выдаёт пусто/мусор — значит скан.

### Пачками, с ранними коммитами
Большую ревизию гони пачками по 5–15 файлов, между пачками — коммит. Причина: сессия/
токены кончаются внезапно, а закоммиченное не теряется. Продолжишь с той же точки.

## 3. Набитые шишки (чтобы не наступать снова)

### Скачивание больших файлов из чата падает
claude.ai не отдаёт на скачивание файл-гигант. Решение: не тащить архив туда-сюда, а
**собрать результат скриптом локально** — скачать только скрипт на 20 КБ, он соберёт всё у
тебя. Или дробить на части < ~300 МБ.

### Юникод в именах файлов (macOS)
macOS хранит имена в NFD-нормализации («й» = «и» + separate accent). Bash-циклы по таким
именам спотыкаются. Решение: обработку делать через Python (`pathlib` дружит с юникодом),
а не через `for f in *`.

### Дельта-сжатие не берёт уже сжатое
PDF-сканы, JPEG, MP4, docx уже сжаты внутри. Прогонять их через ещё одно сжатие
бессмысленно. Для сканов работает только **пересжатие растра** (рендер страниц в меньший
dpi), а не «оптимизация PDF». Для docx/pptx — только конспект в `.md`.

### История git хранит всё навсегда
Удалил тяжёлый файл в новом коммите — он всё ещё в истории, качается при каждом клоне.
Поэтому тяжёлое не должно попадать в репу **вообще**, а не «удалим потом». Детали —
`10-git-reference.md`.

## 4. Рабочие паттерны для типовых задач

### Собрать репу из кучи архивов
1. Claude распаковывает всё во временную папку, чистит мусор (`__MACOSX`, `.DS_Store`,
   артефакты сборки `bin/`/`obj/`/`.exe`).
2. Показывает предложенную структуру с точками решения → ты одобряешь.
3. Раскладывает по разделам, отсеивает чужое/личное/секреты.
4. Отдаёт архив + build-скрипт (чтобы пересобрать локально, если скачивание падает).

### Сжать репу до нормы
1. Замер: где реально вес (по типам файлов). Часто не там, где кажется.
2. Бей по деньгам: сначала самое тяжёлое (несжатые TIFF, раздутые PNG, сканы), потом
   мелочь.
3. docx/pptx → конспекты `.md` (подробные: все таблицы, код, цифры).
4. Финальный замер + проверка что ничего не превысило лимит.

### Конспект тяжёлого документа
Правило: переносится **всё содержательное** (тезисы, таблицы как md-таблицы, код в
fenced-блоки, формулы, числа, выводы), опускается только вода (титульники, колонтитулы,
форматирование). Не «краткий пересказ», а полный перенос смысла минус мусор.

## 5. Модель и усилие под задачу (кратко)

Две независимые ручки — модель (кто думает) и effort (сколько думает):

- **Конспект рукописи, разбор смысла** → сильная модель (Opus), высокий effort. Чтение
  изображений + осмысление требуют мощности.
- **Механика** (скрипты, переименование, сжатие) → рабочая модель (Sonnet), средний
  effort хватает.
- **Мелочь** (обновить журнал, поправить ссылку) → лёгкая модель (Haiku), низкий effort.

Модель ты переключаешь пикером сам; Claude её не крутит, но на старте задачи может
подсказать оптимальную.

---

## 6. Дисциплина сессий

- **Закрытую тему — в новый чат.** Гигантская сессия дорожает с каждым ответом
  (перечитывается вся история) и быстрее упирается в лимиты.
- **Актуальные факты о продукте** (модели, цены, лимиты) — не по памяти, а по докам:
  системный контекст тоже отстаёт от свежих релизов.
- **Журнал по ходу, не в конце** — если прервёшься, контекст не потеряется
  (`04-watchlog-protocol.md`).
