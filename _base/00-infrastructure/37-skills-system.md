# 37 — Система скиллов Cowork (не путать с личным `Skills.md`)

> **Что это и зачем.** Скилл в Cowork — это **упакованный сценарий**, который Claude подгружает и
> выполняет по команде `/name` или когда тема совпала. У скилла своя папка с `SKILL.md` (инструкция) и
> ресурсами (шаблоны, шрифты, скрипты). Это не «поведение Claude вообще», а конкретный воспроизводимый
> рабочий процесс. Документ разводит **две разные вещи с похожим именем** и объясняет, как скиллы устроены
> и как сделать свой.
>
> Кластер: плагины (бандлы скиллов) — `36`, поверхности (где скиллы работают) — `26`, артефакты/дизайн
> (что многие скиллы производят) — `38`, карта тулов — `40`.

---

## 0. Дисклеймер имени: два «Skills», не смешивать

| «Skills» | Что это | Где живёт |
|---|---|---|
| **Мой `Skills.md`** | Мои личные правила поведения Claude (как писать код, что не делать) | кит `01-claude-context/02-instructions/Skills.md` — это `@import`-механизм Cowork |
| **Система скиллов Cowork** (этот док) | Платформенные вызываемые скиллы `/name` с `SKILL.md` | Настройки → Skills; внутри плагинов; примеры Anthropic |

Дальше «скилл» = **платформенный скилл Cowork**, не мой файл.

---

## 1. Одной строкой

Скилл = **папка с `SKILL.md` + ресурсы, которую Claude грузит по релевантности или по `/name`, чтобы
выполнить конкретный сценарий стандартно и хорошо**.

---

## 2. Как скилл устроен и как грузится

- **`SKILL.md`** — инструкция скилла (что и как делать), плюс рядом ресурсы: шаблоны, шрифты, скрипты,
  референсы. Пример из этой сессии: скилл `morning` держит `assets/fonts/…woff2` (шрифт для брифа) прямо в
  своей папке — берётся оттуда, без сети.
- **Загрузка по релевантности.** Скиллы работают на всех поверхностях и грузятся **только когда тема
  совпала** (до нескольких сразу). Поэтому они **токен-эффективнее** длинных always-on инструкций: не
  висят в контексте, пока не нужны (`26` §1).
- **Вызов явный.** `/name` (или `/plugin:name` для плагинных) — прямой запуск. `Skill`-тул подгружает
  инструкции скилла в текущий ход.
- **Порядок операций (важно для output-скиллов):** сначала СБОР материала (веб/коннекторы/чтение),
  **потом** чтение `SKILL.md` формата-вывода. Читать `docx/xlsx/pptx/pdf`-SKILL.md до того, как собран
  контент, — ошибка: якорит на механике документа раньше фактов.

---

## 3. Виды скиллов (по назначению)

| Вид | Примеры | Зачем |
|---|---|---|
| **Output-формат** | `docx`, `xlsx`, `pptx`, `pdf` | Собрать качественный файл-deliverable в нужном формате |
| **Доменные (из плагинов)** | `/engineering:code-review`, `/engineering:debug` (`36`) | Роль-специфичные сценарии |
| **Дизайн/визуал** | `dataviz`, `canvas-design`, `algorithmic-art`, `theme-factory`, `web-artifacts-builder` | Графика, чарты, арт, темы, сложные HTML-артефакты (`38`) |
| **Рабочие процессы** | `morning`, `doc-coauthoring`, `deep-research` | Многошаговые повторяемые процессы |
| **Мета-скиллы** | `skill-creator`, `cowork-plugin`, `mcp-builder`, `setup-cowork` | Создавать сами скиллы/плагины/коннекторы |

## 4. Сделать свой скилл

Инструмент — **`skill-creator`** (создать с нуля, отредактировать, оптимизировать описание под точность
срабатывания, гонять эвалы). Когда полезно тебе:

- **`/finpilot-test`** — «напиши тест по нашему TDD: red-тест → имплементация → гейты (coverage ≥90%,
  flake8=0)». Один раз оформил скиллом — вызываешь `/finpilot-test` вместо того, чтобы каждый раз
  диктовать протокол.
- **`/repo-revision`** — ревизия knowledge-репы по `21` (живое vs замороженное, оси, `revision_check.py`).
- **`/situation-report`** — ситуация-репорт по формату `reports/situations/` (`19`).

Ключ к срабатыванию — **описание скилла** (`description`): именно по нему Claude решает, грузить ли скилл.
Пиши в нём явные триггеры («когда пользователь просит X / упоминает Y»). `skill-creator` умеет это
оптимизировать и мерить.

> Разница со сборкой плагина (`36`): скилл — **один сценарий**; плагин — **набор** скиллов+коннекторов под
> роль. Свой скилл можно потом вложить в свой плагин.

---

## 5. Чек-лист

1. Повторяю один и тот же сценарий руками? → оформить **скиллом** (`skill-creator`).
2. Нужен файл-deliverable (docx/xlsx/pptx/pdf)? → сначала собрать контент, **потом** читать output-SKILL.md.
3. Описание скилла содержит явные триггеры срабатывания?
4. Скилл общий для всех аккаунтов? → внести в репу/плагин, развернуть везде.
5. Не путаю с личным `Skills.md` (это `@import`-инструкции, не платформенный скилл)?
