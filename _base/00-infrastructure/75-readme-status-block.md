# 75 — Блок статуса в README: репа отвечает «что сейчас» за десять секунд

> **Зачем.** README — первое, что открывается, когда нужно быстро понять, что в репе
> происходит. Но обновляют его последним, а забывают чаще всего: версия ушла вперёд,
> реестр пополнился, кампания сдвинулась — README всё ещё описывает состояние
> трёхнедельной давности.
>
> Дефект тихий и потому опасный: файл читается, выглядит правдой, просто правда в нём
> устарела. Это тот же класс, что PIT-063 (документация называет каноном то, что каноном
> быть перестало) и `72-source-of-truth.md` — производное разошлось с источником.
>
> **Решение — не «помнить», а гейт.** Правило, которое держится на внимательности,
> заканчивается в два часа ночи на пятнадцатом коммите (`32-git-hooks-and-secret-scanning.md`).

---

## 1. Контракт

**Источник правды — файл `VERSION`.** Блок статуса в README производен и обязан с ним
совпадать. Блок — ровно один, сразу после заголовка репы:

```markdown
<!-- STATUS -->
> **Сейчас:** `v1.61.0` · 2026-08-20 · Одна строка: что происходит прямо сейчас.
> Открытое — [`ROADMAP.md`](ROADMAP.md) · на владельце — [`TASKS.md`](TASKS.md).
<!-- /STATUS -->
```

| Часть | Что значит | Кто заполняет |
|---|---|---|
| `` `vX.Y.Z` `` | текущая версия репы | гейт (`--fix`) |
| `ГГГГ-ММ-ДД` | когда состояние снималось | гейт (`--fix`) |
| описание | **одна живая строка: где репа стоит прямо сейчас** | человек или вахта |
| вторая строка | ссылки на `ROADMAP` / `TASKS` / журнал | заводится один раз |

**Описание — единственная часть, ради которой всё это существует.** Механику
(номер и дату) проставляет скрипт; смысл автоматически не проставляется никак.

---

## 2. Почему описание нельзя генерировать

Соблазн очевидный: взять верхнюю запись `CHANGELOG.md` и подставить. Так делать нельзя —
и вот почему.

`CHANGELOG` отвечает на вопрос **«что изменилось в этой версии»**, а блок статуса —
на вопрос **«где репа стоит»**. Это разные вопросы, и в момент, когда они расходятся,
автоподстановка даёт правдоподобный, но неверный ответ: версия про правку одного
документа, а репа в середине шестифазной кампании.

Поэтому `--fix` правит номер и дату и **явно предупреждает**, что описание осталось
нетронутым. Формально гейт после этого зелёный — но только если описание и правда
всё ещё верно; проверить это может лишь тот, кто знает состояние.

---

## 3. Что проверяет гейт

`scripts/readme_status_gate.py` — stdlib-only, без зависимостей.

```bash
python3 scripts/readme_status_gate.py          # проверить
python3 scripts/readme_status_gate.py --fix    # проставить версию и дату
python3 scripts/readme_status_gate.py --staged # режим pre-commit
```

| # | Проверка | Что ловит |
|---|---|---|
| 1 | блок есть и разбирается | README без статуса вообще; статус, переписанный в вольной форме |
| 2 | версия в блоке == `VERSION` | README отстал от репы |
| 3 | дата — валидный ISO и не из будущего | опечатка в дате, скопированная будущая дата |
| 4 | описание — не плейсхолдер | шаблон завели и не заполнили |
| 5 | `VERSION` в коммите → `README.md` тоже, **и описание отличается от прошлого** | ровно тот дефект, ради которого всё написано |

**Пятая проверка — главная.** Без неё «обновление README» вырождается в правку одной
цифры: номер новый, текст прежний, несвежесть та же. Гейт сравнивает описание с версией
из `HEAD` и требует, чтобы оно изменилось.

**На обычных коммитах гейт молчит** — срабатывает, только если в индексе `VERSION`
или `README.md`. Гейт, который мешает всегда, обходят через `--no-verify`, и тогда
он не защищает вовсе.

## 4. Где включено

| Место | Роль |
|---|---|
| `.githooks/pre-commit` → `check_readme_status()` | пятый класс проверок, срабатывает сам |
| `scripts/readme_status_gate.py` | сам гейт, запускается и вручную |
| `tests/test_readme_status.sh` | 28 проверок, 6 зон: разбор · версия · дата · описание · `--staged` · `--fix` |
| `templates/REPO_README_TEMPLATE.md` | блок в шаблоне — новые репы получают его сразу |

Включение хука в репе — одной командой, как и всё остальное
(`32-git-hooks-and-secret-scanning.md`):

```bash
git config core.hooksPath .githooks
```

## 5. Как это выглядит в работе

Поднимаешь версию — гейт останавливает коммит:

```
🟠 README ОТСТАЁТ ОТ РЕПЫ — остановлено

   версия поднята, но описание в блоке статуса не изменилось:
      «Идёт кампания «большой синтез»: пройдено 4 репы из 57.»
      Смена цифры без смены текста оставляет README таким же несвежим, каким он был
```

Порядок действий: `--fix` проставляет номер и дату → перечитываешь строку описания →
переписываешь её под текущее состояние → коммит проходит.

## 5а. 🔴 Гейт держит блок статуса. Числа в теле README он не видит

Замер 21.08.2026, найдено на самом README базы: блок статуса был свежим и проходил гейт,
а **тело врало по шести числам сразу**:

| Утверждение в теле | Было | На диске |
|---|---|---|
| документов `00-infrastructure` | 75 | **78** |
| исполняемых инструментов | «девять» | **десять** |
| проверок в наборах тестов | 274 / 32 | **279 / 36** |
| классов в `pre-commit` | «пять» | **четыре** (перечислено тоже четыре) |
| карточек в реестре граблей | 88 | **97** |

Механика та же, что у PIT-091: **число правится руками, а его правка не требуется
ни одним гейтом**. Блок статуса под защитой — и это создаёт ложное ощущение, что
защищён весь файл.

**Что с этим делать:**

1. **Числа в теле README — кандидаты на устаревание по умолчанию.** При ревизии они
   проверяются командой, а не глазами: `ls | wc -l`, `grep -c`.
2. **Где можно — не писать число, а писать способ его получить.** «Все документы кита»
   не устаревает; «75 документов» устаревает на следующей неделе.
3. **Расхождение числа с диском — не мелочь.** Читатель по нему **принимает решения**:
   «88 карточек» намекает, что реестр небольшой, и его можно пробежать целиком.

> **Правило шире README:** любое **число в прозе** — это снимок, сделанный однажды.
> Либо у него есть гейт, либо оно устареет; третьего не бывает.

## 5б. 🆕 README каталога: два слота — что здесь есть и что здесь намеренно ещё не выросло

§1 держит статус **репы**. У **каталога** статуса нет, и это заметная дыра: человек,
открывший папку, видит список файлов и не понимает, полон он или обрублен.

Из `christ-walk`, где все одиннадцать зон написаны по одной форме и она работает:

```markdown
# 03 — Молитвы
Молитвослов и личные молитвы на каждый день.

**Здесь:** основные молитвы, Оптинские старцы, Псалом 91, мини-молитвы,
личные — о деле жизни, о ясности ума, перед испытанием.

**Растить:** святоотеческие толкования, разные интерпретации ключевых мест, догматика.
```

Три строки: **назначение · что лежит сейчас · куда раздел растёт**.

### Зачем второй слот — он и есть весь смысл

> **«Растить» отличает «тут пусто, потому что не дошли руки» от «тут пусто, потому что
> раздел молодой, и вот его вектор».** Без этой строки оба состояния выглядят одинаково,
> и разбирающий не знает, дописывать сюда или сворачивать каталог.

Это **читательская сторона `ROADMAP`**. Роадмап отвечает на вопрос «что делать дальше»
тому, кто пришёл работать; строка «Растить» отвечает на вопрос «что здесь будет» тому,
кто просто открыл папку. Одно не заменяет другое: в роадмап не пишут по пункту на каждый
каталог, а в каталог не переносят приоритеты.

### Правила слота

1. **«Растить» — про содержание, а не про задачи.** «Жития по дням, избранные святые» —
   да. «Разобрать бэклог» — нет, это `ROADMAP`.
2. **Пустой раздел обязан иметь слот «Растить».** Каталог с одним `.gitkeep` и без него —
   это занятое имя, а не раздел (тот же критерий, что у скелета в `83` §1).
3. **Слот не обещает срок.** Он называет направление; сроки живут в приоритетах.
4. **Слот стареет молча.** Ревизия сверяет: то, что перечислено в «Здесь», лежит
   в каталоге; то, что доросло, переезжает из «Растить» в «Здесь».

📍 **Почему форма выдержала в десяти зонах подряд.** Она короткая и в ней нет поля,
которое нечем заполнить: назначение есть всегда, содержимое видно глазами, направление
знает тот, кто заводил раздел. Форма, у которой пустует поле, перестаёт заполняться целиком.

**Родня:** §1 (статус репы) · `83` §1 (критерий выхода из скелета — тот же приём
на уровне репы) · `45-roadmap-and-tasks.md` · `01-repo-standard.md`.

## 5в. 🆕 🔴 Переименование структуры чинит ссылки и не чинит прозу

§5а знает, что гейт держит блок статуса и **не видит чисел в теле README**. Есть случай
хуже чисел: README называет каталоги, **которых больше нет**.

Из `health-vault`, проверено командой 22.08.2026:

| README обещает | На диске |
|---|---|
| `01_Анализы/` · `02_Генетика/` · `04_Психиатрия_ПНД/` … | `01-lab-tests/` · `02-genetics/` · `04-psychiatry-pnd/` … |

**Все десять путей мертвы.** Репу переименовали в kebab-case латиницей, а таблицу структуры
в README — нет. Заодно устарели и числа: «Всего: 255 файлов» при фактических 276 своих.

### Почему это переживает любое переименование

> **Таблица каталогов в README — это проза, а не ссылки.** Инструмент переименования
> правит пути в коде и относительные ссылки в разметке; строка `` `01_Анализы/` `` в клетке
> таблицы для него — обычный текст в обратных кавычках. Он его не трогает и не обязан.

Хуже того, README **выглядит исправным**: таблица на месте, форматирование целое, описания
верные по смыслу. Сломана единственная вещь, которую глазами не проверяют, — **соответствие
имён реальности**.

📍 **И это не одноразовая оплошность.** Тот же класс уже ловился в этой системе:
«тело README врало шестью числами». Числа и имена стареют по одной причине — **они описывают
состояние, а живут в документе, который правят по другому поводу**.

### Проверка — механическая, одной командой

Каждый путь, названный в README, обязан существовать:

```bash
grep -o '`[0-9A-Za-z_][^`]*/`' README.md | tr -d '`' | while read d; do
  [ -e "$d" ] || echo "МЁРТВЫЙ ПУТЬ: $d"
done
```

**Правило.** Переименование структуры — это операция **над двумя объектами**: над файловой
системой и над прозой, которая её описывает. Второй не чинится первым, и его чинят руками
в том же заходе, иначе он не чинится никогда.

**Родня:** §5а (числа в теле) · `80` §5 (массовый скрипт теряет работу молча) ·
`21` §4б · `01` §2а.

## 6. Границы

- Гейт **не проверяет содержательную верность** описания — только что оно есть, не
  плейсхолдер и изменилось вместе с версией. Верность держится на вахте.
- Гейт **не требует README при коммитах без подъёма версии**. Если репа живёт долго
  без релизов, README стареет молча — за это отвечает ревизия
  (`21-revision-protocol.md`), а не хук.
- Репа без `VERSION` гейтом не покрывается: сверять не с чем. На 20.08.2026 таких
  из 57 — девять.
