# MCP: что это, стал ли стандартом, сколько стоит

**Исследование 02.09.2026** по прямому вопросу владельца: *«давай ресёрч
по MCP-серверам — что это вообще и как можно использовать»*.

---

## §0. Прямой ответ

**MCP — открытый протокол Anthropic (анонс 25.11.2024)**, заменяющий проблему
M×N интеграций одним интерфейсом «агент ↔ инструмент».

**На сентябрь 2026 это уже не экосистема одной компании.** 09.12.2025 Anthropic
передала протокол в **Agentic AI Foundation под Linux Foundation**, где
платиновыми членами стоят её прямые конкуренты: AWS, Google, Microsoft, OpenAI,
Bloomberg, Cloudflare, Block
([пресс-релиз LF](https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation)).

Вкладываться стоит.

---

## §1. 🔴 Самоисправление: посылка про «грузится в каждую сессию» устарела

Заказывая исследование, я исходил из того, что каждый подключённый MCP-сервер
грузит описания своих инструментов в контекст **каждой сессии** целиком.
На этом основании я объявил отключение сервера Pencil важнее удаления
самого приложения.

**Это верно как механика протокола и неверно для нашей установки.**

Из официальной документации: `ENABLE_TOOL_SEARCH` по умолчанию **`true`**
начиная с **v2.1.232** — Claude Code «использует `ToolSearch` для поиска
релевантных инструментов перед обработкой запроса, вместо загрузки списков
инструментов всех серверов» ([code.claude.com/docs/en/mcp](https://code.claude.com/docs/en/mcp)).

**Проверено на этой машине 02.09.2026:** версия **2.1.258**, флаг нигде
не переопределён. Механизм работает.

> **Что это меняет.** Двенадцать инструментов Pencil не грузились целиком
> в каждую сессию — они лежали в индексе поиска. Экономия от отключения
> **меньше**, чем я утверждал.
>
> **Решение отключить остаётся верным, но по другой причине** (§5): Pencil
> работал как stdio-сервер, то есть локальный процесс с правами пользователя,
> и любое его обновление — исполняемый код на машине **без нового
> подтверждения**.

Отключается Tool Search только тремя способами: явным `ENABLE_TOOL_SEARCH=false`,
кастомным `ANTHROPIC_BASE_URL`, либо на старых моделях в чужих облаках.

## §2. Что происходит технически

**Архитектура host → client → server** поверх JSON-RPC. Host — само приложение
(Claude Code): держит разрешения и безопасность. Client — по сессии на сервер.
Server — отдаёт возможности и **не видит ни весь диалог, ни другие серверы**.

Что происходит при подключении:

1. клиент шлёт `initialize` — версию протокола и свои возможности;
2. сервер отвечает списком возможностей;
3. клиент шлёт `notifications/initialized` — до этого ничего, кроме ping;
4. клиент вызывает `tools/list` → массив `name`, `description`, `inputSchema`;
5. **хост переводит каждый объект в формат tool-definition своего API**
   и кладёт в поле `tools` запроса к модели;
6. модель решает вызвать → `tools/call` → результат в контекст.

🔴 **Шаг 5 в спецификации MCP не описан вообще** — это зона ответственности
хоста. И именно там сидит цена: Messages API стейтлес, поэтому набор
определений пересылается заново **при каждом обращении к модели**.

Anthropic формулирует прямо: *«tool results and definitions can sometimes
consume 50,000+ tokens before an agent reads a request»*
([anthropic.com/engineering/code-execution-with-mcp](https://www.anthropic.com/engineering/code-execution-with-mcp)).

**Три примитива сервера:** `tools` (действия), `resources` (данные),
`prompts` (шаблоны). Почти вся нагрузка — в `tools`.

**Актуальная ревизия — 2026-07-28**: stateless protocol core, Multi Round-Trip
Requests, формальный Extensions framework, политика депрекации с минимум
12 месяцами на миграцию.

## §3. Стандарт — да, и вот доказательства

**Цифры на дату донации** (первоисточник Anthropic): свыше **97 млн загрузок
SDK в месяц**, свыше **10 000 активных серверов**, поддержка «первого класса»
в ChatGPT, Claude, Cursor, Gemini, Microsoft Copilot и VS Code.

**По вендорам:**
- **OpenAI** — поддержка с марта 2025; в феврале 2026 ChatGPT стал совместим
  со спецификацией **MCP Apps**, то есть OpenAI строит свои приложения поверх
  открытого стандарта, а не проприетарного. Старые ChatGPT plugins мертвы;
- **Google** — платиновый член; **Chrome DevTools MCP делает и поддерживает
  сама команда Chrome DevTools** (48 релизов);
- **Microsoft** — платиновый член; нативная поддержка в Windows 11 анонсирована
  на Build 2025, статус GA не проверен;
- **Meta и xAI** — источников не найдено ни в ту, ни в другую сторону.
  Отсутствие данных, а не отсутствие поддержки.

**Конкурирующих протоколов на территории MCP фактически нет.** Google A2A
решает другую задачу (агент↔агент) и сам передан в Linux Foundation;
IBM/BeeAI ACP слит в A2A и объявлен легаси. Консолидация идёт в связку
**MCP (инструменты) + A2A (агенты)** под одним фондом.

### 🔴 Признаки обратного — названы, а не сглажены

Статья «MCP is dead. Long live the CLI» вышла на первую полосу Hacker News;
Thoughtworks Technology Radar поместил «наивную конвертацию API в MCP»
в кольцо **Hold**. Претензии конкретные: MCP-сервер БД со 106 инструментами
тратит 54 600 токенов только на инициализацию.

Но официального отказа, форка или миграции индустрии на альтернативу нет,
а бэклэш идёт преимущественно от разработчиков, оптимизирующих личный
CLI-workflow.

**Самая слабая часть стандартизации:** официальный MCP Registry, запущенный
в preview 08.09.2025, судя по всему **до сих пор в preview** — дата GA
не найдена ни в одном источнике.

## §4. Цена в токенах — измеренная

| Что измерено | Число | Источник |
|---|---|---|
| 50+ инструментов, до/после Tool Search | **72 000 → 8 700** (−85 %) | Anthropic, 24.11.2025 |
| точность выбора инструмента | Opus 4: 49 %→74 %; Opus 4.5: 79.5 %→88.1 % | там же |
| Programmatic Tool Calling | 43 588 → 27 297 (−37 %) | там же |
| code execution, один кейс | **150 000 → 2 000** (−98.7 %) | Anthropic, 04.11.2025 |
| Claude Code: все MCP vs отобранные | **82 000 (41 % окна) → 5 700 (2.8 %)** | независимый замер, 30.09.2025 |
| Playwright MCP, 21 инструмент | ≈13 647 токенов | там же |

**Рычаги, кроме Tool Search:**
- `MCP_DISCOVERY_CACHE` — список инструментов удалённого сервера из кэша,
  сам сервер подключается при первом вызове. 🔴 **По умолчанию `false`
  начиная с v2.1.238** — то есть у нас выключен, включается как
  `MCP_DISCOVERY_CACHE=1 claude`;
- `MAX_MCP_OUTPUT_TOKENS` — ограничение результата, по умолчанию 25 000;
- `/mcp` — панель: статус, **число инструментов на сервер**, отключение;
- `/context` — показывает строку MCP tool listing.

🔴 **Публичных замеров для наших десяти серверов не существует.** Единственный
достоверный путь — `/context` в реальной сессии и `/mcp` для числа инструментов.

## §5. Что стоит подключать, а что нет

**MCP решает хорошо ровно два класса задач:**

1. **доступ к сервису без CLI и с OAuth** — Notion, Linear, Gmail, Calendar,
   Miro, Gamma. Альтернативы нет;
2. **интерактивные сессии с состоянием** — браузер, отладчик, REPL.
   Здесь есть измерение, противоречащее модному «CLI всегда лучше»: в бенчмарке
   из 120 прогонов MCP-версия оказалась **на 23 % быстрее и на 39 % дешевле**
   на сложной задаче; CLI выигрывал только на простых одношаговых (10-22 %).
   Причина: MCP держит одно соединение, CLI платит оверхед подпроцесса
   на каждый вызов.

**MCP решает плохо:**

- **всё, у чего уже есть CLI** — `git`, `gh`, `aws`, Semgrep. Оборачивать
  значит платить токенами за то, что Bash делает бесплатно;
- 🔴 **локальные Markdown-файлы.** Для системы из 63 репозиториев MCP-сервер
  **не нужен вообще**: типовой Obsidian-сервер несёт ~17 инструментов ради
  того, что `Read`/`Grep`/`Glob` делают быстрее и без единого токена
  определений. **Это закрывает открытый вопрос из `97-claude-code-capabilities.md`**;
- **массивные выгрузки** — потолок 25 000 токенов, дальше файл на диске;
- **всё, чем пользуешься реже раза в неделю.**

### Разбор наших серверов

| Сервер | Вердикт |
|---|---|
| Chrome DevTools | держать — официальный Google, незаменим для веб-интерфейсов |
| Notion, Linear, Gmail, Calendar | держать — классический «OAuth-сервис без CLI» |
| Exa | держать, если веб-поиск нужен глубже встроенного |
| **Semgrep** | кандидат на замену CLI — у него есть полноценный CLI |
| Gamma, Miro | держать, но включать под задачу: низкочастотные |
| **Google Drive** | отключить — по базе «подключён, но пусто» |
| Pencil | отключён верно (§1) |

Рекомендация сообщества: **3-6 активных серверов**, деградация выбора
начинается после 10-15.

## §6. Безопасность

**Что видит сервер:** на каждый вызов только имя инструмента и JSON-аргументы.
Диалог и системный промпт — **нет**.

**Но это половина картины.** Сервер контролирует два канала, которые модель
воспринимает как доверенный контекст: **текст `description` своего инструмента**
и **содержимое `tool_result`**. Отсюда весь класс атак.

Плюс: **stdio-сервер — процесс на вашей машине с вашими правами** (файлы,
переменные окружения, сеть, иногда ключи из связки). Удалённый сервер держит
ваш OAuth-токен со всем его scope в чужой инфраструктуре.

### Подтверждённые инциденты

| Дата | Что |
|---|---|
| май 2025 | **GitHub MCP**: prompt injection через публичный issue → утечка приватных репозиториев. Архитектурная проблема, полного фикса нет |
| июнь 2025 | MCP Inspector, **CVE-2025-49596**, CVSS 9.4 — RCE |
| июнь 2025 | **Asana MCP**: cross-tenant утечка, ~1000 клиентов |
| июль 2025 | **mcp-remote, CVE-2025-6514**, CVSS 9.6 — RCE, 437 000+ загрузок |
| июль 2025 | **CVE-2025-54136** — «rug pull»: одобрение описания инструмента **не переживает изменений на стороне сервера** |
| сен. 2025 | **postmark-mcp backdoor**: 15 «чистых» релизов для набора доверия, потом BCC всех писем атакующему |
| апр. 2026 | системный флав **во всех официальных SDK**: stdio исполняет команду независимо от легитимности сервера; 150 млн+ загрузок |

⚠️ Часть CVE 2026 года получена через вторичные блоги, **не сверена с NVD** —
указатель, а не факт.

### 🔴 Летальная триада — и она у нас собрана

Правило Саймона Уиллисона: опасно не каждое по отдельности, а **сочетание
трёх**: доступ к приватным данным + чтение недоверенного контента + канал наружу.

У нас прямо сейчас: **Gmail и Notion** (приватные данные), **Exa и Chrome
DevTools** (произвольный веб = недоверенный контент), **Gmail и Linear**
(канал наружу).

> **Практический вывод:** первые два угла нужны для работы и разрывать их
> незачем. **Третий — любую отправку, публикацию, создание задачи — держать
> на ручном подтверждении**, никогда не переводя write-операции в auto-approve.

Остальное: не ставить по `latest`, проверять имя посимвольно (typosquatting),
настораживаться на серию патч-релизов без changelog (паттерн postmark),
предпочитать readonly-scope.

## §7. Противоречия, названные прямо

1. **База против официального источника.** `49-token-economy-and-prompting.md`
   §1б утверждает: «−95 %, ~600 вместо ~12 000». Официальная цифра Anthropic —
   **72 000 → 8 700, то есть −85 %**. Порядок совпадает, числа разные,
   происхождение внутренней цифры неизвестно;
2. **«CLI победил MCP» против измерения.** Тезис HN опирается на одношаговые
   задачи; единственный систематический бенчмарк даёт обратное
   на интерактивных. Оба верны в своих границах — обобщать нельзя ни одно;
3. **число серверов:** 10 000 (Anthropic, 12.2025) против 17 000+ (вторичные,
   08.2026). Достоверна только первая.

## §8. Что осталось неизвестным

- **токен-цена наших десяти серверов** — публично не существует, снимается
  своим `/context` + `/mcp`;
- **дата GA официального MCP Registry** — не найдена нигде;
- **CVE 2026 года** — не сверены с NVD;
- **поддержка со стороны Meta и xAI** — данных нет вообще;
- **статус нативной поддержки в Windows 11** — вышла ли из preview.
