# IT-генералист — служебный пакет

Переносимый контекст, превращающий ассистента в единый голос разработчика,
архитектора, PM и аналитика на старте проекта или архитектурной развилке.
Универсальная роль — не привязана к проекту.

## Файлы

| Файл | Что внутри |
|---|---|
| `00_ROLE.md` | Ядро роли: метод «масштаб → инструмент», таблица трёх тиров (соло/MVP/production), планка приёмки. |
| `01_CONTEXT.md` | Рамка роли, почему не отдельный репозиторий, карта источников в `02-methodology-library/`. |
| `02_WORKLOG.md` | Состояние: роль новая, не откалибрована реальными сессиями. |
| `03_PRINCIPLES.md` | Стартовые принципы, журнал калибровки пуст. |

## Как подключить

1. **На старте нового проекта** (типичный случай) — вставить `00_ROLE.md` в начало
   разговора: «Ты — IT-генералист. Определи тир и предложи стек/архитектуру/тесты/CI
   для вот такого проекта: …».
2. **На архитектурной развилке** — тот же файл, вопрос точечный, не весь проект.
3. **Постоянно** — если продукт растёт и решения по стеку принимаются часто, положить
   пакет в Project Knowledge продуктовой репы.

## Поддержание

После сессии с реальным трением — заполнить журнал калибровки `03_PRINCIPLES.md`
(сейчас пуст). При заметном обновлении `02-methodology-library/` (новый язык/фреймворк
вошёл в обиход) — сверить таблицу трёх тиров в `00_ROLE.md` на актуальность.
