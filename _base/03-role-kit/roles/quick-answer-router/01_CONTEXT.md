# Контекст: Быстрые ответы / универсальная роль

## Объект работы

Система из 40+ приватных и нескольких публичных репозиториев-баз-знаний (`~/repos/`),
каждый со своим предметом (см. `mission-control/repos-map.md` и `00-infrastructure/
87-file-to-repo-routing.md`). Роль отвечает на вопрос «в какой репе искать глубину по
этой теме», не сама владеет глубиной каждой темы.

**Чем НЕ является:** не замена профильной роли (юрист, независимый эксперт и т.д.) — те
работают с конкретным принесённым артефактом, эта роль работает с вопросом до артефакта;
не замена чтения конкретной репы, когда нужен точный факт из накопленного материала, а
не общее знание; не отдельный репозиторий — предметного контента, который бы рос со
временем сам по себе, у роли нет (см. `mission-control/ROADMAP.md`, таблица «Что
осознанно НЕ делаем»).

## Ключевые выводы и решения

- Заказана владельцем как оформление прежней разговорной роли («роль... раньше была» —
  практика существовала неформально до этого пакета).
- Решено НЕ заводить отдельный репозиторий-«роутер» — вместо этого роль в `03-role-kit`
  плюс новая ось «вопрос → репа» в `00-infrastructure/87-file-to-repo-routing.md` §6.
  Обоснование то же, что у `independent-expert`: роутер — чистая процедура без своего
  накопительного контента, репа ему не нужна.
- Таблица маршрутизации живёт **в базе** (`87-file-to-repo-routing.md`), не внутри этого
  пакета роли — так она остаётся синхронизирована с реальным списком репозиториев одним
  файлом, а не дублируется в каждой копии роли.

## Зафиксированные параметры

| Параметр | Значение |
|---|---|
| Источник карты маршрутизации | `00-infrastructure/87-file-to-repo-routing.md` §6 — сверяться с актуальной версией, не с копией в памяти |
| Формат подключения | разово, по конкретному вопросу — роль не держится фоном постоянно |

## База знаний домена

- `00-infrastructure/87-file-to-repo-routing.md` §6 — таблица «вопрос → репа», основной
  рабочий инструмент роли. Пополняется по факту работы с конкретными репами — та же
  дисциплина, что у §4 того же файла для оси «файл → репа».
- `mission-control/repos-map.md` — полная карта репозиториев системы, если предмет
  вопроса не нашёлся в сокращённой таблице §6.

*Актуальность сверена: 2026-08-27, на момент завершения волны MVP по 28 доменным репам —
таблица §6 отражает состояние системы на эту дату. Домен быстроменяющийся: новые репы
добавляются, старые наполняются — сверять таблицу §6 при явном подозрении, что она
отстала от `repos-map.md`.*
