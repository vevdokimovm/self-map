# ROLE-KIT — лаборатория ролей

Единый стандарт и инструментарий для создания **переносимых ролей** для ассистента: юрист, архитектор, разработчик, медик, тренер, менеджер, продакт и т.д.

Роль — это набор служебных `.md`-файлов, который кладётся в **Project Knowledge** любого проекта и превращает ассистента в профильного специалиста с памятью: своим методом мышления, контекстом проекта, историей работы и правилами общения. Не отдельный чат под каждого специалиста, а специалист **внутри** проекта.

## Две ветви создания

| Ситуация | Ветвь | Инструмент |
|---|---|---|
| Новая область, работы по ней ещё не было | **A — с нуля** | `GENERATOR_PROMPT.md` + `ROLE_BRIEF.md` |
| Уже есть проект, чаты, файлы, база знаний по теме | **B — извлечение** | `GENERATOR_FROM_SOURCES.md` |
| Материала мало, но он есть | **B**, пробелы добить брифом | оба |

Разница по сути: в ветви A роль **проектируется** из брифа, в ветви B — **реконструируется по свидетельствам** того, как работа уже шла. Ветвь B почти всегда даёт более точную роль, потому что метод и принципы там не выдуманы, а вытащены из реальных решений и правок.

## Быстрый старт

### Ветвь A — роль с нуля

1. **Заполни бриф** — `ROLE_BRIEF.md` (5 минут). Или пропусти: генератор соберёт бриф интерактивно, вопросами с вариантами ответа.
2. **Скорми генератору** — новый чат, вставь `GENERATOR_PROMPT.md` + бриф.
3. **Прими работу** — `CHECKLIST.md` → Project Knowledge проекта → строка в `CATALOG.md`.

### Ветвь B — роль из существующих материалов

1. **Открой чат внутри нужного проекта** — чтобы генератору были доступны его файлы и история.
2. **Вставь `GENERATOR_FROM_SOURCES.md`.** Бриф не нужен: генератор сам инвентаризирует источники, извлечёт метод, контекст, историю и принципы, пометит происхождение каждого блока и в конце спросит только про пробелы.
3. **Прими работу** — `CHECKLIST.md` (включая блок проверки извлечения) → Project Knowledge → `CATALOG.md`.

## Состав кита

| Файл | Зачем |
|---|---|
| `STANDARD.md` | Стандарт роли: структура, обязательные секции, нейминг, версионирование, антипаттерны. Канон. |
| `GENERATOR_PROMPT.md` | **Ветвь A.** Генератор роли с нуля: вставляешь в чат вместе с брифом → пакет роли. |
| `GENERATOR_FROM_SOURCES.md` | **Ветвь B.** Генератор роли из существующих материалов проекта: инвентаризация → извлечение → маркировка происхождения. |
| `ROLE_BRIEF.md` | Бриф-опросник: входные данные для генератора. |
| `CHECKLIST.md` | Приёмка роли перед внедрением. |
| `CATALOG.md` | Реестр созданных ролей: где живёт, версия, статус. |
| `templates/` | Пустые шаблоны 4 файлов роли — если делаешь руками, без генератора. |
| `examples/METHOD_LIBRARY.md` | Библиотека методов по 10 профессиям — самая ценная часть, готовые «способы мышления». |
| `examples/EXAMPLE_lawyer.md` | Эталон: разбор роли «Юрист FINPILOT» по секциям. |

## Главный принцип

**Роль ценна методом и планкой приёмки, а не перечнем знаний.** Знания у ассистента и так есть. Роль задаёт *как думать*: юрист разделяет де-юре и де-факто, архитектор взвешивает trade-offs и даёт один вариант, аналитик отделяет корреляцию от причинности. Метод — сердце роли. Второй рычаг — **планка приёмки**: при каких условиях ответ считается законченным. Именно она превращает «в целом верно» в «профессионально закрыто», потому что заставляет доводить до конкретики и проверять, а не останавливаться на правдоподобном.
