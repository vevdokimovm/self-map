## §1. Python — один инструмент вместо девяти установок

**Главное решение: версиями управляет [`uv`](https://docs.astral.sh/uv/).**

```
uv 0.12.8                    ~/.local/bin/uv
python3 → 3.13.15            ~/.local/bin/python3 (симлинк на uv-сборку)
python  → 3.13.15            то же самое
```

`python` и `python3` — **одна и та же версия**. Раньше это были разные интерпретаторы.

### Команды на каждый день

```bash
uv venv                          # окружение под проект
uv venv --python 3.13            # на конкретной версии
uv pip install -r requirements.txt
uv run pytest                    # запуск без активации окружения
uv python list                   # какие Python есть
uv python install 3.12           # поставить ещё одну версию
```

### Что осталось в системе и почему

| Что | Где | Зачем оставлен |
|---|---|---|
| 3.13.15 (uv) | `~/.local/share/uv/python/` | **основной**, все проекты на нём |
| 3.9.6 | `/usr/bin/python3` | системный macOS — **трогать нельзя**, на нём работает сама ОС |
| 3.13, 3.14 (brew) | `/usr/local/opt/python@3.1*` | зависимости других brew-пакетов, снимать нельзя |

**Удалены 02.09.2026:** Framework 3.7, 3.8, 3.9 (пути в PATH вели в пустоту),
`pyenv` вместе с `~/.pyenv` (3.15.0rc1), `pypy3.10`, дубль `.venv2`
в personal-finance-dss. Framework 3.10 — ждёт sudo.

## §2. Конфиги оболочки

| Файл | Что в нём |
|---|---|
| `~/.zprofile` | **пусто**, только комментарий-предупреждение |
| `~/.zshrc` | PATH (3 строки, по одной на инструмент), оформление, алиасы |
| `/etc/paths` | 🔴 системный, под root — источник anaconda, nasm, mysql в PATH |
| `/etc/paths.d/*` | по файлу на инструмент: dotnet, go, TeX |

🔴 **`/etc/paths` — вторая половина ответа на вопрос «откуда битые пути».**
Правка `.zshrc` не убирает то, что macOS кладёт в PATH до неё. В `/etc/paths`
нашлись `~/opt/anaconda3/bin`, `~/Documents/nasm-2.14.02/` и `/usr/local/mysql/bin/` —
**ни одного из трёх каталогов на диске нет**. Плюс `/etc/paths.d/TeX`
и `dotnet-cli-tools`, тоже в пустоту.

**Бэкапы прежних версий:** `~/.config-backups/zprofile.*` и `zshrc.*` с меткой времени.

### Что было и почему сломалось

```
.zprofile:  ПЯТЬ блоков PATH (3.7, 3.8, 3.9, 3.10, 3.13)
            → три вели в удалённые каталоги
.zshrc:     $HOME/.local/bin ДВАЖДЫ, Antigravity ЧЕТЫРЕЖДЫ
            alias python  → 3.13 Framework
            alias python3 → 3.14 brew        ← перекрывал всё
            alias python3.15 → pyenv
```

🔴 Три алиаса вели в три разные установки. Проекты требуют `>=3.12` — значит любой
`python3 -m venv` работал **случайно**, а не по замыслу.

> **Правило: одна строка на один инструмент.** Дописывая новое — посмотри, нет ли выше.

### 🔴 Почему Node тоже не через brew

Та же история, что с `uv`, и она повторилась в тот же день. `brew upgrade node`
скачал формулу 26.8.1, но каталог в Cellar остался **пустым** — сборка не
завершилась. Мешало и другое: `/usr/local/bin/node` оказался установкой
с nodejs.org от апреля 2025 (222 МБ, под root), которая перекрывала brew-версию,
а `brew link` спотыкался о битую ссылку `node@24`.

Развязка та же: официальный бинарник, распакованный в `~/.local/opt/node`,
и симлинки в `~/.local/bin`. Без sudo, без сборки, за минуту.

> **Правило подтвердилось дважды за день.** Тулчейн ставится готовым
> бинарником с сайта проекта. `brew` — для библиотек.

### 🔴 Почему uv не через brew

`brew install uv` начинает собирать **весь Rust** из исходников: на этом Intel
процесс поднял load average до **103** при четырёх ядрах и не закончился за 10 минут.
Официальный установщик поставил готовый бинарник за секунды.

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

> **Правило.** Инструмент с официальным бинарником под платформу ставится бинарником.
> `brew` хорош для библиотек, не для тулчейнов на Rust и Go.

## §6. Что делать после перезапуска терминала

Изменения в `.zshrc` вступают в силу только в новой оболочке.

```bash
exec zsh          # или просто закрыть и открыть терминал
python3 -V        # ожидается 3.13.15
which python3     # ожидается ~/.local/bin/python3
alias | grep py   # ожидается пусто
```

Если что-то пошло не так — прежние конфиги в `~/.config-backups/`.
