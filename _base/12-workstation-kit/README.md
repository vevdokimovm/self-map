# 12 — Кит рабочей станции

> **Заведён 02.09.2026** по заказу владельца: *«давай обустроим инфраструктуру
> разработческую на моём маке… старое удалим, скачаем актуальное — стандарт рынка,
> рабочее, стабильное»* и *«скилл, который будет считывать состояние сети, нагрузки,
> температуры… какое состояние железа, где проблема может быть»*.

## Как это называется на рынке

Дисциплины с единым именем нет — та же история, что с `principles-audit.md` H3.
Ближайшие устоявшиеся термины, каждый покрывает часть:

| Термин | Что покрывает | Наш случай |
|---|---|---|
| **Developer Experience (DevEx)** | среда, в которой работает разработчик | ✅ ядро кита |
| **Workstation setup / provisioning** | приведение машины к воспроизводимому состоянию | ✅ §2 |
| **Dotfiles management** | конфиги оболочки под версионированием | ⚠️ частично: бэкапы есть, git нет |
| **Toolchain management** | версии языков и пакетов | ✅ §2, `uv` |
| **Системное администрирование** | серверы, сети, пользователи | ⛔ не про нас: одна машина, один человек |

**Честное самоописание: «управление рабочей станцией одного разработчика».**
Не сисадминство — здесь нет ни парка машин, ни пользователей, ни SLA.

## §1. Что в ките

| Файл | Что делает |
|---|---|
| [`bin/machine_probe.py`](bin/machine_probe.py) | снимок Mac: железо, нагрузка, память, диск, батарея, сеть, износ компонентов, бэкап + пороги |
| [`bin/inventory.py`](bin/inventory.py) | индекс приложений и крупных каталогов **с историей** — что появилось, исчезло, сменило версию |
| [`bin/toolchain_check.py`](bin/toolchain_check.py) | сравнение инструментария с эталоном: чего не хватает, что устарело, что лишнее |
| [`STATE.md`](STATE.md) | что стоит на машине сейчас — версии, пути, решения |
| [`reports/`](reports/) | отчёты о проведённых работах |
| `snapshots/` | снимки индекса по датам, для сравнения во времени |

### Три инструмента — три разных вопроса

| Вопрос | Чем отвечать |
|---|---|
| «что с машиной прямо сейчас» | `machine_probe.py` |
| «что вообще установлено и когда появилось» | `inventory.py` |
| «всё ли нужное стоит и не устарело ли» | `toolchain_check.py` |

🔴 **Ни один из трёх ничего не меняет.** Они читают и печатают команды,
которые выполняет владелец. Обновление тулчейна и удаление программ —
необратимые действия, и решает их человек (`/auto` §5).

```bash
python3 12-workstation-kit/bin/machine_probe.py          # срез, зелёное молчит
python3 12-workstation-kit/bin/machine_probe.py --json    # то же машиночитаемо
python3 12-workstation-kit/bin/machine_probe.py --net      # + замер скорости (~15 с)
```

🔴 **Скрипт только читает.** Ни одной команды, меняющей состояние машины, в нём нет —
иначе замер начал бы влиять на измеряемое (тот же инвариант, что у `sync_base_local.py`).

### Что он честно НЕ может

- **температура CPU** — на Intel читается только через `sudo powermetrics`.
  Без пароля отдаётся температура **батареи**, и она подписана именно так,
  а не выдаётся за процессорную;
- **износ SSD** — нужен `smartctl` (`brew install smartmontools`). Без него
  `diskutil` говорит лишь Verified/Failing, без счётчиков;
- **скорость сети** — только по флагу `--net`: замер занимает ~15 секунд,
  и молча тратить их на каждый запуск неправильно.

## §2. Правила, выведенные из наведения порядка 02.09.2026

### 🔴 Один инструмент на одну задачу

Было **девять** установок Python и **три** алиаса, указывающих в разные стороны.
Каждая появилась обоснованно: установщик python.org, brew, pyenv, Framework.
Проблема не в любой из них, а в том, что **ни одна не была назначена главной**.

> **Правило.** Версиями Python управляет `uv` — один инструмент вместо
> `pyenv` + `venv` + `pip` + алиасов. Ставить Python другим способом можно
> только записав в `STATE.md`, зачем.

### 🔴 Установщик дописывает в конец и не смотрит, что уже есть

`.zshrc` содержал `$HOME/.local/bin` дважды и Antigravity **четырежды**.
`.zprofile` — пять блоков PATH, и **три из пяти вели в удалённые каталоги**.
Это не небрежность владельца: так устроены сами установщики.

> **Правило.** Конфиг оболочки читается глазами раз в квартал, а не когда
> «что-то сломалось». Дописывая строку — проверь, нет ли её выше.

### 🔴 Сборка из исходников на Intel — это часы

`brew install uv` начал тянуть **весь Rust** и поднял load average до **103**
на четырёх ядрах. Официальный установщик Astral поставил готовый бинарник
за секунды.

> **Правило.** Инструмент, у которого есть официальный бинарник под платформу,
> ставится бинарником. `brew` хорош для библиотек, не для тулчейнов на Rust/Go.

### Порог «свободно меньше 10 %» — не эстетика

Диск был занят на **95 %** (11 ГБ из 233). macOS при этом ведёт себя странно
неочевидными способами; своп занимал 3.2 ГБ из 4 при 8 ГБ RAM.
После чистки — 60 ГБ свободно.
