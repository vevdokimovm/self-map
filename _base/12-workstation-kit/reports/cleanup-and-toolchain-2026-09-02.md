## Что найдено попутно

### 🔴 Три пути в PATH вели в удалённые каталоги

`.zprofile` содержал блоки для Python 3.7, 3.8, 3.9, 3.10 и 3.13 — их дописывали
установщики python.org. **Каталогов 3.7, 3.8 и 3.9 на диске уже не было.**
Оболочка молча искала в несуществующих папках при каждом запуске команды.

### 🔴 Алиасы указывали в три разные установки

```
alias python      → Framework 3.13
alias python3     → brew 3.14        ← перекрывал всё
alias python3.15  → pyenv 3.15.0rc1
```

Проекты требуют `>=3.12`, и формально это выполнялось. Но **какой именно Python
возьмёт `python3 -m venv`, зависело от порядка алиасов**, а не от решения.
Это работало, пока работало.

### 🔴 brew собирал uv из исходников и положил машину

`brew install uv` начал тянуть **весь Rust**. Замер во время сборки:
load average **103** на четырёх ядрах, `pod2man` и `perl` в топе процессов.
Через 10 минут сборка не закончилась.

Официальный установщик Astral скачал готовый бинарник **за секунды**.

> **Правило в кит:** инструмент с официальным бинарником под платформу
> ставится бинарником. `brew` — для библиотек, не для тулчейнов на Rust/Go.

### Своп 2.9 ГБ из 4 при 8 ГБ RAM

Не следствие чистки — постоянное состояние машины. Физический предел:
браузер, IDE и Docker в 8 ГБ не помещаются.

### 🔴 Половина битых путей приходила НЕ из конфигов пользователя

После полной уборки `.zshrc` и `.zprofile` в PATH всё ещё оставалось
**20 несуществующих каталогов**. Источник нашёлся в системных файлах:

```
/etc/paths                     ~/opt/anaconda3/bin        ← каталога нет
                               ~/Documents/nasm-2.14.02/  ← каталога нет
                               /usr/local/mysql/bin/      ← удалён сегодня
/etc/paths.d/TeX               /Library/TeX/texbin        ← удалён сегодня
/etc/paths.d/dotnet-cli-tools  ~/.dotnet/tools            ← каталога нет
```

> **Урок: чистка пользовательских конфигов не отвечает на вопрос «что в PATH».**
> macOS собирает PATH из `/etc/paths` и `/etc/paths.d/` **до** того, как читает
> `.zshrc`. Проверять надо конечный результат — `echo $PATH` в чистой оболочке, —
> а не файл, который правил.

Остальные битые пути — от плагинов Claude Code (`~/.claude/plugins/cache/.../bin`);
они создаются по требованию и тревоги не стоят.

### Node: три установки поверх друг друга

`node` в PATH оказался бинарником с nodejs.org от **апреля 2025** (222 МБ, root),
он перекрывал brew-версию. При этом `brew upgrade node` скачал 26.8.1, но оставил
**пустой каталог** в Cellar — сборка не завершилась, а `brew link` спотыкался
о битую ссылку `node@24`.

Разрублено так же, как с `uv`: официальный бинарник Node 24 LTS в `~/.local/opt/node`,
симлинки в `~/.local/bin`. **Правило про бинарники подтвердилось дважды за день.**

### 🔴 У control-panel не было списка зависимостей

Я снёс `.venv` проекта, чтобы пересоздать на 3.13 — и обнаружил, что
`requirements.txt` в проекте **нет**. Восстанавливать окружение пришлось
по строкам `import` в коде, а `python-multipart` вообще не всплыл: его требует
FastAPI неявно, и сервер падал уже на старте.

> Пока список зависимостей не записан, окружение — **единственный экземпляр,
> а не копия**. Тот же класс, что «архив релиза — не копия версии, а оригинал».

`requirements.txt` заведён, с объяснением в шапке.

### 🔴 `df` врёт после удаления, пока жив снимок APFS

После снятия моделей ollama и Minecraft (5.2 ГБ) `df` показал **то же самое
число**. Файлы действительно исчезли — но место не вернулось.

Причина: локальный снимок Time Machine (`com.apple.TimeMachine.2026-09-02-101819`)
держит состояние «до удаления». Разница видна, если спросить контейнер, а не том:

```
df -h /System/Volumes/Data     → свободно 66 ГБ
diskutil info /System/Volumes/Data → Container Free Space: 71 ГБ
```

> **Правило: после удаления проверять `diskutil info`, а не только `df`.**
> `df` отвечает про том, `diskutil` — про контейнер APFS, и расхождение между
> ними и есть объём, занятый снимками.

Место не потеряно: macOS освобождает снимки сама, когда оно требуется.
И пока снимок жив, **удаления обратимы** — это страховка, а не помеха.
Снять вручную: `sudo tmutil deletelocalsnapshots <метка>`.

## Осталось владельцу

Три действия, все требуют пароля или перезапуска.

**1. Снять последние старые установки (~2.9 ГБ):**

```bash
sudo rm -rf /Library/Frameworks/Python.framework/Versions/3.10 \
            /usr/local/bin/node /usr/local/lib/node_modules
```

**2. Убрать несуществующие каталоги из системного PATH:**

```bash
sudo cp /etc/paths /etc/paths.backup
printf '/usr/local/bin\n/usr/bin\n/bin\n/usr/sbin\n/sbin\n' | sudo tee /etc/paths
sudo rm -f /etc/paths.d/TeX /etc/paths.d/dotnet-cli-tools
```

**3. Перезапустить терминал** — `exec zsh` или закрыть и открыть окно.
Проверка:

```bash
python3 -V        # 3.13.15
node --version    # v24.11.1
alias | grep py   # пусто
```

Прежние конфиги — в `~/.config-backups/`, системный PATH — в `/etc/paths.backup`.
