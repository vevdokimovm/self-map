# Реестр инцидентов

Краткие сводки по каждому **инциденту** — была реальная поломка/дефект и/или влияние на
пользователя/систему. Расследования, где реального дефекта НЕ оказалось (внешняя причина, артефакт
метода, недопонимание), — в отдельном парном реестре `investigations_summary.md`.

Полные разборы (post-mortem) лежат в `incidents/`. Формат разбора — `incident_postmortem_guide.md`;
шаблон карточки дефекта — `bug_report_template.md`. В каждой записи — не только корень, но и
**решение / шаги** (а если не закрыто — что опробовано и что дальше).

> **Как читать этот файл.** Это реестр-индекс: строки-сводки для быстрого контекста. Полные разборы —
> в `incidents/`. В base-repo (родительский шаблон) реальных инцидентов нет — реестр наполняется по
> мере жизни наследующей репы.

---

## Формат записи

```markdown
### INC-<ТЕМА> / BUG-<NNN> — <короткое имя>

- **Суть:** <что произошло, симптом>
- **Корень:** <настоящая причина, не симптом>
- **Решение / шаги:** <что сделано; если не закрыто — что опробовано / почему / что дальше>
- **Статус:** <закрыт / в работе>. Полный разбор — `incidents/<тема>_incident.md`.
```

### INC-RELEASE-NOTES — описания GitHub Release: три дефекта подряд (2026-07-18)

- **Суть:** за вечер три попытки привести описание релиза к виду `legal-knowledge-base` сломали
  выпуск тремя разными способами: `v1.0.0` — релиз не создан (`publish.sh` не знал `--auto-asset`,
  который вызывает `deploy_from_zip.sh`); `v1.1.0` — в описании нет строки `## [X.Y.Z] — дата — название`;
  `v1.2.0` — заголовок «repo v1.2.0» и описание-фолбэк «Release 1.2.0». Плюс утилита починки
  отработала вхолостую («исправлено 0»). Дерево, теги и ассеты не пострадали ни разу.
- **Корень:** (1) документация и вызывающий скрипт опережали `publish.sh` — контракт `--auto-asset`
  описан и вызывался раньше, чем реализован; (2) правки проверялись `bash -n`, а не выходом парсера —
  синтаксис валиден, результат неверен; (3) предположения об окружении: `basename` корня git-дерева
  считался именем репы (клон лежит в `$WORK/repo`), а bash-семантика — действующей в скрипте,
  запускаемом через `zsh` (нет word splitting).
- **Решение / шаги:** в `publish.sh` добавлен `--auto-asset`, исправлен off-by-one в парсере
  CHANGELOG (`range(start + 1, …)`), заголовок релиза = тег; создан `fix_release_notes.sh` для правки
  уже выпущенных релизов через `gh release edit`; утилита переписана на файл + `while IFS= read -r`.
  Обе копии скриптов (корень и `templates/`) синхронизированы. Проверено прогонами: извлечение всех
  четырёх секций CHANGELOG, 4 итерации цикла версий.
- **Статус:** закрыт (v1.3.1). Полный разбор — `incidents/release-notes-incident.md`.
