# 15 — Claude + Git: сквозные моменты, что легко упустить

> Дополнение к 13 (GitHub) и 14 (Claude). То, что не влезло в них, но важно для `base-repo` и работы в связке.

---

## 1. Главный сквозной инсайт: маленькие текстовые файлы = двойная победа

Наш протокол сжатия в тезисные `.md` оправдан **сразу двумя** ограничениями, а не одним:
- **GitHub:** надёжно рендерит превью только при **< ~2 MB**; большое таймаутит (файл 13).
- **Claude:** контекст **200K токенов** на чат; маленькие файлы дешевле по расходу и Projects их кэширует (файл 14).

То есть «одна репа = зона, тяжёлое → в тезисы» — это не эстетика, а прямое следствие технических лимитов обеих систем. Держим курс.

## 2. zip — транспорт, а не версионируемый исходник
Наш принцип «один zip = полный контекст» — про **передачу вахты / бэкап / отдачу Claude целиком**. Но в git zip **не версионируем** (git пересохраняет бинарник целиком каждое изменение — файл 13 §4.3). Правило: в репе живут **текстовые исходники**, а zip **генерируем на отдачу**. Не коммитить рабочие архивы в историю.

## 3. Claude может отвечать не той моделью, что выбрана
У Fable 5 защитный роутинг: часть запросов уходит на **Opus 4.8** с уведомлением (файл 14 §4). Практический смысл: выбрал Fable — а ответил мог Opus. Для воспроизводимости важных результатов это держать в уме (и это ещё одна причина не строить критичный пайплайн жёстко на одной модели — делать graceful fallback).

## 4. README и структура — точка входа для ТРОИХ
README читают: **человек** (ты через год), **рекрутер** (сигнал зрелости) и **Claude** (первый файл контекста). Один хороший README работает на всех троих. Numbered kebab-case структура — тоже: и человеку навигация, и Claude якоря.

## 5. `.gitattributes` — не только line endings
- `* text=auto` — нормализация CRLF/LF (важно на macOS, файл 13 §4.5).
- `linguist-generated`, `linguist-vendored`, `linguist-documentation` — помечать сгенерированные/сторонние файлы, чтобы **язык репы в статистике GitHub** отражал реальный код (портфолио-вид: чтобы репа не считалась «на 80% HTML» из-за одного дампа).

## 6. Непрерывность между чатами Claude
Помимо Projects (кэш контекста) и памяти — на платных планах есть **поиск по прошлым чатам** (Claude сам находит релевантное из старых разговоров). Плюс генерация памяти из истории. Это снижает необходимость каждый раз пересказывать контекст — но не заменяет актуальные файлы-инструкции (память дрейфует, файлы — источник истины).

## 7. Git — это не бэкап
Один remote = одна точка отказа (снесли/забанили аккаунт → всё). Для важного — второй remote/зеркало или локальные bundle-бэкапы. У нас репы приватные на GitHub — держать это в уме, особенно под миграционный сценарий (доступ к аккаунту может быть завязан на телефон/почту, которые в переезде меняются).

## 8. Приватность репозиториев ≠ невидимость
Репа приватная от посторонних, но её содержимое видят GitHub и (при работе через Claude) обрабатывается Anthropic. Отсюда правило: **секреты — никогда** (файл 13 §4.1). Остальное личное в приватной репе — можно (это наш осознанный выбор).

## 9. Мелкие практические
- `git rm --cached` чтобы убрать уже отслеживаемый файл после добавления в `.gitignore` (файл 13 §4.4).
- `git mv` для переименования только регистра на macOS (файл 13 §4.6).
- `git-sizer` — диагностика раздувания перед тем как чинить.
- Releases на GitHub — раздача больших бинарников **без** лимита размера/трафика (в отличие от LFS).
- Gists — быстрый способ отрендерить/пошарить один файл (ipynb/geojson/csv/stl) без целой репы.

## 10. Приватность и обучение на твоих данных (важно — ты грузишь личное)
Ты кладёшь в Claude здоровье, веру, личное. Поэтому:
- **Проверь Настройки → Приватность:** используются ли твои чаты для улучшения моделей (эта настройка менялась; для платных обычно можно отключить). Реши осознанно.
- **Удаление чата** убирает и производную из памяти (не сразу — по циклу).
- **Разовое чувствительное** — через Incognito / временный чат (не сохраняется в историю и память). Удобно для того, что не должно осесть.
- Память дрейфует и собирается автоматически — источник истины держим в файлах-инструкциях, а не в памяти.

## 11. Мультиаккаунт — риск, который стоит держать в поле зрения
Запуск нескольких аккаунтов ради обхода лимитов **может противоречить пользовательскому соглашению Anthropic** (обычно 1 аккаунт на человека). Риск — блокировка, а с ней **потеря данных и доступа**. Особенно чувствительно под миграцию, где доступ к аккаунтам завязан на почту/телефон, которые в переезде меняются. Осознанный выбор твой — просто: (а) держи это в уме, (б) **ничего критичного без бэкапа** в аккаунтах не храни (кит у тебя и локально — правильно), (в) заранее продумай, как не потерять доступ при смене номера/страны.

## 12. Что ещё незаметно жжёт токены (к файлу 10)
- **Extended thinking** (размышления) считается в выходные токены — включённое «высокое усилие» жжёт заметно быстрее.
- **Вложения/картинки** дорогие: изображение = тысячи токенов в зависимости от размера. PDF/скрин — тоже.
- **Каждый tool call / результат поиска / чтение файла** = токены в контексте (агентные сессии с кучей чтений жгут быстро).
- **Cache TTL:** выигрыш от Projects/кэша не вечен — при простое кэш истекает (порядка минут), и следующее сообщение перечитывает контекст по полной цене. Работать по контексту плотно, не растягивая.

## 13. «Server is temporarily limiting requests» ≠ твой лимит
Это сообщение про **нагрузку на стороне Anthropic**, а не про твой usage. Ничего не стоит и проходит само. Не путать с реальным исчерпанием лимита (там указано время сброса — ему верить буквально).


Три файла (13, 14, 15) закрывают техническую базу: **лимиты GitHub**, **лимиты Claude**, **сквозные грабли**. Наши существующие протоколы (сжатие, нейминг, WATCHLOG, «секреты никогда», HTTPS, пороги размера) этими фактами **подтверждаются** — ничего переделывать не нужно, только держать актуальным при изменении лимитов.
