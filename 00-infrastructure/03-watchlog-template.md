> Репа ведётся с нескольких аккаунтов Claude и в разных сессиях. Токены/контекст
> кончаются внезапно. Поэтому:
> 1. Журнал обновляется **по ходу** работы, не в конце.
> 2. Тяжёлую ревизию отдавай/коммить рано и часто.
> 3. В любой момент этот файл обязан отражать реальную текущую точку.
> Полный протокол — `00-infrastructure/04-watchlog-protocol.md`.

> **Что это.** Снимок-контекст для мгновенного входа в работу с репой. Кто угодно
> (ты с другого аккаунта, ты через месяц) поднимает картину с этого файла, не
> перечитывая всю репу: где стоим, что сделано, что дальше, на какие грабли не наступать.

> ## [!] §3 хранит РОВНО N последних изменений (рекомендую N=10)

> теряет смысл «быстрого снимка». Удалённое не пропадает — история видна в `git log`.

## §1. Аккаунты и протокол вахты

Репа ведётся с нескольких аккаунтов Claude — исторически **V, J, M, S** — несущих вахту по очереди
(плюс несколько чатов внутри одного проекта). У Claude нет общей памяти между аккаунтами; журнал
самодостаточен для любого входящего. Имена нужны только если владелец уточняет «акк V/J/M/S» в
разборе. Непрерывность и чекпоинт-дисциплина — `23-session-continuity.md`; слияние разошедшихся
линий между аккаунтами — `22-merge-protocol.md`.

Приёмка вахты (начиная сессию на любом аккаунте):
1. Прочитай §0 (где стоим) и §2 (куда идём).
2. Пробеги §4 (грабли) и §5 (правила) — чтобы не наступить повторно.
3. Работай, обновляя §0 по ходу.
4. Закончил подшаг → обнови §0; нашёл грабли/факт → §4; значимое изменение → §3 **и** запись в
   `CHANGELOG.md` (`24-changelog-protocol.md`); сработал триггер разбора → отчёт по
   `19-reporting-system.md`.
