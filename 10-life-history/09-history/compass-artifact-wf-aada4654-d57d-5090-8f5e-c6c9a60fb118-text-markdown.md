# Экспорт переписок (Telegram, VK, Instagram) и лимиты Claude — состояние на 2026 год

## TL;DR
- **Telegram: экспорт РАБОТАЕТ и он официальный.** Выгрузить конкретный чат ИЛИ собственный канал в текст (JSON/HTML) можно — но ТОЛЬКО через Telegram Desktop (Windows/Linux) или «Telegram for macOS» (в Mac App Store он называется Telegram Lite). В Telegram Web, в мобильных приложениях и в облегчённой App Store-версии функции нет — именно поэтому сложилось впечатление, что «нельзя».
- **VK и Instagram** оба дают официальную выгрузку архива (VK — ZIP через страницу защиты данных; Instagram — «Скачать свою информацию»/Download Your Information в HTML/JSON). Архивы содержат полный текст постов, подписи, комментарии и даты.
- **Claude Opus 4.8 = 1M токенов контекста (по умолчанию на API; 500K при чате на claude.ai по специализированной справке).** Изображения перестают «видеться» в длинном чате из-за жёсткого лимита claude.ai (20 изображений на сообщение) и вытеснения/суммаризации старого контекста, а НЕ из-за текстового лимита. Уменьшение разрешения снижает токены, но потолок по числу картинок на сообщение жёсткий.

## ТЕМА 1 — Экспорт переписок из Telegram

### Общий вывод
Утверждение «нельзя» неверно по факту: экспорт истории существует и является официальной функцией Telegram с 27 августа 2018 года — версия v4.9.1 на мобильных и v1.3.3 на Windows (анонс в блоге telegram.org/blog/export-and-more). Типичная ошибка: люди смотрят в Telegram Web или в App Store-версии для Mac, где функции действительно нет. Экспорт живёт исключительно в десктопном клиенте Telegram Desktop / Telegram for macOS.

### По клиентам (2026)
- **Telegram Desktop (Windows/Linux)** — ЕСТЬ полный экспорт. Основной клиент для выгрузки.
- **Telegram for macOS** — отдельное нативное приложение. В Mac App Store оно называется **«Telegram Lite»** (на telegram.org/apps — «Telegram for macOS», сайт macos.telegram.org). В нём экспорт ЕСТЬ.
- **Стандартный «Telegram» из Mac App Store** — это НЕ desktop-версия; она построена по логике мобильного клиента, и функции «Export Telegram Data» / «Export chat history» в ней НЕТ.
- **Telegram Web (web.telegram.org, версии A и K)** — экспорта НЕТ.
- **iOS / Android** — полноценного bulk-экспорта НЕТ (можно только пересылать сообщения в «Избранное»/Saved Messages; на некоторых сборках Android встречается частичный «Export chat history» для отдельного чата, но это ненадёжно).

### Где находится функция (пошагово)
Два маршрута в Telegram Desktop:

**A. Один конкретный чат/канал:**
1. Открыть нужный чат или канал.
2. Три точки (⋮) в правом верхнем углу → **Export chat history** / «Экспорт истории чата».
3. Выбрать, что включать (фото, видео, голосовые, видеосообщения, стикеры, GIF, файлы), задать лимит размера файла, путь и **формат HTML или JSON**.
4. Опционально — задать диапазон дат (From/To).
5. Export.

**B. Весь аккаунт:**
Меню (≡) → **Settings → Advanced → Export Telegram Data** → выбрать чаты/типы (все личные чаты, группы, каналы) → формат → Export.

### Форматы и содержимое
- Форматы: **JSON** (машиночитаемый, для скриптов/анализа) и **HTML** (человекочитаемый, открывается в браузере). Можно выбрать оба.
- Один чат → файл `messages.html` или единичный `result.json` в своей подпапке. Полный экспорт → `result.json` + `export_results.html` + подпапки медиа. Схема JSON официально описана на **core.telegram.org/import-export**.
- Экспортируются медиа (фото, видео, голосовые, round-video, стикеры, файлы), контакты (.vcard), истории (stories). Каждое медиа хранится отдельным файлом, JSON ссылается на относительные пути.
- **Можно выгрузить ОДИН конкретный чат** (через ⋮ в чате) — это прямо противоречит мифу «только весь аккаунт».

### Ограничения
- **Только десктоп.** В Web/мобильных/App-Store-Mac функции нет.
- **Задержка до 24 часов** для только что залогиненной новой сессии (анти-абьюз). Можно пропустить, подтвердив запрос с другого уже авторизованного устройства.
- **Secret Chats** (end-to-end) в экспорт НЕ входят — они только на устройствах.
- **Удалённые сообщения** не восстанавливаются.
- **Группы с включёнными Topics (форум-режим)** — подтверждённый баг Telegram Desktop: пункт «Export chat history» в ⋮ не показывается. Это зафиксировано в GitHub issue #27322 репозитория telegramdesktop/tdesktop, открытом пользователем «dzek69» 6 января 2024 г. («There should be an 'Export chat history' entry… это отсутствует»). Обходной путь — полный экспорт аккаунта через Settings → Advanced.
- Чаты с ограничением на копирование/пересылку могут не выгружаться.

### Собственный КАНАЛ
Да, содержимое собственного канала (где человек публиковал заметки) выгружается **той же процедурой**, что и чат: открыть канал → ⋮ → Export chat history. Процедура для канала не отличается от личного чата. Экспорт доступен для личных чатов, групп, супергрупп и каналов.

### Только macOS?
Работает. Нужно скачать **правильное** приложение:
- Идеально — **«Telegram for macOS» / Telegram Lite** (telegram.org/apps или Mac App Store под именем Telegram Lite) — там экспорт есть.
- Либо **Telegram Desktop** с desktop.telegram.org.
- НЕ подходит: стандартный «Telegram» из App Store без слова Lite/Desktop — в нём нет Settings → Advanced → Export.
- Признак: если в меню чата нет «Export chat history» — установлен не тот клиент.

### Неофициальные/сторонние способы
- **Python-библиотеки Telethon и Pyrogram** (MTProto) — реалистично для тех, кто владеет командной строкой. Нужны свой `api_id`/`api_hash` с **my.telegram.org**. Методы `get_chat_history`, `download_media`. У Pyrogram есть режим **takeout** (`takeout=True`), специально для экспорта — реже вызывает FloodWait.
- **Готовые инструменты:** `tg-archive`, `telegram-download-chat`, `telegram-export`, tdlib — используют тот же API.
- **Боты для экспорта** — работают через Bot API, но Bot API не даёт исторический дамп напрямую; бота нужно делать админом чата/канала.
- **Риски бана:** официальная документация Telethon прямо предупреждает, что сторонние библиотеки часто приводят к тому, что аккаунты выглядят забаненными; особенно уязвимы новые номера и номера из некоторых стран (упоминаются Иран, Россия, Казахстан, Китай) и виртуальные (VoIP) номера. Правила: не использовать чужой api_id/api_hash (Telegram расценивает как подозрительное и может забанить), не спамить запросами, добавлять задержки. Для личного экспорта своих чатов это не нарушает ToS, но риск временных ограничений реален.

### ФИНАЛЬНЫЙ ОДНОЗНАЧНЫЙ ОТВЕТ
**МОЖНО.** И конкретный чат, и конкретный канал выгружаются в текст (JSON/HTML) официально. Точный рецепт для человека на macOS:
1. Скачать **Telegram for macOS (Telegram Lite)** из App Store или **Telegram Desktop** с desktop.telegram.org.
2. Войти (код придёт в приложение на телефоне). При необходимости подождать до 24 ч или подтвердить с телефона.
3. Открыть нужный чат/канал → **⋮ → Export chat history**.
4. Выбрать **JSON** (для обработки) или **HTML** (для чтения), при желании снять галочки с медиа для чисто текстового файла, задать диапазон дат.
5. Export → «Show my data».

## ТЕМА 2 — Экспорт данных из VK и Instagram (2026)

### VK
- Функция официальная, запущена 19 ноября 2017 года. Запрос — на **специальной странице защиты пользовательских данных** (vk.com/data_protection); кнопка «Подготовить архив».
- Введение пароля; архив приходит как **ZIP личным сообщением от администрации ВК**. Можно защитить ключом OpenPGP.
- Срок подготовки: **от нескольких часов до нескольких дней** (по свидетельствам — от 2 часов до 2 дней). Ссылка на скачивание доступна ограниченное время и только заказавшему.
- Содержимое: посты, комментарии, фото, диалоги/сообщения, и данные даже из закрытых настройками приватности разделов. При запросе можно исключить платежи, рекламный кабинет и историю переписки с техподдержкой.
- Формат: преимущественно **HTML** (для просмотра). Важная оговорка: фото и голосовые сообщения в архиве представлены ссылками (сжатые версии), а не файлами — для их массового скачивания есть сторонняя утилита VKArchiveDownloader. Функция работает и сейчас (развивается, изначально в тестовом режиме).

### Instagram
- Функция **«Download Your Information» / «Скачать свою информацию»** через **Accounts Center → Your information and permissions → Export your information** (Meta Accounts Center).
- Путь: аватар → меню → Accounts Center → Your information and permissions → Export your information → Create export → Export to device → выбрать диапазон дат, **формат HTML или JSON**, качество медиа (Higher Quality) → Start export → пароль.
- Срок: письмо со ссылкой обычно приходит **в течение примерно часа — до суток** (зависит от объёма). Ссылка на скачивание действует ограниченное время (порядка 4 дней).
- Содержимое: посты и истории (фото, видео, **подписи, комментарии, временные метки**, геолокация если включена), директы, лайки и комментарии, история поиска, активность аккаунта. В JSON — файлы вроде `media/`, `comments/post_comments_1.json`.

### Оценка полноты
- **Instagram** архив **даёт полный текст постов** — подписи (`caption`), комментарии и даты присутствуют (подтверждается структурой JSON). Для полного текстового бэкапа своих постов этого достаточно.
- **VK** архив тоже содержит тексты постов, комментарии и диалоги с датами. Основной «недостаток» — медиа даются ссылками, а не всегда файлами.
- Что теряется/оговорки: у Instagram аналитика/insights в стандартном архиве представлена не так подробно, как в бизнес-инструментах (Professional/Creator insights); у обоих сервисов медиа могут быть в сжатом виде или по ссылкам; удалённый контент не гарантирован.

## ТЕМА 3 — Контекстное окно и лимиты Claude (Opus 4.8, claude.ai, Pro), 2026

### 1. Размеры контекстных окон
По официальной документации Anthropic (platform.claude.com, models overview):
- **Claude Opus 4.8** (ID `claude-opus-4-8`, релиз 28 мая 2026) — **1M токенов по умолчанию** на Claude API, 128k макс. выход.
- **При чате на claude.ai** (специализированная справка support.claude.com «How large is the context window on paid Claude plans»): Sonnet 5 — **1M** на всех платных планах; **Opus 4.8, Opus 4.7, Opus 4.6, Sonnet 4.6 — 500K** при чате на платных планах; остальные модели — **200K**.
- В Claude Code (Pro/Max/Team/Enterprise) Sonnet 5, Fable 5, Opus 4.8/4.7/4.6 поддерживают **1M** (Pro-пользователям для Opus нужно включить usage credits).
- Haiku 4.5 — 200K. Fable 5 и Mythos 5 — 1M.
- ⚠️ Расхождение официальных источников: **общая** справка claude.ai («How do usage and length limits work?») формулирует консервативнее — дословно: *«Claude's context window size is 200K tokens across all models and paid plans, except for Enterprise plans, which have a 500K context window on some models»*. То есть разные справочные страницы Anthropic дают разные цифры (200K vs 500K/1M) — реальный лимит для конкретной модели надёжнее смотреть в специализированной статье и в Settings.

### 2. Как расходуется контекст в длинном чате
- Накапливается **вся история**: системный промпт, каждое сообщение (включая результаты инструментов, изображения, документы), определения инструментов и генерируемый вывод (включая thinking) — всё считается в окно.
- При приближении к пределу claude.ai работает по механизму **rolling FIFO** («first in, first out») — официально подтверждено в API-доке Context windows.
- **Автоматическое управление контекстом:** support.claude.com («How do usage and length limits work?») сообщает дословно: *«When your conversation approaches the context window limit, Claude summarizes earlier messages to continue the conversation seamlessly… Your full chat history is preserved so Claude can reference it even after summarization»* (требуется включённое code execution; при работе видно статус «organizing its thoughts»). То есть старые сообщения **суммаризируются** (сжимаются в текст).
- В API есть отдельные механизмы: **server-side compaction** (beta, для Opus 4.8/4.7/4.6, Sonnet 5/4.6 и др.), **context editing** со стратегией `clear_tool_uses_20250919` (**tool result clearing**) — очищает старые результаты инструментов и заменяет их **placeholder-текстом** («The API replaces each cleared result with placeholder text so Claude knows it was removed»), и **thinking block clearing**. Эти API-функции включаются заголовком `context-management-2025-06-27` и по умолчанию на claude.ai пользователю недоступны для ручной настройки.

### 3. КЛЮЧЕВОЙ ВОПРОС — почему изображения перестают отображаться
Ответ комбинированный, с опорой на официальную документацию:

**a) Жёсткий лимит на число изображений.** Официальная Vision-документация Anthropic (platform.claude.com/docs/en/build-with-claude/vision) прямо указывает:
- **20 изображений на сообщение на claude.ai**;
- 100 на запрос через API для моделей с окном 200k; 600 для остальных.
- Макс. размер файла: **10 MB на claude.ai** (и 10 MB на API напрямую; 5 MB на Bedrock/Google Cloud).
- Макс. размеры: **8000×8000 px**. Если в запросе >20 изображений, действует более строгий лимит — ни одна сторона не должна превышать **2000 px**, иначе `invalid_request_error` про «many-image requests».

**b) Вытеснение/суммаризация.** Когда чат растёт, старые сообщения суммаризируются или вытесняются по FIFO. При суммаризации ранние **изображения** перестают быть доступны модели как картинки, тогда как более свежий текст продолжает работать — это и есть наблюдаемый симптом «текст идёт, картинки пустые».

**c) Важная оговорка об источниках.** Прямого официального заявления Anthropic, что именно **изображения** «элидируются/заменяются плейсхолдером в чатах claude.ai», НЕТ. Формулировка про «placeholder text… so Claude knows it was removed» относится к **API context editing** (tool results), а не к картинкам в claude.ai. Consumer-справка говорит только о суммаризации «earlier messages» (текстовая формулировка), не упоминая изображения отдельно. То есть поведение «картинка превратилась в пустой плейсхолдер» — это наблюдаемый эффект (подтверждается пользовательскими баг-репортами и поведением Claude Code — ошибка «an image in the conversation could not be processed and was removed» и подсказка «Run /compact to remove old images from context»), но официально по claude.ai задокументировано не как отдельный «лимит на картинки в разговоре», а как следствие лимита 20/сообщение + управления контекстом.

**Токены изображения:** Claude считает картинки «патчами» 28×28 px = 1 визуальный токен. Формула: **⌈width/28⌉ × ⌈height/28⌉** визуальных токенов. (Старая формула «ширина×высота/750» — прежнее приближение; актуальная документация 2026 использует патчи 28px.) High-resolution модели (Opus 4.8, Opus 4.7, Sonnet 5, Fable 5, Mythos 5): макс. длинная сторона 2576 px, до 4784 визуальных токенов. Standard: 1568 px / 1568 токенов.

### 4. Лимиты плана Claude Pro (2026)
Официально (support.claude.com «What is the Pro plan?»):
- Pro даёт **не менее 5×** объёма использования на сессию по сравнению с Free (в пиковые часы).
- **Сессионный лимит сбрасывается каждые 5 часов** (rolling window, стартует с первого сообщения сессии).
- Есть **недельный лимит** на все модели; сбрасывается в фиксированное время недели, закреплённое за аккаунтом (видно в Settings → Usage).
- Anthropic **официально не публикует точное число сообщений**. Независимое тестирование IntuitionLabs (28 февраля 2026) зафиксировало: *«the Pro plan was observed to cap around 40–45 messages per 5 hours, while Max 5× extended to ~200 messages, and Max 20× to ~900»*. При этом, как отмечает TokenMix (2026), Anthropic перестал публиковать фиксированное число сообщений на окно, и любая страница, цитирующая «45 сообщений за 5 часов», повторяет устаревшие цифры 2025 года. Реальное число зависит от длины сообщений, вложений, длины диалога, модели и функции.
- **Opus vs Sonnet:** Opus расходует бюджет быстрее; на Pro для Claude Code Opus доступен только через usage credits (базово Claude Code на Pro — Sonnet). Max-планы имеют два недельных лимита (все модели + отдельно Sonnet).
- **Claude Code и claude.ai делят один пул** лимитов на Pro/Max (Anthropic: usage across claude.ai, Claude Code и Claude Desktop «counts towards the same usage limit»).
- В марте 2026 Anthropic вводил **сниженные 5-часовые лимиты в будни в пиковые часы (5–11 AM PT)** и 31 марта признал, что пользователи упираются в лимиты быстрее ожидаемого (подтверждено TrueFoundry). Ряд вторичных источников (Morph, Deployhyre, TECHSY, ExplainX) сообщает, что **6 мая 2026** Anthropic удвоил 5-часовые лимиты Claude Code для Pro/Max/Team/Enterprise и убрал пиковое урезание — это следует проверять по support.claude.com, так как официальной первичной страницы я не подтвердил.
- Точных чисел токенов/сообщений Anthropic не даёт — это честно отмечается: цифры «~40–45 / ~200 / ~900» — независимые оценки, не официальная гарантия.

### 5. Практический вывод — как максимизировать число изображений в одном чате
- **Есть жёсткий потолок: 20 изображений на ОДНО сообщение** на claude.ai — это не обойти уменьшением размера. Но это лимит на сообщение, а не на весь разговор: можно слать картинки порциями в разных сообщениях.
- **Уменьшение разрешения помогает** косвенно: каждое изображение потребляет визуальные токены по формуле патчей; чем меньше картинка (до ~1568 px по длинной стороне на standard, до 2576 px на high-res), тем меньше токенов и тем позже наступит вытеснение/суммаризация контекста. Держите картинки в диапазоне 200–1568 px по стороне.
- **Размер файла** ограничен 10 MB на claude.ai; сверх — отклонение.
- Чтобы картинки «не пропадали»: не допускать разрастания чата до предела окна (иначе ранние изображения суммаризируются), при работе с многими изображениями — начинать новый чат под каждую партию, и сжимать/уменьшать изображения заранее.
- Жёсткий потолок по числу на сообщение (20) действует **независимо от размера**; размер влияет только на токены и на скорость исчерпания окна.

## Рекомендации
1. **Для выгрузки Telegram (первоочередное):** установить Telegram Lite/Desktop на Mac, войти, экспортировать нужный чат и канал в JSON (для дальнейшей обработки) или HTML (для чтения). Это официально, бесплатно, без риска. Бенчмарк смены плана: если пункта «Export chat history» нет — вы в неправильном клиенте, переустановите Desktop/Lite.
2. **Не использовать Telethon/Pyrogram, если нет опыта с командной строкой** — риск временных ограничений аккаунта; для разовой личной задачи встроенный экспорт полностью достаточен. Порог перехода к API: только если нужен инкрементальный/автоматический экспорт или обход бага Topics без полного дампа.
3. **VK/Instagram:** заказать официальные архивы заранее (готовятся часами-днями), выбрать JSON для Instagram если планируется обработка, HTML — для чтения. Скачать быстро — ссылки живут ограниченное время.
4. **Claude Pro и изображения:** слать картинки партиями ≤20 на сообщение, предварительно уменьшать до ~1568 px, и начинать новый чат для новой партии, чтобы избежать вытеснения ранних изображений. Порог, меняющий тактику: если картинки уже «пропали» — текущий чат достиг управления контекстом, дальше только новый чат.

## Оговорки (актуальность и возможное устаревание)
- Лимиты Claude Anthropic меняет часто (2025–2026 — минимум трижды: недельные каппы в августе 2025, промо в марте 2026, удвоение в мае 2026); точные числа сообщений официально не гарантированы. Проверять Settings → Usage и support.claude.com.
- Справочные страницы Anthropic по контекстному окну не полностью согласованы (200K в общей справке vs 500K/1M в специализированной) — отмечено выше.
- Прямого официального описания «элизии изображений» в claude.ai нет; вывод основан на комбинации Vision-лимитов + механизма суммаризации + пользовательских наблюдений.
- Telegram-баг с Topics-группами (issue #27322) может быть исправлен позже; проверяйте актуальную версию клиента.
- VK/Instagram интерфейсы и сроки могут меняться; функции по состоянию на 2026 работают.
- Часть цифр по лимитам Claude Pro и по дате майского удвоения — из вторичных источников (независимые тесты и блоги), а не из первичной документации Anthropic; это явно помечено в тексте.
