Файл приходит **нативными image-блоками**, минуя все инструменты. Страницы видны как есть: текст, эмодзи-реакции, таймстемпы, пометки `edited`, превью вложений, обрезанные скроллом реплики.

👉 **Рабочий максимум: 50–60 страниц на сессию.**

⚠️ **Обязательно БЕЗ архивирования.** PDF — файлом, прямо в сообщение.

### 2. ФАЙЛЫ ПРОЕКТА 🟢 для текста · 🔴 для картинок

`.pdf` в `/mnt/project` — это **ZIP-контейнеры**, которые система собрала сама:
постранично `N.jpeg` + `N.txt` + `manifest.json`.

```python
import zipfile
z = zipfile.ZipFile('/mnt/project/Тест_МГУ_03_12_2025.pdf')
txt = z.read('1.txt').decode('utf-8')   # постранично: 1.txt, 2.txt, ...
```

#### 🔴 КЛЮЧЕВАЯ НАХОДКА: **система НЕ делает OCR.**
Она вытаскивает **только тот текст, который уже лежал внутри PDF**.
Для каждой страницы `N.txt` создаётся честно — но у скриншотов он **пустой**.

**Доказательство:**

| Файл | Что это | `.txt`-файлов | Реальный текст |
|---|---|---|---|
| `Тест_МГУ_03_12_2025.pdf` | текстовый PDF (из HTML) | 12 | **293 симв. настоящего текста** ✅ |
| `VK_421488_compressed.pdf` | скриншоты | 68 | **0 символов. ПУСТО** ❌ |
| `Приятное130.pdf` | скриншоты Telegram | 30 | **0 символов. ПУСТО** ❌ |
| `Дневник_материальный155.pdf` | фото рукописи | 55 | **0 символов. ПУСТО** ❌ |
| `Димаментор_ч_2.pdf` | скриншоты | 61 стр. | **0 символов. ПУСТО** ❌ |

**Вывод:** проект отдаёт текст **только** там, где текст изначально был.
Скриншот, фотография, рукопись → из проекта **не читаются никак**.

**Побочное наблюдение:** индексация проекта **асинхронна**. Свежезалитый PDF какое-то время лежит сырым (настоящий PDF), потом система его перемалывает в ZIP-контейнер. Оба состояния встречались в одной сессии.

### 3. ZIP-АРХИВ В СООБЩЕНИИ 🔴

**Опровергнутая гипотеза:** *«архив не тратит лимит страниц».*

Формально верно — и **абсолютно бесполезно.**
Архив падает мне на диск. Я вижу байты. **Но посмотреть на страницу не могу.**

**`view` не отдаёт изображения. Канал мёртв.** 11 контролируемых опытов:
PNG / JPEG / WEBP · от 3 КБ до 692 КБ · три разных пути · два владельца файла · чужой системный PNG из дистрибутива Ubuntu — **всё возвращает пустоту.**
`image_search` — тоже. Anthropic API из bash — 401.

👉 **Архив не экономит лимит. Он ОТКЛЮЧАЕТ ЗРЕНИЕ.**
Это не «дешевле», это **ноль**. Из архива достаётся только текстовый слой — а у картинок его нет.

## Три «одинаковых» файла — три разных артефакта (по MD5)
| Канал | Что физически | Размер | Качество |
|---|---|---|---|
| **A. Прямой PDF в чат** | настоящий PDF v1.4, 61 растр. страница | 25.5 МБ | 🥇 максимум |
| **B. PDF в ZIP (аплоад)** | **тот же PDF побитово** (+мусор `__MACOSX`) | 23.4 МБ | 🥈 = A (zip только обходит лимит загрузки) |
| **C. Файл в проекте** | **НЕ PDF** — 61 JPEG 1316×924 + 61 пустой `.txt` + manifest | 8.5 МБ | 🥉 **×3 деградация** |

**A и B — идентичны по MD5.** ZIP не меняет качество, только обходит лимит загрузки.
**C — платформа пережимает в JPEG (×3 потеря) и кладёт пустые `.txt`.**

## 🔴 OCR-бенчмарк (стр. 7, разные обработки) — НОВЫЕ ЦИФРЫ
| Обработка | Полезных символов | Оценка |
|---|---:|---|
| C. проектный JPEG **как есть** | 742 | 🔴 половина текста потеряна |
| C. проектный JPEG + инверсия + 2.5× | 2545 | 🟡 апскейл пожатого |
| **A/B. оригинал 300 dpi + инверсия** | **2660** | 🟢 **эталон** |
| A/B. оригинал 300 dpi + инв + кроп сайдбара | 1956 | 🟢 чище, но кроп срезал края |

**Живой пример деградации:**
- JPEG «как есть»: `«er manu мо надо просто постоянно "лото учитьи тогда»` — рассыпается.
- Оригинал 300dpi + инверсия: `«нет магии, но надо просто постоянно что-то учить и тогда процесс сам к тебе придёт»` — совпадает с глазами.

## 🎯 ДВА ПРАВИЛА OCR (если вообще нужен OCR для цитат)
1. **ИНВЕРСИЯ тёмной темы ОБЯЗАТЕЛЬНА.** Tesseract обучен на чёрном-по-белому. Светлый текст на тёмном → мусор. Инверсия — самый крупный прирост качества.
2. **300 dpi против пожатого JPEG = ×3 полезного текста.** Рендерить оригинал, не проектный JPEG. Апскейл JPEG (2.5×) частично догоняет, но утраченное при сжатии не восстанавливает.
3. Команда: `tesseract -l rus+eng --psm 4`. Русский пакет (`tesseract-ocr-rus`) в чистом окружении **надо доустанавливать**.

## Иерархия каналов (подтверждена количественно)
1. **Есть текстовый слой** (`pypdf`/`.txt` непустой) → **читать кодом.** 100% точность, ноль токенов. Это профтесты, РСВ, резюме психолога.
2. **Слоя нет** (скан/скриншот) → **прямой PDF в чат, vision.** >60 стр. → резать порциями.
3. **Нужны searchable-цитаты со скана** → OCR с инверсией + 300dpi. **Подпорка, не источник смысла** (vision > OCR по смыслу и атрибуции реплик).

## Вилка качество ↔ объём
Прямой PDF = максимум качества, но упирается в лимит страниц.
Проект = всегда под рукой, не жрёт лимит сообщения, но пожатые JPEG.
**Разрешение:** держать всё в проекте для доступности (текст читать оттуда), а **тяжёлые сканы дочитывать прямым PDF порциями 50–60 стр.**
